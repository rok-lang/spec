# nok 언어 사양

**한국어** · [English](../README.md)

> **상태** — 활발한 초안. 한국어 사양 (`ko/`) 이 정본이며 계속 작성 중. 영어 및 기타 언어 번역은 _계획 중_ 이지만 아직 없음 — 현재 영어 진입점은 [상위 README](../README.md) 의 짧은 안내문뿐.

이 저장소는 프로그래밍 언어 **nok** 의 형식 사양이다. 언어의 어휘 구조, 타입 시스템, 표현식, 런타임 모델, ABI, 그리고 주변 툴을 정의한다.

구현은 별도 저장소에 있다.

설계 / 유지보수: [한다민 (Han Damin)](https://github.com/miniex) (`@miniex`).

## nok 이 존재하는 이유

저자가 하고 싶은 모든 걸 할 수 있는 언어 하나. 그게 nok 의 전부다. 특정 사용자층이나 학술적 입장은 노리지 않는다. _저자가 직접 쓰고 싶은 코드_ 가 모든 결정의 중심에 있다.

## 철학

설계는 두 슬로건이 끌고 간다.

> [!IMPORTANT]
> **"언어는 작게, 라이브러리는 풍부하게."**

사양은 가능한 한 적게 정의한다. 숫자 의미론, 형 변환, 컬렉션, 입출력, 동시성 — 언어의 _느낌_ 을 결정짓는 거의 모든 것은 표준 라이브러리가 담는다. 작은 코어는 진화 / 검증 / 교육이 쉽고, 풍부한 라이브러리가 영역 (domain) 의 무게를 짊어진다.

> [!IMPORTANT]
> **"통제 속의 자유."**

nok 은 제약을 두려워하지 않는다. 정적 타입, 닫힌 합 타입, 트레잇-as-타입 금지, 묵시적 승급 금지, AOT-only 컴파일 — 이 모든 결정이 사용자의 선택지를 _좁힌다_. 그 좁아진 공간 안에서 코드는 _예측 가능_ 하고 _깊게 통제_ 가능해진다.

- **언어가 통제하는 자리** — 타입·디스패치·메모리 모델·평가 순서. 한 번에 잘 정해서, 사용자가 매 줄마다 그 비용을 치르지 않게 한다.
- **사용자가 자유로운 자리** — 라이브러리 설계, 도메인 모델링, 알고리듬, 코드 구조. 메타 시스템이 언어 자체의 _자기 확장_ 을 허용해, 언어가 강요하지 않고 라이브러리가 의미를 결정한다.

자유와 통제는 대립이 아니다 — _잘 통제된 코어 위에서만_ 자유로운 영역이 안전하게 살 수 있다.

두 슬로건의 본격 논의는 [`refs-lang/000-meta/`](refs-lang/000-meta/) 에서 이어진다.

## 레이아웃

최상위 디렉토리는 언어별로 나뉜다. 각 언어 디렉토리에 두 종류의 참조 (reference) 가 들어간다.

- [`refs-lang/`](refs-lang/) — 언어 참조 (어휘, 타입, 표현식, 런타임 모델, ABI, 툴)
- [`refs-libstd/`](refs-libstd/) — 표준 라이브러리 참조

번역이 추가되면 이 구조를 그대로 따라간다 (`../en/refs-lang/`, `../ja/refs-lang/` 등).

## 정본

> [!IMPORTANT]
> **한국어 (`ko/`) 가 정본이다.** 다른 언어 디렉토리는 — 만들어지면 — 모두 번역.
>
> 번역이 한국어 텍스트와 어긋나면 _한국어가 우선_. 번역은 동기화되지만 설계상 한국어보다 늦는다.

이 원칙은 무조건이다. 명확화 / 결정 / 수정은 한국어에서 먼저 일어나고, 번역자가 그 뒤를 따른다. 의심스러우면 `ko/` 를 보면 된다.
