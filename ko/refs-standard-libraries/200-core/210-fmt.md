# 2.10. fmt — 포맷 트레잇

`rok::core::fmt` 모듈은 값을 사람이 읽을 수 있는 문자열로 변환하는 트레잇 패밀리를 정의합니다. f-string `f"{x}"`, `f"{x:?}"`, `f"{n:08b}"` 등 모든 형식 지정자(format spec) 는 본 장의 트레잇으로 dispatch 됩니다.

[refs-lang 1.7.4 f-string format spec](../../refs-lang/001-lexical/107-string-literals.md) 의 렉시컬 분해와 이 장의 트레잇 dispatch 가 함께 f-string 의 의미를 결정합니다.

## 2.10.1. 8 트레잇 매핑 — type 기호 별

f-string format spec `f"{expr:[fill][align][sign][#][0][width][.precision][type]}"` 의 `type` 기호(마지막 문자) 가 dispatch 할 트레잇을 결정하며, 그 매핑은 다음 표와 같습니다.

| `type` 기호 | 트레잇     | 의미                     | 예시                |
|-------------|------------|--------------------------|---------------------|
| (없음), `s` | `Display`  | 사람-친화적 기본 출력    | `f"{x}"` `f"{x:s}"` |
| `?`         | `Debug`    | 디버그 / 로그 출력       | `f"{x:?}"`          |
| `b`         | `Binary`   | 2진수                    | `f"{n:b}"`          |
| `o`         | `Octal`    | 8진수                    | `f"{n:o}"`          |
| `x`         | `LowerHex` | 소문자 16진수            | `f"{n:x}"`          |
| `X`         | `UpperHex` | 대문자 16진수            | `f"{n:X}"`          |
| `e`         | `LowerExp` | 소문자 지수 표기 (1.5e3) | `f"{x:e}"`          |
| `E`         | `UpperExp` | 대문자 지수 표기 (1.5E3) | `f"{x:E}"`          |

위 8 개가 본 장이 정의하는 권위 트레잇입니다. C 의 `printf` 가 두던 `d` / `f` / `g` 같은 type 강제 기호는 별도 트레잇으로 두지 않고 `Display` 와 정밀도 spec (`{x:.2}` 등) 으로 충분히 표현할 수 있도록 통합되어 있습니다.

## 2.10.2. `Formatter` — 출력 어댑터

모든 fmt 트레잇 메서드는 문자열을 직접 반환하지 않으며, 그 대신 `Formatter` 에 직접 **쓰는** 방식을 취합니다.

```rok
struct Formatter {
    // 내부: 출력 버퍼 + 현재 spec 상태 (fill/align/width/precision/type/...)
}

impl Formatter {
    fn write_str(ref self, s: str) throws (FmtError);
    fn write_char(ref self, c: char) throws (FmtError);
    fn pad(ref self, s: str) throws (FmtError);             // align/width/fill 적용
    fn pad_integral(
        ref self,
        is_nonnegative: bool,
        prefix: str,                                        // "0x" / "0o" / "0b" / ""
        buf: str,                                            // 절댓값을 진수 변환한 결과
    ) throws (FmtError);                                    // sign + alternate prefix + zero/space pad

    fn fill(self) -> char;          // spec 의 fill 문자
    fn align(self) -> Alignment;    // Left, Right, Center, Equal
    fn sign(self) -> Sign | none;   // Plus, Minus, Space
    fn alternate(self) -> bool;     // # 플래그
    fn pad_zero(self) -> bool;      // 0 플래그
    fn width(self) -> usize | none;
    fn precision(self) -> usize | none;
}
```

이 패턴은 불필요한 str 할당 없이 직접 출력 버퍼에 쓸 수 있게 해 줍니다. 따라서 사용자 트레잇 impl 도 `f.write_str("...")` 이나 `f.pad("...")` 만 호출하면 align, width, fill 처리는 Formatter 가 알아서 처리해 줍니다.

## 2.10.3. `Display` — 사람-친화적 출력

```rok
#[lang("display_trait")]
trait Display {
    fn fmt(self, ref f: Formatter) throws (FmtError);
}
```

`f"{x}"` 의 기본 dispatch 이며, 사용자가 읽기 쉬운 문자열 표현을 만들어 내는 데 쓰입니다.

```rok
impl Display for i32 {
    #[intrinsic("rok.fmt.i32")]
    fn fmt(self, ref f: Formatter) throws (FmtError);
}

impl Display for str {
    fn fmt(self, ref f: Formatter) throws (FmtError) {
        try f.pad(self.as_str())
    }
}

impl Display for bool {
    fn fmt(self, ref f: Formatter) throws (FmtError) {
        try f.pad(if self { "true" } else { "false" })
    }
}
```

### 사용 예

다음과 같이 다양한 형식 지정자와 함께 사용할 수 있습니다.

```rok
let s1 = f"{42}";              //→ "42"
let s2 = f"{3.14}";            //→ "3.14"
let s3 = f"hello {name}!";     //→ "hello Alice!"
let s4 = f"{x:>10}";           //→ "       42"  (right-align, width 10)
let s5 = f"{x:0>5}";           //→ "00042"      (fill 0, right-align, width 5)
```

### 사용자 정의

사용자 타입에 대해서도 다음과 같이 직접 `Display` 를 구현할 수 있습니다.

```rok
struct Point { x: f64; y: f64; }

impl Display for Point {
    fn fmt(self, ref f: Formatter) throws (FmtError) {
        try f.write_str("(");
        try self.x.fmt(f);
        try f.write_str(", ");
        try self.y.fmt(f);
        try f.write_str(")");
    }
}

let p = Point { x: 1.5, y: 2.5 };
let s = f"{p}";                //→ "(1.5, 2.5)"
```

`Display` 는 사용자가 직접 구현해야 하며, derive 로 자동 생성되지 않습니다. **표현 결정** 은 어디까지나 타입 디자이너의 책임이기 때문입니다.

## 2.10.4. `Debug` — 디버그 / 로그 출력

```rok
#[lang("debug_trait")]
trait Debug {
    fn fmt(self, ref f: Formatter) throws (FmtError);
}
```

`f"{x:?}"` 의 dispatch 에 해당하며, 문자열로 round-trip 이 가능한 디버그 표현을 목표로 삼습니다.

```rok
impl Debug for i32 {
    #[intrinsic("rok.fmt.debug.i32")]
    fn fmt(self, ref f: Formatter) throws (FmtError);
}

impl Debug for str {
    fn fmt(self, ref f: Formatter) throws (FmtError) {
        // "hello" → `"hello"`  (따옴표 + 이스케이프 포함)
        try f.write_char('"');
        for c in self.chars() {
            match c {
                '"'  => try f.write_str("\\\""),
                '\\' => try f.write_str("\\\\"),
                '\n' => try f.write_str("\\n"),
                _    => try f.write_char(c),
            }
        }
        try f.write_char('"');
    }
}
```

### Display vs Debug 차이

두 트레잇은 목적이 다르며, 다음 표에 그 차이를 정리해 두었습니다.

| 측면     | `Display`                   | `Debug`                                    |
|----------|-----------------------------|--------------------------------------------|
| 대상     | end-user                    | 개발자                                     |
| 정확성   | 가독성 우선                 | 정보 손실 없음 (round-trip 가능 지향)      |
| 따옴표   | 문자열 그대로 (따옴표 없음) | 문자열을 `"..."` 로 감쌈 (이스케이프 포함) |
| 컨테이너 | 대개 정의되지 않음          | 모든 컬렉션 자동                           |
| derive   | **불가** (수동 구현)        | **가능** (`#[derive(Debug)]`)              |

```rok
let s = "hello\nworld";
let d1 = f"{s}";        //→ hello
                        //   world          (Display — 그대로)
let d2 = f"{s:?}";      //→ "hello\nworld"  (Debug — 이스케이프)
```

### 사용자 정의 / derive

```rok
#[derive(Debug)]
struct Point { x: f64; y: f64; }

let p = Point { x: 1.5, y: 2.5 };
let s = f"{p:?}";              //→ "Point { x: 1.5, y: 2.5 }"
```

`Debug` 는 모든 필드의 Debug 출력을 합성하는 방식으로 자동 derive 가 가능합니다.

## 2.10.5. `Binary` / `Octal` / `LowerHex` / `UpperHex` — 진법

```rok
trait Binary   { fn fmt(self, ref f: Formatter) throws (FmtError); }
trait Octal    { fn fmt(self, ref f: Formatter) throws (FmtError); }
trait LowerHex { fn fmt(self, ref f: Formatter) throws (FmtError); }
trait UpperHex { fn fmt(self, ref f: Formatter) throws (FmtError); }
```

이 트레잇들은 정수 타입에만 의미가 있으며, `i32`, `i64`, `u32`, `u64`, `usize`, `isize`, `int` 가 모두 구현합니다. 부동소수에 대해서는 구현되어 있지 않습니다.

또한 `#`(alternate) 플래그가 prefix 를 추가해 주는데, 그 동작은 다음 예시에서 확인할 수 있습니다.

```rok
let n: u32 = 0xCAFE;
let s1 = f"{n:b}";       //→ "1100101011111110"
let s2 = f"{n:#b}";      //→ "0b1100101011111110"

let s3 = f"{n:o}";       //→ "145376"
let s4 = f"{n:#o}";      //→ "0o145376"

let s5 = f"{n:x}";       //→ "cafe"
let s6 = f"{n:X}";       //→ "CAFE"
let s7 = f"{n:#x}";      //→ "0xcafe"

let s8 = f"{n:08b}";     //→ "1100101011111110"  (이미 8자리 초과)
let s9 = f"{42:08b}";    //→ "00101010"
```

prefix 매핑은 다음 표에 정리되어 있습니다.

| 트레잇     | `#` prefix |
|------------|------------|
| `Binary`   | `0b`       |
| `Octal`    | `0o`       |
| `LowerHex` | `0x`       |
| `UpperHex` | `0x`       |

prefix 는 표준 라이브러리가 **내장**해서 처리하므로, 사용자 impl 쪽에서는 prefix 를 따로 처리하지 않아도 됩니다.

## 2.10.6. `LowerExp` / `UpperExp` — 지수 표기

```rok
trait LowerExp { fn fmt(self, ref f: Formatter) throws (FmtError); }
trait UpperExp { fn fmt(self, ref f: Formatter) throws (FmtError); }
```

이 트레잇들은 부동소수(`f32`, `f64`) 를 주 대상으로 하며, precision 이 mantissa 의 자릿수를 결정합니다.

```rok
let x: f64 = 12345.678;
let s1 = f"{x:e}";       //→ "1.2345678e4"
let s2 = f"{x:.3e}";     //→ "1.234e4"      (precision = 3)
let s3 = f"{x:E}";       //→ "1.2345678E4"
let s4 = f"{x:.2E}";     //→ "1.23E4"
```

정수에 대해서도 구현이 가능하여 `f"{42:e}"` 가 `"4.2e1"` 을 만들 수 있지만, 일반적으로는 `f64::from(n)` 으로 변환한 뒤 사용하는 편을 권장합니다.

## 2.10.7. f-string format spec 전체 문법

[refs-lang 1.7.4](../../refs-lang/001-lexical/107-string-literals.md) 가 권위에 해당하며, 본 절은 표준 라이브러리 측 dispatch 표만 요약해서 보여 줍니다.

```
spec    = [fill][align][sign][#][0][width][.precision][type]
align   = "<" | ">" | "^" | "="
sign    = "+" | "-" | " "
type    = "" | "s" | "?" | "b" | "o" | "x" | "X" | "e" | "E"
width     = unsigned-int | "${" expr "}"
precision = unsigned-int | "${" expr "}"
fill      = any single char (default: space)
```

### 동적 spec 삽입 (`${...}`)

precision, width, 또는 spec 전체를 런타임 값으로부터 받아 오고 싶을 때는 `${...}` 문법을 사용할 수 있습니다.

```rok
let prec: usize = 4;
let width: usize = 10;
let x: f64 = 3.141592653589793;

let s1 = f"{x:.${prec}}";              //→ "3.1416"        (precision 동적)
let s2 = f"{x:>${width}.${prec}}";     //→ "    3.1416"    (width + precision 동적)
let s3 = f"{x:${full_spec}}";          //→ ...             (전체 spec 동적)
```

`${expr}` 은 **spec** 안에서만 의미를 가지며, 문자열 본문의 `$` 은 그대로 남습니다. 예컨대 `f"cost: $100"` 은 그대로 `"cost: $100"` 이 됩니다.

### lexer 단계 분해

f-string 은 lexer 가 다음과 같이 토큰열로 분해합니다(refs-lang 107.7.3 참고).

```
F_STRING_START  "f\""
STRING_PART     "hello "
EXPR_START      "{"
<expression>
SPEC_PART       ":>10.2f"        (있으면)
EXPR_END        "}"
STRING_PART     " world"
F_STRING_END    "\""
```

각 EXPR_START..EXPR_END 안의 표현식은 일반 식 파서로 재진입하여 처리되며, SPEC_PART 가 바로 이 장의 트레잇 dispatch 를 매개합니다.

## 2.10.8. align / fill / width / precision

`Formatter::pad` 는 spec 의 align, fill, width 를 자동으로 처리해 주므로, 사용자 impl 은 **컨텐츠**만 만들면 됩니다.

```rok
let n: i32 = 42;

f"{n}";              //→ "42"            (기본)
f"{n:5}";            //→ "   42"         (width 5, default right-align for numbers)
f"{n:<5}";           //→ "42   "         (left)
f"{n:>5}";           //→ "   42"         (right)
f"{n:^5}";           //→ " 42  "         (center)
f"{n:0>5}";          //→ "00042"         (fill 0)
f"{n:*^7}";          //→ "**42***"       (fill *, center, width 7)
f"{n:=5}";           //→ "  +42"         (sign-aware: align 채워 +/- 끝)
```

또한 `precision` 도 같은 방식으로 적용됩니다.

```rok
let x: f64 = 3.141592653589793;
f"{x:.2}";           //→ "3.14"          (소수점 이하 2)
f"{x:.0}";           //→ "3"
f"{x:10.4}";         //→ "    3.1416"    (width 10, precision 4)
```

문자열에 적용되는 precision 은 최대 길이 잘라내기로 해석됩니다.

```rok
f"{:.5}", "hello world";    //→ "hello"
```

## 2.10.9. 모듈 매핑

각 타입별로 어떤 트레잇이 구현되어 있는지는 다음 표에 정리되어 있습니다.

| 타입          | Display | Debug          | Binary | Octal | LowerHex | UpperHex | LowerExp | UpperExp |
|---------------|---------|----------------|--------|-------|----------|----------|----------|----------|
| `i32`,`i64`   | ✓       | ✓              | ✓      | ✓     | ✓        | ✓        | ✓        | ✓        |
| `u32`,`u64`   | ✓       | ✓              | ✓      | ✓     | ✓        | ✓        | ✓        | ✓        |
| `int`         | ✓       | ✓              | ✓      | ✓     | ✓        | ✓        | ✓        | ✓        |
| `f32`,`f64`   | ✓       | ✓              | ✗      | ✗     | ✗        | ✗        | ✓        | ✓        |
| `float`       | ✓       | ✓              | ✗      | ✗     | ✗        | ✗        | ✓        | ✓        |
| `bool`        | ✓       | ✓              | ✗      | ✗     | ✗        | ✗        | ✗        | ✗        |
| `char`        | ✓       | ✓              | ✗      | ✗     | ✗        | ✗        | ✗        | ✗        |
| `str`         | ✓       | ✓              | ✗      | ✗     | ✗        | ✗        | ✗        | ✗        |
| `List<T>`     | ✗       | ✓ (T:Debug)    | ...    | ...   | ...      | ...      | ...      | ...      |
| `Dict<K,V>`   | ✗       | ✓ (K,V:Debug)  | ...    | ...   | ...      | ...      | ...      | ...      |
| `Set<T>`      | ✗       | ✓ (T:Debug)    | ...    | ...   | ...      | ...      | ...      | ...      |
| `(A, B, ...)` | ✗      | ✓ (모두 Debug) | ...    | ...   | ...      | ...      | ...      | ...      |
| `T \| none`   | ✗       | ✓ (T:Debug)    | ...    | ...   | ...      | ...      | ...      | ...      |
| `Result<T,E>` | ✗       | ✓ (T,E:Debug)  | ...    | ...   | ...      | ...      | ...      | ...      |

이러한 매핑의 바탕에는 다음과 같은 **원칙** 이 있습니다. 첫째, `Display` 는 스칼라, 문자열, 그리고 Display 를 직접 impl 한 사용자 타입에만 부여하며 컨테이너에는 두지 않습니다. 둘째, `Debug` 는 거의 모든 타입에 부여하고 derive 로 자동 생성합니다. 셋째, 진법과 지수 트레잇은 숫자 타입에만 부여하며, 컨테이너에는 두지 않습니다.

## 2.10.10. `#[derive(Debug)]`

```rok
#[derive(Debug)]
struct User { id: u64; name: str; }

let u = User { id: 1, name: "Alice" };
let s = f"{u:?}";          //→ User { id: 1, name: "Alice" }
```

derive 의 동작 방식은 다음과 같이 정리할 수 있습니다. 우선 struct 는 `TypeName { field1: <field1:?>, field2: <field2:?>, ... }` 형태로 출력되며, tuple struct 는 `TypeName(<f1:?>, <f2:?>, ...)` 형태로 출력됩니다. enum 의 경우에는 `VariantName` 또는 `VariantName(...)` / `VariantName { ... }` 형태로 출력됩니다. 다만 derive 를 적용하려면 모든 필드가 (재귀적으로) `Debug` 를 구현하고 있어야 합니다.

한편 `#[derive(Display)]` 는 존재하지 않습니다. 표현을 결정하는 일은 사용자의 책임이기 때문입니다.

## 2.10.11. REPL / `print` / 자동 출력

[refs-lang 9.7 JIT 셀 실행 흐름](../../refs-lang/009-tools/907-jit-cells.md) 의 REPL 절에서 다음과 같이 정의합니다.

```rok
> let x = 42;
x: i32 = 42

> 1 + 2
i32 = 3

> "hello"
str = "hello"
```

REPL 에서 마지막 식을 자동으로 출력할 때는 `Display` 가 구현되어 있으면 Display 를, 그렇지 않으면 Debug 를 사용합니다. 표시 라인은 `{type_name_of}: {Display 또는 Debug}` 형태입니다.

이와 달리 `println` 이나 `print` 는 오로지 `Display` 만 dispatch 합니다.

```rok
println(f"x = {x}");          // Display
println(f"x = {x:?}");        // Debug (spec 명시)
```

## 2.10.12. `FmtError` — 포맷 에러

```rok
struct FmtError;     // unit-like — 메시지 없는 단순 에러
```

`Formatter::write_str` 등에서 쓰기에 실패했을 때 반환되는 타입이며, 일반적으로는 출력 buffer 나 stream 이 가득 차거나 I/O 에 실패했을 때 발생합니다. f-string 자체는 GC string 빌더라서 실패할 일이 없으나, `Write` 트레잇으로 stream 에 직접 쓰는 경우에는 실패할 수 있습니다.

본 장의 모든 fmt 트레잇 메서드는 `throws (FmtError)` 시그니처를 가지므로, 일반적인 사용에서는 호출을 `try` 로 표시해 전파만 해 주면 됩니다.

## 2.10.13. 다른 언어와의 비교

다음 표는 Rust, Python 과 비교하여 rok 의 fmt 설계가 어디에 위치하는지를 보여 줍니다.

| 측면               | Rust `Display`/`Debug` | Python `__str__`/`__repr__` | rok                                  |
|--------------------|------------------------|-----------------------------|--------------------------------------|
| 인간 / 디버그 분리 | ✓ 트레잇 분리          | ✓ 메서드 분리               | ✓ 트레잇 분리                        |
| Debug derive       | `#[derive(Debug)]`     | 자동 default                | `#[derive(Debug)]`                   |
| Display derive     | **불가**               | **불가** (직접 구현)        | **불가**                             |
| 진법 / 지수 분리   | ✓ 8 트레잇             | format spec 만 있음         | ✓ 8 트레잇 (`b`/`o`/`x`/`X`/`e`/`E`) |
| 동적 spec          | 위치 인자 (`{0:.*}`)   | f-string `{:.{prec}}`       | `${...}` 식 ($-sigil)                |
| spec syntax        | Python-like            | PEP 3101                    | Python-like + `${...}`               |

rok 이 가장 두드러지게 차별화되는 지점은, 동적 spec 삽입을 `${...}` 로 시각적으로 분리하여 Python 의 `{:.{prec}}` 같은 중첩 괄호 모호성을 회피했다는 데 있습니다. 이 표기는 JS, Kotlin, Scala 의 `$` sigil 과도 동형을 이룹니다.

## 2.10.14. derive 정책 요약

`#[derive(...)]` 목록에는 `Debug` 만 포함됩니다. `Display` 는 derive 대상이 아닙니다. 사용자에게 보이는 표면은 도메인마다 결정이 달라지는 영역이라 자동 도출이 어울리지 않으며, `Display` 의 의미 있는 default 형태도 마땅하지 않기 때문입니다. 따라서 표시가 필요한 타입에는 `Display` 를 직접 구현하는 편이 권장됩니다.
