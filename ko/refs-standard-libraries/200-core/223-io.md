# 2.23. `io::` - 바이트 스트림과 표준 입출력

`rok::core::io`에는 Rok의 입출력 어휘가 모두 모여 있습니다. 에러 타입, 스트림 트레잇 `Read`, `BufRead`, `Write`, `Seek`와 그 async 짝인 `AsyncRead`, `AsyncBufRead`, `AsyncWrite`, `AsyncSeek`, `Close`와 `AsyncClose`, 버퍼, `Cursor`, `copy`, 표준 스트림이 여기 있습니다. OS에 닿는 타입(`File`, 소켓, TLS 연결, 자식 프로세스 pipe)은 `rok::std`에 있고 이 트레잇들을 구현합니다. 이 모듈의 내용은 타깃에 의존하지 않으며, 표준 스트림은 모든 타깃에 있습니다(브라우저에서는 stdout / stderr가 호스트 콘솔로 가고 stdin은 끝에 있습니다, [0.1.4](../000-meta/001-tier-model.md)).

prelude가 모듈 `io`와 트레잇 `Read`, `Write`, `AsyncRead`, `AsyncWrite`를 들여오므로 `io::stdin()`, `io::BufReader::new(f)`, `f.read(buf)`에는 `use`가 필요 없습니다. `BufRead`, `Seek`, `AsyncBufRead`, `AsyncSeek`는 바운드에서 `io::BufRead`처럼 적고, 그 메서드는 가져오지 않아도 찾아집니다. `rok::std::io`는 없습니다.

스트림 메서드의 정의는 하나뿐입니다. `File`, `TcpStream`, `UnixStream`, `tls::Client`, `tls::Server`에는 고유 `read` / `write` / `read_to_end` / `flush`나 그 `_async` 짝이 없고, 호출은 트레잇을 거쳐 찾아집니다.

## 2.23.0. `IoError`

```rok
struct IoError { .. }      // 비공개 필드 (0.5.10)

#[non_exhaustive]
enum IoErrorKind {
    Other,                // 그 밖의 errno 나 Windows 코드
    NotFound,             // ENOENT; Windows: ERROR_FILE_NOT_FOUND, ERROR_PATH_NOT_FOUND, ERROR_INVALID_DRIVE, ERROR_ENVVAR_NOT_FOUND, WSAHOST_NOT_FOUND, WSANO_DATA
    PermissionDenied,     // EACCES, EPERM; Windows: ERROR_ACCESS_DENIED, ERROR_WRITE_PROTECT, ERROR_PRIVILEGE_NOT_HELD, WSAEACCES
    AlreadyExists,        // EEXIST; Windows: ERROR_FILE_EXISTS, ERROR_ALREADY_EXISTS
    NotADirectory,        // ENOTDIR; Windows: ERROR_DIRECTORY
    IsADirectory,         // EISDIR; Windows: ERROR_DIRECTORY_NOT_SUPPORTED
    DirectoryNotEmpty,    // ENOTEMPTY; Windows: ERROR_DIR_NOT_EMPTY
    InvalidInput,         // EINVAL; Windows: ERROR_INVALID_PARAMETER, ERROR_INVALID_NAME, WSAEINVAL
    BrokenPipe,           // EPIPE; Windows: ERROR_BROKEN_PIPE, ERROR_NO_DATA, WSAESHUTDOWN
    Interrupted,          // EINTR; Windows: WSAEINTR
    WouldBlock,           // EAGAIN; Windows: WSAEWOULDBLOCK, ERROR_LOCK_VIOLATION (다른 핸들이 잠근 범위)
    TimedOut,             // ETIMEDOUT, 시간 제한; Windows: ERROR_TIMEOUT, WSAETIMEDOUT
    StorageFull,          // ENOSPC; Windows: ERROR_HANDLE_DISK_FULL, ERROR_DISK_FULL
    CrossesDevices,       // EXDEV; Windows: ERROR_NOT_SAME_DEVICE
    Unsupported,          // ENOTSUP, ENOSYS; Windows: ERROR_NOT_SUPPORTED, ERROR_CALL_NOT_IMPLEMENTED, WSAEOPNOTSUPP
    UnexpectedEof,        // 기대한 바이트 전에 끝남 (read_exact 등)
    InvalidData,          // 형식에 맞지 않는 데이터 (UTF-8 등)
    WriteZero,            // 다 쓰기 전에 쓰기가 0 바이트를 받음
    FilesystemLoop,       // ELOOP; follow_symlinks: false 인 열기의 마지막 심볼릭 링크; Windows: ERROR_STOPPED_ON_SYMLINK, ERROR_CANT_RESOLVE_FILENAME
    ResourceBusy,         // EBUSY, ETXTBSY; Windows: ERROR_SHARING_VIOLATION (다른 핸들의 공유 모드)
}

impl IoError {
    fn new(kind: IoErrorKind, message: str) -> IoError;        // 라이브러리가 낸 오류: os_code() 는 none
    fn from_os_code(code: i32, context: str = "") -> IoError;  // kind 와 message 는 OS 에서; context (경로, 호출) 가 비어 있지 않으면 메시지 앞에 붙음
    fn kind(self) -> IoErrorKind;
    fn os_code(self) -> i32 | none;      // errno (Windows: GetLastError / WSA 코드); 라이브러리가 낸 오류는 none
    fn message(self) -> str;
}
// IoError 는 Display, Debug, Error, PartialEq, Eq, Clone 을 구현;
// IoErrorKind 는 PartialEq, Eq, Clone, Copy, Hash, Debug, Display ("not found") 를 구현

impl IoErrorKind {
    fn of_os(code: i32) -> IoErrorKind; // OS 에러 코드의 종류
}
```

`kind()`는 OS 에러 코드에서 정해집니다(`UnexpectedEof`, `InvalidData`, `WriteZero`는 라이브러리가 정합니다). 코드 자체는 `os_code()`이고, OS의 설명(런타임의 strerror)은 `message()`입니다. 라이브러리가 직접 낸 에러(`IoError::new(InvalidInput, "..")`)와 이름 풀이에 실패한 에러([3.2.4](../300-std/302-net.md))의 `os_code()`는 `none`입니다. resolver(EAI) 코드는 OS 에러 코드가 아니기 때문입니다. 이런 이름 풀이 실패는 resolver의 메시지를 그대로 두고, 이름이 없으면 `NotFound`, 그 밖에는 `Other`입니다. Windows에서는 이름 풀이가 Winsock 코드로 실패하며, `os_code()`는 그 코드를 돌려줍니다. `IoErrorKind`는 `#[non_exhaustive]`라서 `rok::core` 밖의 `match`에는 `_` 갈래가 필요합니다.

## 2.23.1. `Read`

```rok
trait Read {
    fn read(ref self, buf: SliceMut<u8>) throws (IoError) -> usize;  // buf[0..n] 을 채움; 0 = 끝 (또는 빈 buf)

    // 저수준
    fn read_vectored(ref self, bufs: Slice<SliceMut<u8>>) throws (IoError) -> usize;  // 기본: 비지 않은 첫 버퍼
    fn read_exact(ref self, buf: SliceMut<u8>) throws (IoError);                      // buf 전부, 모자라면 UnexpectedEof
    fn read_to_end_into(ref self, out: List<u8>) throws (IoError) -> usize;           // 나머지를 덧붙임; 개수

    // 편의
    fn read_to_end(ref self) throws (IoError) -> List<u8>;
    fn read_to_str(ref self) throws (IoError) -> str;           // UTF-8 이 아니면 InvalidData
    fn bytes(ref self) -> Bytes<Self>;                          // 뷰; TryIterator<Item = u8, Error = IoError>
    fn take(ref self, limit: u64) -> Take<Self>;                // 뷰; 최대 limit 바이트
    fn chain<R: Read>(self, next: R) -> Chain<Self, R>;         // 둘 다 소유: 이 스트림 다음에 next

    // 소유하는 형태
    fn into_bytes(self) -> Owned<Bytes<Self>, Self>;
    fn into_take(self, limit: u64) -> Owned<Take<Self>, Self>;
}
```

필수 메서드는 `read` 하나입니다. 버퍼는 `SliceMut<u8>`입니다([2.9](209-collections.md)). `List<u8>`는 리스트 전체의 뷰로 넘어가고, `buf[a:b]`로 그 일부에 읽어 들일 수 있습니다. `read_to_end_into`는 리스트의 여유 용량에 먼저 0을 채우지 않고 바로 읽습니다. `read_to_end`의 정확한 저수준 형태입니다.

`bytes`와 `take`(그리고 `lines`, `split`, `bytes_async`, `lines_async`, `TcpListener::incoming`)는 스트림의 범위 한정 뷰를 돌려줍니다. 어댑터는 스트림을 거쳐 읽고, 스트림의 소유자는 하나 그대로이며([2.13.4](213-marker.md)) 닫는 것도 그 소유자입니다. 뷰는 잠금 가드의 값처럼([2.16.3](216-sync.md#2163-mutext-배타적-잠금)) 스트림 소유자의 범위 안에 머뭅니다. 뷰를 돌려주거나, 그 범위 뒤까지 저장하거나, 간직하는 함수에 넘기거나, 스트림을 닫거나 옮긴 뒤에 쓰면 컴파일 에러 `E0140`입니다. 스트림을 읽기만 하는 호출은 스트림을 빌려줄 뿐이라(`r.capacity()`, `f"{r:?}"`, [2.13.4](213-marker.md)처럼 호출된 쪽이 간직하지 않는 값 매개변수) 뷰는 계속 쓸 수 있습니다. 뷰는 `Send`도 `Sync`도 아니므로 task가 캡처할 수 없습니다. 스트림을 `ref r`로 받는 도우미 함수는 그 뷰를 돌려줄 수 있습니다. 그러면 뷰는 호출자의 스트림에 묶입니다.

`into_` 형태는 소유하는 어댑터입니다. `r.into_lines()`는 `r`을 받아 `Owned<V, R>`를 돌려줍니다. 이 값은 뷰 `V`처럼 반복하고(읽고, 스트림으로 내놓고), 자신과 함께 `r`을 닫으며(`Close` / `AsyncClose`), `into_inner()`로 `r`을 돌려줍니다. 소유자의 범위 안에서는 뷰를 씁니다(`using r = .. { try for l in r.lines() { .. } }`). 어댑터가 범위를 벗어나야 할 때, 곧 함수에서 돌려주거나 구조체에 두거나 task로 옮길 때는 소유하는 형태를 씁니다. `chain`은 언제나 두 스트림을 소유합니다. 둘 다 닫고, `into_inner()`는 둘을 짝으로 돌려줍니다. `bytes`는 바이트마다 `read`를 한 번 부르므로 버퍼 없는 스트림은 먼저 `BufReader`로 감쌉니다.

## 2.23.2. `BufRead`

```rok
trait BufRead: Read {
    // 저수준
    fn fill_buf(ref self) throws (IoError) -> Slice<u8>;    // 버퍼의 바이트, 비면 다시 채움; 비어 있으면 끝
    fn consume(ref self, n: usize);                         // 버퍼의 n 바이트를 읽은 것으로 표시; 넘으면 panic (`BufReader::consume: ..`)
    fn read_until(ref self, delim: u8, out: List<u8>) throws (IoError) -> usize;  // delim 까지 덧붙임; 0 = 끝
    fn read_line(ref self, out: StrBuf) throws (IoError) -> usize;                // \n 을 포함한 한 줄을 덧붙임; 0 = 끝
    fn skip_until(ref self, delim: u8) throws (IoError) -> usize;

    // 편의
    fn lines(ref self) -> Lines<Self>;                  // 뷰; TryIterator<Item = str>, \n / \r\n 제거
    fn split(ref self, delim: u8) -> Split<Self>;       // 뷰; TryIterator<Item = List<u8>>, delim 제거

    // 소유하는 형태 (2.23.1)
    fn into_lines(self) -> Owned<Lines<Self>, Self>;
    fn into_split(self, delim: u8) -> Owned<Split<Self>, Self>;
}

fn read_line() throws (IoError) -> str | none;          // stdin 의 다음 줄, \n / \r\n 제거; 끝이면 none
```

줄 단위와 구분자 단위 읽기는 `BufRead`에만 있으므로 바이트마다 시스템 호출을 하는 일이 없습니다. `read_line`은 `StrBuf`에 덧붙이고 바이트 수를 돌려주며, 끝에서는 `0`을 돌려줍니다. UTF-8이 아닌 줄은 `InvalidData`입니다. `io::read_line()`은 표준 입력용 편의 형태입니다. 버퍼 없는 스트림은 감싸서 쓰고, 감싼 값을 닫습니다. `using r = io::BufReader::new(f) { try for l in r.lines() { .. } }`처럼 쓰거나, `io::BufReader::new(f).into_lines()`로 소유합니다.

`BufRead`는 `BufReader<R>`, `Cursor<T>`, `Stdin`, `Empty`가 구현합니다. `fill_buf`가 돌려준 뷰는 스트림에 대한 다음 호출 전까지 유효합니다. 버퍼에 있는 바이트를 넘겨 `consume`하면 호출자의 버그이므로 타입 이름을 밝히며 panic합니다(`BufReader::consume: 9 bytes past the 4 buffered; consume at most what fill_buf returned`, `Cursor::consume`, `Stdin::consume`도 같음).

## 2.23.3. `Write`와 `Close`

```rok
trait Write {
    fn write<B: AsBytes>(ref self, buf: B) throws (IoError) -> usize;   // buf 의 앞부분; 그 길이
    fn flush(ref self) throws (IoError);

    // 저수준
    fn write_vectored(ref self, bufs: Slice<Slice<u8>>) throws (IoError) -> usize;  // 기본: 비지 않은 첫 버퍼

    // 편의
    fn write_all<B: AsBytes>(ref self, buf: B) throws (IoError);        // buf 전부; 쓰기가 0 을 받으면 WriteZero
    fn write_display<T: Display>(ref self, x: T) throws (IoError);      // Display 로 x 를 씀, 전체 str 을 만들지 않음
}

#[lang("close_trait")]
trait Close {
    fn close(self) throws (IoError);
}
```

`write`와 `write_all`은 `AsBytes`라면 무엇이든 받습니다([2.11](211-conversion.md)). `str`, `List<u8>`, `Slice<u8>`, `[u8; N]`을 넘길 수 있습니다. 서식 있는 출력은 f-string으로 씁니다. `try w.write_all(f"{x}\n")`.

`write_display`는 값 하나를 `print`가 보여 주는 대로 씁니다. 값이 만들어 내는 대로 조각 단위로 쓰므로(`Formatter::from_sink`, [2.10.2](210-fmt.md)) 큰 값도 하나의 `str`로 만들지 않습니다. 쓰기가 실패하면 서식 작업을 멈추고 그 에러를 그대로 던지며, 그 전에 쓴 조각은 남습니다. `Display`가 스스로 실패하면 종류가 `Other`인 `IoError`가 됩니다.

`Close`는 닫기가 실패할 수 있는 자원입니다([2.13.4](213-marker.md)). 소유자가 `try x.close()`나 `using`으로 닫고, 열어 둔 채 스코프를 벗어나면 에러입니다. `File`, 소켓, TLS 연결, 자식 프로세스 pipe, `BufReader<R: Close>`, `BufWriter<W: Write + Close>`, `LineWriter<W: Write + Close>`, `Owned<V, R: Close>`, `Chain<A: Close, B: Close>`가 구현합니다. 버퍼 있는 writer는 남은 내용을 먼저 씁니다. async 짝은 `AsyncClose`입니다(2.23.5). `try await x.close_async()`는 `close`처럼 값을 닫습니다.

나눈 연결의 반쪽 `net::ReadHalf<T>`와 `net::WriteHalf<T>`([3.2.1](../300-std/302-net.md#반쪽으로-나누기))는 `Close`와 `AsyncClose`를 구현하고, `ReadHalf`는 읽기 트레잇(`Read`, `AsyncRead`)을, `WriteHalf`는 쓰기 트레잇(`Write`, `AsyncWrite`)을 구현합니다. 소켓은 두 번째 반쪽과 함께 닫힙니다.

## 2.23.4. `Seek`

```rok
enum SeekFrom { Start(u64), End(i64), Current(i64) }

trait Seek {
    fn seek(ref self, pos: SeekFrom) throws (IoError) -> u64;   // 처음부터의 새 오프셋
    fn rewind(ref self) throws (IoError);                       // seek(Start(0))
    fn stream_position(ref self) throws (IoError) -> u64;       // seek(Current(0))
}
```

`Seek`는 `File`과 `Cursor<T>`가 구현합니다.

## 2.23.5. async 트레잇

```rok
trait AsyncRead {
    async fn read_async(ref self, buf: SliceMut<u8>) throws (IoError) -> usize;
    async fn read_vectored_async(ref self, bufs: Slice<SliceMut<u8>>) throws (IoError) -> usize;
    async fn read_exact_async(ref self, buf: SliceMut<u8>) throws (IoError);
    async fn read_to_end_into_async(ref self, out: List<u8>) throws (IoError) -> usize;
    async fn read_to_end_async(ref self) throws (IoError) -> List<u8>;
    async fn read_to_str_async(ref self) throws (IoError) -> str;
    fn bytes_async(ref self) -> BytesStream;             // 뷰; TryStream<Item = u8, Error = IoError>
    fn into_bytes_async(self) -> Owned<BytesStream, Self>;
}

trait AsyncBufRead: AsyncRead {
    async fn fill_buf_async(ref self) throws (IoError) -> Slice<u8>;
    fn consume(ref self, n: usize);
    async fn read_until_async(ref self, delim: u8, out: List<u8>) throws (IoError) -> usize;
    async fn read_line_async(ref self, out: StrBuf) throws (IoError) -> usize;
    fn lines_async(ref self) -> LinesStream;             // 뷰; TryStream<Item = str, Error = IoError>
    fn into_lines_async(self) -> Owned<LinesStream, Self>;
}

trait AsyncWrite {
    async fn write_async<B: AsBytes>(ref self, buf: B) throws (IoError) -> usize;
    async fn flush_async(ref self) throws (IoError);
    async fn write_vectored_async(ref self, bufs: Slice<Slice<u8>>) throws (IoError) -> usize;
    async fn write_all_async<B: AsBytes>(ref self, buf: B) throws (IoError);
}

trait AsyncSeek {
    async fn seek_async(ref self, pos: SeekFrom) throws (IoError) -> u64;
}

trait AsyncClose {
    async fn close_async(self) throws (IoError);
}

#[discardable]
async fn copy_async<R: AsyncRead, W: AsyncWrite>(r: R, w: W) throws (IoError) -> u64;
```

async 짝은 따로 둔 트레잇입니다. await할 수 없는 `Read`는 `AsyncRead` 바운드에 들어오지 않으므로 `await` 뒤에 블로킹 호출이 숨지 않습니다. 메서드 이름에는 `_async`가 붙으므로 두 종류를 함께 들여와도 모호하지 않습니다. `f.read(buf)`와 `await f.read_async(buf)`처럼 씁니다. `consume`은 기다리는 일이 없어 `_async` 형태가 없습니다. `BufRead`와 `AsyncBufRead`를 모두 구현하는 타입에서는 `BufRead::consume(ref r, n)`처럼 부릅니다.

`AsyncRead` / `AsyncWrite`는 `File`(호출을 블로킹 스레드에서 돌림, [3.1.4a](../300-std/301-fs.md#314a-비동기-파일-io_async)), `Socket`, `TcpStream`, `UnixStream`, `tls::Client` / `tls::Server`, 자식 pipe, `BufReader<R>`, `BufWriter<W>`, `LineWriter<W>`, `Cursor<T>`, `Empty`, `Sink`, `Repeat`가 구현합니다. OS 스트림의 소유자는 하나입니다([2.13.4](213-marker.md)). `let g = f`는 값을 옮기고, 같은 스트림의 두 번째 핸들은 명시적인 `try_clone()`으로 만듭니다. `copy_async(r, w)`는 부른 자리에서 바로 await하면 둘을 빌려 쓸 뿐이고, 닫는 것은 여전히 호출자입니다.

async 메서드는 동기 짝처럼 `ref self`를 받습니다([refs-lang 4.12.13](../../refs-lang/004-functions/412-async.md#41213-async-메서드)). future가 리시버를 쥐고 있다가 끝날 때 되써 넣으므로, 만든 자리에서 바로 await합니다. `close_async`는 `close`처럼 값을 소비하므로 `self`를 받습니다.

`AsyncClose`는 위의 `Close` 타입 가운데 async 스트림이기도 한 타입이 모두 구현합니다. `File`(닫기를 블로킹 스레드에서 돌림), `Socket`, `TcpStream`, `TcpListener`, `UdpSocket`, Unix 소켓, `tls::Client` / `tls::Server`(close_notify를 막지 않고 보냄), 자식 pipe, `BufReader<R: AsyncClose>`, `BufWriter<W: AsyncWrite + AsyncClose>`, `LineWriter<W: AsyncWrite + AsyncClose>`, `Owned<V, R: AsyncClose>`, `Chain<A: AsyncClose, B: AsyncClose>`가 있습니다. 소켓 닫기는 기다리지 않습니다. 다만 `SO_LINGER` 때문에 보내지 못한 데이터를 기다려야 하면 블로킹 스레드에서 닫습니다.

취소 안전성: 소켓의 `read_async` / `write_async`는 중단된 동안 취소되면 바이트를 옮기지 않은 상태입니다. `File` 호출은 취소되어도 그 스레드에서 끝까지 돌고, 결과는 버려집니다. 그 스레드는 바이트의 자기 복사본으로 일하므로, 취소 뒤 호출자의 버퍼는 호출자만의 것이고 읽기가 나중에 그 버퍼에 쓰는 일은 없습니다.

스트림 입출력이 아닌 연산만 타입의 고유 `_async` 메서드로 남습니다. 열기와 연결(`open_async`, `connect_async`), `accept_async`, `shutdown_async`, 데이터그램(`send_async`, `recv_from_async` 등), fd 넘기기(`send_with_fd_async`), TLS 제어(`close_notify_async`, `key_update_async`), 프로세스(`wait_async`, `output_async`, `status_async`)가 그렇습니다. 규칙은 [0.5.13](../000-meta/005-notation.md#0513-async-짝)에 있습니다.

## 2.23.6. 버퍼와 `Cursor`

```rok
struct BufReader<R> { .. }      // Read + BufRead (R: Read), AsyncRead + AsyncBufRead (R: AsyncRead), Close (R: Close), AsyncClose (R: AsyncClose) 구현
struct BufWriter<W> { .. }      // Write (W: Write), AsyncWrite (W: AsyncWrite), Close (W: Write + Close), AsyncClose (W: AsyncWrite + AsyncClose) 구현
struct LineWriter<W> { .. }     // BufWriter 와 같음; 쓰기에 든 마지막 \n 까지 내보냄
struct Cursor<T> { .. }         // Read + BufRead + Seek 와 async 짝 (T: AsBytes); List<u8> 위에서는 Write

impl<R> BufReader<R> {
    fn new(inner: R) -> BufReader<R>;                   // 8 KiB 버퍼
    fn with_capacity(cap: usize, inner: R) -> BufReader<R>;
    fn into_inner(self) -> R;                           // 버퍼에 남은 바이트는 버림
    fn buffer_len(self) -> usize;                       // 버퍼에 있고 아직 읽지 않은 바이트
    fn capacity(self) -> usize;
}

impl<W> BufWriter<W> {
    fn new(inner: W) -> BufWriter<W>;
    fn with_capacity(cap: usize, inner: W) -> BufWriter<W>;
    fn buffer_len(self) -> usize;                       // 썼지만 아직 넘기지 않은 바이트
    fn capacity(self) -> usize;
}
impl<W: Write> BufWriter<W> {
    fn into_inner(self) throws (IoError) -> W;          // 남은 내용을 쓴 뒤 writer 를 돌려줌
}

impl<W> LineWriter<W> { fn new(inner: W) -> LineWriter<W>; }
impl<W: Write> LineWriter<W> { fn into_inner(self) throws (IoError) -> W; }

impl<T> Cursor<T> {
    fn new(inner: T) -> Cursor<T>;
    fn position(self) -> u64;
    fn set_position(self, pos: u64);
    fn inner(self) -> T;                                // 감싼 값, 공유
    fn into_inner(self) -> T;
}
```

버퍼는 안쪽 스트림을 소유합니다. affine 스트림(`File`, 소켓) 위의 버퍼는 그 자체로 affine이고 소유자가 하나입니다. `Cursor<T>`와 affine이 아닌 스트림 위의 버퍼는 보통 값이고, 복사본은 버퍼와 위치를 함께 씁니다. `Close`인 writer 위의 `BufWriter`는 소유자가 닫습니다. `close()`는 남은 내용을 쓰고 안쪽 writer를 닫으므로 버퍼에 있던 쓰기의 에러를 잃지 않습니다. `Cursor<List<u8>>`는 위치부터 덮어쓰고 그다음 리스트를 늘립니다.

`BufWriter<W: Write>`와 `LineWriter<W: Write>`는 `Drop`도 구현합니다. writer가 `Close`가 아닐 때 해제하면 남은 내용을 쓰고 쓰기 에러는 버립니다. 그 에러를 보려면 해제 전에 `flush()`나 `into_inner()`를 부릅니다.

```rok
using r = io::BufReader::new(try fs::open("data.txt")) {
    try for line in r.lines() {
        println(line);
    }
}
```

## 2.23.7. `copy`와 유틸리티

```rok
#[discardable]
fn copy<R: Read, W: Write>(ref r: R, ref w: W) throws (IoError) -> u64;

fn empty() -> Empty;            // Read + BufRead: 언제나 끝
fn sink() -> Sink;              // Write: 모든 바이트를 버림
fn repeat(byte: u8) -> Repeat;  // Read: byte 가 끝없이 이어짐

struct Take<R> { .. }           // r.take(n), 뷰; limit(), set_limit(n)
struct Chain<A, B> { .. }       // a.chain(b); into_inner() -> (A, B); Close (A, B: Close), AsyncClose (A, B: AsyncClose)
struct Owned<V, R> { .. }       // r.into_lines() 등 소유하는 형태; into_inner() -> R;
                                // V 처럼 TryIterator / Read / TryStream; Close (R: Close), AsyncClose (R: AsyncClose); Send (R: Send)
```

이 장의 타입은 모두 `Debug`를 구현합니다. 스트림, 어댑터, 버퍼(`Take`, `Chain`, `Cursor`, `Empty`, `Sink`, `Repeat`, `BytesStream`, `LinesStream`, `Split` 등)는 타입 이름을 찍습니다.

`copy`는 `r`을 끝까지 읽어 `w`에 쓰고 바이트 수를 돌려줍니다. 두 OS 핸들(파일, 시간 제한이나 논블로킹 모드가 없는 소켓, pipe) 사이에서는 런타임이 커널에 바이트를 옮기게 합니다(`copy_file_range` / `sendfile` / `splice`). 그 밖의 스트림은 8 KiB 버퍼로 `read` / `write_all`을 거쳐 복사합니다.

## 2.23.8. 표준 스트림

```rok
fn stdin() -> Stdin;            // Read + BufRead
fn stdout() -> Stdout;          // Write
fn stderr() -> Stderr;          // Write
fn read_line() throws (IoError) -> str | none;
```

`stdout()`은 `print` / `println`과 같은 런타임 버퍼를 쓰므로 섞어 써도 출력 순서가 지켜집니다. 이 버퍼는 터미널에서는 줄바꿈 때, 찼을 때, `flush()` 때, 종료할 때 비워집니다. `stderr`는 버퍼가 없습니다. `stdin()`은 런타임의 공유 버퍼를 거쳐 읽습니다. `Stdin` 핸들은 `fill_buf`를 위해 최대 한 줄의 나머지만 담아 두므로, 그 핸들이 소비하지 않은 줄은 그 핸들에 남습니다.

### `input`

`io::input(prompt: str = "") throws (IoError) -> str | none`은 `prompt`를 stdout에 쓰고 비운(flush) 뒤 `io::read_line()`을 돌려줍니다. 종결자를 뺀 다음 줄이고, 입력이 끝나면 `none`입니다(Python의 `input(prompt)`는 그때 예외를 던집니다).

## 2.23.9. 예

```rok
// stdin 을 한 줄씩
while let line: str = try io::read_line() {
    process(line);
}

// 버퍼를 둔 파일, 나갈 때 닫힘
using w = io::BufWriter::new(try fs::create("out.txt")) {
    for x in xs {
        try w.write_all(f"{x}\n");
    }
}

// 버퍼의 일부
let buf = List::filled(4096, 0u8);
let n = try conn.read(buf[0:512]);

// 복사
using src = try fs::open("a.txt") {
    using dst = try fs::create("b.txt") {
        try io::copy(ref src, ref dst);
    }
}
```
