# 2.3. 산술 / 비트 / 인덱싱 트레잇

`rok::core::ops` 모듈은 트레잇 패밀리를 정의합니다. Rok의 연산자 토큰([refs-lang 1.10](../../refs-lang/001-lexical/110-punctuation-and-operator-tokens.md))은 이 트레잇으로 디스패치됩니다. `+` `-` `*` `/` `%` `<<` `>>` `&` `|` `^` `~` `&&` `||` 같은 일반 연산자뿐 아니라 `arr[i]` 인덱싱과 `s[1:3]` 슬라이싱도 이 장에서 정의하는 트레잇 메서드를 호출합니다. 다만 [2.3.4](#234-인덱싱-트레잇)의 인덱싱 트레잇은 예외입니다. 이 트레잇은 `rok::core::ops`가 아니라 `rok::core::index`에 있습니다.

[refs-lang 3.1 연산자 디스패치](../../refs-lang/003-expressions/301-operator-dispatch.md)의 메커니즘은 이 장의 **내용**을 찾아 씁니다. 그 내용을 정하는 권위는 이 문서, refs-standard-libraries 2.3에 있습니다.

> [!NOTE]
> 이 장의 연산자 트레잇 메서드는 모두 `throws` 없이 선언됩니다. 따라서 연산자는 에러를 던지지 않습니다. 구현에도 `throws`를 붙일 수 없습니다([refs-lang 4.14.11](../../refs-lang/004-functions/414-throws.md#41411-메서드의-throws)). 실패할 수 있는 연산은 이름 있는 메서드(`checked_div` 등)로 두거나 `Result`를 반환합니다.

## 2.3.1. 산술 트레잇

### `Add`: 산술 덧셈(`+`)

먼저 덧셈 트레잇입니다.

```rok
#[lang("add_trait")]
trait Add<Rhs = Self> {
    type Output;

    #[infix("+")]
    fn add(self, rhs: Rhs) -> Output;
}
```

**의미**: 두 값을 더한 결과를 반환합니다.

```rok
let a: i32 = 5;
let b: i32 = 3;
let c = a + b;        //→ 8 (i32)

let x: f64 = 1.5;
let y: f64 = 2.5;
let z = x + y;        //→ 4.0 (f64)
```

#### Output 규칙

연관 타입 `Output`은 보통 `Self`와 같습니다. 예외는 두 가지입니다. 첫째, `int + int = int`는 임의 정밀도이므로 오버플로가 없습니다. `i32 + i32` 같은 고정 폭 합은 `i32`로 남고, 더 넓은 타입으로 승격하지 않습니다([2.1.6](201-numbers.md#216-산술-결과-타입)). 둘째, `Vec3<f64> + f64 = Vec3<f64>` 같은 사용자 정의 산술은 `impl Add<f64> for Vec3<f64>` 형식으로 정의합니다.

#### 오버플로 동작

오버플로 동작은 타입에 따라 다릅니다. `i32 + i32`는 오버플로 검사가 켜져 있으면 panic이 일어나고, 꺼져 있으면 랩어라운드합니다. 검사 여부는 `rokc -C overflow-checks[=yes|no]`([refs-lang 9.1.2](../../refs-lang/009-tools/901-rokc-cli.md#rokc-build-aot-빌드))로 정합니다. 기본값은 `-O0`에서만 켜는 것입니다. `f32 + f32`와 `f64 + f64`는 IEEE 754 덧셈을 따르므로 오버플로가 나면 ±∞ 또는 NaN이 됩니다. `int + int`는 임의 정밀도이므로 오버플로가 없습니다. 포화, 검사, 랩어라운드 변형은 별도 메서드(`saturating_add`, `checked_add`, `wrapping_add`)로 이 트레잇 밖에 정의합니다.

정수 오버플로 정책 전체는 [2.11 변환](211-conversion.md)의 고정 폭 산술 절에 있습니다.

### `Sub`: 산술 뺄셈(`-`)

뺄셈 트레잇입니다.

```rok
#[lang("sub_trait")]
trait Sub<Rhs = Self> {
    type Output;

    #[infix("-")]
    fn sub(self, rhs: Rhs) -> Output;
}
```

형식은 `Add`와 같습니다. `a - b`는 `Sub::sub(a, b)`로 디스패치됩니다.

```rok
let r = 10i32 - 3i32;     //→ 7
let s = 1.0f64 - 0.5f64;  //→ 0.5
```

### `Mul`: 산술 곱셈(`*`)

곱셈 트레잇입니다.

```rok
#[lang("mul_trait")]
trait Mul<Rhs = Self> {
    type Output;

    #[infix("*")]
    fn mul(self, rhs: Rhs) -> Output;
}
```

```rok
let r = 6i32 * 7i32;      //→ 42
let s = 2.5f64 * 4.0f64;  //→ 10.0
```

#### 사용자 정의 의미

`Mul`에는 산술 곱 말고도 도메인에 맞는 의미를 줄 수 있습니다. 대표적인 예가 행렬 곱입니다.

```rok
struct Matrix2x2 { a: f64; b: f64; c: f64; d: f64; }

impl Mul<Matrix2x2> for Matrix2x2 {
    type Output = Matrix2x2;

    fn mul(self, rhs: Matrix2x2) -> Matrix2x2 {
        Matrix2x2 {
            a: self.a * rhs.a + self.b * rhs.c,
            b: self.a * rhs.b + self.b * rhs.d,
            c: self.c * rhs.a + self.d * rhs.c,
            d: self.c * rhs.b + self.d * rhs.d,
        }
    }
}
```

원소별 곱은 [2.6 broadcast](206-broadcast.md)의 `DotMul`(`m .* n`)이 다룹니다.

### `Div`: 산술 나눗셈(`/`)

나눗셈 트레잇입니다.

```rok
#[lang("div_trait")]
trait Div<Rhs = Self> {
    type Output;

    #[infix("/")]
    fn div(self, rhs: Rhs) -> Output;
}
```

렉서가 `÷`를 `/`로 읽으므로 `a ÷ b`도 `div`로 디스패치됩니다. `÷`에는 따로 중위(infix) 바인딩이 없습니다.

```rok
let r = 20i32 / 7i32;      //→ 2 (정수 나눗셈, 절삭)
let s = 20.0f64 / 7.0f64;  //→ 2.857142857142857
```

#### 0으로 나누기

0으로 나눌 때의 동작은 타입마다 다릅니다. 정수 `i32 / 0`은 panic이 일어납니다. 상수로 접히는 식(`1 / 0`)이면 컴파일 에러입니다. 부동소수 `f64 / 0.0`은 IEEE 754에 따라 ±∞ 또는 NaN이 됩니다.

panic 대신 `none`을 받으려면 `checked_div`를 쓰세요.

```rok
let r = 20i32.checked_div(7i32);  //→ 2
let s = 20i32.checked_div(0i32);  //→ none
```

### `Rem`: 산술 나머지(`%`)

나머지 트레잇입니다.

```rok
#[lang("rem_trait")]
trait Rem<Rhs = Self> {
    type Output;

    #[infix("%")]
    fn rem(self, rhs: Rhs) -> Output;
}
```

```rok
let r = 20i32 % 7i32;     //→ 6
let s = 5.5f64 % 2.0f64;  //→ 1.5 (IEEE 754 fmod)
```

결과의 부호는 피제수(왼쪽 피연산자)를 따릅니다. 그래서 `(-5) % 3 = -2`이고 `5 % (-3) = 2`입니다. C나 Rust처럼 절삭 나눗셈(truncated division)으로 정의합니다.

### `Modulo`: 내림 modulo(`%%`)

몫을 내림하는(floored) 나머지 트레잇입니다.

```rok
trait Modulo<Rhs = Self> {
    type Output;

    #[infix("%%")]
    fn modulo(self, rhs: Rhs) -> Output;
}
```

```rok
let r = (-5i32) %% 3i32;     //→ 1   ( = -5 - (-2)*3 )
let s = 5i32 %% (-3i32);     //→ -1  ( = 5 - (-2)*(-3) )
let t = (-7.5f64) %% 2.0f64; //→ 0.5
```

`Rem`과는 결과의 부호 규칙이 다릅니다. `a %% b = a - floor(a / b) * b`이므로 결과의 부호는 **제수 `b`를 따릅니다**(Python의 `%`와 같음). 제수가 양수이면 결과는 늘 `[0, b)` 범위에 듭니다. 그래서 피제수가 음수여도 양의 나머지를 얻습니다. 제수가 음수이면 결과는 `(b, 0]` 범위입니다(`7 %% -3 = -2`). 유클리드 나머지(늘 0 이상)와는 제수가 음수일 때 다릅니다. 인덱스를 한 바퀴 돌릴 때나 모듈러 산술에서 자주 씁니다. 부동소수 `%%`의 결과가 0이면 그 부호는 제수를 따릅니다(`44.0 %% -4.0 = -0.0`).

```rok
// 자주 쓰이는 패턴: 음수 인덱스 wrap-around
let i: i32 = -1;
let len: i32 = 8;
let wrapped = i %% len;      //→ 7    (i % len 이라면 -1)
```

`Rem`과 `Modulo`의 부호 차이는 다음과 같습니다.

| `a`  | `b`  | `a % b` (Rem) | `a %% b` (Modulo) |
|------|------|---------------|-------------------|
| `7`  | `3`  | `1`           | `1`               |
| `-7` | `3`  | `-1`          | `2`               |
| `7`  | `-3` | `1`           | `-2`              |
| `-7` | `-3` | `-1`          | `-1`              |

두 토큰은 서로 다른 트레잇에 대응하므로 어느 한쪽만 구현하거나 두 의미를 다르게 줄 수 있습니다. 다만 표준 라이브러리의 원시 정수와 부동소수 구현은 위 표의 정의를 따릅니다.

`%%` 토큰은 [refs-lang 1.10 구두점과 연산자 토큰](../../refs-lang/001-lexical/110-punctuation-and-operator-tokens.md)이 정의합니다. 우선순위는 [refs-lang 3.2](../../refs-lang/003-expressions/302-precedence-and-associativity.md) 표에서 `%`와 같은 8단계이고 좌결합입니다.

## 2.3.2. 단항 트레잇

### `Neg`: 단항 부정(`-` 전위)

단항 부정 트레잇입니다.

```rok
#[lang("neg_trait")]
trait Neg {
    type Output;

    #[prefix("-")]
    fn neg(self) -> Output;
}
```

```rok
let r = -5i32;       //→ -5
let s = -3.14f64;    //→ -3.14
let t = -(a + b);    //→ -(a+b)
```

이 트레잇은 부호 있는 정수와 부동소수 타입에서만 의미가 있습니다. `u32`에는 `Neg` 구현이 없습니다.

`i32::MIN`(= -2147483648)의 부정은 표현할 수 없습니다. 그래서 디버그 빌드에서는 panic이 일어나고, 릴리스 빌드에서는 랩어라운드합니다(결과는 i32::MIN 그대로). 명시적으로 랩어라운드하려면 `wrapping_neg`를, `T | none` 결과가 필요하면 `checked_neg`를 쓰세요.

### `Not`: 비트 반전 / 논리 부정(`!`)

`Not` 트레잇입니다.

```rok
#[lang("not_trait")]
trait Not {
    type Output;

    #[prefix("!")]
    fn not(self) -> Output;
}
```

```rok
let r = !true;       //→ false
let s = !0u8;        //→ 255 (모든 비트 1)
let t = !0xFFi32;    //→ 0xFFFFFF00 (전 32비트 반전)
```

`bool::not(true) = false`, `bool::not(false) = true`이므로 bool에서는 논리 부정입니다. 반면 `u8::not(0) = 0xFF`, `i32::not(0) = -1`처럼 정수에서는 비트 반전입니다.

### `BitNot`: 비트 반전(`~`)

`~` 토큰([refs-lang 1.10.3](../../refs-lang/001-lexical/110-punctuation-and-operator-tokens.md))은 정수 전용 비트 반전입니다.

```rok
#[lang("bitnot_trait")]
trait BitNot {
    type Output;

    #[prefix("~")]
    fn bitnot(self) -> Output;
}
```

```rok
let s = ~0u8;        //→ 255
let t = ~0i32;       //→ -1
```

정수 타입에서 `~x`는 `!x`와 같은 결과를 냅니다. 다만 `BitNot`은 `i*` / `u*`에만 구현하고 `bool`에는 구현하지 않습니다. 그래서 `~true`는 컴파일 에러입니다. 논리 부정에는 `!`를, 비트 반전임을 드러낼 때는 `~`를 쓰기를 권장합니다.

## 2.3.3. 비트 트레잇

### `BitAnd`: 비트 AND(`&`)

비트 AND 트레잇입니다.

```rok
#[lang("bitand_trait")]
trait BitAnd<Rhs = Self> {
    type Output;

    #[infix("&")]
    fn bitand(self, rhs: Rhs) -> Output;
}
```

```rok
let r = 0xF0i32 & 0x0Fi32;   //→ 0x00
let s = 0xFFi32 & 0x0Fi32;   //→ 0x0F
let b = true & false;         //→ false (bool 도 BitAnd impl 가짐)
```

> [!NOTE]
> `&&`와 `&`는 다릅니다. `&&`는 단락 평가(short-circuit)하는 논리 AND이고, `&`는 비트 AND입니다.
> bool에서는 두 결과가 같지만 평가 시점이 다릅니다.

### `BitOr`: 비트 OR(`|`)

비트 OR 트레잇입니다.

```rok
#[lang("bitor_trait")]
trait BitOr<Rhs = Self> {
    type Output;

    #[infix("|")]
    fn bitor(self, rhs: Rhs) -> Output;
}
```

```rok
let r = 0xF0i32 | 0x0Fi32;   //→ 0xFF
```

### `BitXor`: 비트 XOR(`^`)

비트 XOR 트레잇입니다.

```rok
#[lang("bitxor_trait")]
trait BitXor<Rhs = Self> {
    type Output;

    #[infix("^")]
    fn bitxor(self, rhs: Rhs) -> Output;
}
```

```rok
let r = 0xFFi32 ^ 0x0Fi32;   //→ 0xF0
let s = 0b1010 ^ 0b1100;     //→ 0b0110
```

### `Shl`: 좌 비트 시프트(`<<`)

좌 시프트 트레잇입니다.

```rok
#[lang("shl_trait")]
trait Shl<Rhs = Self> {
    type Output;

    #[infix("<<")]
    fn shl(self, rhs: Rhs) -> Output;
}
```

```rok
let r = 1i32 << 4;     //→ 16
let s = 0xFFi32 << 24; //→ 0xFF000000
```

시프트 횟수가 음수이거나 비트 폭 이상이면 시프트는 panic합니다(`attempt to shift left with overflow`, `>>`는 `right`). `+` `-` `*` 오버플로와 달리 이 검사는 `-C overflow-checks`와 관계없이 모든 최적화 수준에서 실행됩니다. 횟수를 비트 폭으로 나눈 나머지만큼 밀려면 `wrapping_shl` / `wrapping_shr`를 씁니다.

```rok
let r = 1i32.wrapping_shl(40);  // 명시: 40 % 32 = 8 만큼 shift
```

### `Shr`: 우 비트 시프트(`>>`)

우 시프트 트레잇입니다.

```rok
#[lang("shr_trait")]
trait Shr<Rhs = Self> {
    type Output;

    #[infix(">>")]
    fn shr(self, rhs: Rhs) -> Output;
}
```

```rok
let r = 256i32 >> 4;  //→ 16
let s = -1i32 >> 1;   //→ -1 (signed = arithmetic shift, sign extension)
let t = u32::MAX >> 1;  //→ 0x7FFFFFFF (unsigned = logical shift)
```

부호 있는 정수는 산술 시프트(부호 확장)를, 부호 없는 정수는 논리 시프트를 씁니다.

## 2.3.4. 인덱싱 트레잇

인덱싱과 슬라이싱은 **언어 문법**([refs-lang 3.6](../../refs-lang/003-expressions/306-indexing-and-slicing.md))이지만 실제 디스패치는 이 절의 트레잇이 맡습니다. `Index`, `IndexSet`, `Sliceable`은 `clamp_range`와 함께 `rok::core::index` 모듈에 정의됩니다. struct나 enum에서 `xs[i]`와 `xs[i] = v`는 `index` / `index_set`을 호출합니다. 고정 배열은 호출 없이 바로 인덱싱합니다.

### `Index`: 단일 원소 읽기(`arr[i]`)

`Index` 트레잇입니다.

```rok
#[lang("index_trait")]
trait Index<I> {
    type Output;

    fn index(self, idx: I) -> Output;
}
```

```rok
let xs: List<i32> = [10, 20, 30];
let v = xs[1];        //→ 20
let s: str = "hello";
let c = s.chars().next();   //→ 'h' (char | none), str 에는 Index 가 없음 (2.9.8)
```

#### 경계 검사

범위 밖 인덱스(`xs[100]`)는 panic을 일으킵니다. 연산자는 에러를 던지지 않기 때문입니다. 부호 있는 정수 인덱스가 음수이면 끝에서부터 셉니다(`xs[-1]`은 마지막 원소, [refs-lang 3.6.1](../../refs-lang/003-expressions/306-indexing-and-slicing.md#361-인덱싱-arri)). `len + i < 0`이면 panic이 일어납니다.

panic 대신 `T | none` 결과를 받으려면 `xs.get(i)`를 쓰세요.

```rok
let v = xs.get(100);  //→ none
```

### `IndexSet`: 단일 원소 쓰기(`arr[i] = v`)

`IndexSet` 트레잇입니다.

```rok
#[lang("index_set_trait")]
trait IndexSet<I> {
    type Value;

    fn index_set(self, idx: I, value: Value);     // 컬렉션은 참조 핸들이므로 self
}
```

```rok
let xs: List<i32> = [10, 20, 30];
xs[1] = 99;           // IndexSet::index_set(xs, 1, 99)
xs[1];                //→ 99
```

`Index`와 나눈 이유는 읽기 전용 컨테이너(예: 튜플의 불변 뷰)도 `Index`는 구현할 수 있어야 하기 때문입니다. 그래서 `IndexSet`은 따로 골라서 구현합니다(opt-in).

`IndexSet`도 범위를 벗어나면 panic이 일어납니다. 반면 `xs.set(i, v)`는 `IndexError`를 던집니다(`throws (IndexError)`).

### `Sliceable`: 부분 추출(`s[a:b]`, `s[a:b:step]`)

슬라이스 트레잇입니다. 트레잇 이름은 `Sliceable`이고, 결과 뷰 타입은 `Slice<T>`([2.9.7](209-collections.md#297-slicet-뷰))입니다. 묵시적 glob 가져오기에서는 한 이름이 둘을 가리킬 수 없으므로 이름을 나눴습니다.

```rok
#[lang("slice_trait")]
trait Sliceable<R> {
    type Output;

    fn slice(self, range: R) -> Output;
}
```

`xs[a:b]`는 `xs.slice(a..b)`입니다. `xs[a:b:k]`는 Python의 `slice.indices`로 구한 범위에 `xs.slice(..).step(k)`를 적용한 것입니다([refs-lang 3.6.2](../../refs-lang/003-expressions/306-indexing-and-slicing.md#362-슬라이싱-arrstartend)). 의미는 Python 슬라이스와 같습니다. 경계는 길이에 맞춰 잘라 냅니다. 범위를 벗어나도 panic이 일어나지 않고, `xs`는 한 번만 평가합니다. `xs[a..b]`와 `xs[..]`도 같습니다. 모든 `Sliceable<Range<usize>>` 구현은 `rok::core::index::clamp_range`로 범위를 잘라 맞춥니다.

```rok
let xs: List<i32> = [1, 2, 3, 4, 5];
let s = xs[1:3];       //→ Slice<i32> view of [2, 3]
let r = xs[::2];       //→ [1, 3, 5] (step=2)
let v = xs[::-1];      //→ [5, 4, 3, 2, 1] (역순)

let str_part = "hello"[1:4];  //→ "ell" (새 str)
```

표준 라이브러리는 `List<T>`, `Slice<T>`, `[T; N]`, `str`, `StrBuf`에 `Sliceable<Range<usize>>`를 구현합니다. `List` / `Slice` / 배열은 `Slice<T>` 뷰를 돌려줍니다. `str` / `StrBuf`는 UTF-8 경계를 검사한 뒤 새 `str` 사본을 돌려줍니다. 음수 경계는 끝에서부터 센 뒤 잘라 냅니다. 슬라이스 대입은 지원하지 않습니다. 소유한 사본이 필요하면 `xs[1:3].to_list()`를 씁니다.

## 2.3.5. 트레잇 구현 매트릭스

원시 타입의 ops 트레잇 구현에는 모두 `#[intrinsic("rok.OP.TYPE")]`이 붙어 있습니다. 이 속성이 구현을 컴파일러 백엔드의 PrimOp에 바로 연결합니다([0.3](../000-meta/003-intrinsics.md)). 그래서 다음과 같이 동작합니다.

- 컴파일러는 원시 피연산자에 쓴 연산자(`a + b`)를 메서드 호출 없이 바로 기계 연산으로 낮춥니다.
- 컴파일러는 이름으로 부른 호출(`a.add(b)`, `Add::add(a, b)`)도 같은 기계 연산으로 낮춥니다.

### 산술 트레잇

| 타입                 | 모듈            | 동작                                                            |
|----------------------|-----------------|-----------------------------------------------------------------|
| `i8`..`i64`, `isize` | `rok::core::num` | `rok.add.i32` / `rok.sub.i32` / `rok.rem.i32` / `rok.mod.i32` ... |
| `u8`..`u64`, `usize` | `rok::core::num` | `rok.add.u32` / ... (부호 없는 계열, `Modulo` ≡ `Rem`)           |
| `f32`, `f64`         | `rok::core::num` | `rok.add.f32` / `rok.add.f64` / `rok.mod.f64` (floored)         |
| `int`                | `rok::core::num` | 자동 승격 로직                                                  |
| `float`              | `rok::core::num` | (위와 같음: 자동 승격)                                          |

### 비트 트레잇

| 타입               | 모듈            | intrinsic                                                           |
|--------------------|-----------------|---------------------------------------------------------------------|
| `i*`, `u*`, `bool` | `rok::core::num` | `rok.and.OP`, `rok.or.OP`, `rok.xor.OP`, `rok.shl.OP`, `rok.shr.OP` |

`f32`와 `f64`에는 의미가 없으므로 BitAnd 등을 구현하지 않습니다.

### 인덱싱 트레잇

| 타입         | 정의 위치                                                                    |
|--------------|------------------------------------------------------------------------------|
| `List<T>`    | 표준 라이브러리                                                              |
| `Dict<K, V>` | 표준 라이브러리 (I = K)                                                      |
| `[T; N]`     | 컴파일러 합성 (원시 배열)                                                    |
| `str`        | 표준 라이브러리 (슬라이스만, `Index<usize>` 미정의, 바이트 직접 접근 거부)       |
| `Slice<T>`   | 표준 라이브러리                                                              |
| `Tuple`      | 컴파일러 합성 (`.0`, `.1` 형태), `Index` 미정의 (컴파일 시간 튜플 접근만)  |

## 2.3.6. 사용자 정의 연산

표준 라이브러리 밖에서도 `impl Add for MyType` 등으로 트레잇을 자유롭게 구현할 수 있습니다. 그러면 트레잇 디스패치가 `MyType::add` 호출로 이어집니다.

```rok
struct Vec3 { x: f64; y: f64; z: f64; }

impl Add for Vec3 {
    type Output = Vec3;

    fn add(self, rhs: Vec3) -> Vec3 {
        Vec3 {
            x: self.x + rhs.x,
            y: self.y + rhs.y,
            z: self.z + rhs.z,
        }
    }
}

let a = Vec3 { x: 1.0, y: 2.0, z: 3.0 };
let b = Vec3 { x: 0.5, y: 0.5, z: 0.5 };
let c = a + b;        //→ Vec3 { x: 1.5, y: 2.5, z: 3.5 }
```

다만 사용자 ops에는 `#[intrinsic]`을 **붙일 수 없습니다**(refs-standard-libraries 0.3.5). 권위가 본문에 있기 때문입니다.

## 2.3.7. 트레잇 사이의 관계: `Output` 일관성

여러 트레잇을 함께 쓰는 식(`a + b * c`)에서는 `Output` 타입이 서로 맞아야 합니다.

```rok
let r = a + b * c;
//   = Add::add(a, Mul::mul(b, c))
//   요구: <typeof(b) as Mul<typeof(c)>>::Output 가 Add 의 Rhs 와 호환
```

표준 라이브러리의 원시 산술 구현은 모두 `Output = Self`를 씁니다. 사용자 타입은 자유롭게 정해도 되지만, 컴파일러 에러 메시지 같은 도구 지원을 생각하면 `Output = Self`를 권장합니다.

## 2.3.8. broadcast 트레잇과 관계

`a + b`는 `Add::add`로, `a .+ b`는 `DotAdd::dot_add`로 디스패치됩니다. 따라서 두 연산은 서로 다른 트레잇이 맡습니다. 보통의 산술 타입(Vec3 등)은 두 트레잇을 모두 구현합니다. 자세한 내용은 [2.6 broadcast](206-broadcast.md)에 있습니다.

## 2.3.9. 논리 트레잇: `LogicalAnd`(`&&`) / `LogicalOr`(`||`)

`&&`와 `||`도 다른 연산자와 같은 방식으로 트레잇 메서드에 연결됩니다. 우선순위와 결합성은 [refs-lang 3.2](../../refs-lang/003-expressions/302-precedence-and-associativity.md) 표가 고정합니다.

```rok
#[lang("logical_and_trait")]
trait LogicalAnd<Rhs = Self> {
    #[infix("&&")]
    fn logical_and(self, rhs: Rhs) -> bool;
}

#[lang("logical_or_trait")]
trait LogicalOr<Rhs = Self> {
    #[infix("||")]
    fn logical_or(self, rhs: Rhs) -> bool;
}
```

표준 라이브러리는 이 두 트레잇을 `bool`에만 구현합니다. 두 피연산자가 모두 `bool`이면 컴파일러는 `logical_and_trait` / `logical_or_trait` 슬롯으로 이 구현을 알아봅니다. 그리고 메서드 호출 대신 **단락 평가** 분기로 낮춥니다. `a && b`는 `a`가 `false`이면 `b`를 평가하지 않습니다.

> [!WARNING]
> 사용자 타입이 `LogicalAnd` / `LogicalOr`를 구현하면 `a && b`는 일반 트레잇 메서드 호출이 됩니다. 그래서 두 피연산자를 **모두 평가**합니다(단락 평가 없음). broadcast 형태 `.&&` / `.||` ([2.6](206-broadcast.md))와 같은 규칙입니다. 언어는 `bool` 피연산자에만 단락 평가를 보장합니다.

## 2.3.10. Unicode 수학 연산자 트레잇

[refs-lang 1.10.3](../../refs-lang/001-lexical/110-punctuation-and-operator-tokens.md#unicode-수학-연산자)의 Unicode 연산자는 다음 트레잇에 연결됩니다. 모든 메서드에 ASCII 이름이 있으므로 연산자 대신 메서드로 불러도 됩니다. 우선순위는 [refs-lang 3.2](../../refs-lang/003-expressions/302-precedence-and-associativity.md) 표가 고정합니다. `÷ ≡ ≠ ≤ ≥`에는 따로 트레잇이나 중위 바인딩이 없습니다. 렉서가 이 연산자를 `/ == != <= >=`로 읽으므로 위의 `Div`와 [2.5 cmp](205-cmp.md)의 비교 트레잇으로 디스패치됩니다.

```rok
trait Cross<Rhs = Self> {               // a × b (8 단계)
    type Output;
    #[infix("×")]
    fn cross(self, rhs: Rhs) -> Output;
}

trait Dot<Rhs = Self> {                 // a ⋅ b (8 단계)
    type Output;
    #[infix("⋅")]
    fn dot(self, rhs: Rhs) -> Output;
}

trait Compose<Rhs> {                    // f ∘ g (9 단계), (f ∘ g)(x) = f(g(x))
    type Output;
    #[infix("∘")]
    fn compose(self, rhs: Rhs) -> Output;
}

trait Sqrt {                            // √x (전위 단항)
    type Output;
    #[prefix("√")]
    fn sqrt(self) -> Output;
}

trait Contains<Item> {                  // a ∈ s, a ∉ s (4 단계)
    #[infix("∈", swap)]
    fn contains(self, item: Item) -> bool;
    #[infix("∉", swap)]
    fn not_contains(self, item: Item) -> bool { !self.contains(item) }
}

trait Subset<Rhs = Self> {              // a ⊂ b, a ⊆ b (4 단계)
    #[infix("⊂")]
    fn is_proper_subset(self, rhs: Rhs) -> bool;
    #[infix("⊆")]
    fn is_subset(self, rhs: Rhs) -> bool;
}

trait Union<Rhs = Self> {               // a ∪ b (7 단계)
    type Output;
    #[infix("∪")]
    fn union(self, rhs: Rhs) -> Output;
}

trait Intersect<Rhs = Self> {           // a ∩ b (8 단계)
    type Output;
    #[infix("∩")]
    fn intersection(self, rhs: Rhs) -> Output;
}
```

`∈ ∉`는 컨테이너가 오른쪽에 오므로 `swap`으로 연결합니다([refs-lang 6.7.2](../../refs-lang/006-meta-system/607-operator-magic.md#672-인자)). `a ∈ xs`는 `xs.contains(a)`입니다.

| 트레잇      | 표준 라이브러리 구현                                  |
|-------------|-------------------------------------------------------|
| `Sqrt`      | `f32`, `f64` (`#[intrinsic("rok.sqrt.TYPE")]`)        |
| `Contains`  | `List<T>`, `Set<T>`, `Dict<K, V>` (키), `str` (부분 문자열), `Range<T>` |
| `Subset`, `Union`, `Intersect` | `Set<T>`                           |
| `Compose`   | 함수 타입 `fn(B) -> C`와 `fn(A) -> B`                 |
| `Cross`, `Dot` | 표준 라이브러리 구현 없음, 벡터 타입이 구현         |

`rok::core::ops::broadcast`도 `Dot`을 다시 내보냅니다([2.6](206-broadcast.md)). 그래서 `use rok::core::ops::broadcast::*` 하나로 원소별 트레잇과 내적을 함께 가져옵니다.
