# 1.7. FFI: `extern "C"` / `CStr` / `CString` / `CPtr`

`rok::bare::ffi` 모듈은 C ABI와 호환되는 외부 함수와 데이터를 정의하는 메커니즘입니다. [refs-lang 5.9 extern 블록](../../refs-lang/005-modules/509-extern-block.md)이 정의하는 `extern "C" { ... }` 블록과 함께 동작합니다.

이 장은 전통적인 C FFI만 다룹니다. WASM Component Model 기반 FFI는 [1.8 wit](108-wit.md)에서 따로 설명합니다.

## 1.7.1. `extern "C"` 블록

가장 기본 형태는 다음과 같습니다.

```rok
extern "C" {
    // 함수 선언
    fn malloc(size: usize) -> CPtr<u8>;
    fn free(ptr: CPtr<u8>);
    fn strlen(s: ConstPtr<c_char>) -> usize;

    // 글로벌 (read-only)
    static errno: i32;

    // 글로벌 (mutable): `mut` 키워드 _이 자리에서만_ 허용
    static mut atexit_count: u64;
}
```

여기 나오는 `mut` 키워드는 [refs-lang 1.5 키워드](../../refs-lang/001-lexical/105-keywords.md)에서 정의합니다. 이 위치에서만 의미가 있고, 일반 변수에는 쓸 수 없습니다.

### `#[link("name")]`: 라이브러리 지정

라이브러리를 명시적으로 지정하려면 `#[link]` 속성을 씁니다.

```rok
#[link("c")]
extern "C" {
    fn malloc(size: usize) -> CPtr<u8>;
    fn free(ptr: CPtr<u8>);
}

#[link("m")]
extern "C" {
    fn cos(x: f64) -> f64;
    fn sin(x: f64) -> f64;
}
```

링커가 `-lc`나 `-lm` 같은 플래그를 자동으로 붙입니다.

### 호출 규약(calling convention)

플랫폼과 인터페이스에 따라 호출 규약을 고를 수 있습니다.

```rok
extern "C" { ... }              // System V (Unix) / Microsoft x64 (Windows)
extern "system" { ... }         // Windows: stdcall on x86, C on x64 / aarch64
extern "fastcall" { ... }       // x86 fastcall
extern "stdcall" { ... }        // x86 stdcall
extern "aapcs" { ... }          // ARM AAPCS
extern "thiscall" { ... }       // C++ this pointer (x86 only)
```

대부분은 기본값인 `"C"`면 충분합니다. 그 밖의 규약은 주로 **Windows API**나 C++ 인터페이스를 다룰 때 씁니다.

### `str` 매개변수와 반환

`extern "C"` 함수의 `str` 매개변수는 NUL로 끝나는 `char*`로 전달됩니다. 반환된 `char*`는 `strlen`으로 길이를 잰 `str` 값이 됩니다([refs-lang 5.9.4](../../refs-lang/005-modules/509-extern-block.md#594-ffi-호환-타입)). `(ptr, len)` 전달은 런타임 ABI `extern "rok"`의 방식입니다([5.9.2](../../refs-lang/005-modules/509-extern-block.md#592-abi-명시)).

```rok
extern "C" {
    fn puts(s: str) -> i32;          // "hi" → NUL 로 끝나는 char*
    fn getenv(name: str) -> CPtr<c_char>;   // null 가능, CPtr 로 받음
}
```

## 1.7.2. `CStr` / `CString`: null 종료 문자열

`CStr`는 C 문자열을 다루는 빌림(borrow) 타입입니다.

```rok
struct CStr {
    // 내부: 바이트와 마지막 NUL 을 str 객체 하나에 담음
}

impl CStr {
    fn from_ptr(p: ConstPtr<c_char>) -> CStr | none;
                                    // null pointer → none
                                    // null-terminator 없으면 undefined (호출자 책임)

    fn from_bytes_with_nul(bytes: Slice<u8>) throws (FromBytesWithNulError) -> CStr;
                                    // 검증: 마지막이 0, 중간 0 없음
    fn from_bytes_with_nul_unchecked(bytes: Slice<u8>) -> CStr;

    fn as_ptr(self) -> ConstPtr<c_char>;
    fn as_bytes(self) -> Slice<u8>;            // null-terminator 제외
    fn as_bytes_with_nul(self) -> Slice<u8>;   // null-terminator 포함
    fn to_str(self) throws (Utf8Error) -> str;  // UTF-8 변환

    fn len(self) -> usize;                     // null-terminator 제외
}
```

`from_ptr`는 C 문자열을 복사해 옵니다. `CStr` / `CString`은 바이트와 NUL을 GC 객체 하나에 담습니다. `as_ptr`는 `str::as_ptr`와 같은 기간 동안 유효합니다([2.15.2](../200-core/215-string.md#2152-str-불변-utf-8-문자열)). 포인터 값이 나올 수 있는 함수에서 그 `CStr` / `CString`을 담은 변수가 스코프 안에 있는 동안입니다.

### `CString`: 소유하는 null 종료 문자열

직접 소유하는 형태가 필요하면 `CString`을 씁니다.

```rok
struct CString { /* GC heap, null-terminated */ }

impl CString {
    fn new(bytes: Slice<u8>) throws (NulError) -> CString;
                                        // 중간 null byte 거부
    fn from_str(s: str) throws (NulError) -> CString;

    fn as_c_str(self) -> CStr;
    fn as_ptr(self) -> ConstPtr<c_char>;
    fn into_bytes(self) -> List<u8>;     // owned bytes (null 제외)
    fn into_bytes_with_nul(self) -> List<u8>;
}
```

두 에러 타입은 바이트가 어디서 어긋났는지 담습니다. 둘 다 `Display`, `Debug`, `Error`를 구현합니다.

```rok
struct NulError {
    pub position: usize;        // 중간 NUL 의 index (CString::new / from_str)
}

struct FromBytesWithNulError {
    pub reason: str;            // 마지막 NUL 이 없거나 그 앞에 NUL 이 있음 (CStr::from_bytes_with_nul)
}
```

### 예: strlen

```rok
extern "C" {
    fn strlen(s: ConstPtr<c_char>) -> usize;
}

let s: str = "hello";
let cs = try CString::from_str(s);
let n = unsafe { strlen(cs.as_ptr()) };       //→ 5
```

> [!NOTE]
> `str`와 `CStr` 사이의 변환에는 **할당이 필요합니다**. null 종료 문자를 추가해야 하기 때문입니다. `str`는 보통 null로 끝나지 않으므로 FFI 호출 지점에서만 명시적으로 변환하기를 권장합니다.

## 1.7.3. `CPtr<T>`와 null 가능성

기준 정의는 [1.1.5 CPtr](101-ptr.md#115-cptrt-c-호환-null-가능)에 있습니다. C 함수가 `T*`를 반환할 때는 null 가능성을 명시해야 합니다. 이때 쓰는 타입입니다.

```rok
extern "C" {
    fn fopen(path: ConstPtr<c_char>, mode: ConstPtr<c_char>) -> CPtr<FILE>;
    fn fclose(file: CPtr<FILE>) -> i32;
}

struct FILE;        // opaque

let path = try CString::from_str("data.txt");
let mode = try CString::from_str("r");
let f: CPtr<FILE> = unsafe { fopen(path.as_ptr(), mode.as_ptr()) };

match f.as_ptr() {
    file: Ptr<FILE> => {
        // 사용
        unsafe { fclose(f) };
    }
    none => panic("fopen failed"),
}
```

## 1.7.4. `using` 블록: RAII

GC는 finalizer를 보장하지 않습니다. 모든 GC 언어가 겪어서 배운 원칙입니다. 외부 자원의 RAII는 **명시적인 `using`**으로 처리해야 합니다. `rok::bare::ffi`에는 자체 파일 API가 없습니다. 아래 래퍼는 C 함수를 직접 선언하고 `Drop`에서 핸들을 닫습니다.

```rok
struct FILE;        // opaque (1.7.3)

#[link("c")]
extern "C" {
    fn fopen(path: ConstPtr<c_char>, mode: ConstPtr<c_char>) -> CPtr<FILE>;
    fn fclose(file: CPtr<FILE>) -> i32;
}

// 사용자가 쓴 C handle 소유자; Drop 이 닫음
struct File { raw: CPtr<FILE>; }

impl Drop for File {
    fn drop(ref self) { unsafe { fclose(self.raw) }; }
}

fn open(path: str) -> File {
    let p = try! CString::from_str(path);
    let m = try! CString::from_str("r");
    let raw = unsafe { fopen(p.as_ptr(), m.as_ptr()) };
    if raw.is_null() { panic("fopen failed"); }
    File { raw }
}

using f = open("data.txt") {
    process(f);
}     // ← scope 끝에서 자동 fclose (Drop)

// without using: 자원 누수 가능
let f = open("data.txt");
try process(f);                   // 에러 전파 시 fclose 안 됨
unsafe { fclose(f.raw) };         // _explicit_ 일 때만 해제
```

`using` 구문 자체는 [refs-lang 3.17 using 표현식](../../refs-lang/003-expressions/317-using-expression.md)이 정합니다. 이 구문은 [2.13 marker](../200-core/213-marker.md)의 `Drop` 트레잇과 맞물려 동작합니다.

## 1.7.5. 안전 래퍼 패턴: sys와 safe 분리

Rust 생태계의 표준 관용구는 `*-sys` 크레이트(원시 FFI)와 같은 이름의 크레이트(안전한 래퍼)를 나누는 방식입니다. Rok도 같은 패턴을 권장합니다.

```rok
// libc-sys 모듈: raw FFI
mod c {
    #[link("c")]
    extern "C" {
        pub fn malloc(size: usize) -> CPtr<u8>;
        pub fn free(ptr: CPtr<u8>);
        pub fn strdup(s: ConstPtr<c_char>) -> CPtr<c_char>;
    }
}

// libc: safe wrapper
pub struct AllocError { pub size: usize; }

pub fn alloc_buffer(size: usize) throws (AllocError) -> List<u8> {
    let p = unsafe { c::malloc(size) };
    match p.as_ptr() {
        ptr: Ptr<u8> => {
            // unsafe → safe 경계
            let bytes = unsafe { ptr.as_many().slice(size).to_list() };
            unsafe { c::free(p) };
            bytes
        }
        none => { throw AllocError { size }; }
    }
}
```

이렇게 나누면 unsafe 코드가 좁은 영역에 갇힙니다. 사용자 코드는 안전한 래퍼만 호출하므로 안전합니다.

## 1.7.6. 자동 바인딩 생성

`rokc bindgen`([refs-lang 9.1](../../refs-lang/009-tools/901-rokc-cli.md#rokc-bindgen-c-헤더-바인딩))은 libclang으로 C 헤더에서 Rok 선언을 생성합니다. libclang은 toolchain의 `lib/`에 함께 배포되고, 이 명령만 로드합니다.

```bash
rokc bindgen libfoo.h > libfoo_sys.rok
rokc bindgen libfoo.h --target x86_64-pc-windows-msvc -o libfoo_sys.rok -- -I include -DFOO=1
```

출력은 타깃 하나(`--target`, 기본값은 호스트)용입니다. 크기, 레이아웃, 정수 폭은 그 타깃에 대해 clang이 정한 값입니다. `--` 뒤의 인자는 clang에 넘깁니다. 기계의 시스템 헤더는 세 경우에 씁니다. 그 기계 자신의 플랫폼, Apple 타깃(SDK), MSVC 호스트의 MSVC 타깃입니다. 그 밖의 타깃에서는 `--sysroot`를 주지 않는 한 clang이 내장 헤더만 받습니다. 타깃의 헤더는 `--` 뒤에(`-isystem <dir>`) 넘깁니다. 출력에는 헤더의 선언과, 그 헤더가 포함(include)하는 비시스템 헤더의 선언을 씁니다. 시스템 디렉터리의 헤더라면 자기 디렉터리 트리에서 포함하는 헤더의 선언도 씁니다. 이 선언이 쓰는 다른 헤더의 선언도 함께 씁니다. clang이 거부하는 헤더는 에러(exit 1)이고, clang의 진단을 함께 냅니다.

매핑 규약은 다음과 같습니다.

- C의 정수와 부동소수 타입은 그 타깃에서 같은 크기의 Rok 원시 타입이 됩니다(`int` → `i32`, `long` → `i32` 또는 `i64`, `char` → `c_char`, `_Bool` → `bool`). `size_t` / `uintptr_t` → `usize`, `ssize_t` / `intptr_t` / `ptrdiff_t` → `isize`. 시스템 헤더가 그런 타입에 붙인 typedef는 그 타입 자체입니다.
- typedef는 Rok의 타입 별칭(type alias)이 됩니다.
- struct와 union은 `#[repr(C)] struct` / `union`에 대응합니다(clang의 레이아웃상 필요하면 `#[repr(C, align(N))]`이나 `#[repr(packed)]`). 연속된 bitfield는 그 저장소를 덮는 바이트 배열 필드 `_bitfieldN` 하나가 됩니다. Rok이 표현할 수 없는 레이아웃(N > 1인 `#pragma pack(N)`, union 안의 bitfield)은 같은 크기와 정렬로 `_opaque: [u8; N]`을 담은 struct가 됩니다. 선언만 되고 정의되지 않은 struct는 `struct Name;`(opaque)이 됩니다.
- enum은 그 정수 타입의 별칭과, 열거자마다 하나씩인 `const`가 됩니다(`pub type color = u32; pub const RED: color = 0;`). 이름 없는 enum은 그 상수들입니다.
- 객체 포인터(`T*`, `const T*`)는 `CPtr<T>`가 되며, `void*`는 `CPtr<u8>`가 됩니다.
- 함수는 `extern "C" fn`이 됩니다(C 가변 인자는 `...`). 32비트 x86 Windows의 stdcall 함수는 `extern "system"`에 들어갑니다. 전역 변수는 `static`이 됩니다(const가 아니면 `static mut`). static 함수와 inline 함수는 링크할 심볼이 없으므로 건너뜁니다.
- 함수 포인터는 `unsafe extern "C" fn(...) -> R | none`이 됩니다([refs-lang 5.9.4](../../refs-lang/005-modules/509-extern-block.md#c-함수-포인터-타입), NULL = `none`).
- 정수, 부동소수, 문자열 상수로 평가되는 object-like 매크로는 `const` 항목이 됩니다.
- Rok 키워드나 원시 타입 이름인 C 이름에는 뒤에 `_`가 붙습니다. 함수와 static은 `#[link_name]`으로 C 심볼을 유지합니다.
- 그 밖의 것은 `// skipped ...` 주석을 남기고 건너뜁니다. 128비트 정수, `_Float16`, 8바이트보다 넓은 `long double`, 벡터와 블록 타입, 가변 인자 함수 포인터, 스레드 지역 변수, 다른 호출 규약이 여기에 듭니다. 바이트로 적은 struct(`_opaque`)는 절대 값으로 넘기지 않습니다. 그런 struct를 직접 또는 다른 struct 안에 담아 받거나 돌려주는 함수나 함수 포인터는 건너뜁니다. C는 그런 struct를 필드 단위로 분류하기 때문입니다.

## 1.7.7. 호출 안전 책임 분배

호출 지점에서 누가 무엇을 책임지는지 정리합니다.

| 항목                    | 책임자                         |
|-------------------------|--------------------------------|
| 포인터 null 검사        | C → Rok 시 Rok 코드            |
| 버퍼 길이 검증          | Rok 코드 (길이를 알아야 함)    |
| 문자열 null 종료        | CString 생성 시 자동           |
| GC pin                  | Rok 코드 (오래 도는 FFI일 때)  |
| 메모리 해제 (`free`)    | Rok 코드 또는 안전한 래퍼      |
| 호출 규약 일치          | extern 선언자                  |
| 스레드 안전성           | C 라이브러리 문서 따름         |
| Errno / GetLastError    | 호출 직후 바로 읽음            |

## 1.7.8. 다른 언어와 비교

비교 대상을 넓혀 보면 다음과 같습니다.

| 측면         | C             | Rust                   | Zig               | Go                              | Rok                          |
|--------------|---------------|------------------------|-------------------|---------------------------------|------------------------------|
| 외부 함수    | (직접)        | `extern "C" { ... }`   | `extern "..."`    | `import "C"` (cgo)              | `extern "C" { ... }`         |
| 호출 규약    | (one default) | `extern "system"` etc. | `extern "C"` etc. | `"C"` only                      | 다중 (`"C"`/`"system"`/etc.) |
| C string     | `char*`       | `CStr` / `CString`     | `[*:0]u8`         | `C.CString` / `C.GoString`      | `CStr` / `CString`           |
| nullable ptr | (default)     | `Option<*const T>`     | `?*T`             | `*C.struct_T` (always nullable) | `CPtr<T>`                    |
| binding 도구 | **none**      | `bindgen` / `cbindgen` | `@cImport`        | `cgo`                           | `rokc bindgen`               |
| GC pin       | **N/A**       | **N/A**                | **N/A**           | `runtime.Pinner` (1.21+)        | `rok::bare::gc::pin`          |
| RAII / using | (manual)      | `Drop`                 | `defer`           | `defer`                         | `using` block (Drop)         |

Rok의 가장 큰 차이점은 세 가지입니다.

1. GC와 FFI의 통합. `Pinned<T>` guard와 `using` 블록을 함께 써서 자원 누수와 pin 누락을 함께 막습니다.
2. 엄격한 포인터 모델. `Ptr<T>` / `ConstPtr<T>` / `ManyPtr<T>` / `CPtr<T>`를 나눕니다([1.1](101-ptr.md)).
3. 안전한 래퍼 강제. `as` 캐스트를 거부하고 이름 붙은 캐스트만 허용합니다([1.2](102-cast.md)).
