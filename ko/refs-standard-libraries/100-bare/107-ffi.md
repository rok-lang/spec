# 1.7. FFI — `extern "C"` / `CStr` / `CString` / `CPtr`

`rok::bare::ffi` 모듈은 C ABI 와 호환되는 외부 함수 및 데이터 정의 메커니즘을 제공합니다. 이는 [refs-lang 5.9 extern 블록](../../refs-lang/005-modules/509-extern-block.md) 이 정의하는 `extern "C" { ... }` 블록과 함께 동작합니다.

본 장에서는 전통적인 C FFI 만 다루며, WASM Component Model 기반의 FFI 는 [1.8 wit](108-wit.md) 에서 별도로 서술합니다.

## 1.7.1. `extern "C"` block

가장 기본적인 형태는 다음과 같습니다.

```rok
extern "C" {
    // 함수 선언
    fn malloc(size: usize) -> CPtr<u8>;
    fn free(ptr: CPtr<u8>);
    fn strlen(s: ConstPtr<c_char>) -> usize;

    // 글로벌 (read-only)
    static errno: i32;

    // 글로벌 (mutable) — `mut` 키워드 _이 자리에서만_ 허용
    static mut atexit_count: u64;
}
```

여기에서 등장하는 `mut` 키워드는 [refs-lang 1.5 키워드](../../refs-lang/001-lexical/105-keywords.md) 에서 정의되며, 오직 이 자리에서만 의미를 가집니다. 일반 변수에는 사용할 수 없다는 점에 유의해야 합니다.

### `#[link("name")]` — library 지정

라이브러리를 명시적으로 지정하려면 `#[link]` 어트리뷰트를 활용합니다.

```rok
#[link("c")]
extern "C" {
    fn malloc(size: usize) -> CPtr<u8>;
    fn free(ptr: CPtr<u8>);
}

#[link("m")]
extern "C" {
    fn cos(x: f64) -> f64;
    fn sin(x: f64) -> f64;
}
```

linker 가 `-lc` 또는 `-lm` 같은 플래그를 자동으로 부착해 줍니다.

### 호출 규약 (calling convention)

플랫폼과 인터페이스에 따라 다양한 호출 규약을 선택할 수 있습니다.

```rok
extern "C" { ... }              // System V (Unix) / Microsoft x64 (Windows)
extern "system" { ... }         // Windows: stdcall on x86, C on x64 / aarch64
extern "fastcall" { ... }       // x86 fastcall
extern "stdcall" { ... }        // x86 stdcall
extern "aapcs" { ... }          // ARM AAPCS
extern "thiscall" { ... }       // C++ this pointer (x86 only)
```

대부분의 사용자는 기본값인 `"C"` 만 사용해도 충분합니다. 그 밖의 규약은 주로 **Windows API** 나 C++ 인터페이스를 다룰 때 등장합니다.

### `str` 매개변수와 반환

`rok_*` 가 아닌 `extern "C"` 함수의 `str` 매개변수는 NUL 로 끝나는 `char*` 로 전달되고, 반환된 `char*` 는 `strlen` 으로 길이를 재어 `str` 이 됩니다. `rok_*` 런타임 심볼은 `(ptr, len)` 을 받습니다 ([refs-lang 5.9.4](../../refs-lang/005-modules/509-extern-block.md#594-ffi-호환-타입)).

```rok
extern "C" {
    fn puts(s: str) -> i32;          // "hi" → NUL 로 끝나는 char*
    fn getenv(name: str) -> CPtr<c_char>;   // null 가능 — CPtr 로 받음
}
```

## 1.7.2. `CStr` / `CString` — null-terminated string

C 문자열을 다루는 빌림(borrow) 형태의 타입이 `CStr` 입니다.

```rok
struct CStr {
    // 내부: null-terminated UTF-8 또는 raw bytes (Unix 은 bytes, Windows 는 UTF-16 별도)
}

impl CStr {
    fn from_ptr(p: ConstPtr<c_char>) -> CStr | none;
                                    // null pointer → none
                                    // null-terminator 없으면 — undefined (호출자 책임)

    fn from_bytes_with_nul(bytes: Slice<u8>) throws (FromBytesWithNulError) -> CStr;
                                    // 검증 — 마지막이 0, 중간 0 없음
    fn from_bytes_with_nul_unchecked(bytes: Slice<u8>) -> CStr;

    fn as_ptr(self) -> ConstPtr<c_char>;
    fn as_bytes(self) -> Slice<u8>;            // null-terminator 제외
    fn as_bytes_with_nul(self) -> Slice<u8>;   // null-terminator 포함
    fn to_str(self) throws (Utf8Error) -> str;  // UTF-8 변환

    fn len(self) -> usize;                     // null-terminator 제외
}
```

### `CString` — owned, null-terminated

소유권을 가지는 형태가 필요하다면 `CString` 을 사용합니다.

```rok
struct CString { /* GC heap, null-terminated */ }

impl CString {
    fn new(bytes: Slice<u8>) throws (NulError) -> CString;
                                        // 중간 null byte 거부
    fn from_str(s: str) throws (NulError) -> CString;

    fn as_c_str(self) -> CStr;
    fn as_ptr(self) -> ConstPtr<c_char>;
    fn into_bytes(self) -> List<u8>;     // owned bytes (null 제외)
    fn into_bytes_with_nul(self) -> List<u8>;
}
```

### 사용 예 — strlen

전형적인 활용 사례를 살펴보겠습니다.

```rok
extern "C" {
    fn strlen(s: ConstPtr<c_char>) -> usize;
}

let s: str = "hello";
let cs = try CString::from_str(s);
let n = unsafe { strlen(cs.as_ptr()) };       //→ 5
```

> [!NOTE]
> `str` 와 `CStr` 사이의 변환에는 **할당이 필요합니다** (null-terminator 를 추가해야 하기 때문입니다). `str` 는 일반적으로 non-null-terminated 형태이므로 FFI 자리에서만 명시적으로 변환하는 편이 권장됩니다.

## 1.7.3. `CPtr<T>` 와 nullable

권위 있는 정의는 [1.1.5 CPtr](101-ptr.md#115-cptrt--c-호환-nullable) 에 있습니다. C 함수가 `T*` 를 반환할 때에는 null 가능성을 명시할 필요가 있는데, 그 자리에 등장하는 타입입니다.

```rok
extern "C" {
    fn fopen(path: ConstPtr<c_char>, mode: ConstPtr<c_char>) -> CPtr<FILE>;
    fn fclose(file: CPtr<FILE>) -> i32;
}

struct FILE;        // opaque

let path = try CString::from_str("data.txt");
let mode = try CString::from_str("r");
let f: CPtr<FILE> = unsafe { fopen(path.as_ptr(), mode.as_ptr()) };

match f.as_ptr() {
    file: Ptr<FILE> => {
        // 사용
        unsafe { fclose(f) };
    }
    none => panic("fopen failed"),
}
```

## 1.7.4. `using` 블록 — RAII

GC 는 finalizer 를 보장하지 않습니다. 이는 모든 GC 언어를 학습할 때 짚게 되는 원칙으로, 외부 자원의 RAII 는 **명시적인 `using`** 으로 처리해야 합니다.

```rok
using f = try rok::bare::ffi::fopen(path, "r") {
    let buf = try f.read_all();
    process(buf);
}     // ← scope 끝에서 자동 fclose (Drop)

// without using — 자원 누수 가능
let f = try rok::bare::ffi::fopen(path, "r");
try process(f);                                // 에러 전파 시 fclose 안 됨
rok::bare::ffi::fclose(f);                        // _explicit_ 만 보장
```

`using` 구문 자체는 [refs-lang 3.17 using 표현식](../../refs-lang/003-expressions/317-using-expression.md) 이 권위를 가지며, [2.13 marker](../200-core/213-marker.md) 의 `Drop` 트레잇과 통합되어 작동합니다.

## 1.7.5. 안전 wrapper 패턴 — sys + safe 분리

Rust 생태계의 표준 관용구는 `*-sys` 크레이트(raw FFI) 와 동명 크레이트(safe wrapper) 를 분리하는 것입니다. rok 도 같은 패턴을 권장합니다.

```rok
// libc-sys 모듈 — raw FFI
mod c {
    #[link("c")]
    extern "C" {
        pub fn malloc(size: usize) -> CPtr<u8>;
        pub fn free(ptr: CPtr<u8>);
        pub fn strdup(s: ConstPtr<c_char>) -> CPtr<c_char>;
    }
}

// libc — safe wrapper
pub fn alloc_buffer(size: usize) throws (AllocError) -> List<u8> {
    let p = unsafe { c::malloc(size) };
    match p.as_ptr() {
        ptr: Ptr<u8> => {
            // unsafe → safe 경계
            let bytes = unsafe { Slice::from_raw_parts(ptr, size).to_list() };
            unsafe { c::free(p) };
            bytes
        }
        none => { throw AllocError::OutOfMemory; }
    }
}
```

이러한 분리는 unsafe 코드를 좁은 영역에 가두는 효과를 가집니다. 그 결과 사용자 코드에서는 safe wrapper 만 호출하게 되어 안전성이 자연스럽게 확보됩니다.

## 1.7.6. 자동 binding 생성

C 헤더로부터 rok extern 블록을 생성하는 `rokc bindgen` 도구가 함께 제공됩니다.

```bash
rokc bindgen libfoo.h > libfoo_sys.rok
```

매핑 규약은 다음과 같습니다.

- typedef 는 rok 의 type alias 로 변환됩니다.
- struct 는 `#[repr(C)] struct` 형태로 매핑됩니다.
- enum 은 `#[repr(C)] enum` 또는 const i32 로 변환됩니다.
- function 은 `extern "C" fn` 으로 옮겨집니다.
- function pointer 는 `extern "C" fn(...) -> R` 으로 표현됩니다 ([refs-lang 5.9.4](../../refs-lang/005-modules/509-extern-block.md#c-함수-포인터-타입)). nullable 함수 포인터는 `extern "C" fn(...) -> R | none` 입니다 (null = `none`).

## 1.7.7. 호출 안전 책임 분배

호출 자리에서 누가 무엇을 책임지는지 정리하면 다음과 같습니다.

| 항목                    | 책임자                         |
|-------------------------|--------------------------------|
| Pointer null 검사       | C → rok 시 rok 코드            |
| Buffer 길이 검증        | rok 코드 (length 알고 있어야)  |
| String null-termination | CString 생성 시 자동           |
| GC pin                  | rok 코드 (long-running FFI 시) |
| 메모리 해제 (`free`)    | rok 코드 또는 safe wrapper     |
| 호출 규약 일치          | extern 선언자                  |
| Thread safety           | C 라이브러리 문서 따름         |
| Errno / GetLastError    | 호출 직후 즉시 read            |

## 1.7.8. 다른 언어와의 비교

비교의 시야를 넓히면 rok 의 위치가 더 분명해집니다.

| 측면         | C             | Rust                   | Zig               | Go                              | rok                          |
|--------------|---------------|------------------------|-------------------|---------------------------------|------------------------------|
| 외부 함수    | (직접)        | `extern "C" { ... }`   | `extern "..."`    | `import "C"` (cgo)              | `extern "C" { ... }`         |
| 호출 규약    | (one default) | `extern "system"` etc. | `extern "C"` etc. | `"C"` only                      | 다중 (`"C"`/`"system"`/etc.) |
| C string     | `char*`       | `CStr` / `CString`     | `[*:0]u8`         | `C.CString` / `C.GoString`      | `CStr` / `CString`           |
| nullable ptr | (default)     | `Option<*const T>`     | `?*T`             | `*C.struct_T` (always nullable) | `CPtr<T>`                    |
| binding 도구 | **none**      | `bindgen` / `cbindgen` | `@cImport`        | `cgo`                           | `rokc bindgen`               |
| GC pin       | **N/A**       | **N/A**                | **N/A**           | `runtime.Pinner` (1.21+)        | `rok::bare::gc::pin`          |
| RAII / using | (manual)      | `Drop`                 | `defer`           | `defer`                         | `using` block (Drop)         |

rok 의 가장 큰 차이점은 다음 세 가지로 압축됩니다.

1. GC 와 FFI 의 통합. `Pinned<T>` guard 와 `using` 블록을 함께 사용함으로써 자원 누수와 pin 누락을 동시에 차단합니다.
2. 엄격한 포인터 모델. `Ptr<T>` / `ConstPtr<T>` / `ManyPtr<T>` / `CPtr<T>` 가 분리되어 있습니다 ([1.1](101-ptr.md)).
3. safe wrapper 강제. `as` cast 를 거부하고 named cast 만 허용합니다 ([1.2](102-cast.md)).
