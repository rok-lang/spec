# 3.2. `net::` — 네트워크 (TCP / UDP / Unix + TLS 1.3)

`rok::std::net` 모듈은 저수준 네트워크 primitive 와 함께 **TLS 1.3** 까지 한 묶음으로 제공합니다. 다만 HTTP, HTTP/2, HTTP/3 같은 고수준 프로토콜은 의도적으로 범위 밖에 두었으며, `rok/http` 등 별도 패키지로 위임합니다. 이는 표준 라이브러리가 1.0 으로 동결된 뒤 진화가 멈춰버리는 Go 의 전철을 피하기 위한 선택이기도 합니다.

## 3.2.1. TCP

TCP 쪽은 `TcpListener` 와 `TcpStream` 두 타입을 축으로 구성합니다. 리스너는 바인드와 accept 흐름을 담당하고, 스트림은 읽기·쓰기와 옵션 제어를 모두 노출합니다.

```rok
struct TcpListener { /* OS handle */ }
struct TcpStream { /* OS handle */ }

impl TcpListener {
    fn bind(addr: SocketAddr) -> Result<TcpListener, IoError>;
    fn accept(self) -> Result<(TcpStream, SocketAddr), IoError>;     // suspend
    fn local_addr(self) -> Result<SocketAddr, IoError>;
    fn try_clone(self) -> Result<TcpListener, IoError>;
    fn set_nonblocking(self, nb: bool) -> Result<(), IoError>;
    fn incoming(self) -> impl Iterator<Item = Result<TcpStream, IoError>>;
}

impl TcpStream {
    fn connect(addr: SocketAddr) -> Result<TcpStream, IoError>;     // suspend
    fn connect_timeout(addr: SocketAddr, dur: Duration) -> Result<TcpStream, IoError>;

    fn read(self, buf: ref Slice<u8>) -> Result<usize, IoError>;
    fn read_all(self) -> Result<List<u8>, IoError>;
    fn write(self, buf: Slice<u8>) -> Result<usize, IoError>;
    fn write_all(self, buf: Slice<u8>) -> Result<(), IoError>;
    fn flush(self) -> Result<(), IoError>;

    fn peer_addr(self) -> Result<SocketAddr, IoError>;
    fn local_addr(self) -> Result<SocketAddr, IoError>;
    fn shutdown(self, how: Shutdown) -> Result<(), IoError>;

    // TCP 옵션
    fn set_nodelay(self, nodelay: bool) -> Result<(), IoError>;     // TCP_NODELAY
    fn set_keepalive(self, alive: Duration | none) -> Result<(), IoError>;
    fn set_read_timeout(self, dur: Duration | none) -> Result<(), IoError>;
    fn set_write_timeout(self, dur: Duration | none) -> Result<(), IoError>;
}

enum Shutdown { Read, Write, Both }
```

## 3.2.2. UDP

UDP 는 단일 `UdpSocket` 타입이 모든 역할을 맡습니다. 데이터그램 송수신을 기본으로 하되, `connect` 로 peer 를 고정해두면 `send` / `recv` 만으로도 다룰 수 있도록 했습니다. 멀티캐스트 가입과 TTL 같은 옵션도 함께 노출하며, QUIC 같은 워크로드를 염두에 두고 GSO/GRO 활용을 위한 segment size 제어까지 포함합니다.

```rok
struct UdpSocket { /* OS handle */ }

impl UdpSocket {
    fn bind(addr: SocketAddr) -> Result<UdpSocket, IoError>;

    fn send_to(self, buf: Slice<u8>, addr: SocketAddr) -> Result<usize, IoError>;
    fn recv_from(self, buf: ref Slice<u8>) -> Result<(usize, SocketAddr), IoError>;
    fn connect(self, addr: SocketAddr) -> Result<(), IoError>;       // peer 고정
    fn send(self, buf: Slice<u8>) -> Result<usize, IoError>;
    fn recv(self, buf: ref Slice<u8>) -> Result<usize, IoError>;

    // 멀티캐스트
    fn join_multicast_v4(self, addr: Ipv4Addr, iface: Ipv4Addr) -> Result<(), IoError>;
    fn leave_multicast_v4(self, addr: Ipv4Addr, iface: Ipv4Addr) -> Result<(), IoError>;
    fn set_multicast_loop_v4(self, on: bool) -> Result<(), IoError>;
    fn set_multicast_ttl_v4(self, ttl: u32) -> Result<(), IoError>;

    // QUIC 용 (GSO / GRO)
    fn set_segment_size(self, size: u16) -> Result<(), IoError>;     // UDP_SEGMENT
}
```

## 3.2.3. Unix domain socket

Unix domain socket 은 `UnixListener`, `UnixStream`, `UnixDatagram` 세 타입으로 정리합니다. 전체적인 모양은 TCP 와 닮아 있지만, 같은 호스트 안에서만 통신하므로 파일 경로를 식별자로 쓰며 `pair()` 처럼 `socketpair(2)` 에 대응되는 편의 메서드도 제공합니다. 또한 `SCM_RIGHTS` 를 통한 fd 전달은 Unix 소켓에서만 의미가 있으므로 `send_with_fd` / `recv_with_fd` 로 분리해 두었습니다.

```rok
struct UnixListener { /* unix only */ }
struct UnixStream { /* unix only */ }
struct UnixDatagram { /* unix only */ }

#[cfg(unix)]
impl UnixListener {
    fn bind(path: Path) -> Result<UnixListener, IoError>;
    fn accept(self) -> Result<(UnixStream, SocketAddr), IoError>;
    // ... TcpListener 와 비슷
}

#[cfg(unix)]
impl UnixStream {
    fn connect(path: Path) -> Result<UnixStream, IoError>;
    fn pair() -> Result<(UnixStream, UnixStream), IoError>;          // socketpair

    // SCM_RIGHTS — fd passing
    fn send_with_fd(self, buf: Slice<u8>, fd: RawFd) -> Result<usize, IoError>;
    fn recv_with_fd(self, buf: ref Slice<u8>) -> Result<(usize, RawFd | none), IoError>;
}
```

## 3.2.4. SocketAddr / IpAddr

주소 표현은 IPv4 와 IPv6 를 합집합으로 묶은 `SocketAddr` enum 을 중심으로 합니다. 각 변종은 IP 와 포트, 그리고 IPv6 의 경우 flow info 와 scope id 까지 그대로 노출하므로, 필요할 때 직접 들여다볼 수 있습니다. 문자열 파싱은 `FromStr` 구현을 통해 자연스럽게 이뤄지며, 호스트네임을 다루는 DNS 조회는 별도 함수로 제공합니다.

```rok
enum SocketAddr {
    V4(SocketAddrV4),
    V6(SocketAddrV6),
}

struct SocketAddrV4 { ip: Ipv4Addr; port: u16; }
struct SocketAddrV6 { ip: Ipv6Addr; port: u16; flow_info: u32; scope_id: u32; }

struct Ipv4Addr { octets: [u8; 4]; }
struct Ipv6Addr { segments: [u16; 8]; }

impl Ipv4Addr {
    const LOCALHOST: Ipv4Addr = Ipv4Addr { octets: [127, 0, 0, 1] };
    const UNSPECIFIED: Ipv4Addr = Ipv4Addr { octets: [0, 0, 0, 0] };
    // ...
}

// 파싱
impl FromStr for SocketAddr { ... }       // "127.0.0.1:8080" / "[::1]:8080"
impl FromStr for Ipv4Addr { ... }
impl FromStr for Ipv6Addr { ... }

// DNS
fn resolve(host: str) -> Result<List<SocketAddr>, IoError>;
fn resolve_one(host: str, port: u16) -> Result<SocketAddr, IoError>;
```

## 3.2.5. TLS 1.3 — `net::tls`

TLS 는 `net::tls` 하위 모듈에 모아 두었고, 처음부터 1.3 만을 기본 가정으로 잡았습니다. `ClientConfig` 와 `ServerConfig` 가 인증서, 암호 모음, ALPN 프로토콜 목록을 표현하며, post-quantum 옵션을 통해 ML-KEM 하이브리드 키 교환을 활성화할 수 있습니다. 핸드셰이크 이후에는 `Client` / `Server` 가 평문 스트림처럼 동작하므로 기존 I/O 코드를 거의 그대로 얹을 수 있습니다.

```rok
use rok::std::net::tls;

struct ClientConfig {
    root_certs: List<Certificate>;          // CA bundle
    cipher_suites: List<CipherSuite>;       // 기본 TLS 1.3 only
    alpn_protocols: List<List<u8>>;         // ["h2", "http/1.1"] 등
    enable_pq: bool;                        // post-quantum (ML-KEM hybrid)
}

struct ServerConfig {
    cert_chain: List<Certificate>;
    private_key: PrivateKey;
    cipher_suites: List<CipherSuite>;
    alpn_protocols: List<List<u8>>;
}

struct Client {
    fn new(stream: TcpStream, server_name: str) -> Result<Client, TlsError>;
    fn with_config(stream: TcpStream, server_name: str, cfg: ClientConfig) -> Result<Client, TlsError>;

    fn read(self, buf: ref Slice<u8>) -> Result<usize, IoError>;
    fn write(self, buf: Slice<u8>) -> Result<usize, IoError>;
    fn write_all(self, buf: Slice<u8>) -> Result<(), IoError>;
    fn flush(self) -> Result<(), IoError>;
    fn close_notify(self) -> Result<(), IoError>;

    fn negotiated_alpn(self) -> List<u8> | none;
    fn peer_certificates(self) -> List<Certificate>;
}

struct Server {
    fn new(stream: TcpStream, cfg: ServerConfig) -> Result<Server, TlsError>;
    // ... Client 와 비슷
}
```

> 백엔드는 rustls 와 aws-lc-rs 계열을 기본으로 삼아 메모리 안전성을 확보합니다. 사용자가 OpenSSL 을 직접 호출할 일은 없도록 설계했습니다.

> post-quantum 의 경우 ML-KEM (Kyber) 과 X25519 의 하이브리드 방식을 채택하며, rustls 0.23 이후의 [ML-KEM 통합](https://github.com/rustls/rustls/releases) 진척에 맞춰 따라갑니다.

### 사용 예

실제 사용 흐름은 평문 TCP 연결 위에 TLS 클라이언트를 얹고, 그 위에서 평문 I/O 를 호출하는 모양으로 단순합니다.

```rok
use rok::std::net::{tcp_connect, tls};

let conn = tcp_connect("example.com:443")?;
let tls_conn = tls::Client::new(conn, "example.com")?;
tls_conn.write_all(b"GET / HTTP/1.1\r\nHost: example.com\r\n\r\n")?;
let resp = tls_conn.read_all()?;
tls_conn.close_notify()?;
```

## 3.2.6. 편의 함수

자주 쓰는 패턴은 짧은 helper 로 감싸 두었습니다. 문자열을 받는 형태에서는 DNS 해석까지 자동으로 수행하므로, `tcp_connect("example.com:80")` 처럼 호스트네임을 그대로 넘길 수 있습니다.

```rok
fn tcp_connect(addr: str | SocketAddr) -> Result<TcpStream, IoError>;
fn tcp_listen(addr: str | SocketAddr) -> Result<TcpListener, IoError>;
fn udp_bind(addr: str | SocketAddr) -> Result<UdpSocket, IoError>;
```

## 3.2.7. zerocopy hooks (advanced)

처리량이 곧 비용이 되는 자리, 예컨대 프록시나 파일 서버 같은 경우를 위해 zerocopy 계열 hook 도 별도로 노출합니다. 대부분의 사용자에게는 필요하지 않으며, 정말 필요할 때 손에 닿는 곳에 두는 정도가 목적입니다.

```rok
impl TcpStream {
    fn sendfile(self, file: ref File, offset: u64, count: u64) -> Result<u64, IoError>;
                                            // sendfile(2) / TransmitFile
    fn splice(self, src: ref File, count: u64) -> Result<u64, IoError>;
                                            // Linux splice(2)

    fn write_zerocopy(self, buf: Slice<u8>) -> Result<usize, IoError>;
                                            // MSG_ZEROCOPY (Linux 4.14+)
                                            // io_uring IORING_OP_SEND_ZC (5.20+)
}
```

## 3.2.8. 모듈 매핑

플랫폼별 지원 범위는 다음 표에 정리되어 있습니다. 핵심 기능은 데스크톱 OS 와 wasi 양쪽에서 모두 동작하지만, Unix socket 이나 zerocopy hook 처럼 Linux 고유 자원에 의존하는 항목은 제한적으로만 활성화됩니다.

| 항목             | linux/macos/windows | wasi | 비고                           |
|------------------|---------------------|------|--------------------------------|
| TCP              | ✓                   | ✓    | wasi:sockets                   |
| UDP              | ✓                   | ✓    | wasi:sockets                   |
| Unix socket      | linux/macos         | ✗    | Windows 부분 (named pipe 별도) |
| TLS 1.3          | ✓ (rustls)          | ✓    | rustls + aws-lc-rs             |
| sendfile         | linux               | ✗    |                                |
| splice           | linux               | ✗    |                                |
| MSG_ZEROCOPY     | linux 4.14+         | ✗    |                                |
| io_uring SEND_ZC | linux 5.20+         | ✗    |                                |
