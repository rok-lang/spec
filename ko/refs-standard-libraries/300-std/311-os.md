# 3.11. `os::`: 일부 OS에만 있는 것

크로스 플랫폼 모듈(`fs`, `net`, `process`, `io`)에는 모든 데스크톱 OS가 할 수 있는 것만 둡니다. 일부 OS에만 있는 것은 `rok::std::os` 아래, OS 계열마다 모듈 하나씩에 둡니다. Rust와 같은 나눔입니다.

| 모듈 | 있는 곳 | 담는 것 |
|---|---|---|
| `os::unix` | `target_family = "unix"` (Linux, macOS, FreeBSD) | `fs`, `io`, `net`, `process` |
| `os::linux` | `target_os = "linux"` | `net`, `process` |
| `os::windows` | `target_os = "windows"` | `io`, `process` |

모듈은 해당 타깃에만 있습니다. 다른 타깃에서는 `use rok::std::os::unix::..`가 풀리지 않습니다. 이 모듈을 쓰는 코드는 같은 `#[cfg]` 아래에 씁니다.

## 3.11.1. prelude의 Ext 트레잇

일부 OS에만 있는 메서드는 크로스 플랫폼 타입에 붙는 트레잇 메서드입니다. `PermissionsExt`는 `fs::Permissions`에 `mode`를, `CommandExt`는 `process::Command`에 `process_group`을 더하는 식입니다. 트레잇이 있는 타깃에서는 그 트레잇이 prelude([0.2](../000-meta/002-import.md))에 들어 있어, 메서드에 `use`가 필요 없습니다.

| 타깃 | prelude에 더해지는 이름 |
|---|---|
| unix | `PermissionsExt` (`os::unix::fs`), `CommandExt`, `ExitStatusExt` (`os::unix::process`) |
| linux | unix의 것, 그리고 `ChildExt` (`os::linux::process`), `TcpStreamExt` (`os::linux::net`) |

다른 타깃에서는 트레잇도 impl도 없습니다. 호출하면 메서드에 필요한 cfg를 알려 주는 not-found 에러가 납니다([refs-lang 6.3](../../refs-lang/006-meta-system/603-cfg.md)).

```text
error: no method `process_group` found for type `Command`
 = note: `process_group` is only available on unix (`#[cfg(target_family = "unix")]`)
 = help: put the code that uses it under the same `#[cfg(target_family = "unix")]`
```

raw 핸들 트레잇(`AsRawFd`, `AsRawHandle`, ..)은 prelude에 없습니다. 쓰는 곳에서 가져옵니다.

## 3.11.2. `os::unix::io`: 파일 디스크립터

```rok
// rok::std::os::unix::io
type RawFd = i32;

trait AsRawFd {
    fn as_raw_fd(self) -> RawFd;             // 여전히 self 의 것; self 를 닫은 뒤에는 -1
}

trait FromRawFd {
    unsafe fn from_raw_fd(fd: RawFd) -> Self;    // 이제부터 self 가 fd 를 소유
}
```

`AsRawFd`는 `File`, `Socket`, `TcpStream`, `TcpListener`, `UdpSocket`, Unix 소켓(3.11.4), `ChildStdin` / `ChildStdout` / `ChildStderr`, `Stdin` / `Stdout` / `Stderr`(0, 1, 2)가 구현합니다. `FromRawFd`는 `File`(오류 메시지에서 `fd N`으로 불림)과 소켓들이 구현합니다. `from_raw_fd`는 `unsafe`입니다. `fd`는 열려 있어야 하고, 다른 무엇도 그것을 닫으면 안 됩니다. 그렇지 않으면 두 소유자가 디스크립터 하나를 닫고, 두 번째 닫기는 그 사이 열린 다른 파일에 닿을 수 있습니다.

디스크립터는 계속 핸들의 것입니다. 핸들을 닫으면 디스크립터도 닫히고, 그 뒤 `as_raw_fd`는 -1을 돌려줍니다. `from_raw_fd`로 넘겨받은 소켓은 받은 상태 그대로 씁니다. blocking 디스크립터라면 blocking 호출이 `poll`이 아니라 OS 안에서 멈춥니다(그때는 타임아웃과 `set_nonblocking`이 듣지 않습니다).

## 3.11.3. `os::windows::io`: 핸들과 소켓

```rok
// rok::std::os::windows::io
type RawHandle = isize;                  // Win32 HANDLE, 포인터 크기
type RawSocket = u64;                    // Winsock SOCKET

trait AsRawHandle { fn as_raw_handle(self) -> RawHandle; }       // 닫힌 뒤에는 INVALID_HANDLE_VALUE (-1)
trait FromRawHandle { unsafe fn from_raw_handle(h: RawHandle) -> Self; }
trait AsRawSocket { fn as_raw_socket(self) -> RawSocket; }       // 닫힌 뒤에는 INVALID_SOCKET
trait FromRawSocket { unsafe fn from_raw_socket(s: RawSocket) -> Self; }
```

`AsRawHandle`은 `File`, 자식 pipe, 표준 스트림(`GetStdHandle` 값)이 구현하고, `FromRawHandle`은 `File`이 구현합니다. `AsRawSocket`과 `FromRawSocket`은 `Socket`, `TcpStream`, `TcpListener`, `UdpSocket`이 구현합니다. 값은 Win32가 주는 HANDLE과 SOCKET 그대로입니다. 런타임이 그것을 어떻게 들고 있는지는 드러나지 않습니다. 커널 객체 핸들이 아닌 값(`GetCurrentProcess()` 같은 의사 핸들)을 `from_raw_handle`에 주면 닫힌 `File`이 됩니다.

## 3.11.4. `os::unix::net`: Unix 도메인 소켓

Unix 도메인 소켓은 `UnixListener`, `UnixStream`, `UnixDatagram` 세 타입입니다. 모양은 TCP([3.2](302-net.md))와 비슷합니다. 다만 같은 호스트 안에서만 통신하므로 파일 경로를 식별자로 쓰고, `socketpair(2)`에 대응하는 `pair()`가 있습니다. `SCM_RIGHTS`로 fd를 넘기는 일은 Unix 소켓에서만 의미가 있으므로 `send_with_fd` / `recv_with_fd`로 따로 두었습니다.

```rok
// rok::std::os::unix::net
struct UnixListener { /* opaque */ }
struct UnixStream { /* opaque */ }
struct UnixDatagram { /* opaque */ }

impl UnixListener {
    fn bind(path: Path) throws (IoError) -> UnixListener;             // path 는 아직 없어야 함; backlog 128
    fn accept(self) throws (IoError) -> (UnixStream, Path | none);   // 상대가 바인드한 경로, 이름 없으면 none
    async fn accept_async(ref self) throws (IoError) -> (UnixStream, Path | none);
    fn local_addr(self) throws (IoError) -> Path | none;
    fn set_nonblocking(self, nb: bool) throws (IoError);
    fn try_clone(self) throws (IoError) -> UnixListener;
    fn close(self) throws (IoError);   // OS 가 알린 에러를 던짐
}

impl UnixStream {
    fn connect(path: Path) throws (IoError) -> UnixStream;
    async fn connect_async(path: Path) throws (IoError) -> UnixStream;   // 블로킹 스레드에서
    fn pair() throws (IoError) -> (UnixStream, UnixStream);          // socketpair
    fn send_with_fd<B: AsBytes>(self, buf: B, fd: RawFd) throws (IoError) -> usize;
    fn recv_with_fd(self, buf: SliceMut<u8>) throws (IoError) -> (usize, RawFd | none);
    async fn send_with_fd_async<B: AsBytes>(ref self, buf: B, fd: RawFd) throws (IoError) -> usize;
    async fn recv_with_fd_async(ref self, buf: SliceMut<u8>) throws (IoError) -> (usize, RawFd | none);
    fn peer_addr(self) throws (IoError) -> Path | none;
    fn local_addr(self) throws (IoError) -> Path | none;
    fn shutdown(self, how: Shutdown) throws (IoError);
    async fn shutdown_async(ref self, how: Shutdown) throws (IoError);   // shutdown 은 기다리지 않음
    fn set_read_timeout(self, dur: Duration | none) throws (IoError);
    fn set_write_timeout(self, dur: Duration | none) throws (IoError);
    fn set_nonblocking(self, nb: bool) throws (IoError);
    fn try_clone(self) throws (IoError) -> UnixStream;
    fn close(self) throws (IoError);   // OS 가 알린 에러를 던짐
}

impl UnixDatagram {
    fn bind(path: Path) throws (IoError) -> UnixDatagram;
    fn connect(path: Path) throws (IoError) -> UnixDatagram;         // path 에 연결, 자신은 바인드 안 함
    async fn connect_async(path: Path) throws (IoError) -> UnixDatagram;   // 기다리지 않음
    fn pair() throws (IoError) -> (UnixDatagram, UnixDatagram);      // socketpair
    fn send<B: AsBytes>(self, buf: B) throws (IoError) -> usize;
    fn recv(self, buf: SliceMut<u8>) throws (IoError) -> usize;
    fn send_with_fd<B: AsBytes>(self, buf: B, fd: RawFd) throws (IoError) -> usize;
    fn recv_with_fd(self, buf: SliceMut<u8>) throws (IoError) -> (usize, RawFd | none);
    // + send_async / recv_async / send_with_fd_async / recv_with_fd_async (ref self)
    fn local_addr(self) throws (IoError) -> Path | none;
    fn set_read_timeout(self, dur: Duration | none) throws (IoError);
    fn set_write_timeout(self, dur: Duration | none) throws (IoError);
    fn set_nonblocking(self, nb: bool) throws (IoError);
    fn close(self) throws (IoError);   // OS 가 알린 에러를 던짐
}

impl io::Read for UnixStream { ... }
impl io::Write for UnixStream { ... }
impl io::AsyncRead for UnixStream { ... }
impl io::AsyncWrite for UnixStream { ... }
impl io::Close for UnixListener { ... }   // UnixStream, UnixDatagram 도
impl io::AsyncClose for UnixListener { ... } // UnixStream, UnixDatagram 도
impl Drop for UnixListener { ... }       // 에러 경로에서 해제
impl Drop for UnixStream { ... }
impl Drop for UnixDatagram { ... }
// + 셋 모두 AsRawFd, FromRawFd
```

3.2.0의 공통 규칙이 그대로 적용됩니다. 내부는 non-blocking이고, `set_*_timeout`이 blocking 호출을 제한하며, `*_async`는 태스크를 멈춥니다. 스트림 `connect`는 리스너의 backlog가 가득 찼을 때만 기다리고, `connect_async`는 이를 블로킹 스레드에서 돌립니다. `recv_with_fd`로 받은 디스크립터는 호출한 쪽의 것입니다(close-on-exec). `FromRawFd`로 소유자에게 넘깁니다.

## 3.11.5. `os::unix::process`와 `os::linux::process`

```rok
// rok::std::os::unix::process
trait CommandExt {
    fn process_group(self, pgid: i32) -> Self;   // 0: 자식이 이끄는 새 그룹
}
impl CommandExt for Command { .. }

trait ExitStatusExt {
    fn signal(self) -> Signal | none;            // 프로세스를 끝낸 신호
}
impl ExitStatusExt for ExitStatus { .. }

fn parent_id() -> u32;                           // getppid

// rok::std::os::linux::process
trait ChildExt {
    fn pidfd(self) throws (IoError) -> RawFd;    // Linux 5.3+; 자식을 회수할 때까지 유효
}
impl ChildExt for Child { .. }
```

`ExitStatusExt::signal`은 프로세스가 스스로 끝났을 때 `none`이고, `Signal`에 이름이 없는 신호(실시간 신호)일 때도 `none`입니다. pidfd는 계속 자식의 것입니다. `wait` / `try_wait`가 닫습니다.

## 3.11.6. `os::linux::net`: 커널 복사

프록시나 파일 서버처럼 처리량이 곧 비용인 곳을 위해, Linux 커널 복사 경로를 `TcpStream`에 노출합니다. 대부분의 사용자에게는 필요 없습니다. `io::copy`가 쓸 수 있을 때 이미 이 경로를 씁니다.

```rok
// rok::std::os::linux::net
trait TcpStreamExt {
    fn sendfile(self, ref file: File, offset: u64, count: u64) throws (IoError) -> u64;
                                            // sendfile(2): 보낸 바이트 수, 파일이 먼저 끝나면 더 적음
    fn splice(self, ref src: File, count: u64) throws (IoError) -> u64;
                                            // 커널 pipe 를 거치는 splice(2), src 의 오프셋부터
    fn write_zerocopy(self, buf: List<u8>) throws (IoError) -> usize;
                                            // MSG_ZEROCOPY (Linux 4.14+): buf 의 앞부분, 제자리에서 읽음
}
impl TcpStreamExt for TcpStream { .. }
```

`write_zerocopy`는 커널이 `buf`를 더는 필요로 하지 않을 때 돌아옵니다.

## 3.11.7. `os::windows::process`: Ctrl-Break

```rok
// rok::std::os::windows::process
fn on_ctrl_break(handler: fn() + Send) throws (IoError);
```

`process::on_signal`은 `Signal`이 있는 콘솔 이벤트를 받습니다(Ctrl-C는 `Interrupt`, 콘솔 닫기 / 로그오프 / 종료는 `Hangup`, [3.7.5](307-process.md#375-신호-처리고급)). Ctrl-Break에는 Unix 짝이 없으므로 이 Windows 전용 함수가 받습니다. 콘솔이 Ctrl-Break를 보낼 때마다 `handler`가 `rok-signal` 디스패처 스레드에서 실행되고, 나중 호출이 앞의 것을 바꿉니다. 핸들러가 없으면 Ctrl-Break는 프로세스를 끝냅니다(콘솔의 기본 동작).
