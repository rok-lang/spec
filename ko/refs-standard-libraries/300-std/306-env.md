# 3.6. `env::`: 환경 변수 / args / 디렉터리

`rok::std::env` 모듈은 프로세스 환경에 접근하는 일관된 진입점입니다. 명령행 인자, 환경 변수, 표준 디렉터리 경로를 OS 차이 없이 한곳에서 다룹니다.

## 3.6.1. API

모듈이 노출하는 함수와 타입은 다음과 같습니다. 경로 매개변수는 tier 공통 [인자 규약](README.md#인자-규약)을 따릅니다(`Path`는 `P: AsPath`).

```rok
// 명령행 인자
fn args() -> List<str>;                        // [0] = 프로그램 이름. 런타임이 시작 시 argc/argv 를 잡아 둠. UTF-8 이 아닌 바이트는 U+FFFD
fn args_os() -> List<RawStr>;                  // non-UTF-8 보장 (rare)

// 환경 변수
fn var(name: str) throws (VarError) -> str;
fn var_os(name: str) -> RawStr | none;
fn vars() -> Vars;                             // Iterator<Item = (str, str)> 구현. UTF-8 이 아닌 바이트는 U+FFFD
fn vars_os() -> VarsOs;                        // Iterator<Item = (RawStr, RawStr)> 구현

unsafe fn set_var(name: str, value: str) throws (IoError);   // 잘못된 이름이나 값이면 InvalidInput (3.6.3)
unsafe fn remove_var(name: str) throws (IoError);            // 설정되지 않은 이름은 오류가 아님

// 디렉토리
fn current_dir() throws (IoError) -> Path;
fn set_current_dir(path: Path) throws (IoError);
fn home_dir() -> Path | none;
fn temp_dir() -> Path;
fn config_dir() -> Path | none;               // macOS ~/Library/Application Support, 그 밖 $XDG_CONFIG_HOME / ~/.config
fn cache_dir() -> Path | none;                // macOS ~/Library/Caches, 그 밖 $XDG_CACHE_HOME / ~/.cache
fn data_dir() -> Path | none;                 // macOS ~/Library/Application Support, 그 밖 $XDG_DATA_HOME / ~/.local/share

// PATH 환경 변수 split (OS 별 구분자)
fn split_paths(paths: str) -> List<Path>;     // ":" on unix, ";" on windows
fn join_paths<I: IntoIterator<Item = P>, P: AsPath>(paths: I) throws (JoinPathsError) -> str;

// 실행 파일 자체
fn current_exe() throws (IoError) -> Path;

// 프로세스 ID
// 부모의 id: os::unix::process::parent_id (3.11.5)

enum VarError {
    NotPresent,                                 // 변수가 없음
    NotUnicode,                                 // 값이 UTF-8 이 아님 (var_os 로 읽음)
}                                               // message(); + Display, Debug, Error, PartialEq, Eq, Clone, Copy
```

`RawStr`은 OS가 준 바이트열을 그대로 담은 문자열입니다(UTF-8이 아닐 수 있음). `JoinPathsError`는 경로 중 하나가 구분자(`:` / `;`)를 담고 있을 때 납니다.

```rok
struct RawStr { /* OS 바이트 */ }

impl RawStr {
    fn len(self) -> usize;                       // 바이트 길이
    fn is_empty(self) -> bool;
    fn to_str(self) throws (Utf8Error) -> str;   // UTF-8 이 아니면 throw
    fn to_str_lossy(self) -> str;                // 잘못된 부분은 U+FFFD
    fn as_bytes(self) -> Slice<u8>;              // 복사 없는 view
}
impl PartialEq for RawStr { ... }
impl Debug for RawStr { ... }

struct JoinPathsError { .. }                     // 비공개 필드 (0.5.10)
impl JoinPathsError {
    fn path(self) -> str;                        // 구분자를 담은 경로
    fn message(self) -> str;
}
```

Windows에서 바이트는 OS의 UTF-16을 WTF-8로 담은 것입니다. Windows에는 다음 함수도 있습니다.

```rok
impl RawStr {
    fn from_wide(wide: Slice<u16>) -> RawStr;
    fn as_wide(self) -> Slice<u16>;              // 이를 위해 만든 리스트의 view
}
```

`args`, `vars`, `RawStr::to_str_lossy`는 바이트 중 잘못된 부분을 U+FFFD로 바꿉니다. `str::from_utf8_lossy`처럼 잘못된 최대 부분열마다 하나씩 바꿉니다([2.15.6](../200-core/215-string.md)). Windows에서는 짝 없는 서로게이트 하나가 U+FFFD 하나입니다. `args_os`, `vars_os`, `var_os`는 바이트를 그대로 둡니다. 0.2.0부터는 `args`와 `vars`가 이런 바이트에서 대신 panic하고, 메시지에 `args_os` / `vars_os`를 적습니다.

## 3.6.2. 사용 예

다음 예제는 명령행 인자, 환경 변수, PATH 탐색으로 이어지는 전형적인 흐름을 한 번에 보여 줍니다.

```rok
use rok::std::{env, fs, process};

// CLI 도구
let args = env::args();
if args.len() < 2 {
    eprintln("usage: tool <input>");
    process::exit(1);
}
let input = args[1];
process(input);

// 환경 변수
let log_level = (try? env::var("LOG_LEVEL")) ?? "info";
let home = env::home_dir() ?? panic("HOME not set");
let config = home / ".config" / "myapp.toml";

// PATH 검색
let path_str = try env::var("PATH");
for dir in env::split_paths(path_str) {
    let candidate = dir / "myprog";
    if fs::exists(candidate) {
        log(f"found at {candidate:?}");
    }
}
```

## 3.6.3. `set_var`와 `remove_var`는 `unsafe`

`set_var`와 `remove_var`는 프로세스 전체의 환경을 바꿉니다. 이후에 띄우는 자식 프로세스도 이 환경을 물려받습니다. 자식 하나의 환경만 정하려면 안전한 `Command::env` / `env_remove`([3.7](307-process.md))를 씁니다.

```rok
unsafe { try env::set_var("RUST_LOG", "debug"); }   // main 의 첫 작업으로
let child = try Command::new("tool").env("LEVEL", "2").spawn();   // 안전: 이 자식에게만
```

둘 다 `unsafe fn`입니다. 안전 조건은 호출하는 동안 다른 스레드가 `rok::std::env`를 거치지 않고 환경을 읽거나 쓰지 않는 것입니다. Rok의 `var`, `var_os`, `vars`, `vars_os`, `set_var`, `remove_var`는 내부 락 하나를 함께 잡으므로 Rok 코드끼리는 경쟁하지 않습니다. 하지만 `getenv`나 `setenv`를 부르는 C 코드(FFI로 닿는 라이브러리 등)는 이 락을 잡지 않으며, POSIX 플랫폼에서 `set_var`가 이런 코드와 경쟁하면 정의되지 않은 동작입니다. 단일 스레드 프로그램과 Windows에서는 호출이 안전합니다. 권장 패턴은 스레드를 띄우기 전, 프로그램 시작 시점에 `set_var`를 부르는 것입니다.

둘 다 `IoError`를 던집니다. 이름이 비었거나 `=`나 NUL을 담을 때, 또는 값이 NUL을 담을 때는 `InvalidInput`입니다. 이 검사는 Windows를 포함한 모든 타깃에서 같습니다. 그 밖의 실패는 OS 오류입니다. 설정되지 않은 변수를 지우는 것은 오류가 아닙니다. 오류 대신 panic을 원하면 `try!`를 씁니다.

## 3.6.4. 구현 / 타깃

플랫폼별로 같은 의미를 구현하는 방식은 다음과 같습니다.

| 항목           | linux/macos/windows             | wasi              |
|----------------|---------------------------------|-------------------|
| `args`         | argc/argv / GetCommandLine      | wasi:cli          |
| `var` / `vars` | getenv / GetEnvironmentVariable | wasi:cli          |
| `home_dir`     | $HOME / SHGetKnownFolderPath    | wasi (개념 없음)  |
| `temp_dir`     | $TMPDIR / GetTempPath           | wasi              |
| `config_dir`   | XDG / AppData                   | (없음)            |
| `current_exe`  | /proc/self/exe / _NSGetExecutablePath / GetModuleFileName | `Unsupported` (wasm32) |

표준 경로는 플랫폼마다 다릅니다. macOS에서는 `~/Library/...`를 씁니다. 그 밖의 Unix에서는 XDG Base Directory 사양을 씁니다(`$XDG_*_HOME`은 절대 경로일 때만 쓰고, 아니면 `~/.config` 등). Windows에서는 Known Folders를 씁니다. 홈 디렉터리를 알 수 없으면 `none`입니다.
