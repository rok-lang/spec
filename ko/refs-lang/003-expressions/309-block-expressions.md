# 3.9. 블록 표현식

`{ ... }` 로 둘러싼 문장과 표현식의 묶음은 nok 에서 가장 기본적인 표현식 단위다. 본 문서는 블록의 어휘 형태와 값 평가 규칙을 정의한다.

## 3.9.1. 형태

```
block       ::= "{" stmt* tail_expr? "}"
stmt        ::= expr ";"
              | let_stmt
              | item_decl
tail_expr   ::= expr            // no trailing ";"
```

```nok
{
    문장1;
    문장2;
    ...
    마지막식      // 종결자 없음, 블록의 값이 됨
}
```

- 본체에는 0 개 이상의 문장과 0 또는 1 개의 마지막 식이 온다.
- 마지막 식을 종결자 없이 적으면 그 식의 값이 블록의 값이 된다.
- 마지막 식을 종결자와 함께 적으면 (`expr;`) 블록은 unit 값을 갖는다.

```nok
let a = {
    let x = 1;
    let y = 2;
    x + y               // 블록 값 = 3
};

let b = {
    let x = 1;
    x + 2;              // 종결자 있음 → 결과 폐기
                        // 블록 값 = unit
};

let c = {
    let x = 1;
    return x;           // return 으로 함수 자체에서 빠져나감 (블록 값 도달 안 함)
};
```

## 3.9.2. 사용처

블록은 표현식이 올 자리라면 어디든 등장할 수 있다.

```nok
let v = { ... };                  // 변수 초기값
fn_call({ ... }, other);          // 함수 인자
if { ... > 0 } { ... }            // 조건식 (드물지만 가능)
```

또한 다른 제어 구조 (`if`, `match`, `loop`, 함수 본체) 의 본체 자리는 블록이다.

## 3.9.3. 스코프

블록은 새 스코프를 만든다.

- 블록 안에서 `let` 으로 선언한 변수는 그 블록 안에서만 가시.
- 블록을 벗어나면 그 변수는 폐기된다.
- 바깥 변수는 블록 안에서 그대로 보인다 (같은 이름의 inner `let` 이 가리지 않는 한).

같은 이름의 inner `let` 은 별개 바인딩이며, 바깥 바인딩에 영향을 주지 않는다. 정확한 규칙은 [변수 선언](../005-modules/501-variable-declaration.md) 에서 정의한다.

## 3.9.4. 빈 블록

```nok
{}
```

빈 블록은 unit 값을 갖는다.

## 3.9.5. 블록 안의 마지막 식과 종결자 처리

다음 두 입력은 서로 다르게 평가된다.

```nok
let a = { x };          // a 는 x 의 값
let b = { x; };         // b 는 unit
```

- 종결자 없이 끝난 식은 블록의 값이 된다.
- 종결자와 함께 끝난 식은 결과 폐기 → 블록의 값은 unit.

이 구분은 [문장 종결자](../001-lexical/103-statement-terminator.md) 의 규칙과 일관된다.

## 3.9.6. 함수 본체와의 관계

함수 본체도 블록이며, 마지막 식의 값이 함수의 반환값이 된다. 따라서 `return` 키워드가 필수는 아니다.

```nok
fn add(x: i32, y: i32) -> i32 {
    x + y               // 종결자 없음, 자동으로 반환값
}

fn other(x: i32) -> i32 {
    let r = x + 1;
    return r;           // 명시적 return 도 가능, 위와 동일한 의미
}

fn early(x: i32) -> i32 {
    if x < 0 { return 0; }   // 조기 종료에는 명시적 return
    x * 2                    // 정상 흐름의 마지막 식, 자동 반환
}
```

세 함수 모두 정상 동작한다. 어떤 형태를 선택할지는 스타일의 문제이며, 사양은 두 형태 모두를 정식으로 지원한다.

### 권장 사용

- 마지막 식 (`return` 없이). 정상 흐름의 단일 반환 자리.
- 명시적 `return`. 조기 종료, 함수 중간의 반환, 가독성을 위한 표시.

자세한 함수 본체와 `return` 키워드, 반환 타입 규칙은 [4. 함수](../004-functions/README.md) 에서 정의한다.

## 3.9.7. 블록의 타입

블록의 타입은 그 마지막 식의 타입이다 (마지막 식이 없으면 unit).

```
{ 1i32 }                // i32
{ "hi" }                 // str
{ ; }                    // unit (빈 식)
{ }                      // unit (빈 블록)
```

이 타입 결정은 [표현식 개요](README.md) 의 분기 결과 타입 규칙과 결합된다. 같은 자리에 놓인 여러 블록 표현식이 다른 타입을 만들면 합 타입으로 결과가 합쳐진다.

## 3.9.8. divergent 블록

`return`, `break`, `continue`, `throw`, `loop { /* break 없음 */ }` 등으로 값을 만들지 않는 블록이 있다.

```nok
let x = {
    return 0;       // 함수에서 빠져나감
};
```

이런 블록은 divergent (절대 끝나지 않음) 로 분류된다. divergent 블록의 타입은 임의의 타입과 호환되며, 분기 결과 타입 검사를 통과한다.

```nok
let x: i32 = if cond {
    42i32
} else {
    return -1i32;       // divergent, 분기 일치에 영향 없음
};
```

divergent 의 정확한 검출 규칙은 함수와 제어 흐름 사양에서 정의한다.

## 3.9.9. 블록의 평가 순서

블록 안의 문장과 마지막 식은 적힌 순서대로 (위에서 아래로) 평가된다. 부작용도 그 순서를 따른다.

평가 도중 `return`, `break`, 예외 등이 발생하면 그 시점에 블록의 평가가 중단된다.
