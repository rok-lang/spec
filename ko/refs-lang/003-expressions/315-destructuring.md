# 3.15. 분해 대입(destructuring)

`let`의 좌변에 [패턴](311-patterns.md)의 반증 불가능 패턴을 쓰면 식 하나의 결과를 여러 변수로 풀어 받을 수 있습니다.

## 3.15.1. 형태

분해 대입의 문법은 다음과 같습니다.

```
destructure_let ::= "let" irrefutable_pattern (":" type_expr)? "=" expr ";"
```

```rok
let 패턴 = 식;
```

이 형태는 식의 결과를 패턴에 매칭하고, 패턴 안의 바인딩 변수를 한꺼번에 선언합니다.

## 3.15.2. 튜플 분해

가장 기본적인 형태인 튜플 분해는 다음과 같이 씁니다.

```rok
let (a, b) = (1, 2);                    // a = 1, b = 2
let (q, r) = divmod(10, 3);             // 두 값을 한 번에 받음
let (q, _) = divmod(10, 3);             // 두 번째는 폐기
```

항의 수가 정확히 일치해야 합니다. 다르면 컴파일 에러입니다.

```rok
let (a, b) = (1, 2, 3);                 // ERROR: 길이 불일치
```

## 3.15.3. rest 패턴

나머지 항을 한꺼번에 받으려면 `..`를 쓴 rest 패턴을 씁니다.

```rok
let (first, ..rest) = (1, 2, 3, 4);     // rest = (2, 3, 4)
let (..init, last) = (1, 2, 3, 4);      // init = (1, 2, 3), last = 4
let (head, ..mid, tail) = (1, 2, 3, 4, 5);  // mid = (2, 3, 4)
let (..) = (1, 2, 3);                    // 전부 폐기
```

`..`는 한 패턴에 한 번까지만 쓸 수 있으며, 나머지를 변수 하나에 묶거나 버리는 데 씁니다.

## 3.15.4. 중첩 분해

분해 패턴은 얼마든지 깊게 중첩할 수 있으므로 복잡한 구조도 한 번에 풀 수 있습니다.

```rok
let ((a, b), c) = ((1, 2), 3);          // a = 1, b = 2, c = 3
let (Point { x, y }, scale) = (origin, 2.0f64);
```

분해하는 모양이 값의 구조와 맞기만 하면 됩니다.

## 3.15.5. struct 분해

struct 값에는 [패턴](311-patterns.md)의 `struct` 패턴을 그대로 쓸 수 있습니다.

```rok
let Point { x, y } = origin;            // x = origin.x, y = origin.y
let Point { x, .. } = origin;           // 다른 필드 폐기
let Point { x: px, y: py } = origin;    // 재명명
```

필드를 한꺼번에 꺼내거나, 일부 필드만 받고 나머지는 버리거나, 새 이름으로 받을 수 있습니다.

## 3.15.6. 타입 명시

분해의 각 부분에 타입을 명시해도 되고, 패턴 전체에 한 번에 명시해도 됩니다.

```rok
let (a: i32, b: str) = (1i32, "hi");    // 각 자리에 타입 명시
let (a, b): (i32, str) = (1i32, "hi");  // 전체 패턴에 타입 명시
```

명시한 타입은 슬롯 타입이고, 런타임 타입 검사가 아닙니다. 값의 타입과 일치해야 합니다. 다르면 컴파일 에러입니다.

```rok
let (a: i32, b: str) = (1, 2);          // ERROR: 두 번째 타입 불일치
```

## 3.15.7. 반증 불가능 패턴만

`let 패턴 = 식;`의 패턴은 반증 불가능해야 합니다. 항상 매칭되는 형태여야 한다는 뜻입니다.

허용하는 패턴은 다음과 같습니다.

- 식별자, 와일드카드.
- 튜플, struct, 튜플 struct의 완전 매칭(필드나 위치 누락 없이).
- 위 형태들의 중첩.

다음 패턴은 허용하지 않습니다.

- 리터럴 패턴(`1`, `"hello"` 등).
- `enum`의 특정 변형만 매칭하는 패턴(`Circle(r)`, `Click { x, y }` 등).
- 타입 검사 패턴(합 타입이나 `any` 슬롯에 쓴 `v: i32`).
- 범위 패턴.

이 형태는 매칭에 실패할 수 있으므로 `let`으로 받으면 안전하지 않습니다. 대신 [`let-else`](316-let-else.md), [`match` 표현식](312-match-expression.md), `if let`([`if` 표현식](310-if-expression.md))을 쓰세요.

## 3.15.8. 기본값(없음)

분해 자리의 기본값은 채택하지 않습니다.

```
let (a, b = 0i32) = ...;        // 채택 안 함
```

함수 매개변수의 기본값으로 충분하다고 보았기 때문입니다. 분해 자리에서 없을 수도 있는 값을 다뤄야 하면 `match`나 `let-else`를 쓰세요.

## 3.15.9. 분해 후의 변수 가시성

분해로 선언한 모든 변수는 `let`이 있는 스코프에 도입됩니다.

```rok
let (a, b) = (1, 2);
// 여기서 a, b 모두 가시
```

같은 `let`으로 선언한 변수는 모두 동시에 보입니다. 어느 하나가 먼저 보이는 일은 없습니다.

## 3.15.10. 매칭 식의 평가 횟수

분해의 우변 식은 정확히 한 번 평가하고, 그 결과를 패턴에 매칭합니다. 그래서 부작용이 있는 식도 한 번만 호출된다고 보장합니다.

## 3.15.11. 다중 대입의 일반화

분해 대입은 다중 대입을 일반화한 것으로 볼 수 있습니다.

```rok
let (a, b) = (b, a);                    // swap, 한 식으로
let (q, r) = divmod(num, den);          // 두 결과
let (head, ..tail) = items;             // 분리
```

이 형태로 C나 Python 식의 `a, b = b, a` 패턴도 자연스럽게 쓸 수 있습니다.

## 3.15.12. `let` 없이: 재할당의 분해(없음)

기존 변수에 분해해서 재할당하는 형태는 채택하지 않습니다.

```
(a, b) = (1, 2);                // 채택 안 함
```

새 선언과 재할당을 분명히 구분하려고 `let`을 항상 요구합니다([대입](304-assignment.md)의 결정과 같습니다).

분해한 결과를 기존 변수에 대입하려면 임시 변수를 거치거나 하나씩 따로 대입하세요.
