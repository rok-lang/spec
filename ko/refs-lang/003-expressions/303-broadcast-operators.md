# 3.3. 브로드캐스트 연산자

[구두점과 연산자 토큰](../001-lexical/110-punctuation-and-operator-tokens.md)에서 정의한 점-접두 연산자(`.+`, `.*`, `.==` 등)는 원소별 연산(broadcast)에 쓰는 별도 토큰입니다. 일반 연산자처럼 트레잇 메서드 호출로 풀리지만, 대응하는 트레잇은 따로 있습니다.

## 3.3.1. 풀어 쓰기 패턴

점-접두 연산자는 다음과 같이 풀립니다.

```
a .+ b      →   <typeof(a) as DotAdd<typeof(b)>>::dot_add(a, b)
a .* b      →   <typeof(a) as DotMul<typeof(b)>>::dot_mul(a, b)
a .== b     →   <typeof(a) as DotEq<typeof(b)>>::dot_eq(a, b)
```

[연산자 디스패치](301-operator-dispatch.md)에서 다룬 일반 매핑과 형태가 같고, 대상 트레잇만 다릅니다. 점-접두 연산자는 이름이 **Dot**으로 시작하는 별도의 트레잇 패밀리에 대응합니다. 대응 관계는 다음과 같습니다.

| 점-접두 토큰 | 점 없는 형태      | 점-접두 트레잇  |
|--------------|-------------------|-----------------|
| `.+`         | `+` ↔ `Add`       | `DotAdd`        |
| `.-`         | `-` ↔ `Sub`       | `DotSub`        |
| `.*`         | `*` ↔ `Mul`       | `DotMul`        |
| `./`         | `/` ↔ `Div`       | `DotDiv`        |
| `.%`         | `%` ↔ `Rem`       | `DotRem`        |
| `.%%`        | `%%` ↔ `Modulo`   | `DotModulo`     |
| `.==`        | `==` ↔ `PartialEq::eq` | `DotEq`    |
| `.!=`        | `!=` ↔ `PartialEq::ne` | `DotNe`    |
| `.<`         | `<` ↔ `PartialOrd::lt` | `DotLt`    |
| `.>`         | `>` ↔ `PartialOrd::gt` | `DotGt`    |
| `.<=`        | `<=` ↔ `PartialOrd::le` | `DotLe`   |
| `.>=`        | `>=` ↔ `PartialOrd::ge` | `DotGe`   |
| `.&&`        | `&&` (단축 평가)  | `DotLogicalAnd` |
| `.\|\|`        | `\|\|` (단축 평가)  | `DotLogicalOr`  |
| `.&`         | `&`               | `DotBitAnd`     |
| `.\|`         | `\|`               | `DotBitOr`      |
| `.^`         | `^`               | `DotBitXor`     |
| `.<<`        | `<<`              | `DotShl`        |
| `.>>`        | `>>`              | `DotShr`        |

이 트레잇의 정확한 시그니처와 이를 구현하는 타입은 표준 라이브러리가 정의합니다. 이 문서는 언어가 점-접두 토큰을 별도의 트레잇 패밀리로 풀어 쓴다는 사실만 다룹니다.

> [!IMPORTANT]
> **점-접두 논리 연산자에는 단축 평가가 없음**: `.&&`, `.||`는 점 없는 형태와 달리 단축 평가를 하지 **않습니다**. 브로드캐스트는 융합된 루프로 변환되므로 양쪽 피연산자를 항상 평가합니다. 의미로는 bool 컨테이너의 원소별 논리 결합입니다. 부작용이 있는 함수 호출은 어느 쪽 피연산자에 두든 항상 실행됩니다.

## 3.3.2. 우선순위와 결합성

점-접두 연산자의 우선순위와 결합성은 대응하는 점 없는 연산자와 같습니다.

```
a .+ b .* c     →   a .+ (b .* c)              // .* 가 .+ 보다 강함 (* > + 와 동일)
a .+ b .+ c     →   (a .+ b) .+ c              // 좌결합
```

## 3.3.3. 함수와 메서드 브로드캐스트

함수나 메서드 뒤에 `.`을 붙이면 그 함수나 메서드를 모든 원소에 적용합니다.

```rok
sin.(x)            // x 의 각 원소에 sin 적용
f64::sqrt.(arr)    // 메서드 형태도 가능
g.(a, b)           // 여러 인자
```

이 형태는 일반 함수나 메서드 호출의 결과를 모든 원소에 매핑한 새 컬렉션을 반환합니다. 표준 라이브러리의 `Iterator::map` 호출(또는 동등한 트레잇)로 풀립니다.

```
f.(x)        →   x.iter().map(f)
g.(a, b)     →   a.iter().zip(b.iter()).map(|(x, y)| g(x, y))
```

함수와 메서드 브로드캐스트에는 전용 트레잇이 없습니다. 반복자 변환을 줄여 쓴 형태입니다. 이 점이 이항 점-접두 연산자와 다릅니다.

## 3.3.4. 자동 루프 융합

점-접두 연산자와 함수 브로드캐스트로 이루어진 식 트리는 루프 하나로 융합됩니다.

```
sin.(a) .+ cos.(b) .* 2.0f64
```

컨테이너 피연산자가 모두 core의 `List`, `Slice`, 고정 배열이거나 모두 `Broadcastable`([stdlib 2.6.6](../../refs-standard-libraries/200-core/206-broadcast.md#266-루프-융합))이고, 점 연산자의 나머지 피연산자가 프리미티브이거나 원소 타입이면 융합을 보장합니다. 결과는 중간 컬렉션 없이 한 번의 순회로 만들어집니다. 피연산자는 루프 전에 소스 순서대로 한 번씩 평가됩니다.

- core 컬렉션에서는 길이를 첫 원소 전에 검사합니다(고정 배열은 컴파일 타임). 결과는 `List`이고, 컨테이너 피연산자가 모두 배열이면 배열입니다.
- `Broadcastable` 피연산자(`Array` 또는 직접 만든 타입)는 각각 배열로 보고, 첫 원소 전에 broadcast 규칙([stdlib 2.6.8](../../refs-standard-libraries/200-core/206-broadcast.md#268-numpy-식-broadcasting-규칙))으로 한 모양까지 늘립니다. 결과는 앞선 피연산자(랭크가 가장 높은 것 중 첫째)가 `Materialize`로 만듭니다.
- 두 종류를 섞은 트리는 에러이며, 도움말은 리스트를 바꾸라고 안내합니다(`Array::from_list(xs, [xs.len()])`).

그 밖의 트리, 곧 컨테이너도 프리미티브도 원소 타입도 아닌 피연산자가 있는 트리는 융합하지 않습니다. 연산자마다 점 트레잇(3.3.1)을 호출하고 결과를 따로 만듭니다.

융합된 루프는 보통 루프이므로 다른 루프처럼 벡터화됩니다([0.6.4](../000-meta/006-platform-targets.md#064-simd)).

## 3.3.5. 일반 연산자와 다른 의미

> [!IMPORTANT]
> 점-접두 연산자를 별도의 트레잇으로 둔 이유는 같은 자료에 수학적으로 다른 의미를 둘 수 있기 때문입니다.

```
m * n           // 행렬 곱 (Mul 구현, 사용자 정의)
m .* n          // 원소별 곱 (Hadamard product, DotMul)
```

NumPy의 `*`가 암묵적으로 원소별 연산이 되어 생긴 혼동을 피하려고, Rok은 두 의미를 항상 눈에 보이게 구분합니다.

이 구분은 [언어와 표준 라이브러리의 경계](../000-meta/004-language-vs-standard-libraries.md)에서 제시한 "구문은 언어, 의미는 라이브러리" 원칙을 그대로 적용한 결과입니다. 서로 다른 두 의미에 서로 다른 두 구문이 대응합니다.

## 3.3.6. 사용자 정의 트레잇 구현

타입에 점-접두 연산을 주려면 일반 연산자와 같은 방식으로 **Dot** 트레잇 패밀리를 구현하면 됩니다.

```rok
impl ops::DotAdd for MyVector {
    type Output = MyVector;
    fn dot_add(self, rhs: MyVector) -> MyVector { ... }
}
```

새 트레잇이나 매크로를 더하지 않고 이 패턴만으로 점-접두 연산을 지원합니다. 대신 `Broadcastable`을 구현한 타입은 융합된 식과 제자리 브로드캐스트를 얻습니다(3.3.4, 3.3.7). 이때 그 타입의 점 트레잇 구현은 트레잇 바운드와 이름으로 부르는 호출에 쓰입니다.

## 3.3.7. 제자리 브로드캐스트

`target .= value`는 `value`(점 식, 컨테이너, 스칼라)의 원소를 원소별로 `target`에 씁니다. `+ - * / % **`의 `op`에 대해 `target .op= value`는 `target`을 한 번만 평가하는 `target .= target .op value`입니다. `=`처럼 문(statement)입니다.

```rok
y .= a .* x .+ b;          // 루프 하나, 배열 할당 없음
y .+= 1.0;                 // y .= y .+ 1.0
m[:, 0] .= 0.0;            // 뷰도 대상: m의 열
xs .*= ys;                 // List, 길이가 같아야 함
```

- 대상을 먼저 평가하고, 피연산자를 소스 순서대로 평가합니다.
- `List`나 고정 배열 대상은 같은 길이의 피연산자를 받습니다(첫 원소 전에 검사, 고정 배열은 컴파일 타임). 원소는 `IndexSet`으로 저장합니다. `Slice`는 읽기 전용 뷰이므로 대상이 아닙니다.
- `Broadcastable` 대상은 모양을 유지합니다. 피연산자가 대상까지 늘어나며(stdlib 2.6.8) 랭크가 더 높은 피연산자는 컴파일 에러입니다. 결과 모양이 다르면 panic합니다(`broadcast: the result has shape [2, 3], which does not fit the destination of shape [1, 3]; the destination is not stretched`). 원소는 대상의 뷰를 통해 쓰므로 배열의 슬라이스(`a[1:]`)에 쓰면 그 배열에 씁니다.
- 대상의 버퍼를 다른 위치에서 공유하는 피연산자(`v .= v[::-1]`)는 루프 전에 만든 복사본에서 읽습니다. 같은 뷰(`v .+= v`)나 떨어진 버퍼는 그대로 읽습니다. 결과는 모든 원소를 계산한 뒤에 저장한 것과 같습니다.
- 그 밖의 연산자는 `.=`로 씁니다: `xs .= xs .%% 3`.
- 그 밖의 대상은 에러이며, 도움말은 연산을 풀어 씁니다(`x = x .+ ..;`).

## 3.3.8. 브로드캐스트 병합 `.??`

`a .?? b`는 원소별 `??`입니다. `a`의 `none` 원소마다 `b`의 대응 원소로, `b`가 스칼라이면 `b` 자체로 바꿉니다. 트리의 나머지와 함께 융합되며 `??`처럼 묶입니다(레벨 1, 오른쪽 결합). 결과의 원소는 원소들의 `??`입니다(`List<f64 | none> .?? 0.0`은 `List<f64>`). 컨테이너 피연산자가 없으면 에러이며 도움말은 `x ?? y`입니다.

`none`과 NaN은 구별됩니다. `.??`는 `none`만 바꾸며 NaN 원소는 값으로 그대로 지나갑니다(`[1.0, none, NaN] .?? 0.0`은 `[1.0, 0.0, NaN]`). `f64 | none`은 NaN을 `none`으로 저장하지 않습니다. NaN은 부동소수 연산의 보통 결과이므로 둘을 합치면 빠진 값을 잃거나 없던 것을 만듭니다. NaN을 빠진 값으로 다루려면 마스크를 씁니다: `a[f64::is_nan.(a)] = 0.0`.
