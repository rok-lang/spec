# 3.3. 브로드캐스트 연산자

[구두점과 연산자 토큰](../001-lexical/110-punctuation-and-operator-tokens.md) 의 점-접두 연산자 (`.+`, `.*`, `.==` 등) 는 원소별 연산 (broadcast) 을 위한 별개 토큰이다. 일반 연산자와 같은 메커니즘 (트레잇 메서드 호출로의 desugar) 으로 동작하지만, 별개의 트레잇으로 매핑된다.

## 3.3.1. desugar 패턴

```
a .+ b      →   <typeof(a) as DotAdd<typeof(b)>>::dot_add(a, b)
a .* b      →   <typeof(a) as DotMul<typeof(b)>>::dot_mul(a, b)
a .== b     →   <typeof(a) as DotEq<typeof(b)>>::dot_eq(a, b)
```

[연산자 디스패치](301-operator-dispatch.md) 의 일반 매핑과 같은 형태이며, 대상 트레잇만 다르다. 점-접두 연산자에는 _Dot_ 으로 시작하는 별개의 트레잇 패밀리가 매핑된다.

| 점-접두 토큰 | 점 없는 형태      | 점-접두 트레잇 |
| ------------ | ----------------- | -------------- |
| `.+`         | `+` ↔ `Add`       | `DotAdd`       |
| `.-`         | `-` ↔ `Sub`       | `DotSub`       |
| `.*`         | `*` ↔ `Mul`       | `DotMul`       |
| `./`         | `/` ↔ `Div`       | `DotDiv`       |
| `.%`         | `%` ↔ `Rem`       | `DotRem`       |
| `.==`        | `==` ↔ `Eq`       | `DotEq`        |
| `.!=`        | `!=` ↔ `Ne`       | `DotNe`        |
| `.<`         | `<` ↔ (`Cmp::lt`) | `DotLt`        |
| `.>`         | `>`               | `DotGt`        |
| `.<=`        | `<=`              | `DotLe`        |
| `.>=`        | `>=`              | `DotGe`        |
| `.&`         | `&`               | `DotBitAnd`    |
| `.\|`        | `\|`              | `DotBitOr`     |
| `.^`         | `^`               | `DotBitXor`    |
| `.<<`        | `<<`              | `DotShl`       |
| `.>>`        | `>>`              | `DotShr`       |

위 트레잇의 정확한 시그니처와 어떤 타입에 어떤 구현이 등록되는지는 표준 라이브러리에서 정의된다. 본 문서는 언어가 점-접두 토큰을 별개의 트레잇 패밀리로 desugar 한다는 사실까지 책임진다.

## 3.3.2. 우선순위와 결합성

점-접두 연산자의 우선순위와 결합성은 대응되는 점 없는 연산자와 같다.

```
a .+ b .* c     →   a .+ (b .* c)              // .* 가 .+ 보다 강함 (* > + 와 동일)
a .+ b .+ c     →   (a .+ b) .+ c              // 좌결합
```

## 3.3.3. 함수와 메서드 브로드캐스트

함수나 메서드 뒤에 `.` 를 두어 모든 원소에 그 함수나 메서드를 적용하는 표기도 지원된다.

```nok
sin.(x)            // x 의 각 원소에 sin 적용
f64::sqrt.(arr)    // 메서드 형태도 가능
g.(a, b)           // 여러 인자
```

이 형태는 일반 함수 / 메서드 호출의 결과를 모든 원소에 매핑한 새 컬렉션을 반환한다. desugar 는 표준 라이브러리의 `Iterator::map` (또는 동등한 트레잇) 호출로 변환된다.

```
f.(x)        →   x.map(f)
g.(a, b)     →   a.zip(b).map(|(x, y)| g(x, y))
```

함수와 메서드의 브로드캐스트는 별개 트레잇을 두지 않고 반복자 변환의 sugar 로 처리된다. 이항 점-접두 연산자와 다른 지점이다.

## 3.3.4. 자동 루프 융합

연속된 점-접두 표현식은 컴파일러가 단일 커널로 융합할 수 있다.

```
sin.(a) .+ cos.(b) .* 2.0f64
```

위 표현은 가능하면 중간 배열을 만들지 않고 한 번의 순회로 결과를 만든다.

이 융합은 [컴파일 파이프라인](../000-meta/002-pipeline.md) 의 MLIR 단계에서 인접 점-접두 체인을 하나의 linalg 연산으로 인식하여 가능해진다. SIMD / GPU 도 같은 메커니즘으로 활용 가능하다.

융합 가능 여부는 컴파일러의 분석에 달려 있으며, 사양이 항상 보장하지는 않는다. 대부분의 경우 융합된다는 실용 수준의 약속이다.

## 3.3.5. 일반 연산자와의 의미 차이

> [!IMPORTANT]
> 점-접두 연산자가 별개 트레잇인 이유는, 같은 자료에 수학적으로 다른 의미를 둘 수 있기 때문이다.

```
m * n           // 행렬 곱 (Mul 구현, 사용자 정의)
m .* n          // 원소별 곱 (Hadamard product, DotMul)
```

NumPy 의 `*` 가 암묵적으로 원소별이라 발생했던 혼동을 피하기 위해, nok 은 항상 두 의미를 시각적으로 분리한다.

이 분리는 [언어와 표준 라이브러리의 경계](../000-meta/004-language-vs-stdlib.md) 의 "구문은 언어, 의미는 라이브러리" 원칙을 직접 적용한 것이다. 다른 두 의미에 다른 두 구문이 매핑된다.

## 3.3.6. 사용자 정의 트레잇 구현

사용자가 자신의 타입에 점-접두 연산을 부여하려면 일반 연산자와 같은 방식으로 _Dot_ 트레잇 패밀리를 구현한다.

```nok
impl DotAdd for MyVector {
    type Output = MyVector;
    fn dot_add(self, rhs: MyVector) -> MyVector { ... }
}
```

별도의 새 트레잇이나 매크로 없이 같은 패턴으로 점-접두 연산이 지원된다.
