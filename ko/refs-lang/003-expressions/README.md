## 표현식과 문장

표현식(expression)은 값을 만드는 구조입니다. 표현식을 평가하면 어떤 타입의 값이 나옵니다. **문장**(statement)은 값을 만들지 않는 코드 단위입니다. [문장 종결자](../001-lexical/103-statement-terminator.md)인 `;`로 끝납니다.

Rok은 두 개념을 다음 규칙으로 연결합니다.

```
<문장> = <표현식> ';'        // 표현식의 결과를 버리는 문장
```

문장은 표현식에 종결자를 붙인 것입니다. 거의 모든 코드 구조는 값을 만드는 표현식이고, 그 값을 버리면 문장이 됩니다.

## 제어 구조 = 표현식

모든 제어 구조(`if`, `match`, `loop`, `while`, `for`, `try`)도 표현식입니다. 다음 예시에서 제어 구조가 바로 값을 만듭니다.

```rok
let a = if cond { x } else { y };

let b = match v {
    1 => "one",
    2 => "two",
    _ => "other",
};

let c = loop {
    let v = compute();
    if v.converged { break v; }
};

let d = { let a = 1; let b = 2; a + b };
```

이 결정에는 두 가지 결과가 따릅니다. 첫째, 제어 구조는 함수 인자, 변수 초기값, 다른 표현식의 일부처럼 표현식이 올 수 있는 자리라면 어디에나 올 수 있습니다. 둘째, 삼항 연산자 같은 별도 형태가 필요 없습니다. `cond ? x : y` 같은 토큰은 없고, `if cond { x } else { y }`가 그 역할을 합니다.

각 제어 구조가 반환하는 값은 해당 절에서 정의합니다.

## 분기 결과 타입

표현식의 결과 타입과 그 값을 받는 슬롯의 타입은 따로 정합니다.

### 식의 결과 타입

제어 구조의 모든 분기가 같은 타입의 값을 만들면 그 타입이 식의 결과 타입입니다. 분기마다 다른 타입의 값을 만들면 받는 쪽이 타입(슬롯의 명시 타입, 매개변수 타입, 반환 타입)을 정해야 합니다. 각 분기는 그 타입과 호환되어야 합니다. 받는 쪽에 타입이 없으면 컴파일 에러입니다. 합 타입을 자동으로 추론하지 않고, 공통 슈퍼타입으로 자동 승급하지도 않습니다(예: `i32`를 `i64`나 `f64`로 묵시적으로 올리는 일).

```
if cond { 1i32 } else { 2i32 }          // 식의 결과 타입: i32
if cond { 1i32 } else { 2.0f64 }        // 받는 쪽의 타입이 i32 | f64 등을 정해야 함
```

### 합 타입은 명시로, 승급은 없음

두 경우는 거부하는 이유가 다릅니다. 합 타입을 자동으로 추론하지 않는 것은 분기 하나의 실수가 조용히 합 타입을 만들어 이후 코드 전체로 퍼지지 않게 하려는 것입니다. 합 타입이 필요하면 `let d: i32 | str = if ...`처럼 받는 쪽에 명시하면 됩니다. 자동 슈퍼타입 승급은 사정이 다릅니다. 승급은 한 타입을 다른 타입으로 바꾸는 변환(`i32` → `f64`)이고 정밀도나 표현을 잃을 수 있습니다. 그래서 받는 쪽에 타입이 있어도 허용하지 않습니다.

이 구분은 [언어와 표준 라이브러리의 경계](../000-meta/004-language-vs-standard-libraries.md)에서 정한 명시성 원칙과 일치합니다. 변환이 필요하면 [형 변환](../002-types/214-cast-and-conversion.md)의 세 구문 `as`, `.into()`, `.try_into()` 중 하나로 명시해야 합니다.

### 식 결과를 슬롯이 받기

변수 슬롯이 표현식의 결과를 받을 때 슬롯의 타입은 [변수 선언](../005-modules/501-variable-declaration.md#517-타입-명시와-타입-추론)의 규칙을 따릅니다. 타입을 명시하면 그 타입이 받는 쪽의 타입이 되고, 생략하면 식의 결과 타입으로 추론합니다.

```rok
// 타입 명시 없음 → 슬롯은 식의 결과 타입으로 추론
let a = if cond { 1i32 } else { 2i32 };          // a: i32
let b = if cond { 1i32 } else { 2.0f64 };        // ERROR: 분기 타입 불일치 - 타입 명시 필요

// any 슬롯 → 어떤 분기 조합이든 받음
let g: any = if cond { 1i32 } else { 2.0f64 };   // OK

// 합 타입 슬롯 → 식의 결과가 슬롯의 항 집합에 포함되어야
let c: i32 | f64 = if cond { 1i32 } else { 2.0f64 };   // OK
let d: i32 | f64 = if cond { 1i32 } else { "hi" };     // ERROR: str 이 슬롯에 없음

// 단일 구체 타입 슬롯 → 식의 결과가 정확히 그 타입이어야
let e: i32 = if cond { 1i32 } else { 2i32 };           // OK
let f: i32 = if cond { 1i32 } else { 2.0f64 };         // ERROR: f64 분기가 i32 에 안 맞음
```

### 슬롯 호환 표

식의 결과 타입과 받는 슬롯의 호환 관계는 다음과 같습니다.

| 받는 슬롯                           | 식의 결과 타입                       | 허용                    |
|-------------------------------------|--------------------------------------|-------------------------|
| `any` (`: any` 명시)                | 무엇이든                             | 항상                    |
| 합 타입 `T1 \| T2 \| ...`             | 식의 결과 항이 슬롯의 항 집합에 포함 | 허용                    |
| 단일 구체 타입 `T`                  | 식의 결과가 정확히 `T`               | 허용                    |
| 단일 구체 타입 `T`                  | 식의 결과에 `T` 외 다른 항이 있음    | 거부                    |
| 타입 명시 생략                      | 모든 분기가 같은 타입                | 허용 (그 타입으로 추론) |
| 타입 명시 생략                      | 분기 타입이 서로 다름                | 거부                    |

### 점진과 정적

이 호환 규칙 위에서 세 모드 중 하나를 고를 수 있습니다. 점진 모드(`let x: any = ...`)에서는 슬롯이 `any`이고 어떤 분기 조합이든 받습니다. 런타임 태그 검사로 디스패치하므로 빠르게 탐색할 때 알맞습니다. 정적 합 타입 모드(`let x: T1 | T2 = ...`)에서는 슬롯이 명시한 합 타입이고 분기 결과가 그 항 집합 안에 들어가야 합니다. 타입 좁히기와 패턴 매칭 완전성 검사를 쓸 수 있으므로 안정성과 성능에 알맞습니다. 정적 단일 타입 모드(`let x: T = ...` 또는 타입을 생략한 `let x = ...`)에서는 슬롯이 단일 타입이고 모든 분기가 그 타입이어야 합니다. 최대 성능과 완전한 정적 분석을 얻습니다.

세 모드는 같은 코드 안에서 자유롭게 섞어 쓸 수 있고, 변수마다 따로 고릅니다.

## 표현식과 문장의 구분

코드 한 줄은 대부분 다음 두 형태 중 하나입니다.

```rok
<선언>;                  // let / fn / struct / ... 의 정의 - 문장
<제어구조 또는 식>;      // 표현식의 결과를 버리는 문장
```

`if` / `match` / 루프 / 블록처럼 `}`로 끝나는 식은 문장 자리에서 `;`를 생략할 수 있습니다([1.3.4](../001-lexical/103-statement-terminator.md#134-블록류-식-문장)).

블록 안의 마지막 식은 예외입니다.

```rok
{
    let a = 1;
    let b = 2;
    a + b           // 종결자 없음 - 이 블록의 값
}
```

블록의 마지막 식만 종결자 없이 둘 수 있으며, 이때 그 식이 블록 전체의 값이 됩니다. 자세한 규칙은 [블록 표현식](309-block-expressions.md)에서 정의합니다.

## 부작용

표현식은 평가하는 동안 I/O, 변수 재할당, 외부 호출 같은 부작용을 일으킬 수 있습니다. 평가 순서는 연산자 우선순위와 함수 호출 평가 순서가 정합니다. 둘 다 뒤의 문서에서 정의합니다.

한 표현식 안에서 부작용 때문에 의존 관계가 생기면, 그 의존은 왼쪽에서 오른쪽, 깊이 우선이라는 명시적 순서를 따릅니다. 컴파일러는 이 순서를 바꾸지 않습니다.
