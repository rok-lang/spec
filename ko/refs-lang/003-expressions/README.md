## 표현식과 문장

**표현식 (expression)** 은 값을 만드는 구조다. 평가하면 어떤 타입의 값이 결과로 나온다.

**문장 (statement)** 은 값을 만들지 않는 코드 단위다. [문장 종결자](../001-lexical/103-statement-terminator.md) 의 `;` 로 끝난다.

nok 에서는 다음 변환 규칙이 성립한다.

```
<문장> = <표현식> ';'        // 표현식의 결과를 버리는 문장
```

문장은 표현식에 종결자를 붙인 것이다. 거의 모든 코드 구조가 표현식 형태로 값을 만들고, 그 값을 폐기하면 문장이 된다.

## 제어 구조 = 표현식

`if`, `match`, `loop`, `while`, `for`, `try` 의 모든 제어 구조가 표현식이다.

```nok
let a = if cond { x } else { y };

let b = match v {
    1 => "one",
    2 => "two",
    _ => "other",
};

let c = loop {
    let v = compute();
    if v.converged { break v; }
};

let d = { let a = 1; let b = 2; a + b };
```

이 결정의 귀결은 두 가지다.

- 어떤 식 자리에든 그대로 끼워 넣을 수 있다. 함수 인자, 변수 초기값, 다른 표현식의 일부, 어디든.
- ternary 같은 별도 형태가 필요 없다. `cond ? x : y` 같은 별도 토큰을 두지 않으며, `if cond { x } else { y }` 가 그 자리를 채운다.

각 제어 구조가 어떤 값을 반환하는지의 정확한 규칙은 해당 사양 문서에서 정의한다.

## 분기 결과 타입

표현식의 결과 타입과 그 값을 받는 슬롯의 타입은 별개로 결정된다.

### 식의 결과 타입

제어 구조의 여러 분기가 서로 다른 타입의 값을 만들면, 그 식 자체의 결과 타입은 분기 타입들의 합 타입이 된다. 자동 합 타입 형성은 허용되지만, 자동 공통 슈퍼타입 승급 (예: `i32` 가 `i64` 나 `f64` 로 묵시적으로 승급되는 것) 은 허용되지 않는다.

```
if cond { 1i32 } else { 2i32 }          // 식의 결과 타입: i32
if cond { 1i32 } else { 2.0f64 }        // 식의 결과 타입: i32 | f64
```

### 자동 형성과 자동 승급의 차이

- 자동 합 타입 형성. 분기들이 새 합 타입을 만든다. 정보 손실 없음. 허용된다.
- 자동 슈퍼타입 승급. 한 타입이 다른 타입으로 변환된다 (`i32` → `f64`). 정밀도 / 표현 손실 가능. 허용되지 않는다.

이 구분은 [언어와 표준 라이브러리의 경계](../000-meta/004-language-vs-stdlib.md) 의 명시성 원칙과 일관된다. 변환이 필요하면 [형 변환](../002-types/214-cast-and-conversion.md) 의 세 구문 (`as`, `.into()`, `.try_into()`) 으로 명시한다.

### 식 결과를 슬롯이 받기

표현식의 결과를 변수 슬롯이 받을 때, 슬롯의 타입은 [`any` 슬롯](../002-types/202-any-slot.md) 의 변수 선언 규칙을 따른다. 식 자체의 타입과는 별개로 결정된다.

```nok
// 타입 명시 없음 → 슬롯은 any (202 의 규칙)
let a = if cond { 1i32 } else { 2i32 };          // a: any (값은 i32)
let b = if cond { 1i32 } else { 2.0f64 };        // b: any (값은 i32 또는 f64)

// 합 타입 슬롯 → 식의 결과가 슬롯의 항 집합에 포함되어야
let c: i32 | f64 = if cond { 1i32 } else { 2.0f64 };   // OK
let d: i32 | f64 = if cond { 1i32 } else { "hi" };     // ERROR: str 이 슬롯에 없음

// 단일 구체 타입 슬롯 → 식의 결과가 정확히 그 타입이어야
let e: i32 = if cond { 1i32 } else { 2i32 };           // OK
let f: i32 = if cond { 1i32 } else { 2.0f64 };         // ERROR: i32|f64 이 i32 에 안 맞음
```

### 슬롯 호환 표

식의 결과 타입과 받는 슬롯의 호환:

| 받는 슬롯                           | 식의 결과 타입                       | 허용 |
| ----------------------------------- | ------------------------------------ | ---- |
| `any` (타입 명시 생략 또는 `: any`) | 무엇이든                             | 항상 |
| 합 타입 `T1 \| T2 \| ...`           | 식의 결과 항이 슬롯의 항 집합에 포함 | 허용 |
| 단일 구체 타입 `T`                  | 식의 결과가 정확히 `T`               | 허용 |
| 단일 구체 타입 `T`                  | 식의 결과에 `T` 외 다른 항이 있음    | 거부 |

### 점진과 정적

- 점진 (`let x = ...`). 슬롯이 `any`. 어떤 분기 조합도 자유롭게 받음. 디스패치는 런타임 태그 검사. 빠른 탐색에 적합.
- 정적 합 타입 (`let x: T1 | T2 = ...`). 슬롯이 명시 합 타입. 분기 결과가 항 집합 안에 들어야 한다. 타입 좁히기와 패턴 매칭 완전성 검사 가능. 안정성과 성능에 적합.
- 정적 단일 타입 (`let x: T = ...`). 슬롯이 단일 타입. 모든 분기가 그 타입이어야 한다. 최대 성능, 정적 분석 완전.

세 모드는 같은 코드에서 자유롭게 섞을 수 있다. 사용자가 각 변수마다 선택한다.

## 표현식과 문장의 구분

대부분의 코드 줄은 다음 두 형태 중 하나다.

```nok
<선언>;                  // let / fn / struct / ... 의 정의 — 문장
<제어구조 또는 식>;      // 표현식의 결과를 버리는 문장
```

블록 안의 마지막 식은 예외다.

```nok
{
    let a = 1;
    let b = 2;
    a + b           // 종결자 없음 — 이 블록의 값
}
```

블록의 마지막 식만 종결자 없이 둘 수 있고, 그 식이 블록 전체의 값이 된다. 자세한 규칙은 [블록 표현식](309-block-expressions.md) 에서 정의한다.

## 부작용

표현식은 평가 중 부작용을 일으킬 수 있다 (I/O, 변수 재할당, 외부 호출 등). 평가 순서는 후속 문서에서 정의되는 연산자 우선순위와 함수 호출 평가 순서에 따라 결정된다.

같은 표현식 안에서 부작용으로 인한 의존이 있으면 그 의존은 명시적 순서 (좌→우, 깊이 우선) 를 따른다. 컴파일러는 이 순서를 임의로 바꾸지 않는다.
