# 3.2. 우선순위와 결합성

연산자에는 우선순위(precedence)와 결합성(associativity)이라는 두 속성이 있습니다. 한 표현식에 연산자가 여럿 나오면 이 두 속성이 트리의 모양을 정합니다.

## 3.2.1. 우선순위

```
a + b * c       →   a + (b * c)              // * 가 + 보다 강함
a * b + c       →   (a * b) + c              // 마찬가지
a < b + c       →   a < (b + c)              // + 가 < 보다 강함
```

우선순위 값은 정수이며, 값이 큰 연산자가 먼저 묶입니다.

## 3.2.2. 결합성

```
a - b - c       →   (a - b) - c             // 좌결합
a ?? b ?? c     →   a ?? (b ?? c)           // 우결합 (예시)
a ∈ s == t      →   ?                        // 비결합: 에러
```

결합성은 다음 세 가지 중 하나입니다.

| 표기    | 의미                                           |
|---------|------------------------------------------------|
| `left`  | 좌측부터 묶임. `a OP b OP c` = `(a OP b) OP c` |
| `right` | 우측부터 묶임. `a OP b OP c` = `a OP (b OP c)` |
| `none`  | 묶지 않음. `a OP b OP c`는 컴파일 에러. 3.2.5의 비교 체인은 예외 |

## 3.2.3. 우선순위와 결합성 표

모든 내장 연산자 토큰의 우선순위와 결합성은 언어가 고정하며, 아래 표가 유일한 기준입니다. 표준 라이브러리의 [`#[infix]` / `#[prefix]` / `#[postfix]`](../006-meta-system/607-operator-magic.md)는 토큰과 트레잇 메서드를 연결할 뿐이고, 우선순위나 결합성을 정하거나 바꾸지 않습니다.

### 우선순위 등급

```
등급  연산자                                           결합
14   후위: 멤버 접근 (.), ?., 메서드 호출, 인덱싱, ?   좌
13   전위 단항: - ! ~ √ await                          -
12   as is (후위 형 변환 / 형 검사)                    좌
11   ∘ (함수 합성)                                     좌
10   * / % %% × ⋅ ÷ ∩                                  좌
 9   + - ∪                                             좌
 8   << >>                                             좌
 7   &                                                 좌
 6   ^                                                 좌
 5   |                                                 좌
 4   == != < > <= >= ≡ ≠ ≤ ≥ ∈ ∉ in !in ⊂ ⊆            비결합 (체인: 3.2.5)
 3   &&                                                좌
 2   ||                                                좌
 1   ?? (null 합체)                                    우
 0   .. ..= (범위)                                     비결합
-1   = += -= *= /= %= %%= &= |= ^= <<= >>= (대입)      우  (문장 전용, 3.4.3)
```

표의 Unicode 연산자(`× ⋅ ÷ ∩ ∪ ∘ √ ≡ ≠ ≤ ≥ ∈ ∉ ⊂ ⊆`)는 [1.10.3](../001-lexical/110-punctuation-and-operator-tokens.md#1103-고정-토큰표)의 고정 토큰입니다. 3.2 표에 없는 확장 토큰([1.10.4](../001-lexical/110-punctuation-and-operator-tokens.md#1104-확장-토큰))은 새 단계를 만들지 않습니다. 등록할 때 `like = "+"`처럼 지정한 기존 토큰의 단계와 결합성을 그대로 따릅니다([6.7.2](../006-meta-system/607-operator-magic.md#672-인자)).

> [!IMPORTANT]
> **`??`와 `..`의 상대 우선순위**: `??`(prec=1)는 범위 연산자 `..` / `..=`(prec=0)보다 **강하게** 묶입니다. 따라서 `a ?? 0..3`은 `(a ?? 0)..3`으로 묶입니다. 범위 연산자는 대입을 뺀 모든 이항 연산자보다 약합니다(`a || b..c`는 `(a || b)..c`). 두 연산자는 트레잇으로 디스패치하지 않고 언어가 직접 처리합니다. `??`는 언어가 합 타입 위에서 직접 풀어 쓰는 구문입니다([3.8.4](308-optional-chaining-and-coalescing.md#384-null-합체-)). 범위는 언어가 여섯 형태를 각각 다른 표현식으로 인식하는 구문입니다([3.7](307-range-expressions.md)). 범위 연산자는 비결합이므로 `a..b..c`는 컴파일 에러입니다.

> [!IMPORTANT]
> **`try`와 `catch` / `finally`의 결합**: [에러 제어 흐름](314-error-control-flow.md)의 `try` / `try?` / `try!`와 `catch` / `finally` 절도 트레잇과 연결되지 않은 언어 구문입니다. `try`는 전위 형태이지만, 표의 전위 단항 연산자(prec=13)와 달리 오른쪽 식 전체를 덮습니다. 피연산자는 `catch` / `finally` 절, 문장 종결자 `;`, 닫는 괄호, 콤마 앞까지 이어집니다. 그래서 `try a + b()`는 `try (a + b())`입니다. `try?` / `try!`의 피연산자는 `??` 앞에서도 끝납니다. `try? f() ?? d`는 `(try? f()) ?? d`이고, `try f() ?? d`는 `try (f() ?? d)`입니다. `catch` / `finally` 절은 대입(prec=-1)보다 강하고 다른 모든 연산자보다 약하게 묶여서, 왼쪽 식 전체에 붙습니다. 따라서 `try parse(s) catch _ { 0 }`은 `(try parse(s)) catch _ { 0 }`이고, `x = try f() catch _ { 0 }`은 `x = ((try f()) catch _ { 0 })`입니다.

> [!IMPORTANT]
> **`in` / `!in`과 범위**: `in`과 `!in`은 `∈` / `∉`의 ASCII 철자입니다([1.10.3](../001-lexical/110-punctuation-and-operator-tokens.md#1103-고정-토큰표)). 포함 연산자 오른쪽의 범위는 괄호가 필요 없습니다. 오른쪽 피연산자 뒤의 `..` / `..=`는 범위로 이어지며, 범위의 끝은 오른쪽 피연산자 자체와 같은 세기(prec=5)로 묶입니다. 그래서 `i in 0..n`은 `i ∈ (0..n)`, `i in 0..n + 1`은 `i ∈ (0..(n + 1))`, `i in 0..n && ok`는 `(i ∈ (0..n)) && ok`입니다.

> [!IMPORTANT]
> **`await`**: `await`는 `-`나 `!`처럼 prec=13인 전위 단항 연산자이므로 피연산자는 단항 식입니다. `await f() == x`는 `(await f()) == x`입니다([4.12.2](../004-functions/412-async.md#4122-await-연산자)).

> [!IMPORTANT]
> **`as`와 `is`**: 두 후위 연산자는 트레잇과 연결되지 않은 언어 구문이며 같은 등급(prec=12)입니다. 전위 단항보다 약하고 산술보다 강하므로 `-x as i64`는 `(-x) as i64`이고, `a + b is i32`는 `a + (b is i32)`입니다. `e is T`의 결과는 `bool`입니다([2.2.5](../002-types/202-any-slot.md#225-슬롯의-현재-타입-검사)).

> [!NOTE]
> **점-접두(broadcast) 연산자의 우선순위**: `.+`, `.*`, `.&&`, `.%%` 같은 점-접두 형태는 점 없는 형태와 우선순위와 결합성이 같습니다. 표에 따로 행을 두지 않았지만, 모든 점-접두 토큰은 대응하는 일반 토큰의 등급을 그대로 따릅니다. 예를 들어 `.+`는 `+`와 같은 prec=9 left이고, `.&&`는 `&&`와 같은 prec=3 left입니다.

> [!NOTE]
> 이항 연산자의 등급은 Rust와 같습니다. 산술이 시프트보다 강하고, 시프트가 `&`보다, 그다음 `^`, `|` 순으로 강하며, 모두 비교보다 강합니다. 따라서 `1 + 2 << 3`은 `(1 + 2) << 3 = 24`로, `a ^ b & c`는 `a ^ (b & c)`로, `x & mask == 0`은 `(x & mask) == 0`으로 묶입니다.

### 같은 토큰의 다중 위치

같은 토큰이 전위, 이항, 후위로 모두 나올 수 있으면(예: `-`) 위치마다 우선순위를 따로 정합니다(보통 전위가 이항보다 강합니다).

```
-a + b          →   (-a) + b              // 전위 `-` 가 `+` 보다 강함
```

## 3.2.4. 충돌

우선순위는 표가 고정하므로 등록끼리 우선순위가 충돌하는 일은 없습니다. 같은 (토큰, 위치)에 서로 다른 트레잇을 연결하면 [6.7.5](../006-meta-system/607-operator-magic.md#675-충돌-검사)에 따라 컴파일 에러입니다.

## 3.2.5. 비교 체인

방향이 같은 비교는 수학처럼 이어 쓸 수 있습니다.

```rok
0 <= i < n          // 0 <= i && i < n
a > b >= c          // a > b && b >= c
a == b == c         // a == b && b == c
```

체인은 한 묶음에서 고른 4등급 연산자의 연속입니다. 묶음은 `<`와 `<=`(`≤`), `>`와 `>=`(`≥`), `==`(`≡`) 셋입니다. `e0 o1 e1 o2 e2 ..`는 `e0 o1 e1 && e1 o2 e2 && ..`를 뜻하며, 세 가지를 보장합니다.

- 각 피연산자는 왼쪽부터 한 번씩 평가합니다.
- 처음으로 `false`가 된 비교에서 평가를 멈추고, 그 뒤의 피연산자는 평가하지 않습니다.
- 결과는 `bool`입니다.

가운데 피연산자가 이름, 이름의 필드, 리터럴이면 다음 비교에서 다시 읽습니다. 그래서 리터럴은 여전히 반대편에서 타입을 얻습니다(`x: u8`일 때 `0 <= x < 10`). 그 밖의 가운데 피연산자는 한 번 평가해 임시 값에 둡니다.

나머지는 모두 비결합 그대로입니다. 방향이 섞인 체인(`a < b > c`), `!=`(`a != b != c`), 포함이나 부분집합 연산자(`x ∈ s == t`)는 컴파일 에러(E0019)입니다. help가 `&&` 형태(`a < b && b > c`)를 적어 줍니다.

```
a < b > c       // ERROR: a < b && b > c 로 적음
a != b != c     // ERROR: a != b && b != c 로 적음
```

방향이 같은 체인은 수학과 Python에서 적는 그대로 읽히고, 범위 검사(`lo <= x < hi`)에서 `x`를 한 번만 적게 해 줍니다. 섞인 체인은 하나로 읽을 수 없고 `!=`는 추이적이지 않으므로 에러로 둡니다.

## 3.2.6. 괄호로 강제 묶기

이 규칙으로 만든 트리가 의도한 모양과 다르면 괄호로 묶음을 강제할 수 있습니다.

```
a + b * c       →   a + (b * c)             // 기본 묶임
(a + b) * c     →   (a + b) * c             // 명시적
```

괄호는 어휘 단계와 구문 단계에서 그룹화 토큰으로 동작하며, 트리의 모양을 직접 정합니다.

## 3.2.6a. 구현 한도

연산자 / 후위 연산의 사슬이 4096개를 넘거나 중첩이 256보다 깊으면 에러입니다. 이 값은 Rok의 한도입니다(구현이 정함, [0.4.4](../000-meta/004-language-vs-standard-libraries.md#044-구현-한도)).

## 3.2.7. 우선순위가 같고 결합성이 다른 두 토큰

3.2.3 표에서는 한 단계 안의 토큰은 결합성이 모두 같으므로 이런 경우가 생기지 않습니다. 확장 토큰도 `like`로 기존 토큰의 결합성을 그대로 따르므로 마찬가지입니다.
