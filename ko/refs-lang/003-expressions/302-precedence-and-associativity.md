# 3.2. 우선순위와 결합성

연산자에는 우선순위 (precedence) 와 결합성 (associativity) 이라는 두 가지 속성이 있습니다. 하나의 표현식 안에 여러 연산자가 함께 등장할 때, 이 두 속성이 어떤 모양의 트리가 만들어질지를 결정해 줍니다.

## 3.2.1. 우선순위

```
a + b * c       →   a + (b * c)              // * 가 + 보다 강함
a * b + c       →   (a * b) + c              // 마찬가지
a < b + c       →   a < (b + c)              // + 가 < 보다 강함
```

우선순위 값은 정수로 표현하며, 더 큰 값을 가진 연산자가 먼저 묶이게 됩니다.

## 3.2.2. 결합성

```
a - b - c       →   (a - b) - c             // 좌결합
a ?? b ?? c     →   a ?? (b ?? c)           // 우결합 (예시)
a < b < c       →   ?                        // 비결합 (체이닝 금지)
```

결합성은 다음 세 가지 중 하나로 정해집니다.

| 표기    | 의미                                           |
|---------|------------------------------------------------|
| `left`  | 좌측부터 묶임. `a OP b OP c` = `(a OP b) OP c` |
| `right` | 우측부터 묶임. `a OP b OP c` = `a OP (b OP c)` |
| `none`  | 체이닝 금지. `a OP b OP c` 는 컴파일 에러      |

## 3.2.3. 우선순위와 결합성 표

각 연산자의 우선순위와 결합성은 [연산자 디스패치](301-operator-dispatch.md) 의 원칙에 따라 표준 라이브러리가 등록해 줍니다. 등록은 `#[infix("+", prec = 7, left)]` 와 같은 형태로 트레잇 메서드에 부착하는 방식으로 이루어집니다.

본 문서에서는 언어가 인식하는 우선순위 표의 형태와 충돌이 발생했을 때의 처리 규칙을 정의해 보겠습니다.

### 우선순위 등급

표준 라이브러리는 다음과 같은 상수 등급으로 우선순위를 매기고 있습니다.

```
12   member access (.), method call, indexing
11   prefix unary (-, !, ~)
 9   << >>
 8   * / % %%
 7   + -
 6   & ^
 5   |
 4   == != < > <= >=
 3   &&
 2   ||
 1   ?? (null 합체)          — 언어 고정, 우결합
 0   .. ..= (범위)           — 언어 고정, 비결합
-1   = += -= *= ... (대입)
```

위와 같이 `#[infix("+", prec = 7, left)]` 형태로 트레잇 메서드에 등급을 명시적으로 부착해 줍니다.

이 표는 [구두점과 연산자 토큰](../001-lexical/110-punctuation-and-operator-tokens.md) 에서 정의한 고정 토큰에 대해 표준 라이브러리가 실제로 등록한 등급에 해당합니다. 위 값은 표준 라이브러리의 `rok/ops.rok` 와 일치하므로, 변경이 필요할 때에는 두 자리를 함께 갱신해 주셔야 합니다.

> [!IMPORTANT]
> **`??` 와 `..` 의 상대 우선순위**: `??` (prec=1) 는 범위 연산자 `..` / `..=` (prec=0) 보다 **강하게** 묶입니다. 따라서 `a ?? 0..3` 은 `(a ?? 0)..3` 으로 묶이며, 범위 연산자는 대입을 제외한 모든 이항 연산자보다 약합니다 (`a || b..c` 는 `(a || b)..c`). 두 등급은 트레잇 메서드에 부착되는 `#[infix]` 등록이 아니라 언어가 고정한 값입니다 — `??` 는 합 타입 위의 언어 수준 desugar ([3.8.4](308-optional-chaining-and-coalescing.md#384-null-합체-)) 이고, 범위는 언어가 다섯 형태를 별개의 표현식으로 인식하는 구문 ([3.7](307-range-expressions.md)) 이기 때문입니다. 범위 연산자는 비결합이므로 `a..b..c` 는 컴파일 에러입니다.

> [!NOTE]
> **점-접두 (broadcast) 연산자의 우선순위**: `.+`, `.*`, `.&&`, `.%%` 같은 점-접두 형태의 우선순위와 결합성은 점 없는 형태와 동일합니다. 별도의 행으로 표기하지는 않으나, 모든 점-접두 토큰은 대응하는 일반 토큰의 등급을 그대로 따릅니다. 예: `.+` 는 `+` 와 같은 prec=7 left, `.&&` 는 `&&` 와 같은 prec=3 left.

> [!NOTE]
> 시프트 연산이 산술 연산보다 강하게 묶인다는 점이 C 와 다른 부분입니다. 따라서 `1 + 2 << 3` 은 `1 + (2 << 3) = 17` 으로 묶이게 됩니다. 직관에서 벗어난다고 느껴지신다면 괄호로 명시해 주시는 편이 적합합니다.

### 같은 토큰의 다중 위치

같은 토큰이 전위, 이항, 후위로 모두 등장할 수 있는 경우 (예를 들어 `-`) 에는 각 위치별로 별개의 우선순위가 정해집니다 (보통은 전위가 이항보다 강합니다).

```
-a + b          →   (-a) + b              // 전위 - 가 + 보다 강함
```

## 3.2.4. 충돌

서로 다른 트레잇이 같은 (토큰, 위치) 조합에 대해 서로 다른 우선순위를 등록하려고 하면, 등록 시점에 컴파일 에러가 발생하게 됩니다. 하나의 토큰에는 단 하나의 우선순위만 허용되기 때문입니다.

```
trait MyAdd { #[infix("+", prec = 5, left)] fn add(...) ... }
// 다른 어딘가.
trait Add    { #[infix("+", prec = 7, left)] fn add(...) ... }
// ERROR: '+' 의 우선순위가 5 와 7 로 충돌
```

이러한 강제 규칙은 프로그램의 어느 위치에서든 같은 토큰이 항상 같은 모양의 트리를 만들도록 보장해 줍니다.

## 3.2.5. 비교 체이닝 금지

> [!WARNING]
> 수학적 직관 (`a < b < c` 가 `a < b 그리고 b < c` 를 의미) 에 따른 체이닝은 rok 에서는 허용되지 않습니다.

비교 연산자 (`<`, `>`, `<=`, `>=`, `==`, `!=`) 는 모두 비결합 (`none`) 으로 등록되어 있습니다.

```
a < b < c       // ERROR: 체이닝 금지
a == b == c     // ERROR
```

원하는 의미가 있다면 다음과 같이 명시적으로 적어 주셔야 합니다.

```
a < b && b < c
```

이러한 결정에는 두 가지 근거가 있습니다.

- 비교의 결과는 `bool` 인데, 그 `bool` 을 다시 비교한다는 것은 수학적 직관과 어긋나기 때문입니다.
- 체이닝을 받아들이려면 별도의 체이닝 규칙이 필요한데, 그 규칙은 다른 연산자와 일관되지 않게 되기 때문입니다.

따라서 명시적으로 `&&` 를 사용하는 방식이 가장 단순하고 일관된 표현이라 할 수 있습니다.

## 3.2.6. 괄호로 강제 묶기

위의 규칙에 따라 만들어지는 트리가 의도한 모양과 다를 때에는, 괄호를 사용해 강제로 묶어 주실 수 있습니다.

```
a + b * c       →   a + (b * c)             // 기본 묶임
(a + b) * c     →   (a + b) * c             // 명시적
```

괄호는 어휘 단계와 구문 단계에서 그룹화 토큰으로 동작하며, 트리의 모양을 직접 제어할 수 있게 해 줍니다.

## 3.2.7. 우선순위가 같고 결합성이 다른 두 토큰

같은 우선순위를 가지면서 결합성이 다른 두 연산자가 인접하여 등장하면, 비결합처럼 처리됩니다. 이 경우에는 사용자가 직접 괄호로 명시해 주셔야 합니다.

```
let x = a OP1 b OP2 c;     // OP1 left, OP2 right, 같은 등급
                            // → 컴파일 에러, 괄호 필요
```

이 규칙은 결합성 불일치에서 비롯되는 모호함을 사전에 차단해 주는 역할을 합니다.
