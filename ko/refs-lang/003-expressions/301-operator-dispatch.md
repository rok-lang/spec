# 3.1. 연산자 디스패치

이 장은 [구두점과 연산자 토큰](../001-lexical/110-punctuation-and-operator-tokens.md)에서 정의한 연산자 토큰을 트레잇 메서드 호출로 바꾸는 일반 원칙을 정의합니다. 어느 연산자가 어느 트레잇의 어느 메서드에 대응하는지 정한 구체적인 표는 표준 라이브러리가 정의합니다.

## 3.1.1. 모든 연산자는 트레잇 메서드

[언어와 표준 라이브러리의 경계](../000-meta/004-language-vs-standard-libraries.md)에서 정한 대로, 연산자 구문은 언어가 정하고 그 동작은 표준 라이브러리의 트레잇이 정합니다.

```
a + b         →   <typeof(a) as Add<typeof(b)>>::add(a, b)
a - b         →   <typeof(a) as Sub<typeof(b)>>::sub(a, b)
a * b         →   <typeof(a) as Mul<typeof(b)>>::mul(a, b)
a < b         →   <typeof(a) as Cmp<typeof(b)>>::lt(a, b)
-a            →   <typeof(a) as Neg>::neg(a)
!a            →   <typeof(a) as Not>::not(a)
```

모든 연산자가 같은 패턴을 따릅니다. 언어가 토큰을 인식하고, 그 토큰을 트레잇 메서드 호출로 바꿉니다.

## 3.1.2. 연산자 → 트레잇 매핑은 표준 라이브러리에서

각 연산자 토큰이 어떤 트레잇 메서드에 매핑되는지 정한 정확한 표는 표준 라이브러리가 정의합니다. 이 문서는 매핑이 있다는 사실과 디스패치 메커니즘만 다룹니다.

표준 라이브러리는 메타 시스템의 `#[infix]` / `#[prefix]` / `#[postfix]` 속성으로 트레잇 메서드에 매핑을 붙입니다. 정확한 메커니즘은 [`#[infix]` / `#[prefix]` / `#[postfix]` 매직](../006-meta-system/607-operator-magic.md)에서 정의합니다.

```
trait Add<Rhs = Self> {
    type Output;
    #[infix("+")]
    fn add(self, rhs: Rhs) -> Output;
}

trait Neg {
    type Output;
    #[prefix("-")]
    fn neg(self) -> Output;
}
```

위 예시는 트레잇과 메서드 시그니처의 모양을 보여 줍니다. 그 의미는 2장의 트레잇 사양과 6장의 매직 사양이 함께 정합니다. 3장은 언어가 토큰을 보고 위와 같은 호출로 바꾼다는 것까지만 정의합니다.

## 3.1.3. 디스패치는 vtable 없이

연산자 호출의 디스패치는 [트레잇-as-타입 금지](../002-types/212-trait-as-type-banned.md) 원칙에 따라 vtable 간접 호출 없이 해소되도록 설계합니다.

- 정적 슬롯에서는 컴파일 타임에 트레잇 메서드가 정해지고, 직접 함수 호출로 컴파일됩니다.
- `any` 슬롯에서는 [`any` 슬롯](../002-types/202-any-slot.md)의 런타임 태그 검사로 트레잇 메서드를 정한 뒤 직접 호출합니다. 비용은 태그 검사 한 번과 직접 호출 한 번입니다.

어느 경우든 vtable 조회 때문에 간접 호출이 더 생기지 않습니다. 과학·수치 코드의 핫 루프가 이 비용을 치르지 않게 하려는 것이 [트레잇-as-타입 금지](../002-types/212-trait-as-type-banned.md)의 동기이고, 이 디스패치 규칙은 그 결과입니다.

### impl 고르기

이항 연산 `a op b`는 왼쪽 피연산자 타입에 대한 해당 연산자 트레잇의 impl 중에서 고릅니다.

- 한 타입에 같은 연산자 트레잇의 impl이 여럿 있으면(`Mul<i64>`, `Mul<f64>` 등) `Rhs`가 오른쪽 피연산자의 타입과 맞는 impl을 고릅니다.
- 왼쪽이 원시 타입이고 오른쪽이 struct이면 원시 타입에 대해 선언한 impl을 씁니다(`2.0 * d`는 `impl Mul<Duration> for f64`).

이 규칙은 연산자에만 쓰이지 않습니다. 트레잇의 타입 매개변수를 채우는 값의 타입으로 impl을 고르는 모든 자리에 적용됩니다. 연산자의 `Rhs`, `T::from(x)` / `T::try_from(x)` / `Tr::f(x)`의 인자, 타입이 정해진 자리에 쓴 `.into()` / `.try_into()`의 수신자, 그리고 impl들이 그 매개변수에서 다를 때 메서드 호출 `x.m(v)`나 경로 호출 `T::m(x, v)`의 인자가 여기에 해당합니다. 그 값이 접미사 없는 리터럴이면 다음 순서로 고릅니다.

1. 리터럴의 기본 타입(`i32` / `f64`)에 대한 impl이 있고 값이 그 타입에 들어가면 그 impl.
2. 아니면 매개변수 타입이 그 값을 담을 수 있는 유일한 impl(정수는 범위 안의 정수 타입 또는 `int`, 실수는 값을 유한하게 표현하는 `f32` / `f64` 또는 `float`). `d * 2`는 `Duration`의 `Mul<i64>`입니다.
3. 그런 impl이 여럿이면 접미사를 요구하는 컴파일 에러.

이 규칙은 맨 리터럴과 부호를 붙인 리터럴(`-1`)에만 적용되고, `1 + 1` 같은 식에는 적용되지 않습니다. `Tr::f(..)`처럼 호출한 정적 트레잇 메서드의 `Self`는 기대 타입으로 정합니다. 트레잇의 매개변수를 채우는 인자가 없으면 호출의 기대 타입을 반환 타입으로 갖는 impl(또는 bound)을 고르고, 그런 것이 없으면 호출은 모호합니다([4.9.6](../004-functions/409-method.md#496-자유-함수와-메서드의-호출-형태)).

## 3.1.4. 매핑이 없는 연산

어떤 타입 쌍에 대한 트레잇 구현이 없으면 그 연산자 호출은 컴파일 에러입니다.

```
let a: i32 = 1i32;
let b: str = "hi";
let c = a + b;          // ERROR: Add 의 (i32, str) impl 없음
```

진단은 연산자와 두 피연산자의 타입을 알려 줍니다.

```
error: operator `+` cannot be applied to `i32` and `str`
```

## 3.1.5. 단항, 이항, 후위

연산자는 위치에 따라 다음 세 가지 중 하나로 분류합니다.

| 위치                | 형태     | 매핑 메커니즘      |
|---------------------|----------|--------------------|
| 이항 (infix)        | `a OP b` | `#[infix("OP")]`   |
| 전위 단항 (prefix)  | `OP a`   | `#[prefix("OP")]`  |
| 후위 단항 (postfix) | `a OP`   | `#[postfix("OP")]` |

같은 토큰이 여러 위치에 나올 수도 있습니다. 예를 들어 `-`는 이항(`a - b`)과 전위 단항(`-a`) 양쪽에 쓰입니다. 위치는 토큰이 나온 문맥으로 정합니다. 피연산자가 앞에만 있으면 후위이고, 양쪽에 있으면 이항입니다.

## 3.1.6. 우선순위와 결합

연산자에는 위치별 디스패치 말고도 우선순위(precedence)와 결합성(associativity)이 있습니다. 이 둘은 [우선순위와 결합성](302-precedence-and-associativity.md)에서 정의합니다.

우선순위와 결합성은 토큰 → 트레잇 매핑에 속하지 않습니다. 3.2의 표가 언어 차원에서 고정하며, `#[infix("+")]` 같은 등록은 토큰과 트레잇 메서드를 연결하기만 합니다.

## 3.1.7. 사용자 정의 연산자

표준 라이브러리는 `#[infix]` / `#[prefix]` / `#[postfix]`로 기본 연산자에 의미를 줍니다. 사용자 코드도 같은 메커니즘으로 다른 트레잇에 새 매핑을 붙일 수 있습니다.

```
#[infix("⊕", like = "+")]          // 새 토큰은 기존 토큰의 단계를 따름
fn combine(self, rhs: Rhs) -> Output;
```

같은 (토큰, 위치, 타입 쌍)에 대한 매핑은 하나뿐이어야 하며, 충돌하면 컴파일 에러입니다.

[구두점과 연산자 토큰](../001-lexical/110-punctuation-and-operator-tokens.md)의 고정 토큰표에 없는 문자열을 새 연산자로 등록하려면 같은 메커니즘으로 토큰 자체를 등록해야 합니다. 정확한 절차는 [`#[infix]` / `#[prefix]` / `#[postfix]` 매직](../006-meta-system/607-operator-magic.md)에서 정의합니다.

## 3.1.8. Unicode 연산자

`≤`, `≥`, `≠`, `⊕`, `∈`처럼 ASCII 범위 밖의 연산자는 표준 라이브러리가 같은 트레잇의 여러 별칭으로 등록할 수 있습니다.

```
trait Cmp<Rhs = Self> {
    #[infix("<=")]
    #[infix("≤")]
    fn le(self, rhs: Rhs) -> bool;
}
```

여러 토큰이 같은 트레잇 메서드에 매핑되어 똑같이 동작하므로, 어느 표기를 써도 결과는 같습니다.
