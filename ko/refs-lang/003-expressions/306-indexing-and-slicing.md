# 3.6. 인덱싱과 슬라이싱

대괄호 (`[`, `]`) 로 둘러싼 표현식은 값의 부분에 접근하는 두 가지 형태에 쓰입니다. 하나는 특정 위치의 원소를 꺼내는 인덱싱이고, 다른 하나는 일정 영역을 잘라내는 슬라이싱입니다.

```
index_expr      ::= primary "[" expr ("," expr)* "]"
slice_expr      ::= primary "[" slice_arg ("," slice_arg)* "]"
slice_arg       ::= expr
                  | expr? ":" expr? (":" expr?)?
```

## 3.6.1. 인덱싱: `arr[i]`

인덱싱은 대괄호 안에 인덱스 표현식을 적어 해당 자리의 값을 얻는 방식입니다.

```rok
let v = arr[0];
let last = arr[arr.len() - 1];
let m = matrix[i, j];        // 다차원, 인덱스를 콤마로 구분
```

좌변에는 임의의 표현식이 올 수 있으며, 대괄호 안에는 한 개 이상의 인덱스 표현식을 콤마로 구분해 적습니다. 결과로는 인덱싱된 자리의 값을 돌려받게 됩니다.

### desugar

인덱싱 표현식은 다음과 같이 트레잇 호출로 desugar 됩니다.

```
arr[i]                 →   <typeof(arr) as Index<typeof(i)>>::index(arr, i)
arr[i] = v;            →   <typeof(arr) as IndexSet<typeof(i)>>::index_set(ref arr, i, v)
matrix[i, j]           →   <typeof(matrix) as Index<(typeof(i), typeof(j))>>::index(matrix, (i, j))
```

읽기와 쓰기는 서로 다른 트레잇으로 매핑되기 때문에, 읽기 전용 자료에 쓰기를 시도하면 컴파일 에러가 발생합니다. 또한 다차원 인덱싱은 인덱스들을 튜플로 묶어 단일 인덱스 트레잇 호출로 desugar 된다는 점도 알아두시면 좋겠습니다.

### 음수 인덱스

음수 인덱스의 의미 (예컨대 뒤에서부터 세는 Python 식 동작) 는 표준 라이브러리의 `Index` 구현에 달려 있습니다. 언어 자체는 `[-1]` 을 유효한 식 자리로 받아들이고, 이를 `Index<i32>` (또는 음수가 가능한 적절한 타입) 의 호출로 desugar 할 뿐입니다.

따라서 음수 인덱스의 지원 여부와 동작은 컬렉션마다 달라질 수 있습니다. 예를 들어 `List` 는 음수 인덱스를 지원하지만, `Dict` 는 키 자리이므로 의미가 다르게 해석됩니다.

### 경계 검사와 실패

대괄호 인덱싱은 유효 범위 밖에서 실패할 수 있는데, 실패가 어떤 형태로 드러나는지는 `Index` 구현이 결정합니다. 보통은 panic 이나 에러 발생 형태로 처리됩니다.

만약 panic 없이 `T | none` 값을 받고 싶다면, 라이브러리에서 제공하는 `.get(i)` 같은 메서드를 사용하면 됩니다.

## 3.6.2. 슬라이싱: `arr[start:end]`

슬라이싱은 대괄호 안에 콜론을 포함한 슬라이스 형태가 들어갈 때 사용되는 형식입니다.

```rok
let part = arr[1:3];
let head = arr[:5];
let tail = arr[5:];
let all = arr[:];
let stepped = arr[::2];
let reverse = arr[::-1];
let neg = arr[-3:-1];
let full = arr[a:b:s];
```

대괄호 안에 슬라이스 형태가 들어가면 슬라이싱으로 처리되며, 그 형태는 다음 BNF 를 따릅니다.

```
slice_expr  := expr? ':' expr? (':' expr?)?
              | expr ',' expr ',' ...           // 콤마면 인덱싱
```

기본 형태인 `[start : end]` 는 시작 (포함) 부터 끝 (미포함) 까지의 영역을 의미합니다. 여기에 단계를 더한 `[start : end : step]` 도 쓸 수 있는데, 이때 음수 step 을 주면 역순으로 잘라낼 수 있습니다. 각 부분은 생략할 수 있으며, 생략하면 처음 / 끝 / 1 이 기본값으로 적용됩니다.

### desugar

슬라이싱 역시 트레잇 호출로 desugar 됩니다.

```
arr[a : b]            →   <typeof(arr) as Slice<typeof(a), typeof(b)>>::slice(arr, a, b, 1)
arr[a : b : s]        →   <typeof(arr) as Slice<typeof(a), typeof(b)>>::slice(arr, a, b, s)
arr[: b]              →   동일. 생략된 자리는 표준 라이브러리가 정의한 기본값
```

생략된 자리의 기본값 (`start` 가 생략되면 0, `end` 가 생략되면 길이, `step` 이 생략되면 1, 음수 step 일 때 end 가 길이-1 이 되는 등) 은 표준 라이브러리의 `Slice` 구현이 결정합니다.

### 슬라이스 결과의 종류

슬라이스 결과는 보통 원본의 뷰 (zero-copy view) 입니다. 즉 원소를 복사하지 않고 영역을 가리키기만 합니다. 정확한 반환 타입은 표준 라이브러리에 정의된 `Slice` 의 연관 타입에 따라 달라지게 됩니다.

### 슬라이스 대입

슬라이스에 직접 대입하는 것도 가능합니다 (지원 여부는 트레잇 구현에 따라 다릅니다).

```rok
arr[1:3] = other;
```

이렇게 하면 해당 영역의 원소들을 한꺼번에 갱신하게 됩니다. desugar 는 별개의 **SliceSet** 트레잇으로 처리되며, 결국 `Slice` 와 `SliceSet` 두 트레잇이 읽기와 쓰기를 분리해서 담당하는 셈입니다.

## 3.6.3. 인덱싱과 슬라이싱의 토큰 분리

같은 `[ ... ]` 안이라도, 콤마 (`,`) 가 등장하면 인덱싱 (다차원 또는 키 튜플) 으로, 콜론 (`:`) 이 등장하면 슬라이싱으로 해석됩니다. 한 괄호 안에서 두 형태를 섞는 것은 허용되지 않으니 주의해야 합니다.

```
arr[1, 2]                  // OK — 인덱싱 (i, j)
arr[1:3]                   // OK — 슬라이싱
arr[1:3, 4:6]              // ERROR: 섞임
```

다차원 슬라이싱이 필요하다면, 표준 라이브러리의 다차원 슬라이스 `trait` (예컨대 행렬 라이브러리의 `MatrixSlice` 같은 것) 가 별도 형태로 제공할 수 있습니다.

## 3.6.4. 빈 대괄호와 잘못된 형태

다음과 같은 형태들은 모두 잘못된 사용 예에 해당합니다.

```
arr[]               // ERROR: 빈 대괄호
arr[a:b:c:d]        // ERROR: 콜론 셋 이상
arr[: : :]          // ERROR: 콜론 셋
```

이러한 형태들은 어휘와 구문 단계에서 거부됩니다.

## 3.6.5. 인덱싱과 슬라이싱은 `trait` 의존

언어 자체는 어떤 타입에 인덱싱이나 슬라이싱이 가능한지를 직접 결정하지 않습니다. 표준 라이브러리가 `Index`, `IndexSet`, `Slice`, `SliceSet` 를 적절한 타입에 구현해 두면, 그제서야 `arr[i]` 와 `arr[1:3]` 이 그 타입에 대해 동작하게 됩니다.

요컨대 언어가 정의하는 것은 대괄호의 토큰 형태와 desugar 규칙까지이고, 그 의미는 라이브러리의 몫이라고 보면 됩니다.
