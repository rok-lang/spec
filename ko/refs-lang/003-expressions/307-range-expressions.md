# 3.7. 범위 표현식

`..` / `..=` 토큰 ([구두점과 연산자 토큰](../001-lexical/110-punctuation-and-operator-tokens.md)) 으로 시작 ~ 끝의 범위 값을 만든다.

```
range_expr      ::= expr ".." expr        // half-open
                  | expr "..=" expr       // inclusive
                  | ".." expr             // from start
                  | expr ".."             // unbounded end
                  | ".."                  // full
```

## 3.7.1. 다섯 가지 형태

```nok
0..10           // [0, 1, ..., 9]      배제 끝
0..=10          // [0, 1, ..., 10]     포함 끝
..10            // 0..10 과 동일       시작 생략 (전위)
10..            // [10, 11, ...]       끝 생략, 무한
..              // 전체                양쪽 생략, 주로 슬라이싱에서
```

- `..`. 끝을 배제 (반열림 구간).
- `..=`. 끝을 포함.
- 시작 생략은 0 또는 자료에 따른 기본값으로 처리.
- 끝 생략은 무한 / 자료의 끝으로 처리.

## 3.7.2. desugar

```
a .. b          →   Range::new(a, b)
a ..= b         →   RangeInclusive::new(a, b)
.. b            →   RangeTo::new(b)
a ..            →   RangeFrom::new(a)
..              →   RangeFull
```

이 변환의 정확한 표준 라이브러리 트레잇 / 타입은 라이브러리 사양에서 정의한다. 본 문서는 언어가 다섯 형태를 별개의 표현식으로 인식하고 표준 라이브러리 타입의 인스턴스로 desugar 한다는 사실까지만 책임진다.

## 3.7.3. 우선순위

[우선순위와 결합성](302-precedence-and-associativity.md) 의 등급에서 범위 연산자는 비교보다 낮고 합체보다 높다.

```
0..n + 1            →   0 .. (n + 1)        // + 가 .. 보다 강함
a < b..c < d        // 비교 체이닝 금지로 에러
```

대부분의 산술 연산자보다 약하게 묶이므로, 시작과 끝에 산술 표현식을 넣어도 자연스럽다.

## 3.7.4. 사용처

### 반복

```nok
for i in 0..10 { ... }
```

- 범위 값을 [루프 표현식](313-loop-expressions.md) 의 `for` 루프가 받아 반복한다.
- `Range` / `RangeInclusive` 가 [`trait`](../002-types/208-trait.md) 의 `Iterator` 트레잇을 구현하면 자동으로 반복된다.

### 슬라이싱과는 별개

```
arr[1:3]            // [인덱싱과 슬라이싱](306-indexing-and-slicing.md) 의 슬라이스, 콜론 (`:`) 사용
0..3                // 범위 값, 점 둘 (`..`) 사용
```

두 표기는 서로 다른 토큰이며 다른 의미를 가진다. 슬라이싱은 인덱스 표현식의 내부 형태, 범위는 값 (Range 타입 인스턴스).

### 패턴 매칭

범위 패턴 ([패턴](311-patterns.md)) 도 같은 토큰을 사용한다. 의미는 그 자리에서 정의된다.

```
match x {
    1..=5 => ...,
    _ => ...,
}
```

## 3.7.5. step 은 메서드로

step (보폭) 은 표기 안에 두지 않는다. 대신 표준 라이브러리의 `.step_by(n)` 메서드로 처리한다.

```nok
(0..100).step_by(2)         // [0, 2, 4, ..., 98]
```

이 결정은 i-want-this.txt 의 결정 (언어 syntax 는 단순하게 유지, 부가 기능은 메서드로) 과 일관된다. 슬라이싱의 `[::2]` 는 별개 표기이며, 그 자리에는 step 이 자연스러워 도입했다.

## 3.7.6. 역방향

```nok
(0..10).rev()
```

`.rev()` 메서드로 반대 방향으로 반복한다. 범위 표기 자체에 음수 step 을 두지 않는다.

## 3.7.7. 빈 범위

```nok
5..3            // 빈 범위, 정상 표현, 반복 시 0회
5..=3           // 빈 범위
```

시작이 끝보다 크면 빈 범위가 된다. 컴파일 에러가 아니라 반복 0회인 정상 값이다. 0회 반복이 자연스러운 의미다.

## 3.7.8. 무한 범위의 사용

```nok
for i in 0.. {
    if condition(i) { break; }
}
```

`0..` 같은 무한 범위는 루프 내부의 `break` 로 종료한다. 무한 반복 자체는 `loop { ... }` (후속 사양) 와 등가이며, 사용 편의 차이만 있다.
