# 5.5. `use` (가져오기)

`use` 키워드 ([키워드](../001-lexical/105-keywords.md)) 는 다른 모듈의 항목을 현재 모듈의 가시 이름 공간에 끌어오는 구문이다.

## 5.5.1. 기본 형태

```
use_stmt    ::= "use" use_tree ";"
use_tree    ::= path ("::" "*")?
              | path "::" "**"
              | path "::" "{" use_tree ("," use_tree)* ","? "}"
              | path ("as" identifier)?
path        ::= path_root ("::" identifier)*
path_root   ::= "crate" | "super" | "self" | identifier
```

```nok
use foo::bar;
use std::time::Duration;
use crate::geom::Point;
```

- `use` + 경로 + `;`.
- 경로의 마지막 식별자가 현재 모듈에서 그 항목의 이름이 된다.
- `use` 후에는 `bar`, `Duration`, `Point` 같은 짧은 이름으로 참조할 수 있다.

## 5.5.2. 다중 import: `{...}`

같은 prefix 를 가진 여러 항목을 한 줄로 적는다.

```nok
use foo::{a, b, c};
use std::time::{Duration, Instant};
```

`{...}` 안에 콤마로 구분된 마지막 단계의 식별자들이 들어간다. 위는 다음과 동등하다.

```nok
use foo::a;
use foo::b;
use foo::c;
```

## 5.5.3. 별칭: `as`

가져온 항목의 이름을 변경한다.

```nok
use foo::very_long_name as short;
use std::collections::Dict as Map;
```

- `as` + 새 이름.
- 현재 모듈에서는 새 이름만 보이고 원래 이름은 보이지 않는다.

다중 import 안에서도 사용할 수 있다.

```nok
use foo::{a as alpha, b, c as charlie};
```

## 5.5.4. glob: `*`

모듈의 모든 가시 항목을 가져온다.

```nok
use foo::*;                    // foo 의 가시 항목 전부
```

규칙.

- `*` 가 마지막 토큰이어야 한다. `use foo::*::bar` 같은 형태는 ERROR.
- 가져오는 항목은 외부에 가시화된 것뿐이다 (`pub` 또는 호환 가시성을 가진 항목).
- `pub(shy)` 항목 ([가시성](506-visibility.md)) 은 glob 으로 가져오지 않는다. 명시 import 가 필요하다.

## 5.5.5. 재귀 glob: `**`

서브 모듈까지 재귀적으로 가져온다.

```nok
use foo::**;                   // foo 의 모든 항목 + foo 의 자식 모듈의 모든 항목 + ...
```

- 서브 모듈을 거쳐 모든 가시 항목까지 한 번에 가져온다.
- 일반 glob (`*`) 보다 범위가 넓다.
- 마찬가지로 `pub(shy)` 항목은 가져오지 않는다.

큰 라이브러리의 prelude 형태로 자주 쓴다.

## 5.5.6. glob / 재귀 glob 의 충돌

여러 glob 이 같은 이름을 가져오면 충돌이 난다.

```nok
use foo::*;
use bar::*;
// 둘 다 'item' 이라는 이름이 있으면, 그 이름은 모호해서 사용 시 ERROR.
```

해소하려면 하나를 명시 import 하거나 별칭을 부여한다.

```nok
use foo::item;                 // 명시 — foo::item 만 가시
use bar::item as bar_item;      // 별칭 — 둘 다 다른 이름으로
```

## 5.5.7. 경로의 시작점

경로의 첫 식별자는 [경로](507-paths.md) 의 규칙을 따른다.

- `crate::`: 현재 패키지의 루트부터.
- `super::`: 부모 모듈부터.
- `self::`: 현재 모듈부터 (보통 생략 가능).
- 식별자: 첫 식별자가 현재 가시한 이름일 때 (자식 모듈, 이미 `use` 한 이름 등).

## 5.5.8. `use` 의 위치

`use` 는 모듈 수준 또는 함수 본체 수준에 등장할 수 있다.

```nok
// 모듈 수준 — 그 모듈 전체에서 가시
use foo::bar;

fn f() {
    // 함수 안 — 그 함수 안에서만 가시
    use foo::baz;
    let x = baz();
}
```

함수 안의 `use` 는 그 함수의 지역 import 이며, 외부에 노출되지 않는다. 가시성 키워드 (`pub`) 도 의미가 없다.

## 5.5.9. `use` 의 가시성

```nok
use foo::bar;                   // 모듈 비공개 — 같은 모듈 안에서만 보임
pub use foo::bar;               // 외부 노출 — 재내보내기
pub(pkg) use foo::bar;          // 같은 패키지 내부만 노출
```

`pub use` 는 재내보내기다. [가시성](506-visibility.md) 에서 자세히 정의한다.

## 5.5.10. 자동 import: prelude

[표준 라이브러리 계층](../000-meta/005-stdlib-tiers.md) 의 `core::prelude` 항목은 사용자가 `use` 를 적지 않아도 자동으로 가시화된다. 가장 흔한 컬렉션 타입과 트레잇 등이 여기 포함된다.

prelude 의 정확한 항목은 표준 라이브러리에서 정의한다.

## 5.5.11. 같은 모듈 / 항목 두 번 import: 허용

```nok
use foo::bar;
use foo::bar;                   // OK — 중복 import 무해
```

같은 항목의 중복 import 는 무해하므로 허용한다. (동일성 검사로 정말 같은 것이면 OK.)

## 5.5.12. 다른 모듈에서 같은 이름: 충돌

```nok
use foo::Item;
use bar::Item;                  // ERROR — 'Item' 이 이미 import 됨
```

서로 다른 모듈에서 같은 짧은 이름을 import 하면 충돌이다. 하나를 별칭으로 해소한다.

```nok
use foo::Item;
use bar::Item as BarItem;       // OK
```

## 5.5.13. `use` 의 평가 / 효과

`use` 는 컴파일 타임의 이름 해소 정보만 변경한다. 런타임 동작에 직접적인 영향이 없다.

`use` 자체는 어떤 코드도 실행하지 않는다. 단지 현재 모듈의 이름 표에 별칭을 추가할 뿐이다.

## 5.5.14. 모듈 자체를 import

```nok
use foo::geom;                  // foo::geom 모듈 자체를 import
let p = geom::Point { ... };    // geom 을 짧은 이름으로 사용
```

항목뿐 아니라 모듈 자체도 import 할 수 있다. 그 모듈의 이름 (마지막 식별자) 이 현재 모듈에서 짧은 이름으로 보인다.

자식 모듈을 거쳐 접근하는 패턴이 자주 쓰인다.
