# 5.5. `use`(가져오기)

`use` 키워드([키워드](../001-lexical/105-keywords.md))는 다른 모듈의 항목을 현재 모듈에서 보이는 이름 공간으로 가져옵니다.

## 5.5.1. 기본 형태

```
use_stmt    ::= "use" use_tree ";"
use_tree    ::= path "::" "*"
              | path "::" "**"
              | path "::" "{" use_tree ("," use_tree)* ","? "}"
              | path ("as" identifier)?
path        ::= path_root ("::" identifier)*
path_root   ::= "pkg" | "sup" | identifier
```

glob(`*`, `**`)에는 `as` 별칭을 붙이지 않습니다. 한 번에 여러 항목을 가져오므로 별칭 하나로는 뜻이 서지 않습니다. 따라서 `path ("as" identifier)?`는 항목 하나를 가져올 때만 적용됩니다.

```rok
use foo::bar;
use rok::std::time::Duration;
use pkg::geom::Point;
```

기본 구조는 `use`, 경로, 마지막 `;`입니다. 경로의 마지막 식별자가 현재 모듈에서 그 항목의 이름이 됩니다. `use`로 가져온 뒤에는 `bar`, `Duration`, `Point` 같은 짧은 이름으로 참조할 수 있습니다.

## 5.5.2. 다중 import: `{...}`

접두 경로가 같은 여러 항목은 한 줄로 묶어 적을 수 있습니다.

```rok
use foo::{a, b, c};
use rok::std::time::{Duration, Instant};
```

`{..}`의 각 원소는 그룹의 해소된 접두 경로 뒤에 이어집니다. 접두 경로는 비어 있어도 됩니다(`pkg::{..}`, 루트에 닿는 `sup::{..}`). 따라서 `use p::{a, b}`는 어느 모듈에서든 정확히 다음과 같습니다.

```rok
use foo::a;
use foo::b;
```

- 그룹은 중첩할 수 있고, `*`, `**`, `as`를 담을 수 있습니다(`use foo::{bar::{x, y as z}, baz::*};`).
- 그룹 안의 `self`는 에러입니다.
- 각 잎은 항목, enum 변형, 모듈 중 하나를 가리켜야 합니다. 그렇지 않으면 그 잎 위치에서 "unresolved import" 에러입니다.

## 5.5.3. 별칭: `as`

`as` 키워드로 가져온 항목의 이름을 바꿉니다.

```rok
use foo::very_long_name as short;
use rok::std::collections::Dict as Map;
```

`as` 뒤에 새 이름을 적습니다. 현재 모듈에서는 새 이름만 보이고 원래 이름은 보이지 않습니다.

다중 import 안에서도 쓸 수 있습니다.

```rok
use foo::{a as alpha, b, c as charlie};
```

## 5.5.4. glob: `*`(얕은)

모듈에서 보이는 모든 항목을 한 번에 가져옵니다.

```rok
use foo::*;                    // foo 의 가시 항목 전부
```

규칙은 다음과 같습니다. `*`는 마지막 토큰이어야 합니다. 그래서 `use foo::*::bar` 같은 형태는 에러입니다. 호출자가 볼 수 있는 항목만 가져옵니다([가시성](506-visibility.md)). `pub`이거나, 같은 패키지 안의 `pub(pkg)`처럼 도달 범위(reach)가 호출자를 포함하는 항목만 대상입니다. `foo`의 **직접** 자식만 가져오고 서브 모듈의 항목은 가져오지 않습니다. 서브 모듈까지 가져오는 일은 `**`가 맡습니다. 블록의 glob `use`는 그 블록에 선언한 항목의 머리에도 닿습니다([3.9.1](../003-expressions/309-block-expressions.md#391-형태)). 모듈이 정의한 항목은 glob으로 가져온 같은 이름의 항목보다 우선합니다. 이때 glob은 아무것도 보고하지 않고 양보합니다. 그 이름을 직접 적은 import였다면 에러입니다(5.5.12).

## 5.5.5. 재귀 glob: `**`(깊은)

서브 모듈까지 재귀적으로 가져옵니다.

```rok
use foo::**;                   // foo 의 모든 항목 + foo 의 자식 모듈의 모든 항목 + ...
```

서브 모듈을 거쳐 보이는 모든 항목을 한 번에 가져오므로 얕은 glob(`*`)보다 범위가 훨씬 넓습니다. 큰 라이브러리의 prelude 형태로 자주 씁니다. 재귀 glob은 모듈 항목과 `enum` 변형을 가져옵니다. 타입의 연관 항목은 결코 가져오지 않습니다. 묵시적 `use rok::core::**;`(5.5.10) 아래에서 맨 이름 `MAX`는 `Duration::MAX`를 가리키지 않습니다.

## 5.5.6. glob / 재귀 glob의 충돌

여러 glob이 같은 이름을 가져오면 충돌입니다.

```rok
use foo::*;
use bar::*;
// 둘 다 'item' 이라는 이름이 있으면, 그 이름은 모호해서 사용 시 ERROR.
```

하나를 이름으로 직접 가져오거나 별칭을 붙여 해소하세요.

```rok
use foo::item;                 // 명시 - foo::item 만 가시
use bar::item as bar_item;      // 별칭 - 둘 다 다른 이름으로
```

## 5.5.7. 경로의 시작점

경로의 첫 식별자는 [경로](507-paths.md)의 규칙을 따릅니다. 경우는 세 가지입니다. `pkg::`는 현재 패키지의 루트에서 시작합니다. `sup::`는 부모 모듈에서 시작합니다. 여러 단계를 올라갈 때는 `sup::sup::...`처럼 이어 쓸 수 있습니다. 그 밖의 일반 식별자는 현재 보이는 이름일 때 쓸 수 있습니다(자식 모듈, 이미 `use`한 이름 등). 같은 모듈의 자식은 식별자만으로 닿을 수 있으므로 별도의 `self::`는 없습니다.

### `enum` 변형 가져오기

`enum`의 변형은 그 `enum` 아래의 항목이므로 `use`로 가져올 수 있습니다. `use` 경로는 현재 보이는 타입 이름으로 시작할 수도 있습니다.

```rok
use Shape::{Circle};                // 변형 하나
use Shape::{Square as Sq};          // 별칭
use Shape::*;                       // 모든 변형
use Result::*;                      // 가시한 타입 이름으로 시작
```

묵시적 `use rok::core::**;`(5.5.10)가 `Result` 아래의 변형까지 가져오므로 `Ok` / `Err`는 접두 없이 쓸 수 있습니다. 패턴의 맨 이름이 가져온 변형으로 해소되면, 그 이름은 새 바인딩을 만들지 않고 그 변형과 매칭합니다.

```rok
match r {
    Ok(v)  => v,
    Err(e) => fallback(e),
}
```

## 5.5.8. `use`의 위치

`use`는 모듈 수준과 함수 본체 수준에 올 수 있습니다.

```rok
// 모듈 수준 - 그 모듈 전체에서 가시
use foo::bar;

fn f() {
    // 함수 안 - 그 함수 안에서만 가시
    use foo::baz;
    let x = baz();
}
```

함수 안의 `use`는 그 함수의 지역 import입니다. 외부에 노출되지 않으므로 가시성 키워드(`pub`)는 의미가 없습니다.

## 5.5.9. `use`의 가시성

```rok
use foo::bar;                   // 모듈 비공개 - 같은 모듈 안에서만 보임
pub use foo::bar;               // 외부 노출 - 재내보내기
pub(pkg) use foo::bar;          // 같은 패키지 내부만 노출
```

`pub use`는 재내보내기입니다. 자세한 내용은 [가시성](506-visibility.md)에서 정의합니다.

## 5.5.10. `rok::core` 자동 import

컴파일러는 모든 Rok 소스의 시작에 `use rok::core::**;`를 묵시적으로 적용합니다. 그래서 표준 라이브러리의 foundation 계층 트리가 자동으로 보입니다. `use`를 따로 적지 않아도 `rok::core`의 항목(가장 흔한 컬렉션 타입, 트레잇, 연산자 등)을 짧은 이름으로 바로 쓸 수 있습니다.

`rok::core` 밖의 두 계층인 `rok::bare`(위험 영역)와 `rok::std`(타깃 의존)는 자동으로 보이지 **않습니다**. 명시적으로 가져와야 합니다. 자세한 내용은 [표준 라이브러리 계층](../000-meta/005-standard-libraries-tiers.md)에서 정의합니다.

표준 라이브러리 밖의 모든 모듈(외부 패키지, 사용자 라이브러리)도 명시적으로 가져와야 합니다. `prelude`라는 이름의 모듈도 자동으로 가져오지 않습니다. 이 이름은 라이브러리 작성자의 관례일 뿐입니다. 사용하는 쪽에서 `use my_lib::prelude::*;`처럼 명시적으로 가져와야 합니다.

```rok
// 라이브러리 측
pub mod prelude {
    pub use pkg::api::rok::*;
    pub use pkg::api::ext::*;
}

// 사용자 측
use my_lib::prelude::*;            // 명시적으로 끌어와야 가시
```

## 5.5.11. 같은 모듈 / 항목 두 번 import: 허용

```rok
use foo::bar;
use foo::bar;                   // OK - 중복 import 무해
```

같은 항목을 두 번 가져와도 부작용이 없으므로 허용합니다. 컴파일러가 동일성 검사로 같은 항목임을 확인하면 통과합니다.

## 5.5.12. 다른 모듈에서 같은 이름: 충돌

```rok
use foo::Item;
use bar::Item;                  // ERROR - 'Item' 이 이미 import 됨
```

서로 다른 모듈에서 같은 짧은 이름을 가져오면 충돌입니다. 하나에 별칭을 붙여 해소하세요.

```rok
use foo::Item;
use bar::Item as BarItem;       // OK
```

이름을 적은 import(`use a::f;`, `use a::{f}`, `g`라면 `use a::f as g;`)가 있고 그 import가 채우는 이름공간에 모듈이 같은 이름의 항목을 정의하면 컴파일 에러입니다(`E102`, [9.9.4](../009-tools/909-debug-tools.md#994-진단--에러-메시지)). 항목이 import를 눈에 띄지 않게 가리기 때문입니다. 다른 이름으로 가져오거나(`use a::f as a_f;`) `use`를 지우세요. 같은 이름의 값 항목 옆에 있는 타입 import는 충돌하지 않습니다. glob import는 모듈의 항목에 양보합니다(5.5.4).

```rok
use shapes::square;
fn square(x: f64) -> f64 { x * x }    // ERROR - `square` is both imported from `shapes::square` and defined in this module
```

## 5.5.13. `use`의 평가 / 효과

`use`는 컴파일 타임의 이름 해소 정보만 바꾸므로 런타임 동작에 직접 영향을 주지 않습니다. `use` 자체는 어떤 코드도 실행하지 않고, 현재 모듈의 이름 표에 별칭을 추가하기만 합니다.

## 5.5.14. 모듈 자체를 import

```rok
use foo::geom;                  // foo::geom 모듈 자체를 import
let p = geom::Point { ... };    // geom 을 짧은 이름으로 사용
```

항목뿐 아니라 모듈 자체도 가져올 수 있습니다. 그러면 그 모듈의 이름(마지막 식별자)이 현재 모듈에서 짧은 이름으로 보입니다. 자식 모듈을 거쳐 항목에 접근할 때 자주 씁니다.
