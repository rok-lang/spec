# 5.1. 변수 선언

`let` 키워드([키워드](../001-lexical/105-keywords.md))로 새 변수를 선언합니다. 이 문서는 선언 형태를 정의하고, 재할당과 새 선언을 가르는 규칙을 정합니다.

## 5.1.1. 새 선언: `let`

```
let_stmt    ::= "let" let_lhs (":" type_expr)? "=" expr ";"
let_lhs     ::= identifier
              | irrefutable_pattern    // tuple / struct destructure - 5.1.11 참조
```

가장 흔한 형태는 단일 식별자입니다(`let x = ...`). 좌변에 반증 불가능 패턴(5.1.11)을 두면 [분해 대입(destructuring)](../003-expressions/315-destructuring.md)이 됩니다. `let-else` 형태([let-else](../003-expressions/316-let-else.md))는 별도 문법입니다.

```rok
let x = 42i32;
let y: i32 = 10i32;
let z;                            // ERROR - 초기값 없음
let z: i32;                        // ERROR - 초기값 없음
```

기본 형태는 `let`, 이름, 선택적인 `: 타입`, 그리고 `=`와 초기값 순서입니다. 초기값은 꼭 있어야 합니다. 초기화되지 않은 변수는 없습니다. 타입을 명시하면 그 타입의 정적 슬롯이 되고, 명시하지 않으면 초기값에서 추론한 타입의 정적 슬롯이 됩니다(5.1.7). [`any` 슬롯](../002-types/202-any-slot.md)은 `: any`를 명시할 때만 생깁니다.

따라서 값이 채워지지 않은 슬롯을 읽는 문제(Rust의 borrow checker가 막는 종류의 문제)가 생기지 않습니다. 초기값을 미리 정할 수 없다면 [합 타입](../002-types/206-sum-types.md) `T | none`으로 값이 없는 상태를 명시하세요.

```rok
let cache: Data | none = none;     // "아직 없음" 을 명시
cache = compute();                  // 나중에 채움
```

## 5.1.2. 재할당: `let` 없이

이미 선언된 변수에 새 값을 대입할 때는 `let`을 생략합니다.

```rok
let counter: i32 = 0i32;
counter = counter + 1i32;         // OK - 재할당
counter = counter + 1i32;         // OK - 또 재할당
```

선언한 적 없는 이름에 `let` 없이 대입하면 컴파일 에러입니다.

```rok
let counter: i32 = 0i32;
coutner = counter + 1i32;         // ERROR: 'coutner' not declared.
                                   //        Did you mean 'counter'?
```

Julia와 Python에서는 오타가 조용히 새 변수를 만드는 일이 흔합니다. 이 규칙은 그 함정을 막습니다.

## 5.1.3. 새 선언과 재할당의 결정

| 형태              | 의미                                    |
|-------------------|-----------------------------------------|
| `let name = ...;` | 새 선언. 그 스코프에 새 바인딩.         |
| `name = ...;`     | 재할당. 기존 바인딩의 슬롯에 다시 쓰기. |

명시성이 우선입니다. 오타는 컴파일 에러입니다.

## 5.1.4. 같은 스코프 내 재선언 금지

같은 스코프 안에서 같은 이름을 다시 선언하면 컴파일 에러입니다.

```rok
let x = 1;
let x: i32 = 5i32;                  // ERROR - 같은 스코프에 x 가 이미 있음
```

변수의 슬롯 타입은 선언 시점에 고정되며, 같은 스코프 안에서는 바뀌지 않습니다.

예외는 REPL과 Jupyter 셀의 최상위입니다. 셀을 다시 실행할 수 있도록 셀 최상위에서는 같은 이름을 `let`으로 다시 선언할 수 있습니다. 이 선언은 새 바인딩을 만듭니다([0.1](../000-meta/001-execution-modes.md), [9.7.3](../009-tools/907-jit-cells.md#같은-이름의-재선언)). 일반 소스 파일에는 이 예외가 적용되지 않습니다.

## 5.1.5. 스코프: 블록 단위

변수가 보이는 범위는 [블록 표현식](../003-expressions/309-block-expressions.md)의 블록 단위로 정해집니다.

```rok
let y = 1;
if cond {
    y = 2;                         // 외부 y 재할당 (같은 슬롯)
    let z = 2;                     // 블록 로컬 z 선언
}
// 여기서 z 는 접근 불가
```

블록 안의 `let`은 그 블록에 속한 새 로컬 바인딩입니다. 따라서 블록 바깥에서는 그 변수가 보이지 않습니다. 같은 이름의 안쪽 `let`은 외부 변수를 그 블록 안에서만 가립니다.

## 5.1.6. 중첩 스코프: 별개 바인딩

내부 블록에서 같은 이름의 변수를 새로 선언하면 별개의 바인딩이 됩니다(shadowing이 아닙니다).

```rok
let a = 1;
{
    let a: i32 = 42i32;            // 블록 로컬 a - 외부 a 와 다른 슬롯
    a = 10i32;                     // 블록 안 a 재할당 (외부 a 영향 없음)
}
// 여기서 a = 1 (외부 a 그대로)
```

내부 블록의 `let`은 완전히 새 바인딩을 만듭니다. 외부에 같은 이름이 있어도 두 슬롯은 서로 독립적입니다.

블록이 끝나면 안쪽 변수가 사라진다는 의미와 외부 변수를 보호한다는 의도를 함께 살린 설계입니다.

### shadowing과 다른 점

Rust식 shadowing은 같은 스코프에서 같은 이름을 다시 선언하도록 허용합니다. Rok에서는 같은 스코프 안에서 다시 선언할 수 없습니다(5.1.4).

내부 블록에서 같은 이름을 선언하는 것은 shadowing이 아니라 새 스코프의 별개 바인딩입니다. 효과(블록 안에서 외부 이름이 가려짐)는 비슷해 보이지만 의미는 분명히 다릅니다.

## 5.1.7. 타입 명시와 타입 추론

```rok
let a = 42i32;                     // a: i32 (추론)
let b: i32 = 42i32;                // b: i32 (명시)
let c: any = 42i32;                // c: any (명시)
let d = if cond { 1i32 } else { 2i32 };   // d: i32 (추론)
```

타입을 명시하면 그 타입의 정적 슬롯이 되고, 명시하지 않으면 초기값 식에서 추론한 타입의 정적 슬롯이 됩니다(지역 타입 추론). 이후의 재할당은 그 타입으로 검사합니다. [`any` 슬롯](../002-types/202-any-slot.md)은 `: any`를 명시할 때만 생깁니다.

```rok
let n = 1i32;
n = 2i32;                          // OK
n = "hi";                          // ERROR - n 은 i32
```

초기값만으로 타입이 다 정해지지 않으면, 변수의 스코프 안에서 이후의 쓰임(값을 타입이 정해진 자리로 넘기는 쓰임)으로 마저 추론합니다([2.10.2](../002-types/210-generics.md#타입-인자-추론)). 그래도 정할 수 없으면 컴파일 에러입니다. 이때는 타입을 명시해야 합니다.

```rok
let x = none;                      // ERROR - 타입을 정할 수 없음
let x: Data | none = none;         // OK

let xs = [];                       // 이후 쓰임이 없으면 ERROR - 원소 타입을 정할 수 없음
let xs: List<i32> = [];            // OK

let y = return;                    // ERROR - 초기값이 발산만 함
```

분기의 타입이 서로 다른 `if` / `match` 식으로는 타입을 추론하지 않습니다. 합 타입이 필요하면 슬롯에 명시합니다.

```rok
let e = if cond { 1i32 } else { "hi" };          // ERROR - 분기 타입 불일치
let e: i32 | str = if cond { 1i32 } else { "hi" };   // OK
```

추론 결과 타입과 분기 결과 규칙은 [표현식 개요](../003-expressions/README.md)에 있습니다.

## 5.1.8. 동시 선언(없음)

```
let a = 1, b = 2;                  // 채택 안 함
```

콤마로 여러 변수를 한꺼번에 선언하는 C식 형태는 없습니다. 한 줄에 하나씩 적거나 [분해 대입](../003-expressions/315-destructuring.md)의 튜플 분해를 쓰세요.

```rok
let (a, b) = (1, 2);               // 분해 대입 - OK
let a = 1; let b = 2;              // 두 줄로 - OK
```

## 5.1.9. `let`의 자리

`let`은 문장(statement)입니다. 변환 규칙은 [표현식 개요](../003-expressions/README.md)에 있습니다.

모듈 수준에서는 `let`을 쓸 수 없습니다. 모듈 수준의 값 슬롯은 [`const`](502-const.md)나 [`static`](503-static.md)으로 선언해야 합니다. 함수 본체와 블록 안에서는 쓸 수 있습니다. `if` / `match` / `loop` 같은 제어 구조의 본체도 블록이므로 쓸 수 있습니다. 식 자리에는 `let`이 직접 올 수 없습니다. `let`은 식이 아니라 문장이기 때문입니다.

## 5.1.10. `let`으로 선언된 변수의 수명

변수는 선언한 시점부터 그 변수를 도입한 스코프가 끝날 때까지 살아 있습니다.

`ref` 캡처([캡처 의미론](../004-functions/406-capture-semantics.md))로 클로저에 잡힌 변수는 그 클로저 객체가 살아 있는 동안 계속 살아 있습니다. [GC](../000-meta/007-glossary.md#gc-garbage-collector)가 관리하므로 직접 해제하지 않습니다.

## 5.1.11. `let`의 좌변과 [분해 대입](../003-expressions/315-destructuring.md)의 연결

`let`의 좌변에는 [패턴](../003-expressions/311-patterns.md) 가운데 반증 불가능 패턴을 둘 수 있습니다. 이것이 [분해 대입](../003-expressions/315-destructuring.md)입니다.

```rok
let (x, y) = compute();
let Point { x, y } = origin;
```

분해 대입의 의미는 [분해 대입](../003-expressions/315-destructuring.md)에서 정의합니다. 각 부분 패턴은 해당 변수에 바인딩되고, 모든 변수는 하나의 스코프에 함께 도입됩니다.
