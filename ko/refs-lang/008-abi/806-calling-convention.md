# 8.6. 호출 규약

이 문서는 함수 호출에서 레지스터와 스택을 쓰는 규약을 정의합니다. 기본은 플랫폼 C [ABI](../000-meta/007-glossary.md#abi-application-binary-interface)를 따르고, 다른 부분만 따로 밝힙니다.

## 8.6.1. 기본: 플랫폼 C ABI

[Extern "C" 심볼](805-extern-symbols.md)로 선언한 모든 함수는 플랫폼의 C ABI를 씁니다. Rok 함수끼리 호출할 때도 같은 레지스터를 쓰지만, 집계 값은 다르게 넘깁니다(8.6.6).

| 플랫폼                   | ABI                |
|--------------------------|--------------------|
| Linux x86_64             | System V AMD64     |
| Linux aarch64            | AAPCS64            |
| Linux i686               | System V i386      |
| Linux armv7              | AAPCS              |
| macOS (x86_64 / aarch64) | System V / AAPCS64 |
| Windows x86_64           | MS x64             |
| Windows aarch64          | AAPCS64 (MS 변형)  |
| Windows i686             | MS x86 (cdecl)     |
| Linux riscv64            | RISC-V LP64D       |
| WASM                     | clang의 WebAssembly C ABI  |

LLVM 백엔드는 스칼라 인자를 레지스터에 배치합니다. 하지만 집계(struct / 튜플 / 배열)를 C 경계에서 어떻게 넘길지는 분류하지 않습니다. 이 분류는 **프런트엔드(rokc)의 일**입니다. rokc는 clang과 같은 규칙으로 분류하고 그 결과를 LLVM에 넘깁니다(8.6.3). 이 사양은 그 밖에 달라지거나 추가되는 사항만 정의합니다. WebAssembly C ABI에서는 스칼라 하나로 된 집계를 그 스칼라로 넘깁니다. 그 밖의 집계는 호출자 사본의 포인터로 넘기고, 결과는 `sret`으로 돌려줍니다. 런타임 `str` 인자는 참조로 넘깁니다.

## 8.6.2. 레지스터 인자 / 반환

각 ABI가 정한 기본 인자 레지스터와 반환 레지스터를 그대로 씁니다.

| 플랫폼         | 인자 레지스터 (정수)       | 반환 (정수) |
|----------------|----------------------------|-------------|
| Linux x86_64   | rdi, rsi, rdx, rcx, r8, r9 | rax, rdx    |
| Windows x86_64 | rcx, rdx, r8, r9           | rax         |
| aarch64        | x0 ~ x7                    | x0, x1      |
| i686           | (스택만)                   | eax, edx    |
| armv7          | r0 ~ r3                    | r0, r1      |
| riscv64        | a0 ~ a7                    | a0, a1      |

부동소수점 값과 벡터 값도 각 ABI가 정한 표준 레지스터(xmm0-7, vN, sN 등)를 그대로 씁니다.

## 8.6.3. `struct` 인자 / 반환: 작은 `struct` 규칙

C 경계(`extern "C"` 선언과 정의)에서 집계를 값으로 넘길 때 rokc는 clang과 같은 규칙으로 타깃 ABI에 따라 집계를 분류합니다. 그리고 LLVM이 레지스터로 옮길 수 있는 형태로 바꿉니다(coercion). HFA는 float / double 레지스터 최대 4개에 들어갑니다.

| 타깃                                      | 분류                                                                                      |
|-------------------------------------------|-------------------------------------------------------------------------------------------|
| AAPCS64 (Linux / Apple / Windows arm64)   | HFA (같은 부동소수 원소 1~4개)는 `[n x f32]` / `[n x f64]`. 그 밖의 16바이트 이하 집계는 `i64` / `[2 x i64]` (8바이트 이하 반환값은 `iN`). 더 크면 인자는 호출자 사본의 포인터, 반환은 `sret`  |
| System V x86_64                           | eightbyte마다 INTEGER / SSE로 분류해 정수 / SSE 레지스터에. 레지스터가 모자라면 집계 전체를 `byval`. 16바이트 초과는 인자 `byval`, 반환 `sret`  |
| Windows x64                               | 크기 1 / 2 / 4 / 8바이트 집계는 `iN`. 그 밖은 인자는 참조 (호출자 사본의 포인터), 반환은 `sret` |
| System V i386 / Windows x86 (i686)       | 집계 인자는 스택에 `byval` (4바이트 정렬). 반환은 Windows에서 1 / 2 / 4 / 8바이트 집계면 `iN`, 그 밖의 집계 반환 (System V에서는 모두)은 `sret`   |
| AAPCS hard-float (armv7)                  | HFA는 `[n x f32]` / `[n x f64]`. 그 밖의 64바이트 이하 집계는 `[n x i32]` (정렬 4 이하) 또는 `[n x i64]`, 더 크면 `byval`. 반환은 HFA면 부동소수 레지스터, 4바이트 이하 집계는 `i8` / `i16` / `i32`, 그 밖은 `sret`   |
| WebAssembly (wasm32)                      | 스칼라 하나로 된 집계는 그 스칼라. 그 밖의 집계 인자는 호출자 사본의 포인터, 반환은 `sret` |
| RISC-V LP64D (riscv64)                    | 부동소수 하나, 부동소수 둘, 또는 부동소수와 8바이트 이하 정수로 된 struct (union 없음)는 레지스터가 남는 동안 필드별로 부동소수 / 정수 레지스터에. 그 밖에 8바이트 이하 집계는 `i64`, 16바이트 이하는 `[2 x i64]` (16바이트 정렬이면 `i128`), 더 큰 인자는 호출자 사본의 포인터. 반환은 종류마다 레지스터 두 개로 같은 규칙을 따르며, 더 크면 `sret`  |
| 그 밖의 타깃                              | C 경계를 넘는 집계 값 전달은 컴파일 에러                                                  |

- 좁은 정수 매개변수와 반환값(`i8` / `i16` / `u8` / `u16` / `bool` / `c_char`)의 `signext` / `zeroext`는 플랫폼 C ABI를 따릅니다. x86_64 SysV와 Apple arm64는 `i8` / `i16` / `bool`을 확장합니다. Linux AAPCS64는 아무것도 확장하지 않습니다. Windows x64는 `bool`만 확장합니다.
- 모든 함수에는 인라인 stack probe가 있습니다. 그래서 큰 프레임도 guard page를 건너뛰지 않고 건드립니다.
- `extern "C" fn` **정의**에도 같은 분류를 적용합니다. 정의에는 C가 호출하는 C-ABI 진입점이 따로 있습니다. Rok 쪽에서 오는 호출은 그대로 Rok 규약을 씁니다.
- System V i386에서 집계 안의 `i64` / `u64` / `f64` 정렬은 4바이트입니다(C와 같음).
- Rok 함수끼리 호출할 때는 이 분류를 적용하지 않습니다(8.6.6). 분류는 Rok이 C와 맞물리는 곳에서만 필요합니다. `str`(16바이트 struct, Windows x64에서는 참조)을 받거나 돌려주는 런타임 함수도 여기에 속합니다([8.5](805-extern-symbols.md)).

## 8.6.4. GC 객체 포인터: 일반 포인터로

GC 객체 포인터는 플랫폼의 일반 포인터와 같은 ABI로 넘깁니다. 특별한 레지스터나 tagged pointer는 쓰지 않습니다.

다만 이 포인터는 호출 전후에 [배리어와 루트 추적](../007-runtime/704-barriers-and-roots.md)의 [shadow stack](../000-meta/007-glossary.md#shadow-stack)에 등록되어 있어야 합니다.

컴파일러가 내보내는 shadow stack 프레임을 체인에 잇고 떼는 것(link / unlink)으로 등록합니다([8.9.12](809-lowering-control.md#8912-shadow-stack-프레임)).

## 8.6.5. 던지는 함수의 반환: 값 기반 에러 전달

[`throws` 시그니처](../004-functions/414-throws.md)가 있는 함수는 에러를 반환값의 일부로 돌려줍니다. 별도의 unwinding 메커니즘이나 런타임 심볼은 쓰지 않습니다.

```
fn f(args) throws (E) -> T
```

위 함수의 ABI상 반환 타입은 필드 두 개짜리 `struct`입니다.

```mlir
!Throws_T_E = !llvm.struct<(i1, !Payload_T_E)>
; 필드 0: is_err (0 이면 성공, 1 이면 에러)
; 필드 1: payload, union(T, E). is_err 가 0 이면 T, 1 이면 E 로 해석
```

페이로드는 union이고, 크기와 정렬은 `T`와 `E` 중 큰 쪽을 따릅니다. `T`가 unit이면 페이로드에는 `E`만 담깁니다. 에러 채널은 시그니처로 구분되므로 `T`와 `E`가 같은 타입이어도 됩니다. 에러 타입을 적지 않은 `throws`(`throws (any Error)`)에서 `E`는 [`any`](../002-types/202-any-slot.md)와 같은 tag + payload 표현의 `any Error` 값입니다([8.8](808-lowering-types.md)).

필드 0은 `i1`보다 넓게 저장해도 됩니다. 페이로드에 GC 참조가 있으면 수집기가 합 타입의 tag로 읽도록 `i32`로 저장합니다. 의미가 있는 것은 bit 0뿐입니다. 페이로드가 4 이상으로 정렬되면 오프셋, 크기, 레지스터는 `{i1, payload}`와 같습니다. 에러를 던지는 함수의 `ref` 매개변수([4.7](../004-functions/407-ref-keyword.md)) 값은 반환값의 구현 정의 부분으로서 carrier 옆에 함께 전달됩니다.

이 `struct`는 다른 반환값과 똑같이 플랫폼 C ABI로 전달됩니다. 8.6.3의 한계 안이면 레지스터로, 넘으면 sret으로 돌려줍니다. 호출 지점의 `try`는 필드 0을 검사해 분기합니다. 자세한 lowering 규칙은 [8.9.6](809-lowering-control.md#896-try--catch--finally-값-기반-분기)에서 정의합니다.

이 방식을 택한 이유는 다음과 같습니다.

- 모든 플랫폼에서 똑같이 동작합니다. WASM도 같고, DWARF나 플랫폼 EH 인프라가 필요 없습니다.
- [shadow stack](../000-meta/007-glossary.md#shadow-stack)과 충돌하지 않습니다. 에러도 일반 반환 경로로 프레임을 빠져나가므로 프레임마다 shadow stack을 정상적으로 pop합니다.
- 에러가 없는 경로의 비용은 반환 뒤 분기 하나뿐이고, `try`나 `catch`에 들어가는 데는 비용이 없습니다.

## 8.6.6. Rok 함수 사이의 호출 규약

Rok 함수끼리 호출할 때 스칼라는 8.6.2의 레지스터로 넘깁니다. 64바이트를 넘는 집계 값(struct, 튜플, 배열, `str`)은 주소로 넘기고, 맨 앞의 결과 포인터로 돌려받습니다. 피호출자는 주소로 받은 인자를 진입 시 복사하므로 호출자의 값은 바뀌지 않습니다. 피호출자는 주소로 받은 인자를 복사한 뒤라면 반환하기 전 언제든 결과 포인터로 결과를 써도 됩니다. 따라서 결과 포인터는 주소로 받은 인자를 가리켜도 되지만, 피호출자가 호출 중에 읽는 다른 메모리를 가리키면 안 됩니다. 이 규칙은 Rok과 Rok 사이의 모든 호출에 적용됩니다. 미리 빌드한 코드, 내보낸 함수, 함수 값을 부르는 호출도 포함합니다. 직접 호출은 호출자의 `rok_tls` 블록 주소([8.3.8](803-tls-slots.md#838-컴파일러-출력-형식))도 선언된 인자 뒤에 숨은 마지막 포인터 인자로 넘깁니다. 함수 값, `#[export_name]` Rok 함수, `any` dispatcher는 이 인자를 받지 않습니다(8.6.11). 그보다 작은 집계는 first-class 집계로 넘기고 돌려줍니다. 이때 타깃에서 LLVM SelectionDAG가 낮추는 방식 그대로 낮춥니다. 예외는 하나입니다. 32비트 Arm에서 원소가 1바이트나 2바이트인 배열은 64바이트를 넘는 집계처럼 주소로 넘기고 돌려받습니다. 이런 스택 인자를 LLVM이 낮추는 방식이 호출자와 피호출자에서 서로 다르기 때문입니다. 두 백엔드가 정확히 이 방식을 따르므로 어느 쪽 코드든 서로 호출할 수 있습니다. 이 규약은 8.6.3의 C ABI 분류와 다릅니다. 아래 규칙은 64바이트 이하의 집계에 적용됩니다.

> [!NOTE]
> 주소로 넘기는 값은 메모리 안에서(`memcpy`) 옮깁니다. first-class 집계로 옮기지 않습니다.

**인자**

- 집계는 스칼라 leaf로 나뉘고, 각 leaf가 자기 종류의 다음 레지스터를 차지합니다. 레지스터가 바닥나면 나머지 leaf는 스택으로 갑니다. 그래서 `str`이 마지막 인자 레지스터와 스택에 나뉠 수 있습니다.
- AArch64: `i64` / `ptr` / `f32` / `f64` 배열은 자기 종류의 연속된 레지스터를 차지합니다. 남은 레지스터에 다 들어가지 않으면 통째로 스택에 놓이고, 그 종류의 나머지 레지스터는 쓴 것으로 칩니다. `i8` / `i16` / `i32` 배열은 struct처럼 나뉩니다.
- 스택 슬롯: Apple 타깃에서는 최상위 스칼라 인자가 자연 크기와 정렬을 쓰고, 집계의 `i1` / `i8` / `i16` leaf는 4바이트 슬롯을 씁니다. 다른 타깃에서는 모든 스택 슬롯이 8바이트입니다.

**결과**

- AArch64: 정수 레지스터 8개(`x0`-`x7`)와 부동소수점 레지스터 8개(`v0`-`v7`)까지 씁니다. 더 큰 결과는 `x8`로 받는 sret 포인터로 반환합니다(포인터는 돌려주지 않음).
- x86-64: 정수 레지스터 세 개(`rax`, `rdx`, `rcx`)까지 쓰고, 부동소수점 결과는 `xmm0` / `xmm1` 다음에 x87 `st0` / `st1`을 씁니다. 네 번째 정수 레지스터나 다섯 번째 부동소수점 레지스터가 필요한 결과는 `rdi`로 받고 `rax`로 돌려주는 sret 포인터로 반환합니다.

**Windows**

- Windows x64: 정수 인자와 부동소수점 인자는 레지스터 자리 네 개(`rcx` `rdx` `r8` `r9` / `xmm0`-`xmm3`)를 함께 씁니다. 각 인자는 다음 자리를 차지하되 자기 종류의 레지스터를 씁니다. 스택 슬롯은 8바이트이고 호출자의 32바이트 home area 뒤에 놓입니다. sret 포인터는 `rcx`로 넘기고, 나머지 결과는 x86-64와 같습니다.
- Windows arm64: 위의 AAPCS64와 같습니다. C variadic 호출은 모든 부동소수점 인자를 정수 레지스터로 넘깁니다.

**좁은 정수**

피호출자는 좁은 정수와 `bool` 인자, 결과의 위쪽 비트에 기대면 안 됩니다. 호출자는 확장해도 됩니다. 네이티브 백엔드는 들어온 `bool`을 bit 0만 남기고 가리며 좁은 값을 다시 확장합니다.

다른 모듈이 닿을 수 없는 함수(내부용이며 값으로 쓰지 않는 함수)는 구현이 정하는 규약을 써도 됩니다.

`extern "C"`와 `extern "rok"` 런타임 함수 호출은 8.6.1-8.6.5의 C ABI 규칙을 씁니다.

## 8.6.7. 꼬리 호출

LLVM의 `tail call` 최적화는 일반 함수에 자동으로 적용됩니다. 코루틴은 상태 기계 구조이므로 적용하지 않습니다.

## 8.6.8. 인라인 함수의 ABI

`#[inline]`([내장 속성](../006-meta-system/602-built-in-attributes.md))을 붙이면 호출 자체가 사라질 수 있습니다. 이때 호출 규약은 의미가 없습니다.

`#[inline(never)]` 함수는 항상 호출되며 일반 ABI를 따릅니다.

## 8.6.9. 매개변수 전달의 평가 순서

[매개변수](../004-functions/402-parameters.md)를 왼쪽에서 오른쪽으로 평가하는 순서는 호출 규약과 상관이 없습니다.

왼쪽에서 오른쪽으로 평가한다는 것은 각 인자 표현식을 왼쪽부터 차례로 평가한다는 뜻입니다. 각 결과를 어느 레지스터나 스택 자리에 두는지는 ABI가 정하는 별개의 문제입니다.

C와 C++의 일부 ABI는 스택 push 순서 때문에 오른쪽에서 왼쪽으로 평가하는 쪽을 선호합니다. 그러나 Rok은 왼쪽에서 오른쪽으로 평가함을 보장합니다. 컴파일러는 필요하면 임시 변수와 레지스터를 써서 두 요건을 맞춥니다.

## 8.6.10. 가변 인자(variadic) 함수

[매개변수](../004-functions/402-parameters.md)의 `...T` variadic은 언어 수준의 가변 인자입니다. 인자를 슬라이스 뷰 하나(`Slice<T>`)로 묶어 넘깁니다(보통 struct 인자와 같은 ABI). 플랫폼의 C variadic(`...` 가변 인자)과는 별개의 개념입니다.

C variadic 함수(예: `printf`)는 `extern "C"`로 직접 호출할 수 있습니다. 이때 ABI는 플랫폼의 C 가변 인자 규약을 따릅니다.

```
extern "C" {
    fn printf(fmt: ConstPtr<c_char>, ...);
}
```

- `...`는 `extern` 블록의 선언에서만, 그리고 마지막 매개변수로만 쓸 수 있습니다. Rok 함수 정의에는 C variadic을 둘 수 없습니다.
- 가변 자리의 인자에는 C의 default argument promotion을 적용합니다. `bool`, `i8`, `i16`, `u8`, `u16`, `c_char`는 `c_int`(`i32`)로, `f32`는 `f64`로, `str`은 `char*`(NUL로 끝나는 바이트 포인터)로 넘어갑니다.
- 집계(struct / 튜플 / 배열)는 가변 인자로 넘길 수 없습니다(컴파일 에러).

## 8.6.11. 함수 포인터 ABI

[함수 타입](../004-functions/404-function-type.md)의 `fn(...) -> ...`은 간접 호출에도 같은 calling convention을 씁니다.

```mlir
%fn_ptr = ; ... 함수 포인터 ...
%result = call i32 %fn_ptr(...)
```

인자와 반환의 ABI가 같으므로 직접 호출과 간접 호출의 인터페이스도 같습니다. 예외는 8.6.6의 숨은 `rok_tls` 주소입니다. 함수 값은 이 주소를 받지 않습니다. 함수 값의 코드 포인터는 thunk를 가리킵니다. thunk는 주소를 직접 읽고, 그 주소를 넘겨 함수를 호출합니다.

## 8.6.12. 클로저 호출

[클로저](../004-functions/405-closure.md)에서 다루는 클로저는 환경과 코드 포인터를 묶은 하나의 단위입니다.

호출은 다음과 같이 동작합니다.

```
환경 포인터를 첫 인자로, 그 뒤 일반 인자들.
```

클로저 본체는 이 환경 인자를 거쳐 캡처한 변수에 접근합니다.

LLVM은 클로저 본체를 일반 함수처럼 컴파일합니다. 환경은 그저 첫 번째 인자입니다.

## 8.6.13. 비동기 함수 호출

[비동기](../004-functions/412-async.md)의 `async fn`은 호출하면 바로 future 포인터를 반환합니다. 호출은 일반 함수 호출 ABI를 그대로 따릅니다.

```
let f = async_fn(args);     // 즉시 반환 (Future ptr)
let r = await f;             // 코루틴 메커니즘
```

`await`는 상태 기계의 일반 호출(대상 future 폴링)과 반환으로 이루어집니다([8.10](810-lowering-coroutine-generic.md)). 그래서 일반 ABI 위에서 동작합니다.

## 8.6.14. 안정성

이 호출 규약은 플랫폼 C ABI를 따르므로 안정성을 따로 정하지 않습니다. 플랫폼이 호환성을 보장하는 범위 안에서 Rok도 호환성을 유지합니다.

에러를 던지는 함수의 반환값 레이아웃(8.6.5)은 런타임 ABI의 일부입니다. 바꿀 때는 [개요](README.md)의 안정성 정책을 따릅니다.
