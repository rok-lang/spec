# 2.6. 합 타입 (`A | B`)

합 타입은 여러 기존 타입 중 하나의 값을 갖는 태그형 합집합입니다. `enum` 과 비슷하지만, 변형이 따로 명명되지 않고 기존 타입을 그대로 변형으로 쓴다는 차이가 있습니다.

## 2.6.1. 형태

다음은 합 타입의 형태를 보여 주는 예시입니다.

```rok
i32 | f32
T | none
A | B | C
i32 | str | bool
```

항을 구분할 때에는 [구두점과 연산자 토큰](../001-lexical/110-punctuation-and-operator-tokens.md) 의 `|` 토큰을 사용합니다. 그리고 항의 자리에는 임의의 타입 표현식이 올 수 있는데, 단순 이름이나 경로, 제네릭, 또는 또 다른 합 타입까지 모두 가능합니다.

## 2.6.2. 의미

합 타입의 값은 항 중 하나에 속하며, 어느 항에 속하는지는 태그를 통해 추적됩니다.

```rok
let x: i32 | f32 = 42i32;       // 태그가 i32 자리에 있음
let y: i32 | f32 = 3.14f32;     // 태그가 f32 자리에 있음
```

## 2.6.3. 메모리 표현

기본 표현은 태그와 페이로드를 인라인으로 두는 형태입니다.

```
+------+----------------------+
| tag  | payload (size of     |
|      |  largest variant)    |
+------+----------------------+
```

> tag: 태그. payload (size of largest variant): 페이로드 (변형 중 가장 큰 크기).

이 구조에서 태그는 어느 항이 활성인지 식별하는 역할을 합니다. 페이로드는 모든 항 중 가장 큰 항의 크기만큼 자리를 갖도록 잡히고, 정렬은 모든 항의 정렬 중 가장 큰 값에 맞춰집니다.

다만 이 표현은 [niche 최적화](207-niche-optimization.md) 의 영향을 받기 때문에 태그 자리가 사라지는 경우도 있습니다.

### 정확한 비트 폭

태그의 비트 폭은 컴파일러가 결정하며, 항의 수에 따라 1 비트, 2 비트, 4 비트, 8 비트 등 다양한 값이 가능합니다. 사용자 코드에서 태그 비트에 직접 접근할 방법은 제공되지 않습니다.

## 2.6.4. 집합 의미론

> [!IMPORTANT]
> 합 타입은 집합 연산의 의미론을 갖습니다.

### 정규화

합 타입은 항상 정규형으로 다룹니다.

- 중첩된 합은 펼칩니다. `(A | B) | C`, `A | (B | C)`, `A | B | C` 는 같은 타입입니다.
- 중복은 제거합니다. `A | A | B` 는 `A | B` 입니다.
- 항의 순서는 의미가 없습니다. `A | B` 와 `B | A` 는 같은 타입입니다.
- 항이 하나 남으면 그 타입 자체입니다. `A | A` 는 `A` 입니다.

타입 별칭을 펼치거나 제네릭 파라미터를 치환한 결과도 다시 정규화합니다 (`type N = i32 | f64;` 이면 `N | i32` 는 `i32 | f64`). 예외는 제네릭 `T | none` 의 `none` 층입니다 (2.6.5).

따라서 합 타입의 형태가 같으면 같은 타입이며, 사용자가 `i32 | f32` 와 `f32 | i32` 중 어느 쪽을 적었는지 신경 쓸 필요가 없습니다.

### 정규 순서

정규형의 항에는 정해진 순서가 있습니다.

- `none` 은 늘 마지막입니다.
- 나머지 항 사이의 순서는 구현이 정합니다. 다만 결정적이며, 한 빌드의 모든 모듈에서 같습니다. 적은 순서와는 무관합니다.

합 타입 값의 `PartialOrd` / `Ord` 와 `min` / `max` / `clamp` 는 이 순서를 따릅니다 ([stdlib 2.5.7](../../refs-standard-libraries/200-core/205-cmp.md#257-구현-매트릭스)). 서로 다른 항의 값은 정규 순서로, 같은 항의 값은 그 항 타입의 `Ord` 로 비교합니다. 그래서 `T | none` 에서 `none` 은 어떤 `T` 값보다 큽니다.

### 부분 집합

- 합 타입 값은 그 항을 모두 포함하는 더 큰 합 타입 자리에 그대로 들어갑니다. `i32 | none` 값은 `i32 | str | none` 자리에 넣을 수 있습니다. 항 하나 (`i32`) 의 값도 같습니다.
- 타입 패턴 `v: A | B` 는 더 큰 합의 일부 항에 맞출 수 있습니다. 그 분기에서 `v` 는 `A | B` 입니다.

```rok
let v: i32 | str | f64 | none = ...;
match v {
    n: i32 | f64 => use_num(n),     // n: i32 | f64
    s: str => use_str(s),
    none => {},
}
```

### 제네릭 추론

제네릭 추론은 합을 집합으로 봅니다. `T | none` 을 `i32 | str | none` 에 맞추면, 남는 항을 모아 `T = i32 | str` 입니다.

```rok
fn unwrap_or<T>(x: T | none, d: T) -> T { ... }
let v: i32 | str | none = ...;
unwrap_or(v, 0i32);       // T = i32 | str
```

## 2.6.5. `none` 과의 결합

[진리값과 센티넬 리터럴](../001-lexical/109-other-literals.md) 의 `none` 은 합 타입의 한 항으로 가장 자주 등장합니다.

```rok
T | none
```

이 형태는 값이 있을 수도 있고 없을 수도 있음을 표현하며, 다른 언어의 `Option<T>`, `T?`, `Maybe T` 에 해당하는 자리입니다.

여기에 niche 최적화가 결합되면 (예를 들어 포인터형 T 의 경우) 메모리 오버헤드 없이 null 을 `none` 으로 표현할 수 있습니다. 정확한 규칙은 [niche 최적화](207-niche-optimization.md) 에서 정의합니다.

### 중첩 optional

제네릭 `T | none` (`T?`) 의 `T` 자리에 이미 `none` 을 담은 타입이 오면, 바깥 `none` 층은 펼치지 않습니다. 결과는 **중첩 optional** 이며, 바깥 `none` 과 안쪽 `none` 은 다른 값입니다 (Swift 의 `T??` 와 같음).

- 소스에 구체 타입으로 적은 합은 그대로 펼칩니다. `(i32 | none) | none` 이라고 적으면 `i32 | none` 입니다.
- 중첩은 제네릭 치환에서만 생깁니다. `Maybe<T> = T | none` 에 `T = i32 | none` 을 넣은 `Maybe<i32 | none>` 은 두 층입니다.
- `none` 패턴, `is none`, `?.`, `??`, `?` 는 **바깥 층** 에 작용합니다. none 이 아닌 쪽은 안쪽 `T` (`i32 | none`) 에 묶입니다.

그래서 `List<i32 | none>` 은 저장된 `none` 을 원소로 돌며, `get` / `pop` / `Dict` 조회는 "없음" 과 "저장된 none" 을 구별합니다.

```rok
let xs: List<i32 | none> = [1, none, 3];

for x in xs { print(x); }        // 1, none, 3 — 저장된 none 도 원소

match xs.get(1) {                // get: (i32 | none) | none — 두 층
    none => print("범위 밖"),     // 바깥 none: 원소 없음
    v => match v {               // v: i32 | none — 저장된 값
        none => print("저장된 none"),
        n: i32 => print(n),
    },
}

let d: Dict<str, i32 | none> = {"a": none};
d.get("a") ?? 0i32;              // none — 키는 있고 값이 none (?? 는 바깥 층만 벗김)
d.get("b") ?? 0i32;              // 0 — 키 없음
```

## 2.6.6. `any` 와의 차이

[`any` 슬롯](202-any-slot.md) 의 `any` 는 열린 슬롯이어서, 모든 타입이 가능하고 변형을 자유롭게 추가할 수 있습니다.

반면 합 타입 (`A | B`) 은 닫힌 슬롯이어서, 명시된 변형만 가능합니다. 그 대신 컴파일러가 모든 가능한 항을 알고 있기 때문에 패턴 매칭의 완전성 검사를 수행할 수 있습니다.

| 측면        | `any`                            | `A \| B`                                   |
|-------------|----------------------------------|-------------------------------------------|
| 가능한 타입 | 모든 타입                        | 명시된 항만                               |
| 디스패치    | 런타임 태그 검사                 | 런타임 태그 검사 (단 항이 적어 분기 적음) |
| 완전성 검사 | 불가                             | 가능                                      |
| 메모리      | 태그 + 페이로드 (포괄)           | 태그 + 가장 큰 항 (좁음)                  |
| 점진성      | 점진 (코드 변경 없이 새 타입 OK) | 정적 (변형 추가는 타입 변경)              |

## 2.6.7. `enum` 과의 차이

`enum` 의 경우에는 명명된 변형이 컨테이너 안에 정의되며, 변형 자체가 `enum` 의 일부가 됩니다.

이에 비해 합 타입은 기존 타입을 변형으로 그대로 쓰기 때문에 변형 이름이 따로 존재하지 않습니다.

```rok
enum Result { Ok(i32), Err(str) }       // Ok / Err 변형 이름이 enum 안에 정의됨
type Either = i32 | str;                  // 변형 이름 없음 — 그냥 i32 또는 str
```

선택 기준은 다음과 같이 정리할 수 있습니다. 서로 다른 의미를 가진 변형이라 이름이 필요한 경우에는 `enum` 을 선택하는 것이 적절합니다. 반대로 기존 타입을 그대로 합치는 쪽이 자연스러운 경우에는 합 타입을 선택하면 됩니다.

## 2.6.8. 좁히기 (narrowing)

합 타입의 값은 [`any` 슬롯](202-any-slot.md) 과 같은 방식으로 패턴 매칭이나 `is` 검사를 통해 항을 좁힐 수 있습니다.

```rok
let v: i32 | str = ...;
match v {
    n: i32 => ...,           // 이 분기 안에서 v 는 i32
    s: str => ...,           // 이 분기 안에서 v 는 str
}
```

좁히기의 정확한 문법은 패턴과 표현식 사양에서 정의합니다.

## 2.6.9. type alias 와 결합

긴 합 타입은 `type` 으로 별칭을 줄 수 있습니다 (`type Num = i32 | f64;`). 타입 별칭의 `where` 는 별칭 대상 뒤에 둡니다 (`type A<T> = B<T> where T: X;`). 별칭의 `where` 는 별칭을 쓰는 자리마다 검사됩니다. `type` 은 문맥 키워드로, 항목 시작에서 식별자와 `=` 또는 `<` 가 이어질 때만 키워드입니다 ([1.5.4](../001-lexical/105-keywords.md#154-문맥-키워드)). 정확한 alias 문법은 타입 별칭 사양에서 정의합니다.

```rok
type Number = i32 | i64 | f32 | f64;
type Maybe<T> = T | none;
```
