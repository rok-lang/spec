# 2.6. 합 타입 (`A | B`)

합 타입은 여러 기존 타입 중 하나의 값을 갖는 태그형 합집합이다. `enum` 과 비슷하지만, 변형이 따로 명명되지 않고 기존 타입을 그대로 변형으로 쓴다.

## 2.6.1. 형태

```nok
i32 | f32
T | none
A | B | C
i32 | str | bool
```

- `|` 토큰 ([구두점과 연산자 토큰](../001-lexical/110-punctuation-and-operator-tokens.md)) 으로 항을 구분한다.
- 항은 임의의 타입 표현식이다. 단순 이름, 경로, 제네릭, 또는 또 다른 합 타입.

## 2.6.2. 의미

합 타입의 값은 항 중 하나에 속한다. 어느 항인지는 태그로 추적된다.

```nok
let x: i32 | f32 = 42i32;       // 태그가 i32 자리에 있음
let y: i32 | f32 = 3.14f32;     // 태그가 f32 자리에 있음
```

## 2.6.3. 메모리 표현

기본 표현은 태그 + 페이로드 인라인이다.

```
+------+----------------------+
| tag  | payload (variants    |
|      |  중 가장 큰 크기)     |
+------+----------------------+
```

- 태그는 어느 항이 활성인지 식별한다.
- 페이로드는 모든 항 중 가장 큰 항의 크기만큼 자리를 갖는다.
- 정렬은 모든 항의 정렬 중 가장 큰 값에 맞춘다.

이 표현은 [niche 최적화](207-niche-optimization.md) 영향을 받아 태그 자리가 사라질 수 있다.

### 정확한 비트 폭

태그의 비트 폭은 컴파일러가 결정한다. 항의 수에 따라 1·2·4·8 비트 등이 가능하다. 사용자 코드가 태그 비트에 직접 접근할 방법은 없다.

## 2.6.4. 집합 의미론

> [!IMPORTANT]
> 합 타입은 집합 연산의 의미론을 갖는다.

- 순서 무관: `A | B` 와 `B | A` 는 같은 타입.
- 중복 제거: `A | A` 는 `A` 로 정규화된다 (또는 컴파일러 경고).
- 결합법칙: `(A | B) | C` 와 `A | (B | C)` 와 `A | B | C` 는 모두 같은 타입.

합 타입의 형태가 같으면 같은 타입이고, 사용자가 `i32 | f32` 와 `f32 | i32` 중 어느 쪽을 적었는지 신경 쓸 필요가 없다.

## 2.6.5. `none` 과의 결합

[진리값과 센티넬 리터럴](../001-lexical/109-other-literals.md) 의 `none` 은 합 타입의 한 항으로 가장 자주 등장한다.

```nok
T | none
```

이 형태는 값이 있을 수도 없을 수도 있음을 표현한다. 다른 언어의 `Option<T>` / `T?` / `Maybe T` 자리다.

niche 최적화와 결합하면 (예: 포인터형 T) 메모리 오버헤드 없이 null = `none` 으로 표현된다. 정확한 규칙은 [niche 최적화](207-niche-optimization.md) 에서 정의한다.

## 2.6.6. `any` 와의 차이

[`any` 슬롯](202-any-slot.md) 의 `any` 는 열린 슬롯이다. 모든 타입 가능, 변형 추가 자유.

합 타입 (`A | B`) 은 닫힌 슬롯이다. 명시된 변형만 가능. 컴파일러가 모든 가능 항을 알고 있어 패턴 매칭의 완전성 검사가 가능하다.

| 측면        | `any`                            | `A \| B`                                  |
| ----------- | -------------------------------- | ----------------------------------------- |
| 가능한 타입 | 모든 타입                        | 명시된 항만                               |
| 디스패치    | 런타임 태그 검사                 | 런타임 태그 검사 (단 항이 적어 분기 적음) |
| 완전성 검사 | 불가                             | 가능                                      |
| 메모리      | 태그 + 페이로드 (포괄)           | 태그 + 가장 큰 항 (좁음)                  |
| 점진성      | 점진 (코드 변경 없이 새 타입 OK) | 정적 (변형 추가는 타입 변경)              |

## 2.6.7. `enum` 과의 차이

`enum` 은 명명된 변형이 컨테이너 안에 정의된다. 변형이 `enum` 의 일부다.

합 타입은 기존 타입을 변형으로 그대로 쓴다. 변형 이름이 따로 없다.

```nok
enum Result { Ok(i32), Err(str) }       // Ok / Err 변형 이름이 enum 안에 정의됨
type Either = i32 | str;                  // 변형 이름 없음 — 그냥 i32 또는 str
```

선택 기준:

- 서로 다른 의미의 변형이라 이름이 필요하면 `enum`.
- 기존 타입을 그대로 합치는 쪽이 자연스러우면 합 타입.

## 2.6.8. 좁히기 (narrowing)

합 타입의 값은 [`any` 슬롯](202-any-slot.md) 과 같은 방식으로 패턴 매칭이나 `is` 검사를 통해 항을 좁힐 수 있다.

```nok
let v: i32 | str = ...;
match v {
    n: i32 => ...,           // 이 분기 안에서 v 는 i32
    s: str => ...,           // 이 분기 안에서 v 는 str
}
```

좁히기의 정확한 문법은 패턴과 표현식 사양에서 정의한다.

## 2.6.9. type alias 와 결합

긴 합 타입은 [키워드](../001-lexical/105-keywords.md) 의 `type` 키워드로 별칭을 줄 수 있다. 정확한 alias 문법은 타입 별칭 사양에서 정의한다.

```nok
type Number = i32 | i64 | f32 | f64;
type Maybe<T> = T | none;
```
