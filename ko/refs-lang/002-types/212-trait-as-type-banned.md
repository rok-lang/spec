# 2.12. 트레잇-as-타입 금지

> [!IMPORTANT]
> 트레잇 이름을 타입 표현식 자리에 그대로 적는 것을 금지한다.

## 2.12.1. 무엇이 금지되는가

```nok
let a: Number = 32i32;                          // ERROR — Number 는 트레잇
fn process(x: Display) -> str { ... }            // ERROR
struct Holder { item: Iterator; }                // ERROR
```

위 모든 위치 (변수 타입, 매개변수 타입, 반환 타입, 구조체 필드 타입) 에 트레잇 이름이 그대로 등장하면 컴파일 에러다.

## 2.12.2. 금지의 근거

다른 언어는 트레잇-as-타입을 vtable 디스패치 (간접 호출) 로 구현한다. 이 디스패치는 다음 비용을 동반한다.

- 함수 포인터를 통한 간접 호출. 분기 예측 실패 시 직접 호출 대비 2 배 이상 느려질 수 있다.
- 캐시 친화성 저하. vtable 자료 구조에 대한 추가 메모리 접근.
- 컴파일러의 인라이닝과 최적화 차단.

과학·데이터 코드의 핵심 수치 루프가 이 비용을 떠안지 않도록 nok 은 트레잇-as-타입을 허용하지 않는다. 런타임 다형성은 변수의 동적 슬롯으로만 한정한다.

## 2.12.3. 다형성이 필요할 때. 두 대안

### 1. 닫힌 후보가 있으면 합 타입

```nok
let a: i32 | f32 | f64 = 32i32;
fn process(x: i32 | f32) -> str { ... }
```

- 후보가 컴파일 타임에 정해져 있을 때.
- 메모리와 디스패치 비용이 명확하다. [합 타입](206-sum-types.md).
- 패턴 매칭의 완전성 검사가 가능하다.

### 2. 열린 다형성이면 제네릭

```nok
fn process<T: Display>(x: T) -> str { ... }
struct Holder<T: Iterator> { item: T; }
```

- 후보가 컴파일 타임에 결정되지 않거나, 호출자마다 다를 때.
- 단형화로 직접 호출. 비용 0 ([제네릭](210-generics.md)).
- 트레잇 바운드를 통해 메서드를 호출할 수 있다.

## 2.12.4. 결정 기준

| 상황                                  | 선택                                       |
| ------------------------------------- | ------------------------------------------ |
| 후보가 고정된 작은 집합 (3~5개)       | 합 타입                                    |
| 후보가 유저 / 라이브러리 확장 가능    | 제네릭                                     |
| 후보가 런타임에만 결정 (예: 플러그인) | `any` 슬롯 + 트레잇 메서드의 동적 디스패치 |

세 번째 경우, 런타임에 타입이 정해지는 다형성이 필요할 때는 [`any` 슬롯](202-any-slot.md) 을 쓴다. `any` 슬롯의 동적 디스패치는 트레잇 메서드 호출을 지원하지만, 그 비용이 변수 위치에 명시적으로 모인다.

## 2.12.5. 슈퍼트레잇과 바운드 표현은 허용

금지되는 것은 타입 위치에 등장하는 트레잇 이름이다. 다음은 모두 정상이다.

```nok
trait Ord: Eq { ... }                            // 슈퍼트레잇 선언
fn f<T: Add + Display>(x: T) { ... }              // 트레잇 바운드
fn g<T>(x: T) where T: Ord, T: Clone { ... }      // where 절
impl Display for Point { ... }                    // impl 의 트레잇 자리
```

이 위치에서 트레잇 이름은 제약을 표현하는 것이지 타입을 가리키는 것이 아니다.

## 2.12.6. 컴파일 에러의 형태

트레잇 이름이 타입 위치에 등장하면 컴파일러는 다음과 비슷한 진단을 낸다.

```
ERROR: 'Display' is a trait, not a type.
       To allow multiple types, use generics or a sum type:
         fn f<T: Display>(x: T) { ... }
         fn f(x: SomeType | OtherType) { ... }
```

이 진단은 사용자가 두 대안 중 하나를 선택하도록 안내한다.
