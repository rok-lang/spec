# 2.1. 타입 표현식

타입 표현식은 소스 코드에서 타입을 가리키는 표기다. 변수 선언의 `:` 뒤, 함수 매개변수의 `:` 뒤, 반환 타입의 `->` 뒤, 제네릭 인자, 형 변환의 `as` 뒤 등에 등장한다.

본 문서는 형식만 정의한다. 어떤 이름이 어떤 타입을 가리키는지는 표준 라이브러리가 결정한다.

## 2.1.1. 기본 형태

```
type_expr   ::= sum_type
sum_type    ::= unary_type ("|" unary_type)*
unary_type  ::= path_type
              | fn_type
              | tuple_type
              | array_type
              | "any"
path_type   ::= identifier ("::" identifier)* type_args?
type_args   ::= "<" type_expr ("," type_expr)* ","? ">"
fn_type     ::= "fn" "(" (type_expr ("," type_expr)*)? ")" ("->" type_expr)?
tuple_type  ::= "(" ")"
              | "(" type_expr "," ")"
              | "(" type_expr ("," type_expr)+ ","? ")"
array_type  ::= "[" type_expr ";" const_expr "]"
```

| 형태           | 예                                          |
| -------------- | ------------------------------------------- |
| 단순 이름      | `i32`, `bool`, `Point`                      |
| 경로           | `std::time::Duration`                       |
| 제네릭 적용    | `List<i32>`, `Dict<str, f64>`, `Pair<A, B>` |
| 합 타입 (`\|`) | `i32 \| f32`, `T \| none`                   |
| 함수 타입      | `fn(i32, i32) -> i32`                       |
| 튜플 타입      | `(i32, str)`, `(i32,)`                      |
| 배열 타입      | `[T; N]` (고정 크기)                        |
| 동적 슬롯      | `any`                                       |

각 형태의 정확한 의미는 아래에서 정의한다.

## 2.1.2. 단순 이름

식별자 한 개로 구성된다 ([식별자](../001-lexical/104-identifiers.md) 형식을 따른다).

```nok
i32
bool
Point
변수타입
```

이 이름이 어떤 항목을 가리키는지는 이름 해소(name resolution) 단계에서 결정된다. 같은 모듈에 정의된 항목, 가져온 모듈의 항목, 자동 가시 항목 등이 후보다.

## 2.1.3. 경로

여러 식별자가 `::` 로 이어진다.

```nok
std::time::Duration
core::collections::List
crate::geom::Point
```

`::` 토큰은 [구두점과 연산자 토큰](../001-lexical/110-punctuation-and-operator-tokens.md) 에 정의된 경로 구분자다. 경로의 마지막 토큰이 타입 이름이고, 앞부분은 그 타입을 어디서 찾을지를 가리키는 모듈 / 항목 경로다.

경로의 의미와 해석 규칙은 [타입 경로](213-type-paths.md) 에서 정의한다. 본 문서는 타입 표현식의 한 형태로 경로가 등장할 수 있다는 사실만 명시한다.

## 2.1.4. 제네릭 적용

타입 이름 뒤에 `<...>` 로 타입 인자를 적는다.

```nok
List<i32>
Dict<str, f64>
Pair<A, B>
Result<T, E>
Array<f64, 3>          // const 제네릭 (값 인자)
```

규칙:

- 인자 사이는 콤마로 구분한다.
- 인자에는 다른 타입 표현식 또는 `const` 표현식 (`const` 제네릭의 경우) 이 올 수 있다.
- 빈 `<>` 는 허용되지 않는다. 인자가 없으면 `<>` 자체를 적지 않는다.
- 후행 콤마 (`<A, B,>`) 허용.

값 인자 (예: `Array<f64, 3>`) 의 정확한 의미는 [`const` 제네릭](211-const-generics.md) 에서 정의한다.

### 표현식 위치에서의 turbofish

표현식 안에서 제네릭 인자를 명시할 때는 `::<...>` 형태를 쓴다. 표현식 사양에서 정의한다. 본 문서는 타입 표현식 위치의 `<...>` 만 다룬다.

## 2.1.5. 합 타입 (`|`)

```nok
i32 | f32
T | none
A | B | C | D
```

`|` 로 구분된 각 항은 서로 다른 타입 표현식이며, 결과 합 타입은 그 항들 중 하나의 값을 갖는다. 의미와 메모리 표현은 [합 타입](206-sum-types.md) 에서 정의한다.

`|` 토큰의 우선순위는 다른 타입 결합자보다 낮다. `i32 | List<f32>` 는 `i32 | (List<f32>)` 로 묶인다 (제네릭 적용이 합 타입보다 강하게 묶이기 때문).

## 2.1.6. 함수 타입

```nok
fn(i32, i32) -> i32
fn() -> str
fn(T) -> T
fn(i32)                  // 반환 타입 생략 가능 (단위 타입)
```

규칙:

- `fn` 토큰으로 시작한다.
- 괄호 안에 매개변수 타입만 적는다 (이름 없음).
- 반환 타입은 `->` 뒤에 적는다. 생략하면 반환값이 없다는 뜻이다 (정확한 의미는 함수 사양에서).

## 2.1.7. 튜플 타입

```nok
(i32, str)
(f64, f64, f64)
(i32,)                  // 한 항짜리 튜플은 후행 콤마 필수
()                      // 빈 튜플 (단위 타입)
```

규칙:

- 항이 둘 이상이면 콤마로 구분.
- 항이 하나인 튜플은 반드시 후행 콤마 (`(T,)`). 없으면 그냥 `T` 의 그룹화로 해석된다.
- 항이 없는 튜플 (`()`) 은 단위 타입을 가리킨다.

## 2.1.8. 배열 타입

```nok
[T; N]
[i32; 16]
[f64; 1024]
[u8; SIZE]
```

규칙:

- 대괄호 안에 원소 타입, 세미콜론, 길이 순으로 적는다.
- 길이는 `const` 표현식이며, 컴파일 타임에 결정되어야 한다.
- 길이 0 도 허용 (`[T; 0]`. 빈 배열 타입).

## 2.1.9. 동적 슬롯

```nok
any
```

`any` 는 [키워드](../001-lexical/105-keywords.md) 에 예약된 타입 이름 슬롯 키워드다. 의미는 [`any` 슬롯](202-any-slot.md) 에서 정의한다.

## 2.1.10. 우선순위 / 결합

타입 표현식 안에서 결합자가 섞일 때 우선순위 (강한 결합 ↔ 약한 결합) 는 다음과 같다.

```
강함  ─→  약함

[T; N]   (...)   <...>   ::   .  →  fn(...) -> ...   →   |
```

- 경로 (`::`), 제네릭 적용 (`<...>`), 배열 (`[...]`), 그룹화 (`(...)`) 가 가장 강하게 묶인다.
- 함수 타입 (`fn(...) -> ...`) 이 그 다음.
- 합 타입 (`|`) 이 가장 약하게 묶인다.

그 결과로 `i32 | List<f32>` 는 `i32 | (List<f32>)`, `fn(A | B) -> C` 는 `fn((A|B)) -> C` 로 묶인다.

명시적인 그룹화가 필요하면 괄호로 감싼다.

```nok
fn(i32) -> (i32 | str)         // 반환 타입이 합 타입
(fn(i32) -> i32) | (fn(f64) -> f64)   // 합 타입이 두 함수 타입을 항으로
```
