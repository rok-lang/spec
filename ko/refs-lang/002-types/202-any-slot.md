# 2.2. `any` 슬롯

`any` 는 어떤 타입의 값이든 담을 수 있는 변수 슬롯을 가리키는 타입 이름이며, rok 점진 타이핑 (gradual typing) 의 핵심을 이루는 개념입니다.

> [!IMPORTANT]
> 타입 명시를 생략한 변수는 자동으로 `any` 슬롯이 됩니다. rok 점진 타이핑은 이 한 줄 규칙으로 결정됩니다.

## 2.2.1. 정적 슬롯과의 대비

먼저 정적 슬롯과 `any` 슬롯이 어떻게 구분되는지 살펴보겠습니다.

```rok
let x: i32 = 42i32;     // x 는 i32 — 다른 타입의 값을 담을 수 없다
let y: any = 42i32;     // y 는 any 슬롯 — 어떤 타입이든 가능
let z = 42i32;          // z 는 any 슬롯 (타입 명시 생략 = any)
```

위 세 줄에서 `y` 와 `z` 는 같은 의미를 가지는데, 타입 명시를 생략하면 자동으로 `any` 가 되기 때문입니다. 이러한 결정은 REPL 과 노트북에서 빠르게 입력할 수 있도록 하기 위한 것입니다.

## 2.2.2. 슬롯의 메모리 표현

이어서 `any` 슬롯의 값이 어떻게 표현되는지 알아보겠습니다. `any` 슬롯의 값은 태그와 페이로드를 묶은 형태로 표현됩니다.

```
+------+----------+
| tag  | payload  |
+------+----------+
```

여기서 태그는 페이로드가 어떤 타입을 가리키는지를 나타내는 식별자이고, 페이로드는 값 자체로서 작은 값 (원시 타입 등) 은 직접 저장하며 큰 값은 힙 객체에 대한 참조로 저장합니다.

태그·페이로드의 정확한 비트 폭과 정렬, 인코딩은 [8. 런타임 ABI](../008-abi/README.md) 에서 정의하며, 본 문서는 모양 (태그 + 페이로드 두 부분) 만 약속합니다.

## 2.2.3. 동적 디스패치

`any` 슬롯의 값에 연산을 가하면, 런타임이 태그를 검사해 적절한 트레잇 메서드를 호출합니다.

```rok
let v: any = 42i32;
let w = v + 1i32;           // 런타임에 v 의 태그를 보고 i32::add 호출
```

다만 이 디스패치 비용은 정적 호출보다 명백히 크기 때문에, 성능이 중요한 곳에서는 정적 슬롯을 사용해야 합니다.

## 2.2.4. 재할당. 타입이 바뀌어도 OK

`any` 슬롯은 다른 타입의 값으로 자유롭게 재할당할 수 있습니다.

```rok
let s: any = 42i32;
s = "hello";        // OK — 슬롯이 any 라서
s = 3.14f64;        // OK
```

반면에 정적 슬롯은 같은 타입의 재할당만 허용됩니다.

```rok
let s: i32 = 42i32;
s = 10i32;          // OK
s = "hello";        // ERROR
```

## 2.2.5. 슬롯의 현재 타입 검사

`any` 슬롯에 담긴 값의 현재 타입은 `is` 키워드로 검사할 수 있습니다 (구체 문법은 표현식 사양에서 다룹니다).

```rok
if v is i32 { ... }
```

이 검사는 런타임 태그 비교 한 번으로 끝납니다.

## 2.2.6. 좁히기 (narrowing)

`is` 검사 또는 패턴 매칭이 성공한 분기 안에서, 컴파일러는 슬롯 타입을 해당 검사 타입으로 좁힌 것으로 간주합니다. 따라서 그 분기 안에서는 정적 디스패치가 가능해집니다.

```rok
let v: any = ...;
if v is i32 {
    let w = v + 1i32;       // 이 분기 안에서 v 는 i32 — 정적 디스패치
}
```

좁히기의 정확한 적용 범위는 표현식 / 패턴 사양에서 정의하고 있습니다.

## 2.2.7. 점진의 경계

`any` 슬롯은 변수 위치에서만 의미를 가지며, 다음 위치들에서는 `any` 의 동작이 달라집니다.

### 함수 매개변수에 타입을 적지 않으면

```rok
fn compute(x, y) { ... }
```

위 코드는 제네릭 함수에 해당합니다. 호출 지점의 타입에 따라 단형화되는데, 호출자가 `i32` 두 개를 넘기면 그 호출은 `i32` 두 개를 받는 함수로 컴파일되고, 다른 호출자가 `f64` 두 개를 넘기면 또 다른 함수가 컴파일됩니다.

만약 매개변수를 동적 슬롯으로 만들고 싶다면 명시적으로 `any` 를 적어 주어야 합니다.

```rok
fn compute(x: any, y: any) { ... }    // 동적 슬롯
```

### 구조체 필드

구조체 필드의 경우에는 반드시 타입을 명시해야 합니다.

```rok
struct Point { x: f64; y: f64; }      // OK
struct Mixed { name; value; }          // ERROR — 필드 타입 누락
```

필드를 동적으로 만들려면 마찬가지로 명시적 `any` 를 사용합니다.

```rok
struct Cell { tag: i32; payload: any; }   // OK
```

이러한 강제 규칙은 컴파일러가 구조체 메모리 레이아웃을 결정할 수 있도록 하기 위한 것입니다.

## 2.2.8. 같은 스코프 내 슬롯 모드 전환 금지

같은 변수 이름에 대해 같은 스코프 안에서 점진 → 정적 또는 정적 → 점진으로 전환하는 것은 허용하지 않습니다.

```rok
let x = 1;              // any 슬롯
let x: i32 = 5i32;      // ERROR — 이미 x 가 다른 모드로 선언됨
```

물론 새 스코프에서는 별개 바인딩으로 동작하며, 이에 대한 자세한 내용은 [변수 선언](../005-modules/501-variable-declaration.md) 에서 정의하고 있습니다.

## 2.2.9. 컴파일러 / 도구 친화성

마지막으로 `any` 슬롯이 있는 코드는 형 검사가 약해진다는 점을 알아 두어야 합니다. 컴파일러는 그 슬롯의 실제 타입을 미리 알 수 없기 때문에, 도구 (LSP·정적 분석) 도 이 한계 안에서 최선을 다할 수밖에 없습니다. 결국 점진 vs 정적의 선택은 사용자의 명시적 결정이며, 사양은 두 모드를 모두 정식으로 지원합니다.
