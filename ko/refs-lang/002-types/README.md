## 위치 정의 (positional definition)

타입은 값에 어떤 모양과 동작이 허용되는지를 컴파일러가 결정하는 정보다. nok 의 모든 값은 어떤 타입에 속한다. 타입이 없는 값은 없다.

다만 변수는 한 가지 타입에 고정되거나 (정적), 여러 타입을 담을 수 있는 슬롯이거나 (동적) 둘 중 하나다. 두 모드는 같은 언어 안에 공존한다.

## 두 모드: 정적과 점진

```
정적 (typed)        let x: i32 = 42i32;     x 는 항상 i32
점진 (untyped)      let y = 42i32;          y 는 모든 타입을 담을 수 있는 슬롯
```

- 정적 변수. 선언 시 타입을 명시하면, 그 변수는 항상 그 타입의 값을 담는다.
- 점진 변수. 타입을 명시하지 않으면, 그 변수는 동적 슬롯이 된다.

본 장에서는 두 모드가 같은 언어 안에 있다는 사실까지만 짚는다.

이 결정의 동기는 [실행 엔진과 사용자 표면](../000-meta/001-execution-modes.md) 에 있다. REPL/Jupyter 탐색과 [AOT](../000-meta/007-glossary.md#aot-ahead-of-time) 정적 컴파일이 같은 코드를 공유해야 한다. 탐색용 코드는 점진 스타일, 라이브러리 코드는 정적 스타일을 자연스럽게 섞는다.

## 언어가 정의하는 것

타입에 관해 언어 사양이 직접 정의하는 범위.

1. 타입 표현식의 문법. 타입 이름을 적는 방식.
2. 타입을 만드는 컨테이너 문법. `struct`, `enum`, `union`, `trait`, `impl`, 제네릭, 합 타입(`|`).
3. 동적 슬롯 (`any`) 의 의미.
4. 제네릭의 단형화 규칙. 호출 지점에서 타입 별로 [specialize](../000-meta/007-glossary.md#specialize) 하는 방식.
5. 컴파일러가 인식해야 하는 타입 시스템 불변. 트레잇-as-타입 금지·niche 최적화 규칙 등.

## 표준 라이브러리가 정의하는 것

타입에 관해 표준 라이브러리가 책임지는 범위.

1. 모든 원시 타입의 이름과 의미. `i32`, `f64`, `bool`, `str` 등.
2. 모든 컬렉션 타입. `List`, `Dict`, `Set`, `Tuple` 등.
3. 모든 변환. 타입 간 cast, from, into.
4. 트레잇 내용. 어떤 트레잇이 어떤 메서드를 가지며 어떤 타입에 구현되는가.
5. 리터럴이 어떤 타입으로 평가되는가. 핸들러를 통해 결정.

> [!IMPORTANT]
> 본 2장은 모양만 정의한다. 내용은 라이브러리 사양에서 정의한다.

## 점진 타이핑의 경계

점진 타이핑은 변수 슬롯에만 적용된다. 다음 위치에서는 점진을 허용하지 않는다.

- 함수 매개변수에 타입을 적지 않은 경우. 제네릭 함수로 해석된다 (호출 지점에서 단형화). 동적 슬롯이 되지 않는다. 매개변수가 점진 동작을 하려면 명시적으로 `any` 를 적는다.
- 구조체 필드. 타입 명시 필수.
- 함수 반환 타입을 적지 않은 경우. body 에서 추론한다. 추론할 수 없으면 컴파일 에러.

이 경계는 실행 시 [dispatch](../000-meta/007-glossary.md#dispatch-디스패치) 비용을 변수 위치로 한정하기 위한 것이다. 함수 호출 경계는 항상 정적이거나 명시적 `any` 다.

## 트레잇-as-타입 금지

트레잇 이름을 그대로 변수, 매개변수, 반환 타입으로 적을 수 없다. 다형성이 필요하면 제네릭 또는 합 타입을 쓴다.

런타임 dispatch 는 변수 슬롯의 동적성으로만 한정된다.

## 단형화 (monomorphization)

제네릭 함수와 타입은 호출이나 인스턴스화 지점의 구체 타입 튜플마다 별도 컴파일 결과를 생성한다.

- 같은 제네릭 함수가 `i32` 와 `f64` 두 호출지에서 쓰이면, 두 개의 고유한 함수 본체가 생성된다.
- 결과는 간접 호출 비용 0. 직접 호출과 같은 성능.
- 비용은 컴파일 시간과 바이너리 크기. MLIR + LLVM 의 dead-code-elimination 으로 대부분 상쇄된다.
