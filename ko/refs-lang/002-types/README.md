## 위치 정의 (positional definition)

타입은 값이 어떤 모양과 동작을 가질 수 있는지 컴파일러가 판단하는 근거가 되는 정보입니다. Rok의 모든 값은 어떤 타입에 속합니다. 타입이 없는 값은 없습니다.

변수는 사정이 조금 다릅니다. 변수는 한 타입에 고정되거나(정적) 여러 타입을 담을 수 있는 슬롯(동적)입니다. 두 모드는 한 언어 안에 함께 있습니다.

## 두 모드: 정적과 점진

```
정적 (명시)         let x: i32 = 42i32;     x 는 항상 i32
정적 (추론)         let z = 42i32;          z 는 초기값의 타입 i32 로 고정
점진 (any)          let y: any = 42i32;     y 는 모든 타입을 담을 수 있는 슬롯
```

정적 변수는 선언할 때 타입을 적었거나, 타입을 생략해 초기값에서 추론한 변수입니다. 정적 변수는 항상 그 타입의 값만 담습니다. 점진 변수는 타입 자리에 `any`를 적은 변수이며, 동적 슬롯이 됩니다. 기본은 정적이고, 동적은 `any`라고 적은 곳에만 있습니다.

이 장은 두 모드가 한 언어 안에 있다는 사실만 정해 둡니다.

이렇게 정한 이유는 [실행 엔진과 사용자 표면](../000-meta/001-execution-modes.md)에 있습니다. REPL/Jupyter 탐색과 [AOT](../000-meta/007-glossary.md#aot-ahead-of-time) 정적 컴파일이 같은 코드를 공유해야 하기 때문입니다. 그래서 탐색용 코드는 타입을 생략한 추론 스타일로, 라이브러리 코드는 타입을 적는 스타일로 쓰는 경향이 있고, 동적 슬롯은 꼭 필요한 곳에만 `any`로 적습니다.

## 언어가 정의하는 것

언어 사양은 타입에 관해 다음을 직접 정의합니다.

- 타입 표현식의 문법, 곧 타입 이름을 적는 방식.
- 타입을 만드는 컨테이너 문법: `struct`, `enum`, `union`, `trait`, `impl`, 제네릭, 합 타입(`|`).
- 동적 슬롯(`any`)의 의미와, 호출 지점에서 타입마다 [specialize](../000-meta/007-glossary.md#specialize)하는 제네릭 단형화 규칙.
- 컴파일러가 인식해야 하는 타입 시스템 불변 조건. 트레잇-as-타입 금지와 niche 최적화 규칙이 여기에 속합니다.

## 표준 라이브러리가 정의하는 것

표준 라이브러리는 타입에 관해 다음을 맡습니다.

- 모든 원시 타입의 이름과 의미: `i32`, `f64`, `bool`, `str` 등.
- 모든 컬렉션 타입: `List`, `Dict`, `Set`, `Tuple` 등.
- cast, from, into 같은 타입 간 변환 전부.
- 트레잇의 내용: 어떤 트레잇이 어떤 메서드를 가지며 어떤 타입이 그 트레잇을 구현하는지.
- 리터럴이 어떤 타입으로 평가되는지. 이것도 표준 라이브러리가 핸들러로 정합니다.

> [!IMPORTANT]
> 본 2장은 모양만 정의합니다. 내용은 라이브러리 사양에서 정의합니다.

## 점진 타이핑의 경계

점진 타이핑은 `any`를 적은 자리에만 적용됩니다. 타입 표기를 생략해서 동적 슬롯이 되는 자리는 없습니다.

타입을 적지 않은 변수는 초기값의 타입으로 추론한 정적 슬롯이 됩니다. 타입을 적지 않은 함수 매개변수는 함수를 제네릭으로 만들고, 호출 지점에서 단형화됩니다. 동적 슬롯이 되지 않으므로, 점진적으로 동작해야 하는 매개변수에는 `any`를 명시해야 합니다. 구조체 필드에는 타입 표기가 필수입니다. 반환 타입을 생략한 함수는 본문에서 반환 타입을 추론하며, 추론할 수 없으면 컴파일 에러입니다.

이 경계 덕분에 런타임 [dispatch](../000-meta/007-glossary.md#dispatch-디스패치) 비용은 `any`라고 적은 자리에서만 생깁니다. 변수, 매개변수, 필드는 모두 정적이거나 명시적인 `any`입니다.

## 트레잇-as-타입 금지

트레잇 이름을 변수, 매개변수, 반환 타입에 그대로 적을 수 없습니다. 다형성이 필요하면 제네릭, 합 타입, 또는 제약을 붙인 `any Trait`을 사용합니다.

런타임 dispatch는 `any`라고 적은 자리(`any`, `any Trait`)에서만 일어납니다.

## 단형화 (monomorphization)

제네릭 함수와 타입은 호출 지점이나 인스턴스화 지점의 구체 타입 튜플마다 별도의 컴파일 결과를 만듭니다.

예를 들어 같은 제네릭 함수를 `i32`와 `f64`로 두 곳에서 호출하면 서로 다른 함수 본체 두 개가 생성됩니다. 그 결과 간접 호출 비용은 0이고, 직접 호출과 성능이 같습니다. 대신 컴파일 시간과 바이너리 크기라는 비용이 들지만, MLIR + LLVM의 dead-code elimination이 대부분 상쇄합니다.
