# 2.14. 형 변환

값을 한 타입에서 다른 타입으로 옮기는 구문을 정의한다. 의미론 (어떤 변환이 허용되며 그 결과가 어떻게 결정되는지) 은 표준 라이브러리의 변환 매트릭스가 책임진다. 본 문서는 언어 구문만 다룬다.

```
cast_expr   ::= expr "as" type_expr
into_expr   ::= expr "." "into" "(" ")"
try_into    ::= expr "." "try_into" ("::" "<" type_expr ">")? "(" ")"
```

## 2.14.1. 세 가지 구문

세 구문 모두 [언어와 표준 라이브러리의 경계](../000-meta/004-language-vs-stdlib.md) 의 원칙에 따라 언어가 구문을 제공하고 표준 라이브러리 트레잇 메서드로 desugar 된다.

| 구문               | 형태                   | desugar 대상 트레잇         |
| ------------------ | ---------------------- | --------------------------- |
| `as` 캐스팅        | `expr as 타입`         | `Cast<Target>::cast`        |
| `.into()` 호출     | `expr.into()`          | `Into<Target>::into`        |
| `.try_into()` 호출 | `expr.try_into::<T>()` | `TryInto<Target>::try_into` |

세 트레잇의 정확한 시그니처와 어떤 타입 쌍에 어떤 구현이 등록되는지는 표준 라이브러리의 변환 매트릭스에서 정의한다. 본 문서는 언어 수준의 desugar 규칙까지만 책임진다.

## 2.14.2. `as` 캐스팅

```nok
expr as 타입
```

- `as` 키워드 ([키워드](../001-lexical/105-keywords.md)).
- 좌변은 임의의 표현식, 우변은 [타입 표현식](201-type-expressions.md) 형태.
- desugar: `<typeof(expr) as Cast<Target>>::cast(expr)`.

`Cast<Target>` 트레잇은 좌변 타입에서 `Target` 타입으로의 직접 캐스팅을 뜻한다. 일반적으로 비트 자르기·부호 확장·표현 변환처럼 값이 보존되지 않을 수 있는 변환에 쓴다. 어떤 타입 쌍에 `Cast` 가 구현되어 있는지는 표준 라이브러리가 결정한다.

```nok
let x: i32 = 256i32;
let y: u8 = x as u8;          // Cast<u8>::cast(x)
let z: f64 = x as f64;        // Cast<f64>::cast(x)
```

`as` 의 결과는 항상 성공한다 (`Cast` 구현이 등록된 타입 쌍에 한해서). 실패 가능성이 있는 변환에는 `.try_into()` 를 쓴다.

`Cast` 가 구현되지 않은 타입 쌍에 `as` 를 쓰면 컴파일 에러다.

## 2.14.3. `.into()` 호출

```nok
expr.into()
```

- desugar: `<typeof(expr) as Into<Target>>::into(expr)`.
- 좌변 표현식의 타입에 대상 타입으로 가는 `Into` 구현이 있어야 한다.
- 대상 타입은 문맥에서 추론한다. 변수의 선언 타입, 매개변수 타입 등에서.

```nok
let x: i64 = 100i64;
let y: BigInt = x.into();       // Into<BigInt>::into(x)
```

대상 타입을 추론할 수 없는 위치에서는 turbofish 로 명시한다.

```nok
let y = x.into::<BigInt>();
```

`.into()` 는 값 보존 변환 (정보 손실 없음) 으로 표준 라이브러리에 등록된 경우에만 호출된다. 일반적으로 좁은 타입에서 넓은 타입으로 변환할 때 쓴다.

## 2.14.4. `.try_into()` 호출

```nok
expr.try_into::<타입>()
```

- desugar: `<typeof(expr) as TryInto<Target>>::try_into(expr)`.
- 결과 타입은 `Result<대상타입, 에러타입>` 형태다 (정확한 형은 표준 라이브러리에서).
- 변환이 실패할 수 있을 때 쓴다. 예: 큰 정수를 작은 정수로, 부동소수에서 정수로 변환.

```nok
let big: i64 = 10_000_000_000i64;
let result = big.try_into::<i32>();
match result {
    Ok(n) => ...,
    Err(e) => ...,
}
```

## 2.14.5. 세 구문의 차이 요약

| 구문          | 실패 가능?         | 정보 손실 가능? | 트레잇       |
| ------------- | ------------------ | --------------- | ------------ |
| `as`          | 안 함              | 가능            | `Cast<T>`    |
| `.into()`     | 안 함              | 안 함 (값 보존) | `Into<T>`    |
| `.try_into()` | 가능 (Result 반환) | 안 함 (성공 시) | `TryInto<T>` |

상황별 선택 기준:

- 비트나 정밀도를 의도적으로 바꾸고 싶을 때 → `as`.
- 정보를 잃지 않는 안전한 확장만 → `.into()`.
- 실패 가능성을 명시적으로 다루고 싶을 때 → `.try_into()`.

## 2.14.6. 문맥 기반 자동 변환

리터럴이 타입 주석이 있는 변수에 대입될 때는 [숫자 리터럴](../001-lexical/106-numeric-literals.md) 의 핸들러가 자동 변환을 적용할 수 있다 (예: `42` 라는 bare 리터럴이 `i32: 42` 변수에 대입). 이 자동 변환의 정확한 규칙은 표준 라이브러리의 리터럴과 변환 사양에서 정의한다.

런타임 변수의 자동 변환은 허용하지 않는다. 항상 위 세 구문 중 하나를 명시해야 한다.

```nok
let a: i64 = 100i64;
let b: i32 = a;                 // ERROR — 명시 변환 필요
let b: i32 = a as i32;          // OK
let b: i32 = a.try_into::<i32>().unwrap();  // OK
```

이 명시성 강제는 조용한 정밀도 손실을 막는다.

## 2.14.7. 변환 트레잇의 위치

`Cast<T>`, `Into<T>`, `TryInto<T>` 모두 표준 라이브러리 [표준 라이브러리 계층](../000-meta/005-stdlib-tiers.md) 의 `core` 계층에 정의된다. 어떤 타입 쌍에 어떤 트레잇이 구현되어 있는지에 대한 전체 매트릭스는 표준 라이브러리 사양에서 정의한다.

본 문서는 언어가 세 구문의 형태를 제공하고 각각이 위 세 트레잇으로 desugar 된다는 사실까지만 책임진다.
