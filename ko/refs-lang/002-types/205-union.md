# 2.5. `union`

`union` 은 여러 필드가 같은 메모리를 공유하는 비태그 컨테이너다. 한 시점에 어느 필드의 값이 의미 있는지를 언어가 추적하지 않는다. 사용자가 책임진다.

```
union_decl      ::= "union" identifier generics? "{" named_field_list? "}"
```

## 2.5.1. 기본 형태

```nok
union EpollData {
    ptr: usize;
    fd: i32;
    val: u64;
}
```

- 본체와 필드 문법은 [`struct`](203-struct.md) 의 named `struct` 와 같다.
- 차이는 키워드 (`union`) 와 모든 필드가 같은 메모리 위치를 공유한다는 의미론에 있다.

## 2.5.2. 의미론

```nok
let x = EpollData { fd: 5i32 };
let y = x.val;       // x 의 비트 패턴을 u64 로 재해석
```

- 한 인스턴스를 어떤 필드로 생성하면, 그 필드의 비트가 메모리에 쓰인다.
- 다른 필드로 읽으면, 같은 메모리의 비트를 그 필드 타입으로 재해석한다.
- 이 재해석은 항상 허용한다. `unsafe` 블록을 요구하지 않는다.

nok 의 비트-수준 작업은 [표준 라이브러리 계층](../000-meta/005-stdlib-tiers.md) 의 `unsafe` 영역에만 갇혀 있지 않다. `union` 자체가 언어 수준의 안전한 비트 재해석 도구다.

## 2.5.3. 안전성의 위치

`union` 의 비트 재해석은 언어가 정의한 동작이지만, 그 결과의 의미는 프로그램 도메인의 책임이다. 예를 들어 `i32` 비트를 `f32` 로 읽으면 그 결과는 IEEE 754 의 비트 표현에 따른 실수값이며, 이 값이 도메인적으로 의미 있는지는 언어가 검증하지 않는다.

이 모델은 C 의 `union` 과 다르다. C 는 read-from-different-member 가 미정의 동작이지만, nok 에서는 정의된 동작 (비트 재해석) 이다. 이 차이 덕분에 nok 의 `union` 은 일반 사용자 코드에서도 안전하게 쓸 수 있다.

## 2.5.4. 기본 레이아웃은 컴파일러 자유

기본 `union` 레이아웃은 컴파일러 자유다. 가장 큰 필드의 크기·정렬만 만족하면 된다. 필드 정렬·패딩의 정확한 결정은 컴파일러가 한다.

C [ABI](../000-meta/007-glossary.md#abi-application-binary-interface) 호환 `union` 이 필요하면 `#[repr(C)]` 을 부착한다.

```nok
#[repr(C)]
union CUnion {
    a: i32;
    b: f32;
}
```

`#[repr(C)]` 가 부착된 `union` 은 C 의 `union` 과 비트 수준에서 호환된다. [FFI](../000-meta/007-glossary.md#ffi-foreign-function-interface) 인터페이스에서 쓴다. 정확한 의미는 [내장 속성](../006-meta-system/602-built-in-attributes.md) 에서 정의한다.

## 2.5.5. `union` vs `#[repr(C)] union` 차이

| 형태                         | 사용처    | 레이아웃      | 비트 호환           |
| ---------------------------- | --------- | ------------- | ------------------- |
| `union T { ... }`            | 일반 코드 | 컴파일러 자유 | nok 내부에서만 보장 |
| `#[repr(C)] union T { ... }` | FFI       | C ABI 동일    | C 코드와 호환       |

## 2.5.6. 가시성 / 중복 정의

[`struct`](203-struct.md) 와 같은 규칙을 따른다.

> [!WARNING]
> `union` 의 다른 필드로 읽는 동작은 비트 재해석이다. 도메인적 의미는 프로그램의 책임이다. C 와 달리 미정의 동작은 아니지만, 잘못된 비트 패턴이 의미 있는 값처럼 보이는 함정에 주의.

## 2.5.7. `union` 과 합 타입의 차이

```nok
union  Foo { a: i32; b: f32; }    // 같은 메모리, 태그 없음
type   Bar = i32 | f32;            // 별개 메모리, 태그 있음
```

| 측면                      | `union`                        | 합 타입 (`A \| B`)           |
| ------------------------- | ------------------------------ | ---------------------------- |
| 어느 필드가 활성인지 추적 | 안 함                          | 태그로 추적                  |
| 필드 사이 변환            | 비트 재해석                    | 변형 변경 (값 재구성)        |
| 메모리 사용               | 가장 큰 필드 크기              | 태그 + 가장 큰 변형 크기     |
| 잘못 읽었을 때            | 비트 재해석 결과 (정의된 동작) | 컴파일 에러 또는 런타임 검사 |

용도가 완전히 다르다. `union` 은 비트 수준의 다른 해석, 합 타입은 값 수준의 다른 종류다. 혼동하지 않도록 주의.
