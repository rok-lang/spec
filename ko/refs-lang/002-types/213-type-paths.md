# 2.13. 타입 경로

`::` 토큰 ([구두점과 연산자 토큰](../001-lexical/110-punctuation-and-operator-tokens.md)) 으로 이어진 식별자의 연속은 어떤 항목을 가리키는 경로다. 본 문서는 타입 위치의 경로와 연관 항목 접근에 한정해 정의한다. 모듈 import 의 정확한 의미는 [`use` 선언](../005-modules/505-use.md) 에서 정의한다.

```
type_path       ::= path_root ("::" path_segment)*
path_root       ::= identifier | "crate" | "super" | "self"
path_segment    ::= identifier type_args?
                  | identifier "::" "<" type_expr ">" "::" identifier  // assoc item
```

## 2.13.1. 모듈 경로

타입 이름이 다른 모듈에 정의되어 있으면, 그 위치까지의 모듈 경로 + 타입 이름을 적는다.

```nok
std::time::Duration
core::collections::List
crate::geom::Point
```

- 각 식별자는 모듈이나 항목 이름이다.
- 마지막 식별자가 타입 이름이고, 앞부분은 그 타입을 어디서 찾을지를 가리키는 경로다.

## 2.13.2. 경로의 시작점

경로의 첫 식별자는 현재 모듈에서 보이는 이름이다.

- 자기 자식 모듈 이름.
- import 로 가져온 이름.
- 자동 가시 prelude 항목.
- 키워드 시작. `crate`, `super`, `self` (정확한 의미는 모듈 사양에서).

## 2.13.3. 연관 항목 접근

`::` 는 타입에 부속된 항목에 접근할 때도 쓰인다.

```nok
i32::MAX                  // 정수 타입의 const 항목
Point::origin()           // 정적 메서드
List::<i32>::new()        // turbofish 로 제네릭 명시
T::Output                 // 트레잇 매개변수의 연관 타입
```

- 정적 메서드. `Type::method(args)` 형태.
- 연관 `const`. `Type::CONSTANT`.
- 연관 타입. 트레잇 매개변수의 연관 타입은 `T::AssocType` 으로 참조한다.

## 2.13.4. 완전 자격 형태 (fully qualified path)

같은 메서드 이름이 여러 트레잇과 본질 `impl` 양쪽에 있어 모호하거나, 트레잇의 연관 타입을 어느 트레잇 기준으로 참조하는지 명시해야 할 때 완전 자격 형태를 쓴다.

```nok
<i32 as Display>::display(42i32)
<T as Add<U>>::Output
<Self as Iterator>::next(ref self)
```

- 형식: `<타입 as 트레잇>::항목`.
- 꺾쇠 괄호 안에 `타입 as 트레잇` 을 적고, 뒤에 `::` 와 항목 이름이나 메서드 호출이 온다.
- 여기서 `as` 는 어느 트레잇으로 보는가를 명시하는 키워드 사용이다. 같은 `as` 토큰이 표현식 위치 (이항 사용) 에서는 다른 의미를 갖는다. 표현식 사양에서 정의한다.

완전 자격 형태는 일반 사용에서는 거의 등장하지 않는다. 모호 해소가 필요하거나 자동 추론이 실패할 때만 명시한다.

## 2.13.5. turbofish. 표현식 위치의 제네릭

값 위치에서 제네릭 인자를 명시할 때는 `::<...>` 형태를 쓴다.

```nok
parse::<i32>("42")
collect::<List<f64>>(iter)
```

- 함수나 메서드 이름 뒤 `::<...>`. 그 자리의 제네릭 인자를 적는다.
- 타입 위치 (`:` 뒤·`->` 뒤·`as` 뒤 등) 에서는 `::` 없이 `<...>` 를 직접 쓴다.

이 차이의 이유는 값 위치에서 `<` 가 비교 연산자와 모호해지기 때문이다.

## 2.13.6. 타입의 절대 경로

`::` 로 시작하는 경로는 루트 (현재 패키지의 루트) 부터 시작한다는 의미를 가질 수 있다. 정확한 절대 경로의 의미는 모듈 사양에서 정의한다. 본 문서는 그런 형태가 있다는 사실만 명시한다.

## 2.13.7. 경로와 합 타입의 결합

경로 자체는 [타입 표현식](201-type-expressions.md) 의 단순 이름 또는 경로 형태이고, 합 타입 (`|`) 이나 제네릭 적용 (`<...>`) 등 다른 결합자와 자유롭게 섞을 수 있다.

```nok
std::io::Result<T>
crate::Foo | std::Bar
List<core::Range<i32>>
```

우선순위는 [타입 표현식](201-type-expressions.md) 에서 정의한 대로다. 경로 (`::`) 와 제네릭 적용 (`<...>`) 이 합 타입 (`|`) 보다 강하게 묶인다.

## 2.13.8. 빈 경로와 단독 `::`

빈 경로 (`::` 만 있고 식별자 없음) 는 항상 컴파일 에러다.

`::` 가 식별자 사이에 연속으로 등장하는 형태 (`A::::B`) 도 에러다.
