# 2.13. 타입 경로

`::` 토큰([구두점과 연산자 토큰](../001-lexical/110-punctuation-and-operator-tokens.md))으로 이은 식별자 열은 어떤 항목을 가리키는 경로입니다. 이 문서는 타입 위치의 경로와 연관 항목 접근만 정의합니다. 모듈을 가져오는 정확한 의미는 [`use` 선언](../005-modules/505-use.md)에서 따로 다룹니다.

```
type_path       ::= path_root ("::" path_segment)*
path_root       ::= identifier | "pkg" | "sup"
path_segment    ::= identifier type_args?
                  | identifier "::" "<" type_expr ">" "::" identifier  // assoc item
```

## 2.13.1. 모듈 경로

타입이 다른 모듈에 정의되어 있으면 그 모듈까지의 경로와 타입 이름을 함께 적습니다.

```rok
rok::std::time::Duration
rok::core::collections::List
pkg::geom::Point
```

각 식별자는 모듈이나 항목의 이름입니다. 마지막 식별자가 타입 이름입니다. 앞부분은 그 타입을 찾을 곳을 알려 주는 경로입니다.

## 2.13.2. 경로의 시작점

경로의 첫 식별자는 현재 모듈에서 보이는 이름이어야 합니다. 자기 자식 모듈의 이름, `use`로 가져온 이름, 문맥 키워드 중 하나입니다. 문맥 키워드에는 패키지 루트를 가리키는 `pkg`와 부모 모듈을 가리키는 `sup`이 있습니다. 정확한 의미는 [경로](../005-modules/507-paths.md)에서 정의합니다.

## 2.13.3. 연관 항목 접근

`::`는 타입에 딸린 항목에 접근할 때도 씁니다.

```rok
i32::MAX                  // 정수 타입의 const 항목
Point::origin()           // 정적 메서드
List::<i32>::new()        // turbofish 로 제네릭 명시
T::Output                 // 트레잇 매개변수의 연관 타입
```

연관 항목 접근에는 몇 가지 형태가 있습니다. 정적 메서드는 `Type::method(args)` 형태로 호출합니다. 연관 `const`는 `Type::CONSTANT`처럼 참조하고, 트레잇으로 제약된 매개변수의 연관 타입은 `T::AssocType`으로 참조합니다.

타입 별칭을 거친 경로는 별칭이 가리키는 타입의 항목을 가리킵니다. `type B = S<i32>;`이면 `B::mk(x)`는 `S::<i32>::mk(x)`입니다. `type Al<T> = S<T>;`이면 `Al::mk(x)`는 인자를 추론하는 `S::mk(x)`이고, `Al::<i32>::mk(x)`는 `S::<i32>::mk(x)`입니다. 제네릭 별칭을 인자 없이 쓰면, 별칭이 가리키는 타입의 인자가 별칭의 서로 다른 매개변수일 때만 인자를 추론에 맡깁니다. 그렇지 않으면 인자를 적어야 합니다. 예를 들어 `type Names<V> = Dict<str, V>;`이면 `Names::<i32>::new()`로 적습니다.

## 2.13.4. 완전 한정 경로(fully qualified path)

같은 메서드 이름이 여러 트레잇과 고유 `impl`에 있어 모호하면 완전 자격 형태를 씁니다. 연관 타입을 어느 트레잇을 거쳐 참조하는지 밝혀야 할 때도 씁니다.

```rok
<i32 as Display>::display(42i32)
<T as Add<U>>::Output
<Self as Iterator>::next(ref self)
```

완전 자격 형태는 `<타입 as 트레잇>::항목`입니다. 꺾쇠괄호 안에 `타입 as 트레잇`을 적고, 그 뒤에 `::`와 항목 이름이나 메서드 호출이 옵니다. 여기서 `as`는 타입을 어느 트레잇으로 보는지 밝히는 키워드입니다. 같은 `as` 토큰이 표현식 위치(이항 연산자)에서는 다른 뜻입니다. 그 뜻은 표현식 사양에서 정의합니다.

완전 자격 형태는 타입 자리(`<T as Tr>::X`를 연관 타입으로)와 호출 자리(`<T as Tr>::m(x)`)에서 모두 유효합니다. 제네릭 트레잇이면 인자까지 맞는 impl을 고릅니다. `<T as Tr<A>>::X`와 바운드 `T: Tr<A>` 아래의 `T::X`는 `Tr<A>` impl의 `X`입니다. 같은 타입의 `Tr<B>` impl에 있는 `X`와는 다를 수 있습니다. `<Sq as Shape>::Out` 같은 투영은 함수 시그니처, `static` 타입, struct 필드, enum 페이로드, 타입 별칭(제네릭이든 아니든)에서 유효합니다. 타입, 트레잇, impl을 선언한 순서와는 상관없습니다. 자격 있는 연관 타입 뒤의 호출 `<T as Tr>::X::m()`은 식에서 유효합니다.

평소 코드에는 완전 자격 형태가 거의 나오지 않습니다. 모호성을 풀어야 하거나 자동 추론이 실패할 때만 직접 적습니다.

## 2.13.5. turbofish: 표현식 위치의 제네릭

값 위치에서 제네릭 인자를 적을 때는 `::<...>` 형태를 씁니다.

```rok
parse::<i32>("42")
collect::<List<f64>>(iter)
```

함수나 메서드 이름 뒤에 `::<...>`를 붙여 그 자리의 제네릭 인자를 적습니다. 타입 위치(`:` 뒤, `->` 뒤, `as` 뒤 등)에서는 `::` 없이 `<...>`를 바로 씁니다.

이렇게 다른 까닭은 값 위치에서 `<`가 비교 연산자와 헷갈리기 때문입니다.

## 2.13.6. 타입의 절대 경로

루트에서 시작하는 절대 경로는 `pkg::`로 적습니다([경로](../005-modules/507-paths.md)). 맨 앞에 `::`를 쓰는 형태는 Rok에 없습니다.

## 2.13.7. 경로와 합 타입의 결합

경로 자체는 [타입 표현식](201-type-expressions.md)의 단순 이름 형태나 경로 형태입니다. 그래서 합 타입(`|`), 제네릭 적용(`<...>`) 같은 다른 결합자와 자유롭게 섞을 수 있습니다.

```rok
rok::std::io::Result<T>
pkg::Foo | rok::std::Bar
List<rok::core::Range<i32>>
```

우선순위는 [타입 표현식](201-type-expressions.md)에서 정의한 대로입니다. 경로(`::`)와 제네릭 적용(`<...>`)이 합 타입(`|`)보다 강하게 묶입니다.

## 2.13.8. 빈 경로와 단독 `::`

빈 경로(`::`만 있고 식별자가 없는 경우)는 항상 컴파일 에러입니다. 식별자 사이에 `::`가 연달아 나오는 형태(`A::::B`)도 에러입니다.
