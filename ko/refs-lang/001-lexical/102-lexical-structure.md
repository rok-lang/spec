# 1.2. 어휘 구조

이 절은 문자 흐름이 토큰 흐름으로 바뀌는 전체 그림을 보여 줍니다. 토큰 종류별 세부 형식은 뒤의 문서에서 정의하므로 여기서는 윤곽만 잡습니다.

```
token           ::= identifier
                  | keyword
                  | numeric_lit
                  | string_lit
                  | byte_string_lit
                  | char_lit
                  | sentinel_lit                  // true | false | none
                  | punctuation
whitespace      ::= space_char+
                  | line_comment
                  | block_comment
space_char      ::= U+0009 | U+000A | U+000B | U+000C | U+000D | U+0020
line_comment    ::= "//" <any char except line_terminator>* line_terminator
block_comment   ::= "/*" <any char>* "*/"          // recursive
shebang_line    ::= "#!" <any char except line_terminator>*   // first line only, see 1.2.3
line_terminator ::= U+000A | U+000D U+000A? | U+000D
```

## 1.2.1. 토큰

컴파일러의 어휘 분석기(이하 **렉서**)는 소스 파일을 읽어 토큰 흐름을 만듭니다. 토큰의 종류는 다음과 같습니다.

| 종류                   | 예                                  |
|------------------------|-------------------------------------|
| 식별자(identifier)     | `count`, `α`, `Δt`                  |
| 키워드(keyword)        | `let`, `if`, `fn`                   |
| 숫자 리터럴            | `42`, `3.14`, `0xFF`, `1_000`       |
| 문자열 리터럴          | `"hello"`, `r"raw\n"`, `f"x = {x}"`, `b"bytes"` |
| 문자 리터럴            | `'A'`, `c'A'`                       |
| 진리값 / 센티넬 리터럴 | `true`, `false`, `none`             |
| 연산자 / 구두점        | `+`, `==`, `..`, `[`, `;`           |

종류별 정확한 형식 규칙은 이어지는 문서에서 차례로 정의합니다.

## 1.2.2. 공백

공백 문자는 토큰 사이를 구분하기만 하고 그 자체로는 토큰이 되지 않습니다.

다음 코드포인트를 공백으로 인정합니다.

| 코드포인트 | 이름             |
|------------|------------------|
| `U+0009`   | 탭(TAB)          |
| `U+000A`   | 줄바꿈(LF)       |
| `U+000B`   | 수직 탭(VT)      |
| `U+000C`   | 폼 피드(FF)      |
| `U+000D`   | 캐리지 리턴(CR)  |
| `U+0020`   | 스페이스         |

위 표에 없는 유니코드 공백류(`U+00A0` NO-BREAK SPACE, `U+200B` ZERO WIDTH SPACE 등)는 공백이 아닙니다. 이 문자들은 식별자나 문자열 안에서 일반 코드포인트로만 쓰입니다.

들여쓰기에는 의미가 없습니다. Rok은 Python처럼 들여쓰기에 의미를 두지 않습니다.

## 1.2.3. 주석

Rok의 주석은 한 줄 주석, 블록 주석, 문서 주석 세 종류입니다. 파일 첫 줄의 shebang 줄은 주석처럼 무시합니다.

### Shebang 줄

파일의 첫 줄(BOM 뒤)이 `#!`로 시작하면 그 줄은 shebang 줄이며 주석처럼 무시합니다. 그래서 `#!/usr/bin/env rok`이 든 스크립트는 `./script.rok`으로 실행할 수 있습니다([9.10.1](../009-tools/910-rok-frontend.md#9101-서브명령과-전역-옵션)). 예외가 하나 있습니다. `#!` 뒤에서 공백과 주석을 건너뛰고 처음 나오는 토큰이 `[`이면 `#!`는 내부 속성(`#![allow(unused)]`)의 시작입니다. 이때 문서 주석은 건너뛰지 않습니다. 둘째 줄 이후의 `#!`는 shebang 줄이 아닙니다.

### 한 줄 주석

```rok
// 이 줄 끝까지 주석
```

`//`부터 그 줄의 줄 종결자까지가 주석입니다. 줄바꿈 자체는 주석에 들어가지 않습니다.

### 블록 주석

```rok
/* 여러 줄
   걸쳐서 */
```

`/*`와 `*/` 사이가 주석이며 중첩할 수 있습니다. 안쪽의 `/*`/`*/` 쌍이 모두 닫혀야 바깥쪽이 닫힙니다. Rust와 같은 규칙입니다. 그래서 큰 코드 영역을 잠시 꺼 둘 때 쓰기 좋습니다.

```rok
/* 바깥
   /* 안쪽 */
   여전히 주석 */
```

### 문서 주석

문서 주석은 Rust처럼 네 형태가 있습니다.

```rok
/// 외부 문서 주석 (뒤따르는 항목)
//! 내부 문서 주석 (둘러싸는 파일, 모듈, 함수)
/** 외부 블록 문서 주석 */
/*! 내부 블록 문서 주석 */
```

- 한 줄 문서 주석은 줄 종결자까지입니다. `/// text`는 `#[doc = "text"]`이고 `//! text`는 `#![doc = "text"]`입니다. 표시 뒤의 공백 하나는 버립니다([6.2.8](../006-meta-system/602-built-in-attributes.md#628-doc---문서-주석-형태)). `////`로 시작하는 줄은 일반 주석입니다.
- 블록 문서 주석은 짝이 맞는 `*/`까지이며 블록 주석처럼 중첩됩니다. `/**/`, `/***/`, `/***`로 시작하는 주석은 일반 주석입니다. 블록 문서 주석의 텍스트는 `#[doc]` / `#![doc]` 속성 하나가 됩니다. 빈 첫 줄과 빈 마지막 줄은 버립니다. 주석이 여러 줄에 걸치고 첫 줄 뒤의 모든 줄이 선택적 공백과 `*`로 시작하면 그 접두어를 지웁니다. 그다음 비어 있지 않은 줄에 공통인 들여쓰기와 `*/` 앞의 공백을 지웁니다. 줄바꿈은 LF입니다.
- 내부 문서 주석은 파일, 모듈 본체, 함수 본체의 시작에만 옵니다. 그 밖의 자리에서는 에러입니다.
- 외부 문서 주석은 뒤따르는 항목을 설명합니다. 아무것도 설명하지 않는 외부 문서 주석은 에러입니다. `}`, `)`, `]` 앞이나 파일 끝에 온 경우입니다. 함수 매개변수에 붙은 것도 에러입니다. 문장, match 가지, struct 리터럴 필드, 튜플 필드, 식에 붙은 것은 어떤 도구도 보존하지 않습니다. 이런 주석은 `unused_doc_comments` 린트를 일으킵니다([6.2.9](../006-meta-system/602-built-in-attributes.md#629-allow--deny--warn-린트-제어)).
- 미리 빌드한 패키지의 ROKHIR 인터페이스 텍스트([9.4](../009-tools/904-rokhir-bytecode.md))는 문서 주석을 보존합니다.

## 1.2.4. 컴파일러 출력

렉서의 출력은 토큰 흐름과 위치 정보입니다. 위치 정보는 [소스 파일](101-source-files.md)의 진단 단위 규칙을 따릅니다.

이 출력이 다음 단계인 구문 분석기의 유일한 입력입니다. 구문 분석기는 원본 소스를 다시 보지 않습니다.
