# 1.2. 어휘 구조

문자 흐름이 토큰 흐름으로 바뀌는 큰 그림. 각 토큰 종류의 세부 형식은 후속 문서에서 정의한다.

```
token           ::= identifier
                  | keyword
                  | numeric_lit
                  | string_lit
                  | char_lit
                  | sentinel_lit                  // true | false | none
                  | punctuation
whitespace      ::= space_char+
                  | line_comment
                  | block_comment
space_char      ::= U+0009 | U+000A | U+000B | U+000C | U+000D | U+0020
line_comment    ::= "//" <any char except line_terminator>* line_terminator
block_comment   ::= "/*" <any char>* "*/"          // recursive
line_terminator ::= U+000A | U+000D U+000A? | U+0085
```

## 1.2.1. 토큰

컴파일러의 어휘 분석기 (이하 _렉서_) 는 소스 파일을 읽어 토큰 흐름을 만든다. 토큰은 다음
종류로 나뉜다.

| 종류                   | 예                                  |
| ---------------------- | ----------------------------------- |
| 식별자 (identifier)    | `count`, `α`, `Δt`                  |
| 키워드 (keyword)       | `let`, `if`, `fn`                   |
| 숫자 리터럴            | `42`, `3.14`, `0xFF`, `1_000`       |
| 문자열 리터럴          | `"hello"`, `r"raw\n"`, `f"x = {x}"` |
| 문자 리터럴            | `'A'`, `c'A'`                       |
| 진리값 / 센티넬 리터럴 | `true`, `false`, `none`             |
| 연산자 / 구두점        | `+`, `==`, `..`, `[`, `;`           |

각 종류의 정확한 형식 규칙은 다음 문서들에서 정의한다.

## 1.2.2. 공백

공백 문자는 토큰 사이의 구분자로만 의미를 갖는다. 토큰을 만들지 않는다.

다음을 공백으로 인정한다.

| 코드포인트 | 이름             |
| ---------- | ---------------- |
| `U+0009`   | 탭 (TAB)         |
| `U+000A`   | 줄바꿈 (LF)      |
| `U+000B`   | 수직 탭 (VT)     |
| `U+000C`   | 폼 피드 (FF)     |
| `U+000D`   | 캐리지 리턴 (CR) |
| `U+0020`   | 스페이스         |

위 외의 유니코드 공백류 (`U+00A0` NO-BREAK SPACE, `U+200B` ZERO WIDTH SPACE 등) 는
공백으로 인정하지 않는다. 식별자나 문자열 안에서 일반 코드포인트로 등장한다.

들여쓰기는 의미를 갖지 않는다. Python 식의 의미 있는 들여쓰기는 도입하지 않는다.

## 1.2.3. 주석

세 종류의 주석을 지원한다.

### 한 줄 주석

```nok
// 이 줄 끝까지 주석
```

`//` 부터 그 줄의 줄 종결자까지가 주석이다. 줄바꿈 자체는 주석에 포함되지 않는다.

### 블록 주석

```nok
/* 여러 줄
   걸쳐서 */
```

`/*` 와 `*/` 사이가 주석이다. **중첩이 허용된다.** 안쪽의 `/*`/`*/` 쌍이 정확히 닫혀야
바깥쪽이 닫힌다 (Rust 와 같은 규칙). 큰 코드 영역을 잠시 비활성화할 때 유용하다.

```nok
/* 바깥
   /* 안쪽 */
   여전히 주석 */
```

### 문서 주석

문서 주석은 두 형태가 있다.

```nok
/// 이 항목은 ...      (외부 문서 주석 — 직후 항목에 부착)
//! 이 항목은 ...      (내부 문서 주석 — 둘러싸는 항목 / 모듈에 부착)
```

어휘 단계에서는 일반 한 줄 주석과 동일하게 처리된다. 시작 토큰부터 그 줄의 줄 종결자까지가
주석이다.

차이는 *내용이 보존되어 다음 단계로 전달된다는 점*이다. 일반 주석은 어휘 단계 직후
폐기되지만, 문서 주석의 텍스트는 유지되어 후속 단계가 적절한 항목에 부착한다. 부착
메커니즘과 활용 방법은 메타 시스템 사양에서 정의한다.

외부와 내부의 한 쌍은 사양 전체에 일관되게 등장한다. 속성 도입자에서도 같은 패턴이 다시
나타난다 (후속 문서).

블록 형태 문서 주석 (`/** ... */`, `/*! ... */`) 은 도입하지 않는다. 도구 친화성과 일관성을
위해 한 줄 형태로 통일한다.

## 1.2.4. 컴파일러 출력

렉서의 출력은 토큰 흐름과 위치 정보다. 위치 정보는 [소스 파일](101-source-files.md) 의 진단 단위 규칙을
따른다.

이 출력이 다음 단계인 구문 분석기의 유일한 입력이다. 구문 분석기는 원본 소스를 다시 보지
않는다.
