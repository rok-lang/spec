# 1.8. 문자 리터럴

문자 리터럴은 코드포인트 하나나 바이트 하나를 나타내는 토큰입니다.

## 1.8.1. 세 종류

```
char_lit    ::= "'" char_item "'"
              | "c'" byte_item "'"
              | "b'" byte_item "'"
char_item   ::= <any unicode codepoint except "'" or "\\"> | escape_seq
byte_item   ::= <any ASCII byte except "'" or "\\"> | byte_escape
byte_escape ::= "\\x" hex_digit hex_digit | escape_seq
```

### 일반 문자: `'A'`

```rok
'A'
'세'
'\n'
'\u{1F600}'
```

작은따옴표(`'`) 한 쌍 안에는 코드포인트를 정확히 하나 두어야 합니다. 이스케이프 시퀀스는 [문자열 리터럴](107-string-literals.md)의 표를 그대로 따릅니다. `\\`, `\'`, `\"`, `\n`, `\r`, `\t`, `\0`, `\x`, `\u{...}` 등을 쓸 수 있습니다. `'\x41'`처럼 1바이트 형태로 적어도 되며, 결과는 ASCII 범위의 코드포인트 하나입니다. `'AB'`처럼 두 글자 이상을 담거나 빈 `''`을 쓰면 어휘 단계에서 에러입니다.

이 형태의 리터럴은 `char`(유니코드 스칼라값, 컴파일러 기본 타입)입니다. 메서드는 [stdlib 2.15](../../refs-standard-libraries/200-core/215-string.md)가 정의합니다.

### C 호환 문자: `c'A'`

```rok
c'A'
c'\n'
c'\x7F'
```

이 형태는 `c` 접두와 작은따옴표 한 쌍으로 이루어집니다. 이스케이프 시퀀스는 [문자열 리터럴](107-string-literals.md)의 표를 그대로 따릅니다. 값은 `U+0000`-`U+00FF` 범위 안이어야 하며, 범위를 넘으면 어휘 에러입니다. 예를 들어 `c'세'`는 에러입니다. `'세'`는 `U+C138`이어서 한 바이트에 담을 수 없기 때문입니다. 소스가 UTF-8이므로 직접 적을 수 있는 글자는 ASCII뿐입니다. 비 ASCII 1바이트 값(`U+0080`-`U+00FF`)은 `\xHH` 또는 `\u{H...}` 이스케이프로 적어야 합니다.

이 형태는 기본 타입 `c_char`로 평가됩니다. 이 타입은 [FFI](../000-meta/007-glossary.md#ffi-foreign-function-interface)(Foreign Function Interface)의 8비트 문자 타입입니다.

### 바이트: `b'A'`

```rok
b'0'          // 48u8
b'\n'         // 10u8
b'\xFF'       // 255u8
```

이 형태는 `b` 접두사와 작은따옴표 한 쌍으로 이루어지며, 내용과 이스케이프는 `c'x'`와 같습니다. 직접 쓴 ASCII 글자 하나, 또는 값이 `\xFF` 이하인 이스케이프 하나입니다. `b'é'`처럼 ASCII가 아닌 글자는 어휘 에러이며, 메시지가 `\xHH`로 적으라고 알려 줍니다. 리터럴은 그 바이트 값을 가진 `u8` 정수 리터럴이므로 `u8`이 쓰이는 곳 어디서나 쓸 수 있습니다. 패턴과 패턴 범위(`b'0'..=b'9' => ..`)도 됩니다. 바이트 문자열 `b"..."`([1.7](107-string-literals.md))의 한 바이트짜리 짝입니다.

## 1.8.2. 두 종류를 분리한 이유

같은 토큰 형태(`'X'`)에 의미를 둘 붙이지 않고 접두로 나눕니다. 유니코드 의미의 문자와 C [ABI](../000-meta/007-glossary.md#abi-application-binary-interface)의 1바이트는 의미론이 다릅니다. 같은 표기로 묶으면 호환 함수를 호출할 때 의도를 밝힐 방법이 없습니다. `c` 접두는 "FFI와 닿는 코드"라는 표시를 눈에 보이게 남기기도 합니다.

## 1.8.3. 길이 강제 검증

일반 문자 리터럴은 코드포인트를, C 호환 문자 리터럴과 바이트 리터럴은 바이트를 정확히 하나 담아야 합니다. 컴파일러는 어휘 단계에서 이 길이를 검사합니다. 길이가 맞지 않으면 바로 에러입니다.

이렇게 정하면 다음 같은 모호함이 없어집니다. 결합 문자(`e\u{0301}` = `é`)는 문자 리터럴 하나에 담을 수 없습니다. 코드포인트가 둘이기 때문입니다. 이런 글자는 문자열 리터럴에 두어야 합니다. 그래핌 클러스터 단위로 "눈에 한 글자"로 보이는 것도 문자 리터럴이 아니라 문자열 쪽 개념으로 다룹니다.

이렇게 단순화하면 "문자 = 코드포인트 한 개"라는 정의가 어휘 단계부터 일관되게 유지됩니다.
