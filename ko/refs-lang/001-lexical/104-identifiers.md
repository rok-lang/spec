# 1.4. 식별자

식별자는 변수와 함수, 타입, 모듈 등에 이름을 붙이는 토큰입니다.

## 1.4.1. 형식

식별자는 유니코드 표준 부속서 #31 (UAX #31), Unicode Identifier and Pattern Syntax 의 기본 정의를 따릅니다.

```
identifier      ::= identifier_start identifier_continue*
identifier_start    ::= xid_start | "_"
identifier_continue ::= xid_continue
```

위에서 `xid_start` 는 `XID_Start` 속성을 갖는 코드포인트를 가리키며, `xid_continue` 는 `XID_Continue` 속성을 갖는 코드포인트를 가리킵니다.

`XID_Start` 와 `XID_Continue` 의 정의는 유니코드 표준이 결정하며, 본 사양은 그 표를 그대로 따릅니다. 사용자가 외워야 할 규칙은 다음 한 줄로 충분합니다.

> [!IMPORTANT]
> **사람의 언어로 변수 이름을 쓸 수 있습니다. 첫 글자가 숫자가 아니면 됩니다.**

### 정상 예

식별자로 인정되는 표기는 다음과 같습니다.

```rok
count
my_var
α
β2
Δt
σ²
변수1
データ
_internal
```

### 비정상 예

반면에 다음 표기는 식별자가 될 수 없습니다.

```rok
2x         // 첫 글자가 숫자
my-var     // '-' 는 식별자 글자가 아님
my var     // 공백
```

## 1.4.2. 정규화

식별자는 NFC (Normalization Form C) 로 정규화된 형태로 비교됩니다. 따라서 동일한 의미를 갖는 두 표기, 예를 들어 사전합성된 `é` 와 결합 형태인 `e + ◌́` 는 같은 식별자로 취급됩니다. 컴파일러는 식별자를 토큰화한 직후에 NFC 로 정규화합니다.

이러한 결정은 검색 가능성과 진단 메시지의 일관성을 확보하기 위한 것입니다.

## 1.4.3. 대소문자

식별자는 대소문자를 구분합니다. 따라서 `count` 와 `Count` 는 서로 다른 토큰입니다.

권장 명명 규약인 `snake_case`, `PascalCase`, `SCREAMING_SNAKE` 은 스타일 가이드의 영역에 속하며, 사양이 강제하지는 않습니다.

## 1.4.4. 키워드와의 충돌

다음 문서에서 정의하는 예약어와 정확히 일치하는 토큰은 식별자가 아니라 키워드로 분류됩니다. 예약어를 식별자로 쓸 수 있게 하는 raw 식별자, 이를테면 Rust 의 `r#fn` 과 같은 장치는 도입하지 않습니다. 혼동의 비용이 거기서 얻는 가치보다 크다고 판단했습니다.

## 1.4.5. 길이 제한

본 사양은 식별자 길이의 상한을 정하지 않으며, [소스 파일](101-source-files.md) 의 일반 규칙을 따릅니다.

## 1.4.6. 단일 밑줄

밑줄 한 글자 (`_`) 는 식별자로 인정됩니다만, 패턴 매칭과 값 폐기에서 특별한 의미를 갖습니다. 그 의미는 패턴 사양에서 정의합니다. 어휘 단계에서는 한 글자짜리 식별자로 토큰화됩니다.
