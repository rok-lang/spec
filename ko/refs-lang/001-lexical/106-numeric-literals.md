# 1.6. 숫자 리터럴

이 절은 소스 코드에 직접 적은 숫자 글자열을 토큰화하는 규칙과 각 리터럴의 타입을 정하는 규칙을 다룹니다.

## 1.6.1. 기본 형태

숫자 리터럴의 문법은 다음과 같습니다.

```
numeric_lit ::= int_lit | float_lit
int_lit     ::= dec_lit | hex_lit | bin_lit | oct_lit
dec_lit     ::= dec_digit ("_"? dec_digit)*
hex_lit     ::= ("0x" | "0X") hex_digit ("_"? hex_digit)*
bin_lit     ::= ("0b" | "0B") bin_digit ("_"? bin_digit)*
oct_lit     ::= ("0o" | "0O") oct_digit ("_"? oct_digit)*
float_lit   ::= dec_lit "." dec_digit_seq? exponent?
              | dec_lit exponent
exponent    ::= ("e" | "E") ("+" | "-")? dec_digit_seq
dec_digit_seq ::= dec_digit ("_"? dec_digit)*
dec_digit   ::= [0-9]
hex_digit   ::= [0-9a-fA-F]
bin_digit   ::= [01]
oct_digit   ::= [0-7]
```

### 진법

지원하는 진법과 표기는 다음과 같습니다.

| 진법 | 접두           | 허용 자릿수               | 예             |
|------|----------------|---------------------------|----------------|
| 10진 | 없음           | `0`-`9`                   | `42`, `1024`   |
| 16진 | `0x` 또는 `0X` | `0`-`9`, `a`-`f`, `A`-`F` | `0xFF`, `0X1a` |
| 2진  | `0b` 또는 `0B` | `0`, `1`                  | `0b1010`       |
| 8진  | `0o` 또는 `0O` | `0`-`7`                   | `0o755`        |

10진 외의 진법은 정수 리터럴에만 씁니다. 부동소수 리터럴은 10진 표기만 쓸 수 있습니다.

앞에 0이 붙은 10진 정수 리터럴(예: `0123`)은 컴파일 에러입니다. Rok은 C나 Java에서 흔한 "앞자리 0 = 8진수" 규칙을 따르지 않고, `0123`을 10진수 `123`으로 읽으면 그 규칙에 익숙한 사람이 헷갈리기 때문입니다. 8진수는 `0o` 접두를 붙여 적습니다. help는 8진수인 `0o123`과 10진수인 `123`을 제안합니다. `0` 자체와 부동소수 리터럴(`0.5`, `00.5`)은 괜찮습니다.

### 자릿수 구분자

읽기 쉽도록 자릿수 사이에 밑줄(`_`)을 넣을 수 있습니다.

```rok
1_000_000
0xFFFF_FFFF
0b1010_0101
3.141_592_653
```

밑줄 규칙은 다음과 같습니다.

- `_`는 숫자와 숫자 사이에만 올 수 있습니다. 첫 글자나 마지막 글자가 `_`이면 안 됩니다.
- 진법 접두 바로 뒤(`0x_FF`)나 소수점 바로 앞(`1_.0`)에 `_`가 오면 안 됩니다. `1._0`은 실수 리터럴이 아닙니다. `1` 뒤에 필드 접근 `._0`이 오는 것으로 어휘 분석되며, `i32`에는 그런 필드가 없습니다.
- 연속된 밑줄(`1__000`)은 컴파일러가 거부합니다.
- `_`는 평가할 때 무시하므로 `1_000`과 `1000`은 같은 값입니다.

### 부동소수 형태

다음 두 형태 가운데 하나에 맞으면 부동소수 리터럴입니다. 그렇지 않으면 정수 리터럴이거나 별개의 토큰입니다.

```
digit+  '.'  digit*  exponent?         // 1.5, 1., 1.5e10, 0.5
digit+              exponent           // 2e10  (점 없이 지수만 있어도 부동소수)
```

부동소수 리터럴은 소수점 앞에 자릿수가 있어야 합니다. `0.5`로 적으며 `.5`는 부동소수가 아닙니다. `.` 다음에 자릿수가 오는 형태는 언제나 튜플 인덱스(`t.0`, `t.5`)입니다.

지수부(`exponent`)는 `e` 또는 `E`, 선택적인 부호(`+` 또는 `-`), 한 자리 이상의 10진 자릿수로 이루어집니다. 따라서 `1.`, `0.5`, `1.5e10`, `2e-3`, `6.022e23`은 모두 올바른 부동소수 리터럴입니다. 점만 있고 양쪽이 빈 경우(`.`)는 부동소수가 아니라 별개의 토큰입니다.

#### `1.`과 `1.foo`의 구분

`digit+ '.'` 형태(`1.`)는 점 뒤에서 식별자가 시작되지 않을 때만 부동소수로 토큰화합니다. 경우별 결과는 다음과 같습니다.

| 입력                       | 토큰화                                                |
|----------------------------|-------------------------------------------------------|
| `1.5`                      | 부동소수 `1.5` 한 토큰                                |
| `1.` (뒤가 끝/공백/구두점) | 부동소수 `1.` 한 토큰                                 |
| `1.foo`                    | 정수 `1`, `.`, 식별자 `foo` 세 토큰                   |
| `1 .foo`                   | 같음(공백은 토큰 분리 결과에 영향 없음)               |
| `1..2`                     | 정수 `1`, `..`, 정수 `2` 세 토큰(`..`가 더 긴 일치)  |
| `1.+2`                     | 부동소수 `1.`, `+`, 정수 `2` 세 토큰                  |

한 줄로 줄이면 이렇습니다. 숫자 중간의 `.` 뒤 첫 글자가 `XID_Start`이거나 또 다른 `.`이면 그 `.`은 부동소수의 일부가 아닙니다. 그 밖의 경우(구두점, 연산자 글자, 입력 끝)에는 부동소수에 들어갑니다.

## 1.6.2. 타입 접미사

리터럴 뒤에 접미사를 붙이면 그 리터럴의 구체 타입을 정할 수 있습니다.

```rok
42i32
3.14f64
2i              // 패키지가 등록한 접미사(6.5), 예: 허수 단위
0xFFu8
1_000_000i64
```

접미사는 리터럴의 마지막 글자 바로 뒤에 공백 없이 붙고 식별자 글자(`XID_Continue`)로만 이루어집니다. 어휘상으로는 토큰 하나의 일부입니다. 렉서는 숫자 본체와 접미사 문자열을 묶어 토큰 하나로 만듭니다.

숫자 타입 이름 접미사(`i8` `i16` `i32` `i64` `isize` `u8` `u16` `u32` `u64` `usize` `c_char` `f32` `f64`)는 언어가 정의합니다. 이 접미사는 리터럴의 타입을 그 타입으로 정합니다. `i128` / `u128`은 예약어입니다. Rok에는 128비트 정수가 없습니다(`int`가 모든 크기를 담음). 이 두 접미사가 붙은 리터럴은 에러이며, 에러 메시지가 대신 쓸 64비트 접미사나 `int`를 알려 줍니다. `f32` / `f64` 접미사는 10진 정수 형태에도 붙일 수 있습니다(`1f64`). 16진 리터럴에서 `f`는 숫자이므로 `0x1f32`는 `0x1`에 접미사 `f32`가 붙은 것이 아니라 16진 값 `0x1F32`입니다. 그 밖의 접미사(`2i` 등)는 핸들러가 해석합니다. 핸들러는 패키지가 [`#[literal(...)]` 매직](../006-meta-system/605-literal-magic.md)으로 등록합니다.

## 1.6.3. 접미사 없는 리터럴

접미사가 없는 리터럴(`42`, `3.14`)의 타입은 기대 타입이 정합니다.

- 정수 리터럴: 기대 타입이 정수 또는 실수 타입이면 그 타입입니다. 기대 타입이 없으면 `i64`입니다.
- 실수 리터럴: 기대 타입이 실수 타입이면 그 타입입니다. 기대 타입이 없으면 `f64`입니다. 정수 타입 자리에는 올 수 없습니다.
- 임의 정밀도 표준 타입 `int`와 `float`도 여기에 들어갑니다. 정수 리터럴은 `int`나 `float`가, 실수 리터럴은 `float`가 될 수 있습니다. 이 타입은 어떤 값이든 담으므로 범위 검사가 없습니다.
- 이항 연산에서 한쪽 피연산자의 타입이 정적으로 정해져 있으면 그 타입이 리터럴 쪽의 기대 타입이 됩니다.
- 정수 리터럴을 실수 타입 자리에 둘 때 그 실수 타입이 값을 정확히 표현하지 못하면 컴파일 에러입니다(`let f: f32 = 16777217;`).
- 기대 타입이 정수 타입 항이 있는 합 타입이면 정수 리터럴은 그 정수 타입이 됩니다(`let v: i64 | f64 = 1;`의 `1`은 `i64`).
- 합 타입에 정수 항이 둘 이상이고 부동소수점 항이 있으면, 접미사 없는 정수 리터럴은 모호하므로 컴파일 에러입니다(`let v: u16 | u8 | f32 = 1;`). 접미사를 붙여 `1u16`이나 `1u8`로, 부동소수점 항이라면 `1.0`으로 씁니다. 부동소수점 항이 없으면 그런 리터럴은 `i64`이고, 다른 `i64` 값처럼 합 타입과 대조합니다.
- 접미사 없는 리터럴끼리의 산술(`1 + 2`, `-1`, `2 * (3 + 4)`)은 타입이 정해진 피연산자나 기대 타입을 만날 때까지 타입이 정해지지 않은 채 남습니다. 만나면 식 전체가 그 타입이 됩니다. 끝까지 만나지 않으면 위 기본값(`i64` / `f64`)이 됩니다.
- `if` / `else`의 한 분기, 또는 슬롯이 타입을 정하지 않는 `match`의 한 갈래가 접미사 없는 정수 리터럴이고 다른 것이 정수 타입이면 리터럴은 그 타입을 따릅니다.
- C 가변 인자 함수의 `...` 자리([8.6](../008-abi/806-calling-convention.md))에서 접미사 없는 정수 리터럴은 `i32`(C `int`)입니다.

기대 타입은 `let`의 타입 주석, 인자 자리의 매개변수 타입, 반환 자리의 반환 타입, 위 이항 연산 규칙에서 나옵니다.

주석 없는 `let`이 묶는 리터럴은 선언 자리에 기대 타입이 없습니다. 그 타입은 추론 변수이고, 변수의 범위(블록의 나머지, 클로저 포함)에서 뒤따르는 사용이 정합니다([5.1.7](../005-modules/501-variable-declaration.md#517-타입-명시와-타입-추론)). 어떤 사용도 정하지 않을 때만 기본값이 적용됩니다.

- 대상: 초기화 식이 리터럴(`let c = 0`, `let c = -1`), 리터럴 산술(`let n = 1 + 2`), 분기가 모두 리터럴인 `if` / `match`(`let f = if b { 1 } else { 0 }`)이거나, 초기화 식의 직접 원소나 인자(`let xs = [0, 0]`, `let (a, b) = (0, 1)`, `let n = Atomic::new(0)`)인 리터럴입니다.
- 타입을 정하는 사용: 열린 `let`의 타입을 정하는 모든 사용(인자, 대입, 주석 있는 `let`, `return`, 본문의 값)과, 다른 피연산자의 타입이 정해진 연산자(`c += x`, `c < limit`)입니다.
- 경계가 리터럴인 `for i in 0..10`도 같습니다. `i`의 타입은 루프 본문이 정합니다.
- 음수 리터럴은 사용 때문에 부호 없는 타입이 되지 않습니다. `let i = -1; xs[i]`의 `i`는 `i64`(끝에서 세는 인덱스)로 남습니다.
- 함수 본문에서 기대 타입이 없는 접미사 없는 리터럴은 처음부터 정수 또는 실수 타입 변수(`{integer}` / `{float}`)입니다. 모든 쓰임이 다른 타입 변수처럼 이를 단일화합니다. 인자와 제네릭 바운드(`where` 절 포함) 및 연관 타입(`List<Task<i32>>`로 가는 `tasks.push(spawn(async { 0 }))`), 클로저 반환과 주석 붙은 클로저 매개변수, 반복자 어댑터를 거친 타입이 정해진 `collect()` 대상(`(0..4).chain(7..10).collect::<List<i32>>()`), 연산자, `if` / `match` 분기와 `break` 값, 합 슬롯의 숫자 멤버 하나, 타입 패턴, 구조체 바운드 아래의 구조체 리터럴 타입 인자(`B<T: Num>`의 `B { v: 3 }`), 암묵 제네릭의 본문(`add(1, x_i32)`로 부른 `fn add(a, b) { a + b }`), 그 종류의 숫자 타입 가운데 맞는 impl·트레잇·연산자 하나(`Twice`가 `i32`에만 구현될 때 `9.once()`, `Foo`가 `(i32, i32)`에만 있을 때 `(1, 2).foo()`, `Wave::hi(3)`, `i32`에 `Div<NonZero<i32>>`가 있을 때 `84 / nz`)가 그렇습니다. 본문은 한 번 검사되고, 그 끝에서 아무것도 정하지 않은 변수가 기본값을 받습니다.
- `const` 항목의 값, 필드 기본값, 매개변수 기본값은 각각 선언된 타입에 맞춰 따로 검사된 뒤 평가됩니다.
- 타입이 곧바로 하나여야 하는 쓰임은 그 자리에서 변수를 정합니다. 그 종류의 숫자 타입 가운데 정확히 하나만 맞으면 변수는 그 타입이고, 아니면 그 자리에서 기본값을 받습니다. 변수의 타입이 아직 갖지 않은 메서드 호출(제네릭 impl이나 블랭킷 impl의 메서드는 열어 둡니다), 트레잇으로 한정한 호출(`Tr::f(x)`), 오버로드 호출(`int::from(i)`), `any`에 담기가 그렇습니다. f-string 구멍은 변수를 정하지 않습니다.
- 숫자 슬롯에 놓인 리터럴 수신자는 슬롯의 타입을 받고(`let n: i32 = 7.max(-2)`), 합으로 가는 튜플이나 리스트 리터럴은 그 모양의 멤버를 받습니다.
- 변환은 더해지지 않습니다. 정수 리터럴은 실수 타입이 되지 않고, 서로 다른 타입을 원하는 두 사용은 두 번째 사용에서 에러이며, 리터럴로 묶은 `let`이면 첫 번째를 가리킵니다(`` conflicting uses of `c`: `i64` here, but `i32` fixed at 16:16 ``). 도움말은 사용 자리의 캐스트가 아니라 선언(`let c: i64 = 0`, `let t = 0.0`)을 가리킵니다.

```rok
let a = 42;              // i64
let b = 3.14;            // f64
let x: f64 = 1;          // f64
let y: u8 = 200;         // u8
let r = a * 2;           // 2 는 i64 (a 를 따름)
let s: f64 = 2.0;
let t = s * 2;           // 2 는 f64 (s 를 따름)
let e: i32 = 1.5;        // ERROR: 실수 리터럴은 정수 타입 불가
let w: i64 = 7i64;
let k = w + (1 + 2);     // 1 + 2 는 i64 (w 를 만나서)
let m: u8 = 2 * 100;     // 2 * 100 은 u8 (기대 타입)
let n = 1 + 2;           // i64 (끝까지 정해지지 않음 → 기본값)
let v = if flag { 0 } else { w };   // 0 은 i64 → v: i64

fn count(xs: List<i32>) -> i32 {
    let c = 0;                // i32: 아래 본문의 값이 정함
    for x in xs { if x > 0 { c += 1; } }
    c
}
let t = 0;
let big: List<u64> = [1, 2];
for x in big { t += x; }      // t: u64
let z = 0;
let f: f64 = z;               // ERROR: `z`는 정수; `let z = 0.0;`으로 씀
```

## 1.6.4. 범위 검사

리터럴 값이 타입의 범위를 벗어나면 컴파일 에러입니다. 16진, 8진, 2진 리터럴도 10진과 같은 범위 규칙을 따릅니다.

```rok
let a: u8 = 256;         // ERROR: u8 범위 밖
let b = 0xFFi8;          // ERROR: 255 는 i8 범위 밖
let c = 0xFFu8 as i8;    // OK: 비트 패턴이 필요하면 as 로 변환 (-1)
```

리터럴과 상수만으로 된 산술은 컴파일 타임에 접습니다. 결과가 타입의 범위를 넘거나 0으로 나누면 컴파일 에러입니다([5.2.4](../005-modules/502-const.md#524-상수-식과-평가기)).

```rok
let m: u8 = 2 * 200;     // ERROR: 400 은 u8 범위 밖
```

## 1.6.5. 거부되는 형태

다음 입력은 어휘 단계에서 바로 에러입니다.

| 입력    | 거부 사유                |
|---------|--------------------------|
| `0x`    | 16진 접두 뒤 자릿수 없음 |
| `0b`    | 2진 접두 뒤 자릿수 없음  |
| `0o`    | 8진 접두 뒤 자릿수 없음  |
| `1__0`  | 연속된 `_`               |
| `1_`    | `_`로 끝남              |
| `0x_FF` | 진법 접두 바로 뒤 `_`    |
| `1e`    | 지수부에 자릿수 없음     |

`_1`은 숫자 리터럴이 아니라 식별자로 토큰화합니다. 거부되는 입력이 아니라 종류가 다른 토큰입니다.

## 1.6.6. 음수

음수 리터럴이라는 별도 토큰은 없습니다. `-42`는 단항 연산자 `-`와 리터럴 `42`, 두 토큰입니다. 리터럴 자체는 항상 음이 아닌 형태로 토큰화합니다.

범위 검사에는 예외가 하나 있습니다. 단항 `-` 바로 뒤의 리터럴은 그 타입의 `MAX + 1`까지 쓸 수 있습니다. 그래서 `-128i8`은 `i8`의 최솟값입니다. 이항 연산의 피연산자에는 이 예외가 없습니다.

```rok
let m = -128i8;          // OK: i8::MIN
let n = a - 128i8;       // ERROR: 128 은 i8 범위 밖
```
