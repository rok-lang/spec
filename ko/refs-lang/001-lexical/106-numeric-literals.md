# 1.6. 숫자 리터럴

소스 코드에 직접 적힌 숫자 글자열을 토큰화하는 규칙. 본 문서는 형식만 다룬다. 각 리터럴이
어떤 타입으로 평가되는지는 타입 시스템과 표준 라이브러리의 몫이다.

## 1.6.1. 기본 형태

```
numeric_lit ::= int_lit | float_lit
int_lit     ::= dec_lit | hex_lit | bin_lit | oct_lit
dec_lit     ::= dec_digit ("_"? dec_digit)*
hex_lit     ::= ("0x" | "0X") hex_digit ("_"? hex_digit)*
bin_lit     ::= ("0b" | "0B") bin_digit ("_"? bin_digit)*
oct_lit     ::= ("0o" | "0O") oct_digit ("_"? oct_digit)*
float_lit   ::= dec_lit "." dec_digit_seq? exponent?
              | "." dec_digit_seq exponent?
              | dec_lit exponent
exponent    ::= ("e" | "E") ("+" | "-")? dec_digit_seq
dec_digit_seq ::= dec_digit ("_"? dec_digit)*
dec_digit   ::= [0-9]
hex_digit   ::= [0-9a-fA-F]
bin_digit   ::= [01]
oct_digit   ::= [0-7]
```

### 진법

| 진법 | 접두           | 허용 자릿수               | 예             |
| ---- | -------------- | ------------------------- | -------------- |
| 10진 | 없음           | `0`-`9`                   | `42`, `1024`   |
| 16진 | `0x` 또는 `0X` | `0`-`9`, `a`-`f`, `A`-`F` | `0xFF`, `0X1a` |
| 2진  | `0b` 또는 `0B` | `0`, `1`                  | `0b1010`       |
| 8진  | `0o` 또는 `0O` | `0`-`7`                   | `0o755`        |

10 진수 외의 진법은 정수 리터럴에만 사용한다. 부동소수 리터럴은 10 진 표기만 허용한다.

선행 0 (예: `0123`) 은 오직 한 가지 의미만 갖는다. 10진수 `123` 이다. C 와 Java 식의
_선행 0 = 8진수_ 규칙은 도입하지 않는다 (8진은 반드시 `0o` 접두를 사용한다).

### 자릿수 구분자

가독성을 위해 자릿수 사이에 밑줄 (`_`) 을 둘 수 있다.

```nok
1_000_000
0xFFFF_FFFF
0b1010_0101
3.141_592_653
```

규칙:

- `_` 는 숫자 사이에만 위치한다. 첫 글자나 마지막 글자가 `_` 일 수 없다.
- `_` 는 진법 접두 직후 (`0x_FF`) 나 소수점 직전이나 직후 (`1_.0`, `1._0`) 에 올 수 없다.
- 연속된 `_` (`1__000`) 는 거부된다.
- `_` 는 평가 시 무시된다. `1_000` 과 `1000` 은 같은 값.

### 부동소수 형태

다음 세 형태 중 하나면 부동소수 리터럴이다 (그 외는 정수 리터럴 또는 별개 토큰).

```
digit+  '.'  digit*  exponent?         // 1.5, 1., 1.5e10
        '.'  digit+  exponent?         // .5
digit+              exponent           // 2e10  (점 없이 지수만 있어도 부동소수)
```

- 지수부 (`exponent`): `e` 또는 `E`, 선택적 부호 (`+` 또는 `-`), 한 자리 이상의 10진 자릿수.
- `1.`, `.5`, `1.5e10`, `2e-3`, `6.022e23` 모두 정상 부동소수 리터럴이다.
- 점만 있고 양쪽이 비면 (`.`) 부동소수가 아니라 별개 토큰으로 분리된다.

#### `1.` 와 `1.foo` 의 구분

`digit+ '.'` 형태 (`1.`) 는 점 뒤에 식별자가 시작되지 않을 때만 부동소수로 토큰화된다.

| 입력                       | 토큰화                                                |
| -------------------------- | ----------------------------------------------------- |
| `1.5`                      | 부동소수 `1.5` 한 토큰                                |
| `1.` (뒤가 끝/공백/구두점) | 부동소수 `1.` 한 토큰                                 |
| `1.foo`                    | 정수 `1`, `.`, 식별자 `foo` 세 토큰                   |
| `1 .foo`                   | 동일 (공백은 토큰 분리 결과에 영향 없음)              |
| `1..2`                     | 정수 `1`, `..`, 정수 `2` 세 토큰 (`..` 가 더 긴 일치) |
| `1.+2`                     | 부동소수 `1.`, `+`, 정수 `2` 세 토큰                  |

규칙을 한 줄로: 숫자 도중의 `.` 뒤 첫 글자가 `XID_Start` 이거나 또 다른 `.` 이면 그 `.`
은 부동소수의 일부가 아니다. 그 외(구두점, 연산자 글자, 입력 끝) 면 부동소수에 흡수된다.

## 1.6.2. 타입 접미사

리터럴 뒤에 접미사를 붙이면 그 리터럴이 어떤 구체 타입으로 평가될지를 명시할 수 있다.

```nok
42i32
3.14f64
2i              // 허수 단위 (예: 복소수)
0xFFu8
1_000_000i64
```

접미사의 형식은 다음과 같다.

- 리터럴의 마지막 글자 직후, 공백 없이 붙는다.
- 식별자 글자 (`XID_Continue`) 로만 구성된다.
- 어휘적으로는 한 토큰의 일부로 보존된다. 렉서는 숫자 본체와 접미사 문자열을 함께 토큰
  하나로 만든다.

접미사가 어떤 타입을 의미하는지에 대한 해석은 본 1장의 영역이 아니다. 표준 라이브러리의 리터럴
핸들러 ([`#[literal(...)]` 매직](../006-meta-system/605-literal-magic.md)) 가 결정한다. 컴파일러는 어휘 단계에서 문법적으로 유효한
접미사인지만 검사하며, 의미 검증은 후속 단계에서 수행한다.

## 1.6.3. 접미사 없는 리터럴

접미사가 없는 리터럴 (`42`, `3.14`) 도 정상 토큰이다. 이 경우 어떤 타입으로 평가될지도
표준 라이브러리의 리터럴 핸들러가 결정한다. 본 문서 범위 밖이다.

## 1.6.4. 거부되는 형태

다음 입력은 어휘 단계에서 즉시 에러다.

| 입력    | 거부 사유                |
| ------- | ------------------------ |
| `0x`    | 16진 접두 뒤 자릿수 없음 |
| `0b`    | 2진 접두 뒤 자릿수 없음  |
| `0o`    | 8진 접두 뒤 자릿수 없음  |
| `1__0`  | 연속된 `_`               |
| `1_`    | `_` 로 끝남              |
| `0x_FF` | 진법 접두 직후 `_`       |
| `1e`    | 지수부에 자릿수 없음     |

`_1` 은 숫자 리터럴이 아니라 식별자로 토큰화된다. 거부가 아니라 다른 종류의 토큰이다.

## 1.6.5. 음수

음수 리터럴이라는 별도 토큰은 없다. `-42` 는 단항 연산자 `-` 와 리터럴 `42` 두 토큰이다.
리터럴 자체는 항상 음이 아닌 형태로 토큰화된다.

이 결정은 어휘 단계를 단순하게 유지하기 위한 것이다. 표현식 단계에서 단항 마이너스가 적용된다.
