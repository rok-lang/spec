# 1.3. 문장 종결자

> [!IMPORTANT]
> Rok의 문장은 세미콜론(`;`)으로 끝납니다. 줄바꿈만으로는 문장을 끝낼 수 없습니다.

```
stmt_terminator ::= ";"
```

## 1.3.1. 규칙

문장 종결자의 규칙은 단순합니다. 한 문장은 `;` 하나로 끝나며, 한 줄에 여러 문장을 둘 수 있습니다. 한 문장이 여러 줄에 걸쳐도 됩니다. 줄바꿈은 토큰 사이의 공백일 뿐이기 때문입니다.

도식은 다음과 같습니다.

```
<문장> ;
<문장> ; <문장> ;             // 한 줄에 여러 개
<문장의
 일부가 여러 줄에 걸침> ;    // 여러 줄. 마지막 ; 에서 종료
```

## 1.3.2. 줄바꿈 자동 삽입을 두지 않는 이유

Rok은 JavaScript의 ASI(Automatic Semicolon Insertion), Go의 줄 끝 자동 세미콜론, Swift의 줄 단위 종료 같은 자동 규칙을 도입하지 않습니다.

이유는 세 가지입니다. 첫째, 자동 규칙은 드물게 모호성을 만듭니다. JavaScript의 ASI 함정이 잘 알려진 예입니다. 둘째, 종결자를 직접 적어야 포매터, LSP, 에디터의 다음 문장 점프 같은 도구가 문장 경계를 확실하게 알 수 있습니다. 셋째, 한 줄에 여러 문장을 두는 표기는 REPL에서 빠르게 입력할 때처럼 자연스러운 곳이 있습니다.

## 1.3.3. 빈 문장

`;`만 있는 빈 문장도 쓸 수 있으며 아무 효과가 없습니다.

```rok
;;;
```

위 코드는 빈 문장 세 개입니다. 도구가 생성하는 코드에 여유를 주려고 이런 형태를 받아들입니다.

## 1.3.4. 블록류 식 문장

블록류 식은 `}`로 끝나는 식입니다. `if`, `match`, `loop`, `while`, `for`, 블록(`{ }`, `unsafe { }`, 라벨 블록)이 여기에 속합니다. 블록류 식이 문장 자리에 오면 뒤의 `;`를 생략할 수 있습니다. Rust와 같은 규칙입니다. 이때 그 식의 값은 unit이어야 합니다. unit이 아닌 값을 버리려면 `;`를 붙입니다.

본문이 블록인 [트레일링 클로저](../004-functions/408-trailing-closure.md)가 붙은 호출(`retry(3) { .. }`, `xs.each |x| { .. }`)도 `;` 없이 문장을 끝냅니다([4.8.8](../004-functions/408-trailing-closure.md)). 이때 호출의 값은 `;`를 붙인 것처럼 버려집니다.

```rok
if ready { start(); }        // ; 없음
for x in xs { print(x); }
let n = if a { 1 } else { 2 };   // let 문은 여전히 ; 로 끝남
```

키워드로 시작하는 블록류 식 문장(`if`, `match` 등)의 `}` 다음에 이항 연산자가 오면 새 문장이 시작됩니다. 앞 식에 이어지는 것은 `.method()` 같은 멤버 접근과 후위 `?`뿐입니다. 트레일링 클로저 호출 뒤의 이항 연산자는 그 호출에 이어지는 것으로 파싱합니다.

```rok
if c { a(); } else { b(); }
-x;                          // 새 문장 (if 문 - x 가 아님)
match v { ... }.len();       // . 는 이어짐
```

블록류가 아닌 식이 블록 중간에 문장으로 오면 `;`가 필요합니다. `;` 없이 둘 수 있는 것은 블록의 마지막 식(블록의 값)뿐입니다.

문법은 [블록 표현식](../003-expressions/309-block-expressions.md#391-형태)의 `stmt`에서 정의합니다.

## 1.3.5. 다른 토큰과 인접

`;` 토큰은 앞뒤 토큰과 공백 없이 붙어 있어도 됩니다. `<문장>;<문장>;`처럼 붙여 써도 두 문장으로 토큰화됩니다. 읽기 쉽게 공백을 두는 스타일을 권장하지만 사양이 스타일을 강제하지는 않습니다.
