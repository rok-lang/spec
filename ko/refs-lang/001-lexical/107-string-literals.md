# 1.7. 문자열 리터럴

문자열 리터럴은 문자의 나열을 표현하는 토큰이다. 본 문서는 어휘 형식만 다룬다. 결과가 어떤
라이브러리 타입으로 평가되는지는 표준 라이브러리의 리터럴 핸들러가 결정한다.

## 1.7.1. 일반 문자열

```
string_lit  ::= '"' string_item* '"'
string_item ::= string_char | escape_seq
string_char ::= <any unicode codepoint except '"' or '\'>
escape_seq  ::= "\\" ("\\" | "\"" | "'" | "n" | "r" | "t" | "0")
              | "\\x" hex_digit hex_digit
              | "\\u" "{" hex_digit ("_"? hex_digit){0,5} "}"
              | "\\" line_terminator whitespace*
```

쌍따옴표 (`"`) 로 둘러싼다.

```nok
"hello"
"hello, 세계"
""
"여러
줄에
걸친 문자열"
```

규칙:

- 내부에 임의 유니코드 코드포인트를 포함할 수 있다.
- 줄바꿈을 그대로 포함할 수 있다. 끝까지 닫히지 않으면 컴파일 에러.
- 닫는 `"` 가 같은 파일에 있어야 한다. 파일 끝에서 닫히지 않은 문자열은 에러.

### 이스케이프 시퀀스

다음 이스케이프 시퀀스를 인식한다.

| 시퀀스     | 의미                                                           |
| ---------- | -------------------------------------------------------------- |
| `\\`       | 백슬래시 (`U+005C`)                                            |
| `\"`       | 쌍따옴표 (`U+0022`)                                            |
| `\'`       | 작은따옴표 (`U+0027`)                                          |
| `\n`       | 줄바꿈 (`U+000A`)                                              |
| `\r`       | 캐리지 리턴 (`U+000D`)                                         |
| `\t`       | 탭 (`U+0009`)                                                  |
| `\0`       | NULL (`U+0000`)                                                |
| `\xHH`     | 1바이트 (16진 두 자리, `U+0000`-`U+007F` 만 허용 — ASCII 범위) |
| `\u{H...}` | 임의 유니코드 코드포인트 (16진 1~6 자리, 최대 `U+10FFFF`)      |

`\u{...}` 의 16진 자리는 `_` 로 구분할 수 있다 (`\u{1_F600}`).

위 외의 백슬래시 시퀀스는 모두 어휘 에러다. 알려지지 않은 이스케이프를 암묵적으로 원본
문자로 두지 않는다.

### 줄 바꿈 잇기

문자열 안의 백슬래시가 줄 종결자 바로 앞에 오면, 그 백슬래시, 줄 종결자, 다음 줄의 선행
공백이 모두 생략된다.

```nok
"한 줄로 \
 보이는 긴 문자열"
// 결과 내용: "한 줄로 보이는 긴 문자열"
```

이 규칙은 긴 문자열을 소스에서 여러 줄로 쓰면서도 결과에 줄바꿈을 넣지 않기 위한 것이다.

## 1.7.2. 원시 문자열

`r` 접두와 쌍따옴표.

```nok
r"raw\n"
r"C:\path\to\file"
```

원시 문자열 안에서는 어떤 이스케이프도 처리되지 않는다. `\n` 은 두 글자 그대로 보존된다.

원시 문자열에 닫는 `"` 가 내용에 필요한 경우, 양쪽에 같은 수의 `#` 을 둘러 구분자를
바꾼다.

```nok
r#"문자열 안에 "쌍따옴표"가 있어도 됨"#
r##"r#"이런 형태"#도 가능"##
```

여는 `r##"` 은 닫는 `"##` 와 정확히 같은 수의 `#` 으로 끝나야 한다. 실제 세는 글자는 여는
쪽의 `#` 개수다.

원시 문자열은 줄바꿈 잇기 (`\` + 줄 종결자) 를 지원하지 않는다. 모든 글자를 그대로 보존하는
것이 원시 문자열의 정의다.

## 1.7.3. 형식 문자열

`f` 접두와 쌍따옴표. 표현식 삽입을 지원한다.

```nok
f"x = {x}"
f"sum = {a + b}, diff = {a - b}"
```

규칙:

- `{` 와 `}` 사이는 임의의 표현식으로 해석된다. 본 어휘 사양은 그 경계 검출까지 책임진다.
- 리터럴 중괄호가 필요하면 `{{` 와 `}}` 로 이스케이프한다.

### 형식 지정자

표현식 뒤에 콜론 (`:`) 을 두고 형식 지정자를 적을 수 있다.

```nok
f"{x:.2f}"        // 소수점 둘째 자리까지
f"{n:0>5d}"       // 5자리 0 채움 우측 정렬
f"{val:?}"        // 디버그 형식
```

형식 지정자의 문법:

```
spec  := [fill][align][sign]['#'][0][width]['.'precision][type]
align := '<' | '>' | '^' | '='
type  := 'd' | 'b' | 'o' | 'x' | 'X' | 'f' | 'e' | 'E' | 'g' | 's' | '?'
```

각 type 글자가 어떤 트레잇 메서드를 호출하는지의 매핑은 표준 라이브러리의 형식화 사양에서
정의한다. 본 문서 범위 밖이다.

### 동적 형식 지정자

형식 지정자 안에서 `${ ... }` 로 표현식을 끼워 넣을 수 있다.

```nok
f"{x:.${prec}f}"          // 동적 정밀도
f"{x:>${width}.${prec}f}" // 동적 너비 + 정밀도
f"{val:${full_spec}}"     // 전체 지정자 동적
f"{count:0${w}d}"         // 동적 너비의 0 채움
```

`${ ... }` 안의 표현식은 평가되어 문자열로 변환된 뒤 형식 지정자 텍스트의 일부가 된다.
펼친 결과는 다시 위의 `spec` 문법을 만족해야 한다. 만족하지 않으면 형식화 시점 에러다.
표현식의 평가 시점은 일반 표현식과 같다 (형식화 직전).

리터럴 `$` 가 형식 지정자 안에 필요하면 `$$` 로 표기한다. Python 의 중첩 `{{...}}` 식 표기를
지정자 안에서 채택하지 않은 이유는 시각적 잡음을 줄이기 위함이다.

`f"cost: $100"` 처럼 `${...}` 패턴이 아닌 단독 `$` 는 그대로 보존된다.

### 어휘 처리

렉서는 형식 문자열을 다음과 같이 분해된 토큰 시퀀스로 출력한다.

```
F_STRING_START
  STRING_PART      "x = "
  EXPR_START
    (일반 토큰들 — 표현식)
  EXPR_END         (선택적 SPEC_PART 동반)
  STRING_PART      ", y = "
  EXPR_START
    ...
  EXPR_END
F_STRING_END
```

이 분해 덕분에 형식 문자열 안의 표현식은 일반 표현식 분석기가 그대로 처리한다. 형식 문자열
전용 파서가 따로 필요 없다.

## 1.7.4. 인접 문자열의 자동 결합

C 와 Python 식의 인접 문자열 자동 결합 (`"abc" "def"` → `"abcdef"`) 은 도입하지 않는다.
연결이 필요하면 명시적인 연산자나 메서드를 쓴다.
