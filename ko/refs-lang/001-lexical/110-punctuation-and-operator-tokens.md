# 1.10. 구두점과 연산자 토큰

연산자와 구두점 글자열의 토큰화 규칙. 어휘 형태만 다룬다. 각 토큰의 의미(우선순위, 결합성,
어떤 트레잇으로 디스패치되는지) 는 [3. 표현식](../003-expressions/README.md) 에서 정의한다.

## 1.10.1. 토큰화 원칙

연산자와 구두점 토큰화는 두 단계로 이루어진다.

1. **고정 토큰표.** 본 문서에 명시된 글자열은 항상 정해진 토큰으로 분리된다.
2. **확장 토큰표.** 표준 라이브러리가 메타 시스템을 통해 추가 등록한 글자열도 토큰이 된다.
   등록 메커니즘은 [`#[infix]` / `#[prefix]` / `#[postfix]` 매직](../006-meta-system/607-operator-magic.md) 에서 정의한다.

두 표 사이에 충돌이 생기면 등록 시점에 거부된다. 고정 토큰은 덮어쓸 수 없다.

## 1.10.2. 최장 일치

> [!IMPORTANT]
> 여러 토큰 후보가 가능한 입력에서는 가장 긴 일치가 선택된다.

| 입력  | 토큰화                            |
| ----- | --------------------------------- |
| `==`  | 한 토큰                           |
| `=`   | 한 토큰                           |
| `= =` | 두 토큰 (공백이 분리)             |
| `..=` | 한 토큰 (`..=` 가 `..` 보다 길다) |
| `..`  | 한 토큰                           |
| `<<=` | 한 토큰 (`<<=` 가 `<<` 보다 길다) |

## 1.10.3. 고정 토큰표

다음은 언어가 예약하는 ASCII 영역의 연산자, 구두점 글자열의 전체 목록이다. 표준 라이브러리는
이 토큰들에 의미를 부여(트레잇 메서드 매핑) 할 뿐이며, 토큰 형태는 본 표가 결정한다.

### 산술 / 비교 / 논리

```
+       -       *       /       %
==      !=      <       >       <=      >=
&&      ||      !
&       |       ^       ~       <<      >>
```

각 토큰이 어떤 트레잇 메서드를 호출하는지에 대한 매핑은 표준 라이브러리의 연산자 사양에서
정의된다. 본 문서는 어휘 토큰화만 보장한다.

### 브로드캐스트 (`.` 접두)

원소별 (broadcast) 연산을 위한 점-접두 형태. 위 산술/비교/논리 연산자에 점을 한 글자
앞에 붙인 형태가 별개의 토큰으로 분리된다.

```
.+      .-      .*      ./      .%
.==     .!=     .<      .>      .<=     .>=
.&      .|      .^      .<<     .>>
```

이 형태는 각각 점이 없는 형태와 다른 트레잇 메서드로 매핑된다 (예: `+` → `Add::add`,
`.+` → `DotAdd::dot_add`). 매핑은 표준 라이브러리에서 정의한다.

#### 부동소수 리터럴과의 구분

부동소수 리터럴 (`1.`, `1.5`) 이 점을 포함하므로, 다음 두 입력의 토큰화는 위치에 따라 달라진다.

| 입력   | 토큰화         | 이유                                               |
| ------ | -------------- | -------------------------------------------------- |
| `1.+2` | `1.`, `+`, `2` | `.` 가 숫자 직후이므로 부동소수의 일부로 흡수      |
| `a.+b` | `a`, `.+`, `b` | `.` 가 숫자 직후가 아니므로 브로드캐스트 토큰 시작 |

규칙: 숫자 리터럴 도중의 `.` 은 항상 부동소수의 일부이며, 그 외 위치의 `.` 은 다른 토큰
형태를 우선한다 ([숫자 리터럴](106-numeric-literals.md) 의 `.` 처리 규칙 참조).

### 대입 / 복합 대입

```
=       +=      -=      *=      /=      %=
&=      |=      ^=      <<=     >>=
```

복합 대입의 의미 (좌변 평가 횟수, 트레잇 매핑) 는 표현식 사양에서 정의한다.

### 범위 / 슬라이스

```
..      ..=     :       ::
```

- `..` 와 `..=`. 범위 표기.
- `:`. 슬라이스의 자리 구분자, 형식 지정자 도입자, 그 외 여러 문맥.
- `::`. 경로 구분자 (모듈이나 타입의 정적 항목 접근).

### 점 / 물음표

```
.       ?.      ??      ?
```

- `.`. 멤버 또는 메서드 접근.
- `?.`. 합 타입을 통과시키는 점 접근.
- `??`. 빈 자리 (`none`) 를 대체값으로 메우는 이항 연산.
- `?`. 단독 물음표. 의미는 후속 문서.

### 람다 / 화살표

```
|       ||      ->      =>
```

- `|`. 비트 OR, 합 타입 구분자, 람다 인자 구분자 (문맥에 따라).
- `||`. 논리 OR, 인자 없는 람다 시작.
- `->`. 함수 반환 타입 화살표.
- `=>`. `match` 가지 화살표.

### 구두점

```
(   )   [   ]   {   }
,   ;   @
```

- `( )`. 그룹화, 튜플, 호출.
- `[ ]`. 인덱싱, 슬라이스, 캡처 리스트, 배열 리터럴.
- `{ }`. 블록, 복합 리터럴, 구조체 리터럴.
- `,`. 인자나 항목 구분자.
- `;`. 문장 종결자 ([문장 종결자](103-statement-terminator.md) 참조).
- `@`. 메타 시스템의 토큰 (정확한 의미는 6장).

### 속성 도입자

```
#[      #![
```

- `#[`. 다음 항목에 부착되는 속성 (외부 속성).
- `#![`. 둘러싸는 항목 또는 모듈에 부착되는 속성 (내부 속성).

이 두 도입자는 각각 하나의 고정 토큰으로 분리된다. `#` 과 `[` 사이에 공백을 둘 수 없다.
별개 토큰 `#` + `[` 는 정의되지 않는다.

외부와 내부의 한 쌍은 [어휘 구조](102-lexical-structure.md) 의 문서 주석 `///` 와 `//!` 와 같은 패턴이다. 부착
방향만 다를 뿐 의미는 동일하게 묶인다.

## 1.10.4. 확장 토큰

위 고정 표 외에, 표준 라이브러리가 등록할 수 있는 글자열의 후보는 다음을 만족해야 한다.

- ASCII 범위 밖의 연산자류 코드포인트, 또는 위 고정 표에 없는 ASCII 기호 시퀀스일 것.
- 식별자 글자 (`XID_Start`, `XID_Continue`) 가 전혀 포함되지 않을 것.
- 공백과 줄 종결자가 포함되지 않을 것.

예: `≤`, `≥`, `≠`, `⊕`, `∈`, `≡`.

이런 글자열을 등록하면 렉서가 그 글자열을 한 토큰으로 잘라낸다. 등록 시점과 구문, 의미는 [`#[infix]` / `#[prefix]` / `#[postfix]` 매직](../006-meta-system/607-operator-magic.md) 에서 정의한다.

## 1.10.5. 토큰화 대상이 아닌 것

다음은 토큰이 아니라 더 큰 단위의 일부분이다.

- `f"..."` 의 `f`. [문자열 리터럴](107-string-literals.md) 의 형식 문자열 접두.
- `r"..."` 의 `r` 와 `r#"..."#` 의 `r#`. 원시 문자열 접두.
- `c'...'` 의 `c`. [문자 리터럴](108-character-literals.md) 의 C 호환 문자 접두.
- 숫자 리터럴 뒤에 붙는 타입 접미사. [숫자 리터럴](106-numeric-literals.md) 참조.

이들은 본 문서의 토큰표에 등장하지 않으며, 그 자리에서 식별자나 일반 토큰으로 토큰화되지도 않는다.
