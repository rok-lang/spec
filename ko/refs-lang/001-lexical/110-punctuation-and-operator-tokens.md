# 1.10. 구두점과 연산자 토큰

이 문서는 연산자와 구두점 글자열의 토큰화 규칙을 다루며, 어휘 형태만 설명합니다. 각 토큰의 의미(우선순위, 결합성, 어떤 트레잇으로 디스패치되는지 등)는 [3. 표현식](../003-expressions/README.md)에서 정의합니다.

## 1.10.1. 토큰화 원칙

연산자와 구두점의 토큰화에는 두 단계가 있습니다. 첫째는 고정 토큰표입니다. 이 문서에 적힌 글자열은 항상 정해진 토큰으로 분리됩니다. 둘째는 확장 토큰표입니다. 표준 라이브러리가 메타 시스템으로 추가 등록한 글자열도 토큰이 됩니다. 등록 메커니즘은 [`#[infix]` / `#[prefix]` / `#[postfix]` 매직](../006-meta-system/607-operator-magic.md)에서 정의합니다.

두 표가 충돌하면 등록 시점에 거부하며, 고정 토큰은 덮어쓸 수 없습니다.

## 1.10.2. 최장 일치

> [!IMPORTANT]
> 여러 토큰 후보가 가능한 입력에서는 가장 길게 일치하는 쪽을 고릅니다.

| 입력  | 토큰화                              |
|-------|-------------------------------------|
| `==`  | 한 토큰                             |
| `=`   | 한 토큰                             |
| `= =` | 두 토큰 (공백이 분리)               |
| `..=` | 한 토큰 (`..=`가 `..`보다 깁니다) |
| `..`  | 한 토큰                             |
| `<<=` | 한 토큰 (`<<=`가 `<<`보다 깁니다) |

## 1.10.3. 고정 토큰표

다음은 언어가 예약하는 ASCII 영역 연산자와 구두점 글자열의 전체 목록입니다. 표준 라이브러리는 이 토큰들에 의미(트레잇 메서드 매핑)를 붙일 뿐이며, 토큰 형태는 이 표가 정합니다.

### 산술 / 비교 / 논리

```
+       -       *       /       %       %%
==      !=      <       >       <=      >=
&&      ||      !
&       |       ^       ~       <<      >>
```

`%`는 산술 나머지(Rem, 부호는 피제수를 따름)이고, `%%`는 floored modulo(결과의 부호가 제수를 따르므로 양수 제수에서는 늘 `[0, divisor)` 범위, Python의 `%`)입니다. 두 토큰은 서로 다른 트레잇으로 매핑되며 의미가 다릅니다.

각 토큰이 어떤 트레잇 메서드를 호출하는지는 표준 라이브러리의 연산자 사양에서 정의합니다. 이 문서는 어휘 토큰화만 보장합니다.

### 브로드캐스트 (`.` 접두)

원소별(broadcast) 연산을 위한 점 접두 형태입니다. 위 산술, 비교, 논리, 비트, shift 연산자 앞에 점 하나를 붙인 형태가 별개의 토큰으로 분리됩니다.

```
.+      .-      .*      ./      .%      .%%
.==     .!=     .<      .>      .<=     .>=
.&&     .||
.&      .|      .^      .<<     .>>
```

이 형태들은 각각 점이 없는 형태와 다른 트레잇 메서드로 매핑됩니다. 예를 들어 `+`는 `Add::add`로, `.+`는 `DotAdd::dot_add`로 매핑되며, 이 매핑은 표준 라이브러리에서 정의합니다. 점 접두 논리 연산자(`.&&`, `.||`)는 점 없는 형태와 달리 short-circuit 평가를 하지 **않습니다**. broadcast는 fused loop으로 lower되므로 양쪽 인자를 모두 평가합니다(자세한 내용은 [2.6 broadcast](../../refs-standard-libraries/200-core/206-broadcast.md) 참고).

#### 부동소수 리터럴과의 구분

부동소수 리터럴 `1.`이나 `1.5`에도 점이 들어 있으므로, 다음 두 입력의 토큰화는 위치에 따라 달라집니다.

| 입력   | 토큰화         | 이유                                               |
|--------|----------------|----------------------------------------------------|
| `1.+2` | `1.`, `+`, `2` | `.`가 숫자 직후이므로 부동소수의 일부로 흡수      |
| `a.+b` | `a`, `.+`, `b` | `.`가 숫자 직후가 아니므로 브로드캐스트 토큰 시작 |

정리하면, 숫자 리터럴 중간의 `.`은 항상 부동소수의 일부이고, 그 밖의 위치의 `.`은 다른 토큰 형태가 우선합니다([숫자 리터럴](106-numeric-literals.md)의 `.` 처리 규칙 참고).

### Unicode 수학 연산자

다음 Unicode 연산자도 고정 토큰입니다. 우선순위는 [3.2.3](../003-expressions/302-precedence-and-associativity.md#323-우선순위와-결합성-표) 표가 정하고, 연결되는 트레잇은 표준 라이브러리 [2.3 ops](../../refs-standard-libraries/200-core/203-ops.md)가 정합니다.

```
×       ⋅       ÷       ∘       √
≡       ≠       ≤       ≥
∈       ∉       ⊂       ⊆       ∪       ∩
```

| 토큰 | 코드포인트 | 의미 (ASCII 이름 메서드)       |
|------|------------|--------------------------------|
| `×`  | U+00D7     | 외적 (`cross`)                 |
| `⋅`  | U+22C5     | 내적 (`dot`)                   |
| `÷`  | U+00F7     | 나눗셈 (`div`, `/`의 동의어)  |
| `∘`  | U+2218     | 함수 합성 (`compose`)          |
| `√`  | U+221A     | 제곱근, 전위 (`sqrt`)          |
| `≡ ≠ ≤ ≥` | U+2261, U+2260, U+2264, U+2265 | `== != <= >=`의 동의어 |
| `∈ ∉` | U+2208, U+2209 | 원소 포함 (`contains`)     |
| `⊂ ⊆` | U+2282, U+2286 | 부분집합 (`is_proper_subset`, `is_subset`) |
| `∪ ∩` | U+222A, U+2229 | 합집합, 교집합 (`union`, `intersection`) |

연산자 글자는 모두 Unicode `Pattern_Syntax` 속성을 가진 코드포인트 중에서 고릅니다. `∑ ∏ ∫`는 `Pattern_Syntax`이지만 식별자 글자로 정했으므로([1.4.1](104-identifiers.md#수학-표기-프로필)) 연산자가 아닙니다.

### 대입 / 복합 대입

```
=       +=      -=      *=      /=      %=      %%=
&=      |=      ^=      <<=     >>=
```

복합 대입의 의미(좌변 평가 횟수, 트레잇 매핑 등)는 표현식 사양에서 정의합니다. `%%=`는 `%%`(floored modulo)의 복합 대입 형태이며, 최장 일치 규칙에 따라 `%%=`가 `%=`나 `%`보다 먼저 매칭됩니다.

### 범위 / 슬라이스

```
..      ..=     :       ::
```

`..`와 `..=`는 범위 표기에 씁니다. `:`는 슬라이스의 자리 구분자, 형식 지정자의 시작 등 여러 문맥에서 씁니다. `::`는 경로 구분자이며 모듈이나 타입의 정적 항목에 접근할 때 씁니다.

### 점 / 물음표

```
.       ?.      ??      ?
```

`.`은 멤버나 메서드에 접근할 때 씁니다. `?.`은 합 타입을 통과시키는 점 접근입니다. `??`는 빈자리(`none`)를 대체값으로 채우는 이항 연산입니다. 단독 물음표 `?`는 후위 단항 연산자로, `T | none` 값이 `none`이면 둘러싼 함수에서 `none`을 조기 반환합니다. 자세한 의미와 desugar 규칙은 [에러 제어 흐름](../003-expressions/314-error-control-flow.md#31410--연산자---none-조기-반환)의 `?` 연산자 절에서 정의합니다.

`try?`와 `try!`는 토큰 하나가 아닙니다. 어휘 분석은 키워드 `try`와 구두점 `?` 또는 `!`를 각각 토큰으로 만들고, 구문 분석이 `try` 바로 뒤에 공백 없이 붙은 `?` / `!`를 [`try?` / `try!`](../003-expressions/314-error-control-flow.md#3143-try-와-try) 접두 연산자로 해석합니다. 공백이 있으면 `try !ready()`처럼 `try`와 논리 부정 `!`로 해석합니다.

### 작은따옴표 토큰: 문자 리터럴 vs 라벨

`'` 토큰은 두 형태로 갈립니다. 첫째는 `'X'` 또는 `'\X'` 형태, 곧 문자 하나(또는 escape) 다음에 닫는 `'`가 오는 형태이며 [문자 리터럴](108-character-literals.md)입니다. 둘째는 `'identifier` 형태, 곧 닫는 `'`가 없는 식별자 형태이며 라벨 토큰입니다([라벨](../003-expressions/313-loop-expressions.md#3134-라벨-중첩-루프-제어)과 [라벨 블록](../003-expressions/309-block-expressions.md#3910-라벨-블록-label---) 참고).

어휘 분석은 `'` 다음 두 바이트를 보고 정합니다. 식별자 시작 다음에 닫는 `'`가 오면 문자입니다. 식별자 시작 다음에 식별자 글자, 콜론, 공백처럼 닫는 `'`가 아닌 것이 오면 라벨입니다. escape(`'\...`)는 항상 문자 리터럴입니다.

### 람다 / 화살표

```
|       ||      ->      =>
```

`|`는 문맥에 따라 비트 OR, 합 타입 구분자, 람다 인자 구분자로 씁니다. `||`는 논리 OR이나 인자 없는 람다의 시작에 씁니다. `->`는 함수 반환 타입 화살표이고, `=>`는 `match` 가지 화살표입니다.

### 구두점

```
(   )   [   ]   {   }
,   ;   @
```

`( )`는 그룹화, 튜플, 호출에 씁니다. `[ ]`는 인덱싱, 슬라이스, 캡처 리스트, 배열 리터럴에 씁니다. `{ }`는 블록, 복합 리터럴, 구조체 리터럴에 씁니다. `,`는 인자나 항목 구분자이고, `;`는 문장 종결자입니다([문장 종결자](103-statement-terminator.md) 참고). `@`는 메타 시스템의 토큰이며, 정확한 의미는 6장에서 다룹니다.

### 속성 도입자

```
#[      #![
```

`#[`는 다음 항목에 붙는 속성, 곧 외부 속성을 엽니다. `#![`는 둘러싼 항목이나 모듈에 붙는 속성, 곧 내부 속성을 엽니다.

두 도입자는 각각 고정 토큰 하나로 분리됩니다. `#`과 `[` 사이에 공백을 둘 수 없으며, 별개 토큰 `#` 다음에 `[`가 오는 형태는 정의되지 않습니다.

외부/내부 한 쌍은 [어휘 구조](102-lexical-structure.md)의 문서 주석 `///`와 `//!`와 같은 패턴입니다. 붙는 방향만 다르고 의미는 같은 방식으로 묶입니다.

## 1.10.4. 확장 토큰

위 고정 표 밖에서 표준 라이브러리나 사용자가 등록하는 글자열은 다음 조건을 만족해야 합니다. 모든 글자가 `Pattern_Syntax` 코드포인트여야 하고, 식별자 글자([1.4.1](104-identifiers.md#141-형식))가 하나도 없어야 하며, 공백과 줄 종결자도 없어야 합니다. 고정 토큰과 같아서도 안 됩니다.

`⊕`, `⊗`, `⋆`, `°` 같은 글자열이 그 예입니다. 확장 토큰의 우선순위는 등록할 때 `like`로 지정한 기존 토큰을 따릅니다 ([6.7.2](../006-meta-system/607-operator-magic.md#672-인자)).

이런 글자열을 등록하면 렉서가 그 글자열을 토큰 하나로 잘라 냅니다. 등록 시점과 구문, 의미는 [`#[infix]` / `#[prefix]` / `#[postfix]` 매직](../006-meta-system/607-operator-magic.md)에서 정의합니다.

## 1.10.5. 토큰화 대상이 아닌 것

다음 요소는 토큰이 아니라 더 큰 단위의 일부입니다. `f"..."`의 `f`는 [문자열 리터럴](107-string-literals.md)의 형식 문자열 접두입니다. `r"..."`의 `r`와 `r#"..."#`의 `r#`는 원시 문자열 접두입니다. `b"..."`의 `b`는 바이트 문자열 접두입니다. `c'...'`의 `c`는 [문자 리터럴](108-character-literals.md)의 C 호환 문자 접두입니다. 숫자 리터럴 뒤에 붙는 타입 접미사도 여기에 속합니다(자세한 내용은 [숫자 리터럴](106-numeric-literals.md) 참고).

이 요소들은 이 문서의 토큰표에 없으며, 그 자리에서 식별자나 일반 토큰으로 토큰화되지도 않습니다.
