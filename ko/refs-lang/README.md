# Rok 언어 참조

이 문서는 Rok 프로그래밍 언어의 형식 사양(formal specification)입니다. 언어의 **문법**(syntax)과 **의미**(semantics)를 정의합니다. 컴파일러와 런타임은 이 규범(normative) 기준을 따라야 합니다.

기준 시점은 2026-10-23입니다. 컴파일러와 런타임 구현은 이 사양을 규범 기준으로 따라야 합니다. 컴파일러와 표준 라이브러리의 실제 구현은 별도 저장소에 있습니다.

---

## 장 목차

Rok 사양은 0장부터 9장까지 열 개 장으로 이루어집니다. 장 순서는 임의로 정하지 않았습니다. 각 장의 정의가 앞 장의 개념만 쓰도록 의존 순서대로 배치했습니다. 0장 메타가 맨 앞에 옵니다. 그다음 어휘 구조에서 시작해 점점 추상적인 영역을 거치고, 실행 환경과 도구로 끝납니다.

| # | 장                                                     | 다루는 영역                                                         |
|---|--------------------------------------------------------|---------------------------------------------------------------------|
| 0 | [메타 - 언어 / 빌드 모델](000-meta/README.md)          | 실행 모드, 파이프라인, 표준 라이브러리 계층, 플랫폼, 표기법, 용어집 |
| 1 | [어휘 구조](001-lexical/README.md)                     | 식별자, 키워드, 토큰, 리터럴, 문자열, 구두점                        |
| 2 | [타입 시스템](002-types/README.md)                     | 원시, 합 / 합성, 제네릭, niche, 변환, 경로                          |
| 3 | [표현식](003-expressions/README.md)                    | 연산자, 패턴 매칭, 제어 흐름, 옵셔널 체이닝, throw                  |
| 4 | [함수](004-functions/README.md)                        | 매개변수, 클로저, trailing closure, 코루틴, async/await             |
| 5 | [변수 / 모듈 / 가시성 / 패키지](005-modules/README.md) | let, const, static, mod, use, 가시성, 경로, 재내보내기              |
| 6 | [메타 시스템](006-meta-system/README.md)               | 속성, lang/literal/keyword 매직, 메타 블록, 리플렉션                |
| 7 | [런타임 모델](007-runtime/README.md)                   | 객체 layout, GC, 스케줄러, 코루틴, 안전점                           |
| 8 | [런타임 ABI / MLIR lowering](008-abi/README.md)        | 헤더, 스캔 테이블, TLS, calling convention, MLIR 다이얼렉트         |
| 9 | [실행 / 툴](009-tools/README.md)                       | rokc CLI, AOT 파이프라인, .a 패키지, ROKHIR, JIT, Jupyter             |

0장은 뒤의 모든 장이 전제하는 빌드 모델, 플랫폼 가정, 표기법을 모아 둡니다. 한 번 읽어 두면 본문에서 되풀이되는 약속을 다시 찾아보지 않아도 됩니다. 다음에 1장 어휘 구조가 오는 이유는 간단합니다. 토큰의 모양을 정의해야 타입과 식이 형태를 갖출 수 있기 때문입니다. 이어서 2장 타입, 3장 표현식, 4장 함수가 핵심 구조를 차례로 도입합니다. 한 모듈 안에서 값을 만들고 다루는 데 필요한 구조입니다.

모듈, 가시성, 패키지는 일부러 5장에서야 등장합니다. 한 파일 안의 의미가 완전히 정의된 뒤에야 파일 경계와 캡슐화를 다룰 수 있기 때문입니다. 6장 메타 시스템은 1~5장을 모두 전제합니다. 속성, `lang` / `literal` / `keyword` 매직, 리플렉션은 어휘, 타입, 식, 함수, 모듈을 '대상으로' 동작합니다. 그래서 그 대상을 모두 정의한 뒤에야 의미가 분명해집니다.

마지막으로 7장 런타임 모델, 8장 ABI와 MLIR lowering, 9장 실행과 툴은 표층 언어를 실제 실행으로 옮기는 단계를 다룹니다. 7장은 객체 layout, GC, 스케줄러를 추상적으로 기술합니다. 8장은 그것을 메모리와 레지스터의 어떤 비트로 구현하는지 못 박습니다. 9장은 이 모두를 묶어, 사용자가 직접 다루는 `rokc` CLI와 빌드 산출물의 형태를 정합니다.

본문에서 자주 인용하는 부록과 참고 자료는 다음과 같습니다.

- [표기법(BNF, 상호 참조, 코드 관례)](000-meta/008-notation.md)
- [용어집](000-meta/007-glossary.md)

## 읽는 방법

### 처음 읽을 때(0 → 9 순서대로)

이 사양은 0장부터 9장까지 순서대로 읽으면 새 개념을 항상 이미 본 개념만으로 설명하도록 썼습니다. 어느 장이든 그 앞 장의 개념만 쓴다는 불변식(invariant)이 성립합니다. 처음 읽는다면 건너뛰지 말고 순서대로 따라가세요. 그쪽이 가장 짧은 길입니다.

상호 참조(cross-reference)의 정의 의존은 앞쪽으로만(backward-only) 향합니다. 현재 문서를 이해하는 데 그보다 뒤에 오는 문서의 정의가 필요하면 안 됩니다. 여러 장에 걸친 주제(메서드 디스패치 ↔ 트레잇 디스패치, 산술 식 ↔ 연산자 매직 등)에서는 뒤쪽을 가리키는 포인터가 보조 참조로 나올 수 있습니다. 이때도 그 참조 대상이 현재 문서를 읽는 데 '필수'이면 안 됩니다. 보조 참조는 추가 맥락을 안내하는 역할만 합니다.

### 참조용(특정 항목 찾아보기)

사양은 학습보다 특정 항목을 빨리 찾는 데에도 자주 씁니다. 그래서 모든 항목에 안정 절 번호(`<chapter>.<section>` 또는 `<chapter>.<section>.<subsection>`)가 붙어 있습니다. 상호 참조는 항상 이 번호를 씁니다. 파일 경로는 바뀔 수 있으므로 인용에 쓰지 않습니다.

```
spec 2.7.4    →  002-types/207-niche-optimization.md (4번째 하위 절)
spec 4.8      →  004-functions/408-trailing-closure.md
spec 6.10     →  006-meta-system/610-reflection.md
```

### 검색

사양 전체가 마크다운이므로 ripgrep이나 grep으로 바로 검색할 수 있습니다. 별도 인덱스나 검색 도구가 필요 없도록 일부러 설계했습니다. 사양을 읽는 일과 빌드하는 일에 같은 도구를 씁니다.

```bash
rg "trait" spec/ko/refs-lang/
rg "::=" spec/ko/refs-lang/                # BNF 정의 검색
rg "i32" spec/ko/refs-lang/002-types/      # 장 한정
```

## 표기 규약

아래 표는 본문 전체에서 일관되게 쓰는 표기 약속을 요약합니다. 자세한 정의와 예외는 [000-meta/008-notation.md](000-meta/008-notation.md)에 있습니다.

| 표기                         | 의미                                  |
|------------------------------|---------------------------------------|
| `` `let` ``                  | 키워드 / 식별자 (코드 폰트)           |
| `` `i32` ``                  | 타입 이름 (코드 폰트)                 |
| `*emphasis*`                 | 개념 강조 (이탤릭)                    |
| `**strong**`                 | 경고 / 핵심 결정사항 (볼드)           |
| `> [!NOTE]` / `> [!WARNING]` | GitHub 스타일 정보 박스               |
| `name ::= ...`               | BNF 스타일 문법 정의                  |
| `<chapter>.<section>`        | 안정 cross-reference 키 (예: `2.7.4`) |

코드 폰트는 표층 언어에 실제로 나오는 토큰에만 씁니다. 개념 강조는 이탤릭으로 합니다. 핵심 결정 사항과 주의할 점은 볼드로 표시합니다.

## 디렉터리와 파일 이름

파일과 디렉터리 이름은 그 자체로 상호 참조 키 역할을 하도록 정했습니다.

| 위치   | 형태                        | 예                               |
|--------|-----------------------------|----------------------------------|
| 장     | `<NNN>-<descriptive-name>/` | `002-types/`, `006-meta-system/` |
| 절     | `<NNN>-<name>.md`           | `207-niche-optimization.md`      |
|        | (장 한 자리 + 절 두 자리)   |                                  |
| README | 각 장에 `README.md`         | 장 목차 + 안내                   |

세 자리 접두어의 첫 자리는 장 번호, 뒤 두 자리는 절 번호입니다. 예를 들어 `207`은 "2.7", 곧 타입 시스템 장의 7번째 절을 가리킵니다. 이 숫자가 그대로 상호 참조의 안정 키입니다.

이 명명 방식은 두 방식을 절충했습니다. [Rust Reference](https://doc.rust-lang.org/reference/)의 서술형 파일명과 계층형 장 구성, 그리고 [Python Language Reference](https://docs.python.org/3/reference/)의 번호 매긴 장 / 절 방식입니다. 번호는 기계가 읽기 좋고 이름은 사람이 읽기 좋습니다. 이 방식은 두 요구를 함께 만족합니다.
