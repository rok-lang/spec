# 6.3. `#[cfg]` 조건부 컴파일

`#[cfg(...)]` 속성은 컴파일 타임 조건에 따라 항목을 포함하거나 제외한다.

```
cfg_predicate   ::= identifier                              // flag
                  | identifier "=" string_lit               // key=value
                  | "all" "(" pred_list ")"
                  | "any" "(" pred_list ")"
                  | "not" "(" cfg_predicate ")"
pred_list       ::= cfg_predicate ("," cfg_predicate)* ","?
cfg_attr        ::= "#" "[" "cfg" "(" cfg_predicate ")" "]"
cfg_attr_attr   ::= "#" "[" "cfg_attr" "(" cfg_predicate ("," attr_body)+ ")" "]"
cfg_macro       ::= "cfg" "!" "(" cfg_predicate ")"
```

## 6.3.1. 기본 형태

```nok
#[cfg(target_os = "linux")]
fn linux_specific() { ... }

#[cfg(target_arch = "x86_64")]
const HAS_AVX: bool = true;

#[cfg(test)]
mod tests { ... }
```

- 인자에 predicate 를 받는다. 조건이 참이면 항목이 컴파일에 포함되고, 거짓이면 제외된다.
- 제외된 항목은 처음부터 적히지 않은 것처럼 동작한다. 다른 코드의 이름 해소에서 보이지 않는다.

## 6.3.2. predicate 종류

### key = value

```nok
#[cfg(target_os = "linux")]
#[cfg(target_arch = "x86_64")]
#[cfg(target_pointer_width = "64")]
#[cfg(feature = "gpu")]
```

표준 키:

| 키                     | 가능한 값                                              |
| ---------------------- | ------------------------------------------------------ |
| `target_arch`          | `"x86_64"`, `"aarch64"`, `"i686"`, `"arm"`, `"wasm32"` |
| `target_os`            | `"linux"`, `"macos"`, `"windows"`, `"wasi"`, `"none"`  |
| `target_pointer_width` | `"64"`, `"32"`                                         |
| `target_endian`        | `"little"`, `"big"`                                    |
| `target_family`        | `"unix"`, `"windows"`, `"wasm"`                        |
| `target_env`           | `"gnu"`, `"musl"`, `"msvc"`                            |
| `feature`              | 사용자 정의. CLI 또는 패키지 매니저에서 설정한다       |

### 단순 플래그

```nok
#[cfg(test)]                 // 테스트 빌드에서만
#[cfg(debug_assertions)]      // 디버그 빌드에서만
```

값 없이 키만 적는 부울 플래그다.

### 결합자

```nok
#[cfg(all(target_os = "linux", target_arch = "x86_64"))]
#[cfg(any(target_os = "linux", target_os = "macos"))]
#[cfg(not(target_os = "windows"))]
```

| 결합자     | 의미           |
| ---------- | -------------- |
| `all(...)` | 모든 인자가 참 |
| `any(...)` | 하나라도 참    |
| `not(...)` | 인자가 거짓    |

자유롭게 중첩할 수 있다.

```nok
#[cfg(all(
    target_os = "linux",
    any(target_arch = "x86_64", target_arch = "aarch64"),
    not(feature = "minimal"),
))]
fn linux_native() { ... }
```

## 6.3.3. 부착 위치

`#[cfg]` 는 거의 모든 항목에 부착할 수 있다.

```nok
#[cfg(...)] fn f() { ... }
#[cfg(...)] struct S { ... }
#[cfg(...)] mod m { ... }
#[cfg(...)] use foo::bar;
#[cfg(...)] static X: i32 = 0;

struct Foo {
    #[cfg(target_pointer_width = "64")]
    big_field: u64,                              // 64-bit 에서만 존재
}
```

조건이 거짓이면 그 항목은 없는 것처럼 처리된다.

## 6.3.4. `#[cfg_attr(...)]` 조건부 다른 속성

```nok
#[cfg_attr(target_os = "windows", link("kernel32"))]
extern "C" { ... }

#[cfg_attr(test, derive(Debug))]
struct S { ... }
```

- `cfg_attr(조건, 적용할_속성)` 형태다. 조건이 참이면 적용할 속성이 부착된 것처럼 작동한다.
- 첫 예에서는 Windows 에서만 `#[link("kernel32")]` 가 적용된다.
- 두 번째 예에서는 테스트 빌드에서만 `#[derive(Debug)]` 가 적용된다.

여러 속성을 한 번에 적용할 수도 있다.

```nok
#[cfg_attr(test, derive(Debug), allow(unused))]
struct S { ... }
```

## 6.3.5. `cfg!(...)` 컴파일 타임 bool 값

```nok
const IS_LINUX: bool = cfg!(target_os = "linux");

if cfg!(feature = "gpu") {
    use_gpu()
} else {
    use_cpu()
}
```

- 식 자리에 등장하여 컴파일 타임에 bool 값으로 평가된다.
- `#[cfg]` 와 같은 predicate 를 받는다.
- 결과는 [`const`](../005-modules/502-const.md) 의 `const` 표현식이며, 다른 `const` 자리에 사용할 수 있다.
- `cfg!` 는 컴파일러 내장 형태이며 사용자 정의 매크로가 아니다 (nok 에는 일반 매크로 시스템이 없다. [메타 시스템 개요](README.md) 참조).

`#[cfg]` 와 `cfg!()` 의 차이는 다음과 같다.

- `#[cfg]`: 항목 전체를 빌드에 포함하거나 제외한다.
- `cfg!()`: 런타임 분기처럼 보이지만 실제로는 컴파일 타임 상수다. 한쪽 분기는 dead-code-elimination 으로 제거된다.

```nok
// #[cfg] — 두 함수 중 하나만 컴파일됨
#[cfg(feature = "gpu")] fn run() { use_gpu() }
#[cfg(not(feature = "gpu"))] fn run() { use_cpu() }

// cfg!() — 한 함수 안에서 분기, 컴파일러가 한쪽 제거
fn run() {
    if cfg!(feature = "gpu") { use_gpu() } else { use_cpu() }
}
```

두 형태는 사용 편의성과 코드 구조에 따라 선택한다.

## 6.3.6. 매개변수의 출처

### target\_\* 키

빌드의 대상 플랫폼에 따라 자동으로 설정된다. [플랫폼 타깃](../000-meta/006-platform-targets.md) 의 13 개 Tier 1 타깃에 대해 명확한 값을 갖는다.

### `feature` 키

CLI 옵션 또는 패키지 매니저와 빌드 도구가 설정한다.

```bash
nokc --cfg feature=gpu
```

향후 패키지 매니저가 매니페스트 파일의 feature 정의와 의존성 활성화 등을 자동화할 예정이다 (본 사양 범위 밖).

### `test` / `debug_assertions`

빌드 모드에 따라 결정된다.

- `test`: `nokc test` 또는 동등한 명령으로 빌드할 때 참.
- `debug_assertions`: 디버그 빌드 (최적화 없음) 일 때 참.

## 6.3.7. 평가 시점

`#[cfg]` 의 평가는 parse 직후에 일어난다. 거짓 조건의 항목은 AST 에서 즉시 제거된다. 후속
패스 (이름 해소, 타입 검사, 코드 생성) 는 남은 AST 만 본다.

이 시점은 메타 확장 패스 ([템플릿 토큰과 확장](609-template-tokens.md)) 보다 먼저다. cfg 가 거짓인 항목에
부착된 사용자 정의 derive 와 attribute 도 처리되지 않는다.

## 6.3.8. 부정/충돌하는 cfg

```nok
#[cfg(target_os = "linux")]
fn impl_a() { ... }

#[cfg(target_os = "linux")]    // 같은 cfg + 같은 이름 → 충돌
fn impl_a() { ... }            // ERROR — 두 정의가 같은 빌드에 동시에 존재
```

같은 빌드에서 조건이 동시에 참이 되어 두 정의가 살아남으면 일반적인 중복 정의 에러가 발생한다.

```nok
#[cfg(target_os = "linux")]
fn impl_a() { ... }

#[cfg(not(target_os = "linux"))]
fn impl_a() { ... }            // OK — 두 cfg 가 상호 배타
```

위는 OK 이다. 어떤 빌드에서도 한 정의만 활성이 된다.

## 6.3.9. cfg 와 모듈/파일

```nok
#[cfg(target_os = "linux")]
mod linux_only {
    // 이 모듈 전체가 Linux 빌드에서만 존재
}
```

모듈 전체에 cfg 를 부착할 수 있다. 그 모듈의 파일과 디렉토리는 디스크에 있지만, cfg 가 거짓이면 읽지 않는다 (또는 읽고 즉시 폐기한다).

## 6.3.10. cfg 안에 매크로 (없음)

```
#[cfg(custom_macro!())]                // 채택 안 함
```

cfg predicate 안에 임의의 식이나 매크로 호출은 도입하지 않는다. 정해진 키-값 형태와 결합자만 허용한다.

## 6.3.11. 디버깅 도구

`nokc --print cfg` 같은 명령으로 현재 빌드에서 활성인 cfg 값들을 출력할 수 있다 (정확한 명령은 컴파일러 사양에 따른다).
