# 6.6. `#[keyword(...)]` 매직

`#[keyword("name")]` 속성은 표준 라이브러리가 새 키워드를 등록하는 메커니즘입니다.

## 6.6.1. 동기

[키워드](../001-lexical/105-keywords.md)의 예약 키워드 목록은 언어가 직접 정의하는 고정된 집합입니다. 그렇다고 키워드를 하나 더할 때마다 언어 사양을 고쳐야 한다면 곤란합니다.

표준 라이브러리는 라이브러리 DSL의 도메인 키워드처럼 키워드로 보이는 토큰을 도입하고 싶을 때가 있습니다. 이럴 때 라이브러리는 `#[keyword]` 매직으로 언어 수준 키워드를 등록합니다. 사양이 허용하는 통로는 이것 하나입니다.

## 6.6.2. 형태

```
keyword_attr    ::= "#" "[" "keyword" "(" string_lit ")" "]"
```

```rok
#[keyword("yield_priority")]
fn yield_priority_handler(...) { ... }

#[keyword("with")]
fn with_handler(...) { ... }
```

기본 형태는 `#[keyword("name")]`이고, 인자로 키워드 이름(식별자 모양의 문자열 리터럴)을 받습니다. 핸들러는 **자유 함수**입니다. 메서드나 트레잇 항목에는 붙일 수 없습니다.

`struct`에 붙인 `#[keyword("name")]`는 **타입 키워드**를 등록합니다. 타입 자리에서 그 이름은 그 struct를 가리킵니다(`int` → `rok::core::num::bigint::Int`, `float` → `rok::core::num::bigfloat::Float`, [stdlib 2.1.2](../../refs-standard-libraries/200-core/201-numbers.md#212-int-무한-정밀도-정수)). 타입 키워드는 표준 라이브러리만 등록할 수 있습니다. 함수와 struct가 아닌 항목에 붙이면 에러입니다.

## 6.6.3. 등록의 효과

`#[keyword("name")]`를 등록하면 다음 효과가 생깁니다.

1. 그 컴파일 단위에서 식별자 `name`이 키워드로 토큰화됩니다.
2. 키워드를 쓴 곳은 핸들러 호출로 풀립니다. `name(args)`는 핸들러를 절대 경로로 호출하는 식이 됩니다. 뒤에 블록이 오면 그 블록은 [트레일링 클로저](../004-functions/408-trailing-closure.md) 인자가 됩니다.

```rok
#[keyword("with")]
fn with_handler(m: Mutex<i32>, body: fn()) { ... }

with(m) { critical(); }
// ⇒ pkg::with_handler(m) { critical(); }     - 핸들러 + 트레일링 클로저
```

등록 전에는 `name`을 일반 식별자로 쓸 수 있었습니다. 등록 후에는 키워드 토큰이 됩니다. 따라서 `name`을 선언이나 멤버의 이름으로 쓰면 컴파일 에러입니다. 해당하는 자리는 `let name`, `fn name`, `struct name`, `enum name`, `trait name`, `mod name`, `for name in`, `.name`, `::name`, `name:`(필드 / 인자 이름), `name::`입니다. f-string의 `{..}` 안에서도 같은 규칙으로 바뀝니다.

## 6.6.4. 충돌 검사

```rok
#[keyword("if")]                  // ERROR - 'if' 는 예약 키워드
fn ... { ... }
```

[키워드](../001-lexical/105-keywords.md)의 예약 키워드, 고정된 위치에서만 키워드인 이름(`type`, `any`, `in`, `where`, `throws`, `rethrows`, `catch`, `finally`, `const`, `static`, `extern`, `mut`, `union`), 경로 루트(`pkg`, `sup`, `rok`)는 등록할 수 없습니다. 컴파일러가 등록 시점에 바로 거부합니다.

한 빌드 안에서 같은 키워드를 두 번 등록하면 에러입니다. 같은 패키지 안이든 서로 다른 라이브러리이든 마찬가지입니다.

```
package_a 가 #[keyword("with")] 등록
package_b 도 #[keyword("with")] 등록    → 두 패키지를 한 빌드에 쓰면 ERROR
```

## 6.6.5. 적용 범위

`#[keyword]`는 그 등록이 들어 있는 컴파일 단위(보통 패키지) 안에서만 효력이 있습니다. 다른 패키지에서는 같은 이름이 일반 식별자입니다. 단, 표준 라이브러리의 타입 키워드(`int`, `float`)는 모든 패키지에 적용됩니다.

효력이 지역적이므로 라이브러리 사이의 충돌이 줄어듭니다. 사용자는 어떤 패키지가 어떤 키워드를 도입할지 직접 정할 수 있습니다.

## 6.6.6. 사용 패턴

`#[keyword]`는 드물게 씁니다. 주로 다음 경우에 도입합니다.

- 도메인 특화 언어(DSL). 표 데이터, 그리드, 회로처럼 도메인 단어가 식별자 자리에서 키워드처럼 동작하는 편이 자연스러울 때입니다.
- 연산자 매직으로 표현하기 어려운, 블록이나 본체 형태의 새 구문이 필요할 때입니다.

대부분은 함수와 트레일링 클로저를 조합하기만 해도 키워드처럼 보이는 패턴을 만들 수 있습니다([트레일링 클로저](../004-functions/408-trailing-closure.md)). 그렇게 할 수 있다면 그 방법을 먼저 쓰세요.

## 6.6.7. scanner pre-pass와 결합

`#[keyword]` 등록은 컴파일러의 스캐너 사전 패스(scanner pre-pass)가 인식합니다.

1. 컴파일러는 파싱 전에 소스 파일을 빠르게 스캔해 `#[keyword(...)]` 등록을 모읍니다.
2. 등록 표를 렉서에 넘깁니다.
3. 본 어휘 분석에서 등록된 이름을 키워드 토큰으로 분리합니다.
4. 파서가 그 토큰을 등록된 핸들러 호출로 풉니다.

이 사전 패스 덕분에 등록 위치(어느 파일, 몇 번째 줄)와 상관없이 컴파일 단위 안에서 결과가 같습니다. 등록 순서는 신경 쓰지 않아도 됩니다.

## 6.6.8. 키워드 핸들러의 시그니처

컴파일러는 핸들러의 시그니처를 따로 검사하지 않습니다. 키워드 사용이 핸들러 호출로 바뀐 뒤(6.6.3), 그 호출을 보통 함수 호출로 타입 검사합니다. 따라서 키워드를 쓰는 형태(인자, 트레일링 클로저)는 핸들러의 매개변수가 정합니다.

## 6.6.9. 컨텍스트 키워드의 부재(재확인)

[키워드](../001-lexical/105-keywords.md)는 컨텍스트 키워드를 도입하지 않는다고 정합니다. 이 원칙은 등록된 키워드에도 그대로 적용됩니다.

`#[keyword("with")]`를 등록하면 `with`는 어디서든 키워드로 토큰화됩니다. "특정 위치에서만 키워드"인 형태는 도입하지 않습니다.

이 일관성 덕분에 렉서와 파서가 단순해집니다.

## 6.6.10. 등록의 가시성

`#[keyword]`가 붙은 항목의 가시성([가시성](../005-modules/506-visibility.md))은 항목 접근에만 적용됩니다. 키워드 등록 효과와는 별개입니다.

```rok
pub(pkg) fn keyword_handler(...) { ... }

#[keyword("with")]
fn another_handler(...) { ... }     // 키워드 등록 - 패키지 전체에 적용
```

핸들러를 외부에서 호출할 수 있는지는 가시성이 정합니다. 키워드 등록은 그와 상관없이 컴파일 단위 전체에 영향을 줍니다.

## 6.6.11. `#[keyword]`와 사용자 정의 매크로의 차이

다른 언어의 매크로 시스템과 비교하면 다음과 같습니다.

- Rust proc macro: 토큰을 마음대로 변환하고, 사용자가 코드를 자유롭게 생성합니다. 위생은 별개 문제입니다.
- Lisp macro: 동적 매크로입니다. 런타임에도 등록할 수 있습니다.
- Rok `#[keyword]`: 컴파일 타임에 키워드를 등록합니다. 키워드가 무엇으로 풀릴지는 핸들러 함수가 정합니다. 토큰을 자유롭게 변환할 수는 없습니다.

Rok은 매크로 시스템을 일부러 제한합니다. 표현력과 도구 친화성 가운데 도구 친화성을 우선합니다.

## 6.6.12. 등록된 키워드와 함수 호출

```rok
// 키워드 형태
with(mutex) { critical(); }

// 함수 호출 형태 (등록 없이)
with_lock(mutex) { critical(); }     // 함수 + 트레일링 클로저
```

DSL 같은 패턴은 대부분 함수와 트레일링 클로저의 조합으로 충분합니다. `#[keyword]` 등록은 그 형태로 표현하기 부자연스러울 때만 쓰기를 권장합니다.

## 6.6.13. 평가 시점

컴파일러는 키워드 등록을 스캐너 사전 패스에서 처리합니다. 다른 메타 처리(cfg, 메타 블록 확장 등)보다 먼저입니다.

이 순서 덕분에 키워드 핸들러 자체에 cfg를 조건부로 적용할 수 있습니다. 메타 블록 본체 안에서 키워드를 쓸 수도 있습니다. 메타 블록이나 키워드 핸들러의 `#[cfg]`는 그것을 정의한 패키지의 cfg로 평가합니다. 그 패키지 자신의 feature([9.10.4c](../009-tools/910-rok-frontend.md#9104c-feature))를 쓴다는 뜻입니다.

## 6.6.14. 사용 자제 권장

`#[keyword]`는 드물게, 신중하게 쓰기를 권장합니다. 등록할 때마다 언어 표면이 늘어납니다. 다른 사용자는 새 키워드를 보고 의미를 짐작해야 합니다.

널리 쓰일 키워드라면 [키워드](../001-lexical/105-keywords.md)의 예약 목록에 직접 추가하는 편이 더 적절할 수 있습니다. 언어 사양을 바꾸는 방법입니다.
