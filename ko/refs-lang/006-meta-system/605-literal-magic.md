# 6.5. `#[literal(...)]` 매직

`#[literal(...)]` 속성은 사용자가 쓴 문법 패턴을 리터럴로 등록합니다. 컴파일러는 이 리터럴을 라이브러리 핸들러로 디스패치합니다.

## 6.5.1. 동기

Rok에는 [숫자 리터럴](../001-lexical/106-numeric-literals.md)부터 [진리값과 센티넬 리터럴](../001-lexical/109-other-literals.md)까지에서 정의한 어휘 리터럴(숫자, 문자열, 문자, 진리값)이 있습니다. 이 밖에 컬렉션, 범위, 슬라이스 같은 복합 리터럴은 표준 라이브러리가 등록합니다.

```
[1, 2, 3]                 → List<T> 인스턴스 (기대 타입이 [T; N] 이면 고정 배열 - 컴파일러)
{"a": 1, "b": 2}          → Dict<K, V>
{1, 2, 3}                 → Set<T>
(1, "hi", true)            → Tuple (컴파일러)
0..5                       → Range<T>
0..=5                      → RangeInclusive<T>
1:3                        → Slice<T> (컴파일러)
2i                         → Complex<T>
```

`(컴파일러)` 표시가 붙은 것은 핸들러 없이 컴파일러가 직접 만드는 리터럴입니다. 고정 배열, 튜플, 인덱스 안의 슬라이스 `a[i:j]`는 언어 고유의 문법이므로 등록할 수 없습니다(6.5.7, 6.5.9).

이 리터럴의 문법은 [구두점과 연산자 토큰](../001-lexical/110-punctuation-and-operator-tokens.md)의 토큰과 [타입 표현식](../002-types/201-type-expressions.md) 등의 형태로 이루어집니다. 하지만 어떤 라이브러리 타입을 만들지는 라이브러리가 정합니다.

`#[literal]` 매직은 그 결정을 트레잇이나 함수에 붙입니다.

숫자 리터럴의 타입은 이 매직이 아니라 언어가 정합니다([1.6.2](../001-lexical/106-numeric-literals.md#162-타입-접미사), [1.6.3](../001-lexical/106-numeric-literals.md#163-접미사-없는-리터럴)). 숫자에서 `#[literal]`이 다루는 것은 `2i`처럼 언어가 정의하지 않은 접미사뿐입니다.

## 6.5.2. 형태

패턴은 문자열이 아니라 속성 괄호 안에 **토큰으로 직접** 씁니다. 따옴표는 패턴 안에서 리터럴 토큰 하나를 감쌀 때만 씁니다.

```
literal_attr    ::= "#" "[" "literal" "(" pattern ("," "priority" "=" "-"? int_lit)? ")" "]"
pattern         ::= pat_elem+
pat_elem        ::= pat_atom pat_rep?
pat_atom        ::= string_lit                          // 리터럴 토큰 하나
                  | "expr" | "number" | "string" | "ident"  // 캡처
                  | "{" pattern "}" | "(" pattern ")"     // 그룹
pat_rep         ::= ("%" string_lit)? ("*" | "+")
                  | "?"
```

```rok
#[literal("[" {expr} % "," * "]")]
fn list_literal<T>(items: ...T) -> List<T> { ... }

#[literal("{" {expr ":" expr} % "," * "}")]
fn dict_literal<K: Hash, V>(pairs: ...(K, V)) -> Dict<K, V> { ... }

#[literal("{" {expr} % "," + "}")]
fn set_literal<T: Hash>(items: ...T) -> Set<T> { ... }

#[literal(expr ".." expr)]
fn range_literal<T>(start: T, end: T) -> Range<T> { ... }

#[literal(expr "..=" expr)]
fn range_inclusive_literal<T>(start: T, end: T) -> RangeInclusive<T> { ... }

#[literal(number "i")]
fn imaginary_literal(n: f64) -> Complex<f64> { ... }

#[literal("m" "[" {{expr} % "," +} % ";" + "]", priority = 2)]
fn matrix_literal<const C: usize>(rows: ...[f64; C]) -> Matrix { ... }   // 행마다 [f64; C]
```

기본 형태는 `#[literal(패턴)]`입니다. 뒤에 `, priority = N`을 붙일 수 있습니다(6.5.5). N은 음수일 수 있고 기본값은 0입니다. 핸들러는 함수입니다. 패턴에 매칭되는 리터럴은 그 함수의 호출이 됩니다.

표준 라이브러리의 등록은 모든 패키지에서 보입니다. 사용자 패키지의 등록은 그 패키지 안에서만 보입니다. 컴파일러는 파싱 전에 등록을 모으므로 등록한 위치와 상관없이 적용됩니다.

## 6.5.3. 문법 패턴의 형식

문법 패턴은 작은 질의 언어입니다.

| 토큰       | 의미                                          |
|------------|-----------------------------------------------|
| `"문자열"` | 리터럴 토큰 (구두점 또는 키워드). 그대로 매칭 |
| `expr`     | 임의의 표현식                                 |
| `number`   | 숫자 리터럴                                   |
| `string`   | 문자열 리터럴                                 |
| `ident`    | 식별자                                        |
| `{ ... }`  | 그룹                                          |
| `( ... )`  | 그룹 (`{ }`와 같음)                          |
| `% ","`    | 구분자 (쉼표 등). 뒤에 `*` / `+`가 와야 함   |
| `+`        | 1회 이상 반복                                 |
| `*`        | 0회 이상 반복                                 |
| `?`        | 선택적 (0회 또는 1회)                         |

예시를 나누어 읽으면 다음과 같습니다.

```
"[" {expr} % "," * "]"
 │   │      │       │
 │   │      │       └── close token
 │   │      └── zero or more
 │   ├── separated by comma
 │   └── expr group
 └── open token
```

> open token은 여는 토큰, close token은 닫는 토큰, expr group은 expr 그룹, separated by comma는 쉼표로 구분, zero or more는 0회 이상 반복을 뜻합니다.

이 패턴은 `[]`, `[1]`, `[1, 2]`, `[1, 2, 3]` 등 쉼표로 구분한 모든 리스트에 매칭됩니다. 구분자 반복은 끝에 구분자 하나를 더 허용합니다(`[1, 2,]`).

따옴표 안은 토큰 하나여야 합니다. `"ab cd"`처럼 여러 토큰이면 에러입니다. 토큰마다 따로 따옴표를 씌우세요.

## 6.5.4. 매칭과 디스패치

소스의 `[1, 2, 3]`은 다음 단계로 처리됩니다.

1. 파서가 등록된 `#[literal]` 패턴 가운데 매칭되는 것을 찾습니다.
2. 매칭되면 매칭된 부분 표현식을 인자로 넘겨 그 핸들러 함수를 호출합니다.
3. 핸들러 함수가 값을 만들어 반환합니다.

```rok
[1, 2, 3]
   ↓
list_literal(1, 2, 3)          // items: Slice<i32>
   ↓
List<i32> 인스턴스
```

캡처는 순서대로 핸들러의 인자가 됩니다.

| 패턴 부분                   | 인자                                                                            |
|-----------------------------|---------------------------------------------------------------------------------|
| 캡처 하나 (`expr` 등)       | 값 하나                                                                         |
| `?` 그룹 안의 캡처          | 캡처마다 값 또는 `none`                                                         |
| `*` / `+` 반복              | 인자 하나에 모든 원소. 원소는 값, 캡처가 여럿이면 튜플, 중첩 반복이면 배열      |
| variadic `...T` 자리의 반복 | 각 원소가 가변 인자가 됨 ([4.2.5](../004-functions/402-parameters.md#425-variadic-t)) |

컴파일러는 핸들러 시그니처가 캡처 개수와 반복 위치에 맞는지 검사합니다.

## 6.5.5. 다중 핸들러(모호성)

같은 입력에 여러 패턴이 매칭되면 먼저 **가장 긴 매치**를 고릅니다(사용자 패턴끼리). 매치 길이가 같거나 한 패턴에 핸들러가 여럿이면 다음 규칙을 차례로 적용합니다.

1. 반환 타입이 받는 슬롯의 타입과 같은 핸들러를 고릅니다. 받는 슬롯이 `Set<T>`이면 set 핸들러가 우선합니다.
2. 남은 핸들러 가운데 `priority`가 가장 높은 것을 고릅니다.
3. 그래도 둘 이상 남으면 모호성 에러입니다.

슬롯 타입은 고른 핸들러의 타입 매개변수도 정합니다. `let s: Set<i64> = {1, 2};`에서 `set_literal`의 `T`는 `i64`입니다.

같은 패턴을 같은 `priority`, 같은 반환 타입으로 두 번 등록하면 위 규칙으로 구별할 수 없습니다. 그래서 쓰는 시점이 아니라 등록하는 시점에 에러입니다.

## 6.5.6. Dict와 Set의 모호성

```
{ "a": 1 }              // Dict (`:` 패턴 매칭)
{ 1, 2 }                 // Set (값만)
{ 1, }                   // Set (단일 원소 - 후행 콤마)
{ 1 }                    // 항상 block
{ stmt; stmt; expr }    // block ([블록 표현식](../003-expressions/309-block-expressions.md))
```

`{ ... }`는 [블록 표현식](../003-expressions/309-block-expressions.md)으로도 쓰이므로 다음 규칙으로 구분합니다.

- `{ expr ; ... }`처럼 문이 있으면 [블록](../000-meta/007-glossary.md#block-블록)입니다.
- `{ expr : expr , ... }`처럼 `:`가 있으면 Dict입니다.
- `{ expr , ... }`처럼 쉼표가 하나라도 있으면 Set입니다. 원소가 하나인 Set은 `{ expr , }`로 씁니다.
- `{ expr }`은 받는 슬롯의 타입과 상관없이 항상 블록입니다.

set 패턴 `"{" {expr} % "," + "}"`은 글자로만 보면 `{e}`에도 맞습니다. 하지만 `{e}`는 위 규칙에 따라 블록이므로 핸들러로 가지 않습니다. 원소가 하나인 set은 `{e,}`입니다.

파서는 내용을 보고 이 규칙대로 결정합니다. 읽기 쉽도록 `s{1, 2}` 같은 set 전용 접두어는 두지 않습니다.

## 6.5.7. 사용자 정의 리터럴

드물지만 사용자도 리터럴을 직접 등록할 수 있습니다.

```rok
struct Coord { x: f64; y: f64; }

#[literal("(" expr "," expr ")" "@")]
fn coord_literal(x: f64, y: f64) -> Coord { Coord { x, y } }

let p = (3.14, 2.71)@;        // → coord_literal(3.14, 2.71) → Coord
```

등록할 수 있는 패턴은 세 가지입니다.

| 패턴                                                 | 처리                                                               |
|------------------------------------------------------|--------------------------------------------------------------------|
| 내장 모양 (`[..]`, `{k: v}`, `{a, b}`, 범위 여섯 가지) | 파서가 언어 규칙대로 파싱하고, 그 모양에 등록된 핸들러를 부름      |
| `number "suffix"`                                    | 언어에 없는 숫자 접미사 (`2i`, [1.6.2](../001-lexical/106-numeric-literals.md#162-타입-접미사)) |
| 따옴표 토큰으로 시작하는 그 밖의 패턴                | 모든 식 시작에서 내장 문법보다 먼저 시도, 가장 긴 매치             |

사용자 패턴은 따옴표 토큰으로 시작해야 합니다. 캡처로 시작할 수 있는 것은 내장 범위 모양(`expr ".." expr` 등)뿐입니다. 다음은 에러입니다.

- 튜플 모양 `"(" expr "," {expr} % "," * ")"`을 등록하는 것. 튜플은 언어 고유입니다.
- 언어의 숫자 접미사(`i32`, `f64` 등)를 등록하는 것.

식별자 토큰으로 시작하는 패턴(`"m" "["`)은 이름이 같은 변수의 인덱싱(`m[i]`)보다 먼저 시도되므로 그 이름을 가립니다.

## 6.5.8. 리터럴 핸들러의 `const` 호환

```rok
#[literal("[" {expr} % "," * "]")]
const fn list_literal<T>(items: ...T) -> List<T> { ... }
```

- `const fn` 핸들러는 인자가 모두 상수이면 컴파일 타임에 평가합니다([5.2.4](../005-modules/502-const.md#524-상수-식과-평가기)). 그 안의 panic이나 `throw`는 리터럴 위치의 컴파일 에러가 됩니다.
- 결과가 힙을 쓰면(`List` 등) 컴파일 타임에는 검사만 하고 값은 런타임에 만듭니다([5.2.5](../005-modules/502-const.md#525-const-fn-컴파일-타임-평가-가능한-함수)).
- 인자에 런타임 값이 있으면 일반 호출입니다.
- `const fn`이 아닌 핸들러는 런타임에 호출합니다.

## 6.5.9. 슬라이스

인덱스 안의 `a[i:j]` / `a[i:j:k]`는 리터럴이 아니라 언어의 슬라이싱 구문입니다. 그래서 `#[literal]`로 등록할 수 없습니다. 의미와 트레잇 매핑은 [인덱싱과 슬라이싱](../003-expressions/306-indexing-and-slicing.md)에서 정합니다.

## 6.5.10. 평가 시점

`#[literal]` 매핑은 컴파일 타임에 다음 순서로 일어납니다.

1. 파서가 입력을 토큰화합니다.
2. 파서가 입력의 식 자리마다 등록된 패턴을 시도합니다.
3. 매칭되는 패턴이 있으면 그 자리에 핸들러 호출을 넣습니다.
4. 이후 패스(이름 해소, 타입 검사)가 그 결과를 처리합니다.

따라서 `[1, 2, 3]`이 어떤 함수 호출인지는 컴파일 타임에 확정됩니다.

## 6.5.11. 매직과 표준 라이브러리

`#[literal]`은 거의 표준 라이브러리에서만 씁니다. 주로 Rok의 컬렉션 리터럴을 등록하는 데 씁니다.

사용자가 자기 라이브러리에 등록할 수도 있습니다. 이때는 기본 토큰과 충돌하지 않는 패턴을 신중히 골라야 합니다.
