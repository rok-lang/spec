# 0.1. 실행 엔진과 사용자 표면

Rok의 실행 모델은 두 축으로 이루어집니다. 하나는 코드가 기계어가 되는 방식을 정하는 실행 엔진이고, 다른 하나는 사용자가 코드를 입력하고 결과를 받는 환경인 사용자 표면입니다. 엔진은 두 가지, 표면은 세 가지입니다. 여러 표면이 같은 엔진을 공유하므로 엔진 수가 표면 수보다 적습니다.

## 0.1.1. 실행 엔진

### JIT (Just-in-Time)

JIT 엔진은 코드 조각이 입력되는 즉시 컴파일해서 실행합니다. 입력 단위(한 줄이나 한 셀)는 직전까지 쌓인 상태, 곧 변수, 함수, 가져온 모듈 등을 참조합니다. 새 입력이 기존 정의를 덮어쓰면 이후 입력은 새 정의를 봅니다. 컴파일 결과는 메모리와 디스크에 캐시되므로 같은 입력을 다시 실행하면 바로 끝납니다.

### AOT (Ahead-of-Time)

AOT 엔진은 소스 전체를 미리 컴파일해서 산출물 하나(실행 파일 또는 정적 라이브러리 `.a`)로 만듭니다. 실행을 시작할 때 컴파일 비용이 들지 않고, 다른 Rok 코드에서 라이브러리로 링크할 수 있습니다. 다만 런타임에 새 코드를 추가할 수는 없습니다.

### 의미론은 같습니다

> [!IMPORTANT]
> 두 엔진은 같은 의미론을 공유합니다. JIT에서 동작한 코드는 AOT 빌드에서도 같은 결과를 냅니다. 차이는 **컴파일 시점**에만 있습니다. 본 사양은 두 엔진에 동시에 적용되며, 한쪽에만 적용되는 의미론은 없습니다.

이 원칙은 진입점에도 적용됩니다. REPL과 Jupyter의 입력은 실행 패키지의 `main.rok` 끝에 top-level 문과 항목을 차례로 덧붙인 것과 의미가 같습니다. 대화형 표면에만 있는 것은 세션 조작뿐입니다. 셀 최상위에서 같은 이름을 `let`으로 다시 선언해 새 바인딩을 만드는 일, 셀 재실행이 여기에 속합니다 ([4.16.10](../004-functions/416-entry-point.md#41610-jit--repl-과의-관계)).

JIT와 AOT라는 약어는 [용어집](007-glossary.md)에 적힌 그대로 씁니다.

### 같은 파이프라인을 공유합니다

JIT와 AOT는 rok-mir까지 같은 컴파일 파이프라인을 통과합니다 ([0.2. 컴파일 파이프라인](002-pipeline.md)). 갈라지는 곳은 코드 생성뿐입니다. **JIT 엔진**은 입력마다 Rok의 native backend로 곧바로 기계어를 만들어, 세션 내내 살아 있는 host 프로세스에서 실행합니다 ([9.6](../009-tools/906-jit-engine.md)). **AOT 엔진**은 `-O0`에서는 native backend로, `-O1` 이상에서는 MLIR → LLVM 파이프라인으로 코드를 만들고 네이티브 바이너리로 링크합니다 ([9.2](../009-tools/902-aot-pipeline.md)). 두 backend는 같은 런타임 ABI를 따릅니다.

이 구조에서는 컴파일러 구현 하나가 두 엔진을 모두 맡습니다. 그러므로 동작 차이가 생긴다면 원인은 컴파일러가 아니라 실행 시점의 환경(메모리, 스레드, OS 자원)에 있다고 보아야 합니다.

## 0.1.2. 사용자 표면

### REPL

REPL 표면에서는 터미널에 한 줄 또는 식 하나를 입력하면 바로 평가해서 결과를 출력합니다. 주로 탐색, 수식 시연, 타입 확인에 씁니다. 변수와 함수 정의는 입력 사이에 누적되고, 마지막 표현식의 값과 타입은 자동으로 표시됩니다.

엔진은 JIT이고, 입력 단위는 한 줄 또는 한 식입니다.

### Jupyter

Jupyter 표면은 Jupyter / JupyterLab의 Rok 커널로 동작합니다. 셀 단위로 평가하고, 결과는 노트북 안에 시각화, 테이블, 텍스트로 남습니다. 데이터 분석의 표준 작업 흐름이 이 방식이며, 셀을 다시 실행하면 이전 정의가 교체됩니다.

엔진은 JIT이고, 입력 단위는 한 셀입니다. Jupyter 프론트엔드 (JupyterLab, Notebook, VS Code 등)가 Rok 커널을 별도 프로세스로 실행하고 ZeroMQ 기반 Jupyter wire protocol로 통신합니다 ([9.8](../009-tools/908-jupyter-integration.md)). 커널은 OS의 파일 시스템, 네트워크, 외부 프로세스를 그대로 씁니다.

### AOT 산출물

AOT 산출물 표면에서는 소스를 빌드해 만든 실행 파일을 직접 실행하거나, 정적 라이브러리를 다른 빌드에 링크합니다.

엔진은 AOT입니다.

## 0.1.3. 엔진과 표면의 매핑

```
              ┌── REPL (terminal)
   JIT  ──────┤
              └── Jupyter (kernel, ZMQ)

   AOT  ────── direct artifact execution
```

세 표면이 두 엔진을 공유합니다.

## 0.1.4. 의미의 기준

사양이 모호한 지점에서는 AOT 의미가 우선합니다. JIT는 AOT의 의미를 셀 단위로 재현합니다.
