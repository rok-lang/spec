# 0.4. 언어와 표준 라이브러리의 경계

언어가 정의하는 것과 표준 라이브러리가 정의하는 것 사이의 경계를 선언한다. 이 경계는 nok
사양의 핵심 결정이며, 이후 사양 문서는 모두 이 경계를 전제한다.

## 0.4.1. 언어가 정의하는 것

언어 사양이 직접 다루는 범위는 다음 다섯이다.

### 1. 로직 흐름

값을 흘려보내는 구문과 의미.

- 분기, 반복, 패턴 매칭, 예외 처리, 라벨 점프
- 비동기와 생성자(generator)의 구문 (선언자, 연산자 키워드)

### 2. 컨테이너 문법

사용자 타입을 정의하는 형태.

- 곱 타입(레코드형): 여러 필드의 묶음
- 합 타입(태그형): 여러 변형 중 하나를 골라 가짐
- 비태그 `union`: 같은 메모리를 여러 형으로 해석
- 트레잇: 동작의 묶음 선언
- `impl` 블록: 트레잇과 메서드의 구체 구현
- 제네릭: 타입을 파라미터로 받는 형태

### 3. 메타 시스템

위 두 범주에 부착되어 동작을 바인딩하는 속성(attribute) 체계.

- 표준 속성 (언어가 인식하는 정해진 이름 묶음)
- 사용자 정의 속성과 derive 의 템플릿 시스템

### 4. 변수 / 가시성 / 모듈

- 변수 선언 키워드, 참조 수식어, 전역·상수 키워드
- 가시성 단계
- 모듈, 패키지 단위의 이름 노출 규약

### 5. 연산자 구문

`a + b`, `s[1:3]`, `x.f`, `f(args)` 같은 표기법의 모양.

표기법이 어떤 동작을 의미하는지는 언어가 정의하지 않는다. 표기법은 표준 라이브러리에 등록된
트레잇 메서드로 desugar 된다.

## 0.4.2. 표준 라이브러리가 정의하는 것

위 다섯을 제외한 거의 모든 의미.

- **숫자·문자** 타입과 그 연산
- **연산자 의미론**: 산술, 비교, 논리, 비트, 인덱싱, 범위. 모두 표준 라이브러리의 트레잇
  `impl` 로 정의.
- **변환 매트릭스**: 형 간 변환 규칙 전체
- **컬렉션**: 리스트, 맵, 셋, 튜플, 문자열 등
- **반복자, 스트림, 미래값**
- **동시성 프리미티브**: atomic, mutex, channel
- **태스크, 스레드, 병렬 실행 API**
- **입출력, 시간, 랜덤, 네트워크**
- **에러 타입 전체**

언어는 이들의 이름을 모른다. 컴파일러가 특정 라이브러리 타입을 인식하는 경우는 메타 시스템의
속성 바인딩을 통해서만 일어나며, 바인딩 자체가 표준 라이브러리 안에 작성된다.

## 0.4.3. 경계가 만드는 결과

### Syntax 는 언어, 동작은 라이브러리

> [!IMPORTANT]
> 모든 표기법은 언어가 정의하지만, 값에 가하는 연산의 의미는 표준 라이브러리에 등록된
> 트레잇 메서드가 결정한다.

| 표기        | 언어가 정하는 것      | 라이브러리가 정하는 것                   |
| ----------- | --------------------- | ---------------------------------------- |
| `a + b`     | 토큰 시퀀스, 우선순위 | `+` 가 어떤 트레잇 메서드인지, 결과 타입 |
| `s[1:3]`    | 슬라이스 표기 형태    | 인덱싱, 경계 검사, 결과 타입             |
| `x.f()`     | 메서드 호출 형태      | 메서드 디스패치 규칙                     |
| `let x = 1` | 선언 형태             | 리터럴 `1` 의 타입 결정                  |

### 언어 수준 질문의 범위

설계나 구현 결정이 언어 수준 질문인지 라이브러리 수준 질문인지를 먼저 구분한다.

언어 수준에 남는 질문은 다음 영역에 한정된다.

- 컴파일러 의미론 (이름 해소, closure capture, 가시성, 에러 진단)
- 구문 결정 (이스케이프, 우선순위, 리터럴 접미사, 슬라이스 표기 모양)
- 런타임 호출 규약과 메모리 모델 (객체 레이아웃, calling convention)
- 리소스 관리 (수명, 예외 전파 메커니즘)
- 타입 시스템 규칙 (트레잇-as-타입 금지, 점진 타이핑, niche 최적화)

### 라이브러리 수준으로 위임되는 것

위 목록 외의 거의 모든 값에 대한 연산은 라이브러리 결정이다. 본 사양 문서는 이러한 연산의
시맨틱을 직접 규정하지 않는다.

대신 사양은 다음을 명시한다.

- 그 연산이 어떤 트레잇 메서드 호출로 desugar 되는지.
- 그 트레잇이 라이브러리의 어느 계층에서 정의되는지의 위치 규약.
- 정의되지 않은 경우의 컴파일 에러 형태.

이 분리가 nok 의 설계 슬로건(작은 언어, 풍부한 라이브러리)을 사양 수준에서 구현한다.
