## nok 이란

**nok** 은 과학과 데이터 분석을 주된 대상으로 하는 범용 프로그래밍 언어이다.

- 과학: 수치 계산, 시뮬레이션, 모델링.
- 데이터 분석: 표 데이터 처리, 통계, 시각화.
- 범용: 위 영역에 한정되지 않는다. 시스템 도구, 웹 백엔드, CLI 도 합리적으로 작성할 수 있다.

실제 작업 흐름은 이 셋을 가로지른다. 노트북에서 시작한 코드가 정적 산출물의 일부가 되고,
다시 라이브러리로 묶여 다른 노트북에서 호출된다. nok 은 그 흐름이 한 언어 안에서 자연스럽게
이어지도록 설계되었다.

## 설계 슬로건

> [!IMPORTANT]
> **"언어는 작게, 라이브러리는 풍부하게."**

언어 사양이 직접 정의하는 범위를 좁게 잡는다. 숫자 연산, 형 변환, 컬렉션, 입출력, 동시성
등은 모두 표준 라이브러리에 위임한다. 언어 코어는 작고, 라이브러리가 영역 의미를 결정한다.

이 분리에는 두 동기가 있다.

- 수정 가능성: 영역(과학·데이터)에 특화된 결정을 라이브러리 수준에서 진화시킬 수 있다.
- 검증 가능성: 언어 사양이 작을수록 구현, 검증, 교육의 비용이 낮다.

언어와 라이브러리의 정확한 경계는 [0.4. 언어와 표준 라이브러리의 경계](004-language-vs-stdlib.md)
에서 선언한다.

## 통제 속의 자유

> **"규칙이 명확할수록 그 안에서 자유로워진다."**

nok 은 제약을 두려워하지 않는다. 정적 타입, 닫힌 합 타입, 트레잇-as-타입 금지, 묵시적 승급
금지, AOT-only 컴파일. 이 결정들은 사용자의 선택지를 좁힌다. 그러나 좁아진 선택지 안에서
사용자는 예측 가능하고 깊게 통제할 수 있는 코드를 쓴다.

이 철학은 두 방향에서 나온다.

- 언어가 통제하는 영역: 타입, 디스패치, 메모리 모델, 평가 순서. 사용자가 매번 결정하지 않고
  언어가 한 번에 정한다.
- 사용자가 자유로운 영역: 라이브러리 설계, 도메인 모델링, 알고리듬 선택, 코드 구조. 언어는
  강요하지 않고, 라이브러리와 메타 시스템이 깊은 표현을 허용한다.

점진(gradual) `any` 슬롯과 정적 타입의 공존, JIT 와 AOT 의 동의미 보장, 메타 시스템을 통한
언어 자체의 확장은 모두 이 원칙의 구체적 형태다. 잘 통제된 코어 위에서만 자유로운 영역이
가능하다.

## 비목표

다음은 nok 의 우선 지원 영역이 아니다. 영원히 배제한다는 뜻은 아니며, 초기 사양과 구현이
이들을 위해 타협하지 않는다는 뜻이다.

- 모바일 앱 개발 (iOS, Android)
- bare-metal 임베디드, 운영체제 없는 환경
- 16-bit, 8-bit 마이크로컨트롤러

이 영역은 별도의 언어 생태계가 이미 충분히 성숙했고, 과학·데이터 작업 흐름의 핵심 경로에서
벗어난다.
