## Rok 이란

**Rok**은 과학과 데이터 분석을 주된 대상으로 하는 범용 프로그래밍 언어입니다. 과학 쪽에서는 수치 계산, 시뮬레이션, 모델링을 다루고, 데이터 분석 쪽에서는 표 데이터 처리, 통계, 시각화를 다룹니다. 범용 언어이므로 이 영역에만 한정되지 않고, 시스템 도구, 웹 백엔드, CLI도 무리 없이 작성할 수 있습니다.

실제 작업 흐름은 이 셋을 가로지릅니다. 노트북에서 시작한 코드가 정적 산출물의 일부가 되고, 다시 라이브러리로 묶여 다른 노트북에서 호출됩니다. Rok은 이 흐름이 한 언어 안에서 끊기지 않도록 설계했습니다.

## 설계 슬로건

> [!IMPORTANT]
> **"언어는 작게, 라이브러리는 풍부하게."**

언어 사양이 직접 정의하는 범위는 좁게 잡습니다. 숫자 연산, 형 변환, 컬렉션, 입출력, 동시성 등은 모두 표준 라이브러리에 맡깁니다. 언어 코어는 작게 유지하고, 영역별 의미는 라이브러리가 정합니다.

이렇게 나누는 이유는 두 가지입니다. 첫째는 수정 가능성입니다. 과학, 데이터처럼 특정 영역에 맞춘 결정을 라이브러리 수준에서 발전시킬 수 있습니다. 둘째는 검증 가능성입니다. 언어 사양이 작을수록 구현, 검증, 교육 비용이 낮아집니다.

언어와 라이브러리의 정확한 경계는 [0.4. 언어와 표준 라이브러리의 경계](004-language-vs-standard-libraries.md)에서 선언합니다.

## 통제 속의 자유

> [!IMPORTANT]
> **"규칙이 명확할수록 그 안에서 자유로워집니다."**

Rok은 제약을 피하지 않습니다. 정적 타입, 닫힌 합 타입, 트레잇-as-타입 금지, 묵시적 승급 금지, AOT-only 컴파일이 그런 결정입니다. 이 결정들은 사용자의 선택지를 좁힙니다. 대신 좁아진 선택지 안에서 사용자는 예측할 수 있고 깊이 통제할 수 있는 코드를 씁니다.

이 철학은 두 방향으로 나타납니다. 한쪽은 언어가 통제하는 영역으로, 타입, 디스패치, 메모리 모델, 평가 순서가 여기에 속합니다. 이 영역은 사용자가 매번 결정하지 않고 언어가 한 번에 정합니다. 다른 쪽은 사용자가 자유로운 영역으로, 라이브러리 설계, 도메인 모델링, 알고리듬 선택, 코드 구조가 여기에 속합니다. 이 영역에서 언어는 아무것도 강요하지 않으며, 라이브러리와 메타 시스템으로 깊은 표현을 할 수 있습니다.

점진(gradual) `any` 슬롯과 정적 타입의 공존, JIT와 AOT의 동일 의미 보장, 메타 시스템으로 언어 자체를 확장하는 일은 모두 이 원칙이 구체화된 모습입니다. 자유로운 영역은 잘 통제된 코어 위에서만 가능합니다.

## 비목표

다음은 Rok의 우선 지원 영역이 아닙니다. 영원히 배제한다는 뜻은 아니며, 초기 사양과 구현이 이들을 위해 타협하지 않는다는 뜻입니다. 대상은 모바일 앱 개발(iOS, Android), bare-metal 임베디드와 운영체제 없는 환경, 16-bit와 8-bit 마이크로컨트롤러입니다.

이 영역들에는 이미 충분히 성숙한 언어 생태계가 따로 있고, 과학과 데이터 작업 흐름의 주된 경로에서도 벗어나 있습니다.
