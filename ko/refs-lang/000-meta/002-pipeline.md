# 0.2. 컴파일 파이프라인

nok 컴파일러를 본 사양에서는 `nokc` 라 부른다. `nokc` 는 소스 코드를 표준 MLIR 텍스트로
방출하는 것까지를 책임진다. 이후의 최적화와 바이너리 생성은 표준 도구체인이 담당한다.

## 0.2.1. 단계

```
  source code
        │
        ▼
   nok-hir         (High-level IR — 타입 추론 전, 사용자 코드 구조 그대로)
        │
        ▼
   nok-mir         (Mid-level IR — 단형화 / 연산자 desugar 완료, 모든 타입 확정)
        │
        ▼
   표준 MLIR        (upstream MLIR 다이얼렉트 텍스트 — `func`, `arith`, `scf`, ...)
        │
        ▼
   LLVM IR / 네이티브 (mlir-opt → mlir-translate → clang / lld)
```

## 0.2.2. 단방향 가시성

각 단계는 직전 단계만 본다.

- `nok-hir` 생성기는 소스만 본다.
- `nok-mir` 생성기는 `nok-hir` 만 본다.
- MLIR 방출기는 `nok-mir` 만 본다.

상위 단계의 결과를 아래 단계에서 다시 참고하지 않는다. 사양 문서도 같은 규칙을 따른다.
번호가 작은 파일은 번호가 큰 파일을 참조하지 않는다.

## 0.2.3. 표준 MLIR 다이얼렉트만 사용

nok 전용 MLIR 다이얼렉트는 정의하지 않는다. 사용 다이얼렉트는 모두 upstream MLIR 의 공식
다이얼렉트다.

| 다이얼렉트 | 용도                                     |
| ---------- | ---------------------------------------- |
| `func`     | 함수 정의 / 호출                         |
| `arith`    | 정수 / 부동소수 산술 / 비교              |
| `scf`      | 구조적 제어흐름 (`if` / `for` / `while`) |
| `cf`       | 비구조적 분기 (switch, cond_br)          |
| `memref`   | 스택 / 힙 메모리 참조                    |
| `index`    | memref 인덱싱                            |
| `math`     | 수학 함수                                |
| `llvm`     | 저수준 op (intrinsic, `struct`)          |

이 선택은 다음을 보장한다.

- upstream MLIR 의 개선이 자동으로 nok 에 흘러든다.
- IREE, Enzyme, Triton 같은 외부 MLIR 기반 도구와 상호운용한다.
- 자체 다이얼렉트의 등록과 유지보수 비용이 없다.

대가로 nok 의 고차원 의미를 표준 다이얼렉트로 떨어뜨리는 책임이 컴파일러, 특히 `nok-mir → MLIR`
단계에 모인다. 이는 의도된 부담이다. 파이프라인 끝단의 선택지를 닫지 않기 위해 안으로 부담을
옮긴다.

## 0.2.4. MLIR 텍스트 직접 생성

컴파일러는 MLIR 을 텍스트로 출력한다. MLIR 라이브러리 바인딩(C++ 또는 그 외)을 호출하지
않는다.

- 외부 라이브러리 의존을 줄인다.
- 크로스 컴파일 매트릭스가 단순해진다. MLIR 도구가 설치된 환경이면 어디서든 결과를 받는다.
- `nokc --emit=mlir` 같은 디버그 출력이 그대로 표준 도구로 흘러간다.
