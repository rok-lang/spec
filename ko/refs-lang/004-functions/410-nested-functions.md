# 4.10. 중첩 함수

함수 본체 안에서 또 다른 함수를 정의할 수 있다.

## 4.10.1. 형태

```nok
fn outer(x: i32) -> i32 {
    fn inner(y: i32) -> i32 {
        y + 1
    }

    inner(x) + inner(x * 2)
}
```

- `fn` 키워드를 외부 함수의 본체 안에 둔다.
- 정의와 사용 규칙은 [함수 선언](401-function-declaration.md) 의 모듈 수준 함수와 같다.

## 4.10.2. 가시 범위

중첩 함수는 정의된 블록 스코프 안에서만 보인다.

```nok
fn outer() {
    fn helper() { ... }
    helper();                     // OK
}

helper();                          // ERROR — outer 밖에서는 보이지 않음
```

블록을 벗어나면 중첩 함수의 이름은 더 이상 보이지 않는다.

## 4.10.3. 외부 변수 캡처 (없음)

중첩 함수는 외부 함수의 변수를 캡처하지 않는다.

```nok
fn outer(n: i32) {
    fn inner() {
        let x = n;                // ERROR — n 이 보이지 않음
    }
    inner();
}
```

이 결정은 중첩 함수가 깨끗한 함수 단위임을 분명히 하기 위해서다. 외부 변수에 의존하는 상태 있는 함수가 필요하면 [클로저](405-closure.md) 를 쓴다.

```nok
fn outer(n: i32) {
    let inner = |x| x + n;        // OK — 클로저는 캡처 가능
    inner(5);
}
```

이 분리:

- 중첩 함수. 외부 변수를 못 본다. 가시 범위 제한 외에는 모듈 수준 함수와 같다.
- 클로저. 캡처 가능 ([캡처 의미론](406-capture-semantics.md)).

## 4.10.4. 호출 시 동작

중첩 함수의 호출은 모듈 수준 함수 호출과 같은 규칙을 따른다. 직접 함수 주소로 호출하며, 캡처도 오버헤드도 없다.

## 4.10.5. 정의 순서

같은 블록 안에서는 중첩 함수의 정의 전후 어디서든 호출할 수 있다. 다음 두 형태 모두 OK.

```nok
fn outer() {
    helper();                     // 정의 전 호출
    fn helper() { ... }
}

fn outer() {
    fn helper() { ... }
    helper();                     // 정의 후 호출
}
```

호이스팅 (Hoisting) 으로 블록 전체에서 보이며, 어느 위치에서든 호출할 수 있다.

## 4.10.6. 중첩 함수와 클로저 사이의 선택

| 특성                    | 중첩 함수              | 클로저           |
| ----------------------- | ---------------------- | ---------------- |
| 정의 형태               | `fn name(...) { ... }` | `\| ... \| body` |
| 외부 변수 캡처          | 불가                   | 가능             |
| 이름                    | 있음                   | 없음             |
| 다른 함수에 인자로 전달 | 가능 (이름으로)        | 가능             |
| 상태 없는 도우미        | 적합                   | 가능하지만 과도  |
| 상태 있는 콜백          | 부적합                 | 적합             |

선택 기준:

- 외부 변수가 필요 없고 이름이 있어야 가독성에 도움이 되면 중첩 함수.
- 외부 변수가 필요하거나 익명으로 충분하면 클로저.

## 4.10.7. 중첩 함수의 가시성

중첩 함수는 외부 함수의 본체 안에서만 보인다. 가시성 키워드 (`pub` 등) 는 의미가 없다.

```nok
fn outer() {
    pub fn helper() { ... }       // ERROR — 중첩 함수에 pub 무의미
}
```

가시성은 모듈 수준의 항목에만 적용된다.

## 4.10.8. 같은 이름의 중첩 함수와 외부 변수

```nok
fn outer() {
    let helper = 42;
    fn helper() { ... }            // ERROR — 같은 이름의 변수와 함수
}
```

같은 블록 안에 같은 이름의 변수와 함수는 충돌한다. 컴파일 에러.

## 4.10.9. 다단 중첩

함수는 임의의 깊이로 중첩할 수 있다.

```nok
fn outer() {
    fn middle() {
        fn inner() { ... }
        inner();
    }
    middle();
}
```

각 단계의 함수는 그 단계 본체 안에서만 보인다. 안쪽 함수가 바깥쪽의 변수나 함수를 캡처하지 않는다는 규칙은 그대로 유지된다.

## 4.10.10. 중첩 함수의 유용한 곳

```nok
fn parse(input: str) -> AST {
    fn parse_expr(s: str) -> Expr { ... }
    fn parse_stmt(s: str) -> Stmt { ... }

    let result = AST::new();
    while !input.is_empty() {
        result.add(parse_stmt(input));
    }
    result
}
```

큰 함수의 내부 도우미. 다른 모듈에 노출할 필요가 없고, 외부 함수의 컨텍스트와 묶여 있을 때 자연스럽다.
