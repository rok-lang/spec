# 4.10. 중첩 함수

함수 본체 안에서 다른 함수를 정의할 수 있습니다.

## 4.10.1. 형태

```rok
fn outer(x: i32) -> i32 {
    fn inner(y: i32) -> i32 {
        y + 1
    }

    inner(x) + inner(x * 2)
}
```

`fn` 선언을 바깥 함수의 본체 안에 두면 되며, 정의와 사용 규칙은 [함수 선언](401-function-declaration.md)에서 다루는 모듈 수준 함수와 같습니다.

## 4.10.2. 가시 범위

중첩 함수는 자신을 정의한 블록 스코프 안에서만 보입니다.

```rok
fn outer() {
    fn helper() { ... }
    helper();                     // OK
}

helper();                          // ERROR: outer 밖에서는 보이지 않음
```

그 블록을 벗어나면 중첩 함수의 이름은 보이지 않습니다.

## 4.10.3. 외부 변수 캡처 (없음)

중첩 함수는 바깥 함수의 변수를 캡처하지 않습니다.

```rok
fn outer(n: i32) {
    fn inner() {
        let x = n;                // ERROR: n 이 보이지 않음
    }
    inner();
}
```

중첩 함수가 깔끔한 함수 단위라는 점을 분명히 하려는 결정입니다. 바깥 변수에 기대는 상태 있는 함수가 필요하면 [클로저](405-closure.md)를 씁니다.

```rok
fn outer(n: i32) {
    let inner = |x| x + n;        // OK: 클로저는 캡처 가능
    inner(5);
}
```

그래서 역할이 이렇게 나뉩니다.

- 중첩 함수는 바깥 변수를 보지 못하며, 가시 범위가 좁다는 점만 빼면 모듈 수준 함수와 같습니다.
- 클로저는 캡처할 수 있습니다([캡처 의미론](406-capture-semantics.md) 참고).

중첩 함수는 자기 블록과 둘러싼 블록들의 항목(`const` 포함)과 `use` 선언을 봅니다 ([3.9.1](../003-expressions/309-block-expressions.md#391-형태)). 닿지 못하는 것은 그 블록들의 지역 변수, 매개변수, 제네릭 매개변수뿐입니다.

## 4.10.4. 호출 시 동작

중첩 함수 호출은 모듈 수준 함수 호출과 같은 규칙을 따릅니다. 함수 주소로 직접 호출하므로 캡처도 오버헤드도 없습니다.

## 4.10.5. 정의 순서

같은 블록 안에서는 중첩 함수를 정의 앞에서도 뒤에서도 호출할 수 있습니다. 다음 두 형태 모두 허용합니다.

```rok
fn outer() {
    helper();                     // 정의 전 호출
    fn helper() { ... }
}

fn outer() {
    fn helper() { ... }
    helper();                     // 정의 후 호출
}
```

호이스팅(Hoisting)으로 블록 전체에서 보이므로 어느 위치에서든 호출할 수 있습니다.

## 4.10.6. 중첩 함수와 클로저 사이의 선택

| 특성                    | 중첩 함수              | 클로저          |
|-------------------------|------------------------|-----------------|
| 정의 형태               | `fn name(...) { ... }` | `\| ... \| body`  |
| 외부 변수 캡처          | 불가                   | 가능            |
| 이름                    | 있음                   | 없음            |
| 다른 함수에 인자로 전달 | 가능 (이름으로)        | 가능            |
| 상태 없는 도우미        | 적합                   | 가능하지만 과도 |
| 상태 있는 콜백          | 부적합                 | 적합            |

바깥 변수가 필요 없고 이름이 있어야 읽기 좋다면 중첩 함수를, 바깥 변수가 필요하거나 이름 없이도 충분하면 클로저를 씁니다.

## 4.10.7. 중첩 함수의 가시성

중첩 함수는 바깥 함수의 본체 안에서만 보이므로, `pub` 같은 가시성 키워드는 의미가 없습니다.

```rok
fn outer() {
    pub fn helper() { ... }       // ERROR: 중첩 함수에 pub 무의미
}
```

가시성은 모듈 수준의 항목에만 적용됩니다. 블록에 선언한 모든 항목도 마찬가지입니다 ([3.9.1](../003-expressions/309-block-expressions.md#391-형태)).

## 4.10.8. 같은 이름의 중첩 함수와 외부 변수

```rok
fn outer() {
    let helper = 42;
    fn helper() { ... }            // ERROR: 같은 이름의 변수와 함수
}
```

같은 블록 안에서 이름이 같은 변수와 함수는 충돌하므로 컴파일 에러입니다.

## 4.10.9. 다단 중첩

함수는 깊이 제한 없이 중첩할 수 있습니다.

```rok
fn outer() {
    fn middle() {
        fn inner() { ... }
        inner();
    }
    middle();
}
```

중첩 함수는 자기 블록 전체에서 보입니다(hoist). 자기 블록과 바깥의 모든 블록에 있는 중첩 함수, 그 밖의 항목, `use` 선언은 보지만, 그 어느 블록의 지역 변수도 보지 않습니다. 블록의 `use`는 같은 이름의 바깥 중첩 함수를 가립니다.

## 4.10.10. 중첩 함수의 유용한 곳

```rok
fn parse(input: str) -> AST {
    fn parse_expr(s: str) -> Expr { ... }
    fn parse_stmt(s: str) -> Stmt { ... }

    let result = AST::new();
    while !input.is_empty() {
        result.add(parse_stmt(input));
    }
    result
}
```

큰 함수의 내부 도우미로 쓰기 좋습니다. 다른 모듈에 노출할 필요가 없고 바깥 함수의 맥락에 묶인 보조 로직이라면 중첩 함수가 잘 맞습니다.
