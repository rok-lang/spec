# 4.5. 클로저

클로저는 이름 없이 표현식 위치에 쓰는 함수 값입니다. 바깥 환경의 변수를 캡처할 수 있습니다. 그래서 주변 상태에 기대는 작은 함수를 짧게 쓸 수 있습니다.

## 4.5.1. 형태

```
closure_expr   ::= capture_list? closure_params return_type? closure_body
closure_params ::= "||"
                 | "|" closure_param_list "|"
closure_param_list ::= closure_param ("," closure_param)* ","?
closure_param ::= identifier (":" type_expr)?
closure_body   ::= expr | block
capture_list   ::= "[" capture_item ("," capture_item)* "]"
```

매개변수가 없는 형태인 `||`는 토큰 하나입니다([구두점과 연산자 토큰](../001-lexical/110-punctuation-and-operator-tokens.md) 참고). `|` 두 개로 나뉘지 않습니다.

```rok
|매개변수들| 본체
```

매개변수는 좌우의 `|` 토큰([구두점과 연산자 토큰](../001-lexical/110-punctuation-and-operator-tokens.md))으로 감쌉니다. 본체는 식이거나 블록입니다.

### 단일 식 본체

```rok
|x| x + 1
|x: i32| x * 2
|a, b| a + b
```

`|...|` 바로 뒤에 식 하나가 옵니다. 그 식의 값이 클로저의 반환값이 됩니다.

### 블록 본체

```rok
|x: i32| -> i32 {
    let y = x * 2;
    y + 1
}
```

블록 본체일 때는 반환 타입을 `->`로 명시할 수 있습니다. 생략하면 추론합니다.

### 매개변수 없는 형태

```rok
|| body
|| { body }
```

매개변수가 없으면 파이프 두 개를 붙인 `||`를 씁니다. [구두점과 연산자 토큰](../001-lexical/110-punctuation-and-operator-tokens.md)의 고정 토큰표는 `||`를 토큰 하나로 정의합니다.

## 4.5.2. 매개변수의 타입

매개변수 타입은 명시해도 되고 생략해도 됩니다.

```rok
|x: i32| x * 2                    // 명시
|x| x * 2                          // 추론
```

생략한 타입은 클로저를 쓰는 문맥에서 추론합니다. 함수 인자로 넘기는 자리의 함수 타입, 변수 선언의 타입 등이 그 문맥입니다. 문맥이 없으면 이후의 호출이 매개변수 타입을 정합니다(`let f = |x| x * 2; f(4);`의 `x: i32`, [2.10.2](../002-types/210-generics.md#타입-인자-추론)).

```rok
let f: fn(i32) -> i32 = |x| x * 2;   // 문맥에서 x: i32 추론
list.map(|x| x * 2);                  // map 의 시그니처에서 추론
```

## 4.5.3. 반환 타입의 추론 / 명시

```rok
|x| x * 2                          // 추론
|x: i32| -> i32 { x * 2 }          // 명시 - 블록 본체일 때만
```

반환 타입 명시(`-> 타입`)는 블록 본체에서만 씁니다. 단일 식 본체는 항상 추론합니다.

## 4.5.4. 캡처

클로저는 외부 스코프의 변수를 캡처할 수 있습니다.

```rok
let n = 10;
let f = |x| x + n;                // n 을 캡처
f(5);                              // 15
```

캡처 의미론은 [캡처 의미론](406-capture-semantics.md)에서 자세히 정의합니다. 기본은 값 캡처이고, `[ref x]` 같은 캡처 리스트로 참조 캡처를 고를 수 있습니다.

## 4.5.5. 클로저와 함수

| 측면           | `fn` 명명 함수   | `\| ... \|` 클로저 |
|----------------|------------------|------------------|
| 이름           | 있음             | 없음             |
| 정의 위치      | 모듈이나 `impl`  | 모든 표현식 위치 |
| 외부 변수 캡처 | 불가             | 가능             |
| 호출           | `name(...)`      | `value(...)`     |
| 타입           | `fn(...) -> ...` | 같음             |

둘 다 같은 함수 타입이고 인터페이스가 서로 호환됩니다. 그래서 같은 자리에 어느 쪽이든 들어갈 수 있습니다.

## 4.5.6. 클로저 값의 사용

```rok
// 변수 대입
let f = |x| x * 2;

// 함수 인자
list.map(|x| x * 2);

// 함수 반환
fn make_adder(n: i32) -> fn(i32) -> i32 {
    |x| x + n
}

// 컬렉션
let handlers: List<fn(i32) -> i32> = [|x| x + 1, |x| x - 1, |x| x * 2];
```

## 4.5.7. 호출

```rok
let f = |x| x * 2;
let r = f(5);                     // 일반 함수 호출과 동일 형태
```

`f(args)` 형태로 호출합니다. 호출하면 캡처한 환경과 인자로 본체를 평가합니다.

## 4.5.8. 즉시 호출: IIFE

클로저를 정의하자마자 바로 호출할 수도 있습니다.

```rok
let r = (|x: i32| -> i32 { x * 2 })(5);     // 10
```

자주 쓰지는 않지만, 지역 스코프와 즉시 평가를 나타내는 방법 중 하나입니다. 대개는 [블록 표현식](../003-expressions/309-block-expressions.md)의 일반 블록이 더 자연스럽습니다.

## 4.5.9. 가독성: 단일 식과 블록

```rok
list.map(|x| x * 2)               // 단일 식 - 짧고 명확
list.map(|x| { let y = x * 2; y + 1 })   // 블록 - 다단계 처리
```

본체 길이에 맞는 형태를 고르면 됩니다. 사양은 두 형태를 모두 정식으로 지원합니다.

## 4.5.10. 트레일링 클로저

함수 호출의 마지막 인자가 클로저이면 괄호 밖으로 빼서 더 읽기 좋게 적을 수 있습니다. 자세한 내용은 [트레일링 클로저](408-trailing-closure.md)에서 정의합니다.

## 4.5.11. 특수 변형: `async`와 `yield` 수식어

클로저에 `async`나 `yield` 수식어를 붙이면 비동기 클로저나 제너레이터 클로저가 됩니다.

```rok
async || { ... }                  // Future 반환 클로저
yield || { ... }                  // Iterator 반환 클로저
async yield || { ... }            // Stream 반환 클로저
```

자세한 규칙은 [제너레이터](411-generators.md), [비동기](412-async.md), [스트림](413-stream.md)에서 정의합니다.

## 4.5.12. 인자 없는 클로저의 단축형: `{ body }`

특정 문맥에서는 `{ body }`를 매개변수 없는 클로저로 보는 단축 형태가 있습니다. 이 단축은 트레일링 클로저와 함께 자주 씁니다.

```rok
thread::spawn { heavy_work() }    // == thread::spawn(|| { heavy_work() })
```

이 단축의 정확한 규칙은 [트레일링 클로저](408-trailing-closure.md)에서 정의합니다.
