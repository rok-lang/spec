# 4.5. 클로저

클로저는 이름 없이 표현식 위치에 등장하는 함수 값이다. 외부 환경의 변수를 캡처할 수 있어, 주변 상태에 의존하는 작은 함수를 자연스럽게 쓸 수 있다.

## 4.5.1. 형태

```
closure_expr ::= capture_list? "|" closure_params? "|" return_type? closure_body
closure_params ::= closure_param ("," closure_param)* ","?
closure_param ::= identifier (":" type_expr)?
closure_body ::= expr | block
capture_list ::= "[" capture_item ("," capture_item)* "]"
```

```nok
|매개변수들| 본체
```

- 좌우 `|` 토큰 ([구두점과 연산자 토큰](../001-lexical/110-punctuation-and-operator-tokens.md)) 으로 매개변수를 둘러싼다.
- 본체는 식 또는 블록.

### 단일 식 본체

```nok
|x| x + 1
|x: i32| x * 2
|a, b| a + b
```

`|...|` 직후에 단일 식. 그 식의 값이 클로저의 반환값.

### 블록 본체

```nok
|x: i32| -> i32 {
    let y = x * 2;
    y + 1
}
```

블록 본체일 때는 반환 타입을 `->` 로 명시할 수 있다 (생략 시 추론).

### 0-매개변수 형태

```nok
|| body
|| { body }
```

매개변수가 없을 때는 `||` (두 파이프 연속). 토큰화는 [구두점과 연산자 토큰](../001-lexical/110-punctuation-and-operator-tokens.md) 의 고정 토큰표에서 `||` 한 토큰.

## 4.5.2. 매개변수의 타입

매개변수 타입을 명시할 수도, 생략할 수도 있다.

```nok
|x: i32| x * 2                    // 명시
|x| x * 2                          // 추론
```

추론은 클로저가 사용되는 문맥에서 결정된다. 함수 인자로 넘기는 자리의 함수 타입, 변수 선언의 타입 등.

```nok
let f: fn(i32) -> i32 = |x| x * 2;   // 문맥에서 x: i32 추론
list.map(|x| x * 2);                  // map 의 시그니처에서 추론
```

## 4.5.3. 반환 타입의 추론 / 명시

```nok
|x| x * 2                          // 추론
|x: i32| -> i32 { x * 2 }          // 명시 — 블록 본체일 때만
```

반환 타입 명시 (`-> 타입`) 는 블록 본체와 함께만 사용한다. 단일 식 본체는 항상 추론에 의존한다.

## 4.5.4. 캡처

클로저는 외부 스코프의 변수를 캡처할 수 있다.

```nok
let n = 10;
let f = |x| x + n;                // n 을 캡처
f(5);                              // 15
```

캡처의 의미론 (값 기본 / `[ref x]` 캡처 리스트) 은 [캡처 의미론](406-capture-semantics.md) 에서 자세히 정의한다.

## 4.5.5. 클로저 vs 함수

| 측면           | `fn` 명명 함수   | `\| ... \|` 클로저 |
| -------------- | ---------------- | ------------------ |
| 이름           | 있음             | 없음               |
| 정의 위치      | 모듈이나 `impl`  | 모든 표현식 위치   |
| 외부 변수 캡처 | 불가             | 가능               |
| 호출           | `name(...)`      | `value(...)`       |
| 타입           | `fn(...) -> ...` | 같음               |

같은 함수 타입으로 표현되며, 인터페이스 측면에서 서로 호환된다. 한 자리에 둘 다 적합하다.

## 4.5.6. 클로저 값의 사용

```nok
// 변수 대입
let f = |x| x * 2;

// 함수 인자
list.map(|x| x * 2);

// 함수 반환
fn make_adder(n: i32) -> fn(i32) -> i32 {
    |x| x + n
}

// 컬렉션
let handlers: List<fn(i32) -> i32> = [|x| x + 1, |x| x - 1, |x| x * 2];
```

## 4.5.7. 호출

```nok
let f = |x| x * 2;
let r = f(5);                     // 일반 함수 호출과 동일 형태
```

`f(args)` 형태로 호출. 호출 시 캡처된 환경 + 인자가 본체 평가에 사용된다.

## 4.5.8. 즉시 호출: IIFE

클로저를 정의 직후 즉시 호출하는 형태도 가능.

```nok
let r = (|x: i32| -> i32 { x * 2 })(5);     // 10
```

자주 쓰지는 않지만 지역 스코프와 즉시 평가를 표현하는 한 가지 방법이다. 대부분은 [블록 표현식](../003-expressions/309-block-expressions.md) 의 일반 블록이 더 자연스럽다.

## 4.5.9. 단일 식 vs 블록의 가독성

```nok
list.map(|x| x * 2)               // 단일 식 — 짧고 명확
list.map(|x| { let y = x * 2; y + 1 })   // 블록 — 다단계 처리
```

본체 길이에 따라 자연스러운 형태를 고른다. 사양은 둘 다 정식 지원.

## 4.5.10. 트레일링 클로저

함수 호출의 마지막 인자가 클로저일 때, 괄호 밖으로 빼서 더 읽기 좋게 적을 수 있다. [트레일링 클로저](408-trailing-closure.md) 에서 정의한다.

## 4.5.11. 특수 변형: `async` 와 `yield` 수식어

클로저에 `async` 나 `yield` 수식어를 붙여 비동기나 제너레이터 형태의 클로저를 만들 수 있다.

```nok
async || { ... }                  // Future 반환 클로저
yield || { ... }                  // Iterator 반환 클로저
async yield || { ... }            // Stream 반환 클로저
```

자세한 규칙은 [제너레이터](411-generators.md), [비동기](412-async.md), [스트림](413-stream.md) 에서 정의한다.

## 4.5.12. 0-arg 클로저의 단축: `{ body }`

특정 문맥에서 `{ body }` 가 0-매개변수 클로저로 인식되는 단축 형태가 있다. 트레일링 클로저와 결합해 자주 쓰인다.

```nok
task::spawn { heavy_work() }      // == task::spawn(|| { heavy_work() })
```

이 단축의 정확한 규칙은 [트레일링 클로저](408-trailing-closure.md) 에서 정의한다.
