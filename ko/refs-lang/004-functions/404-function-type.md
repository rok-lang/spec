# 4.4. 함수 타입

함수와 클로저는 값이며, 그 값에는 타입이 있다. 본 문서는 [타입 표현식](../002-types/201-type-expressions.md) 의 함수 타입 형태를 자세히 다룬다.

## 4.4.1. 형태

```nok
fn(매개변수타입들) -> 반환타입
fn(i32, i32) -> i32
fn(str) -> bool
fn() -> ()
```

- `fn` 키워드 + 괄호로 둘러싼 매개변수 타입 목록 + `->` + 반환 타입.
- 매개변수 이름은 적지 않는다. 타입만.
- 반환 타입 생략 시 unit. `fn(i32, i32)` 는 `fn(i32, i32) -> ()`.

## 4.4.2. 함수 / 클로저 값의 타입

```nok
fn add(x: i32, y: i32) -> i32 { x + y }
let f = add;                                    // f: fn(i32, i32) -> i32

let g = |x: i32| -> i32 { x * 2 };              // g: fn(i32) -> i32
let h: fn(i32) -> i32 = |x| x + 1;              // 명시 타입
```

함수와 클로저는 모두 같은 함수 타입으로 표현된다. 한 자리에 둘 다 적합하다.

## 4.4.3. 변수에 대입

```nok
let f: fn(i32) -> i32 = |x| x * 2;
let g: fn(str, i32) -> str = format;
```

함수 타입 슬롯에 함수나 클로저를 대입할 수 있다.

## 4.4.4. 함수 인자 / 반환값으로 사용

```nok
fn apply(f: fn(i32) -> i32, x: i32) -> i32 { f(x) }
fn make_adder(n: i32) -> fn(i32) -> i32 { |x| x + n }
```

- 고차 함수: 함수를 인자로 받는다.
- 함수 반환: 함수를 결과로 만든다.

위 두 패턴이 함수 타입의 핵심 쓰임새다.

## 4.4.5. 컬렉션 안의 함수

```nok
let handlers: List<fn(Event) -> ()> = [...];
let dispatch: Dict<str, fn(Request) -> Response> = {...};
```

함수 타입은 다른 타입과 같이 컬렉션의 원소 타입이 될 수 있다.

## 4.4.6. 캡처가 있는 클로저

캡처가 있는 클로저도 같은 함수 타입으로 표현된다. 사용자가 보기에는 같은 인터페이스.

```nok
let n = 10;
let f: fn(i32) -> i32 = |x| x + n;     // n 을 캡처하지만 타입은 fn(i32) -> i32
```

캡처는 클로저 객체에 내부적으로 부속되며, 호출 시 자동으로 사용된다. 사용자 코드는 캡처 유무를 신경 쓸 필요가 없다. 타입에는 드러나지 않는다.

Rust 의 `Fn`, `FnMut`, `FnOnce` 트레잇 구분은 nok 에 없다. 캡처가 값 기본이라 의미상 복잡성이 줄어들기 때문이다. 자세한 캡처 의미는 [클로저](405-closure.md) 에서 정의.

## 4.4.7. 매개변수 / 반환의 점진성

함수 타입에 제네릭 매개변수를 두는 것은 본 표기에서 직접 표현되지 않는다. 제네릭 함수의 값은 호출 지점에서 단형화되어 구체 타입을 가진 함수 값이 된다.

```nok
fn id<T>(x: T) -> T { x }

let f = id;                       // ERROR — id 자체는 제네릭, 어떤 T 인지 결정 안 됨
let f: fn(i32) -> i32 = id;       // OK — i32 로 단형화
let g = id::<i32>;                // OK — turbofish 로 단형화
```

함수 타입에 동적 슬롯을 두려면 매개변수나 반환에 `any` 를 적는다.

```nok
fn(any) -> any
```

이 형태는 어떤 타입이든 받고 어떤 타입이든 반환하는 함수의 타입이다. 동적 디스패치 비용이 든다.

## 4.4.8. divergent 함수의 타입

[반환](403-return.md) 의 divergent 함수도 함수 타입으로 표현할 수 있다. 반환 타입 자리에 표준 라이브러리의 발산 타입을 둔다 (정확한 이름은 라이브러리 사양). divergent 함수는 임의의 함수 타입에 호환된다. `fn(i32) -> i32` 자리에 `fn(i32) -> 발산` 도 들어갈 수 있다.

## 4.4.9. 함수 타입의 부분 집합 관계 (없음)

> [!IMPORTANT]
> Rust 나 TypeScript 같은 언어의 함수 타입 부분형 (subtyping) 은 nok 에 없다. 한 함수 타입을 더 일반적이거나 더 구체적인 함수 타입으로 자동 변환하지 않는다. 매개변수와 반환 타입은 정확히 일치해야 한다.

```nok
let f: fn(i32 | f64) -> i32 = |x: i32| x;     // ERROR — 매개변수 타입이 정확히 일치 안 함
```

매개변수와 반환 타입은 정확히 일치해야 한다.

이 결정의 동기는 명시성 우선이다. 함수 변환은 [형 변환](../002-types/214-cast-and-conversion.md) 의 명시적 형태로 사용자가 적도록 한다.

## 4.4.10. 함수 타입의 평가

함수 타입은 값을 만들지 않는 타입이다. 어떤 모양의 함수가 받힐지에 대한 명세일 뿐이다. 평가 동작은 없다.

함수의 호출 동작은 [멤버 접근과 메서드 호출](../003-expressions/305-member-access-and-method-call.md) 의 일반 호출 규칙을 따른다 (`f(...)` 형태).

## 4.4.11. 매개변수 이름의 부재

함수 타입에는 매개변수 이름이 없다. 정의 (`fn name(x: i32)`) 에는 이름이 있지만, 타입 표기 (`fn(i32)`) 에서는 위치만 있다.

```nok
fn(i32, i32) -> i32                // OK
fn(x: i32, y: i32) -> i32          // ERROR — 함수 타입에 이름 없음
```

호출 시 named 인자 ([매개변수](402-parameters.md)) 는 함수 정의의 이름을 본다. 함수 타입을 거쳐 호출하면 named 인자가 작동하지 않는다 (값을 통한 호출은 위치 인자만).

```nok
fn make_user(name: str, age: i32) -> User { ... }
let f: fn(str, i32) -> User = make_user;

make_user(name: "A", age: 30i32);    // named OK — 정의 이름 사용
f("A", 30i32);                        // 위치 OK
f(name: "A", age: 30i32);             // ERROR — 타입에 이름 없음
```
