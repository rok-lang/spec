# 4.8. 트레일링 클로저

함수나 메서드 호출의 마지막 인자가 클로저일 때, 그 클로저를 괄호 밖으로 빼서 더 자연스러운 형태로 적을 수 있다.

## 4.8.1. 형태

```
trailing_call   ::= primary "(" arg_list? ")" trailing_closure
                  | primary trailing_closure                    // 0-arg call
trailing_closure ::= ("|" closure_params? "|")? block
```

```nok
함수(인자들) |매개변수| { 본체 }
함수(인자들) { 본체 }            // 0-매개변수 단축
```

- 호출 괄호 직후에 클로저가 위치.
- 본체는 [블록 표현식](../003-expressions/309-block-expressions.md) 의 블록.

### 0-매개변수 단축: `{ body }`

매개변수가 없는 클로저는 `|| { body }` 대신 `{ body }` 형태로 단축된다.

```nok
let t = task::spawn { heavy_work() };
// == task::spawn(|| { heavy_work() })

with_lock(mutex) { critical_section() };
```

이 단축은 함수 호출 직후의 `{ ... }` 에서만 의미가 있다. 다른 자리의 `{ ... }` 는 [블록 표현식](../003-expressions/309-block-expressions.md) 의 일반 블록 표현식.

### 1+ 매개변수

```nok
let doubled = xs.map |x| { x * 2 };
let pos = xs.filter |x| { x > 0 };
let opened = with_file(path) |f| {
    let data = f.read();
    process(data)
};
pairs.for_each |k, v| { print(k, v) };
```

- 파이프 (`|...|`) 는 괄호 밖, 본체 직전에 위치.
- 본체는 블록. `|x| body` 한 줄 형태가 아니라 항상 `|x| { body }` 형태.

트레일링 클로저는 가독성과 일관성을 위해 블록 본체를 기본으로 한다.

## 4.8.2. 명시 괄호와의 자유 선택

트레일링 클로저는 허용이지 강제가 아니다.

```nok
xs.map(|x| x * 2);                // 명시 괄호 — OK
xs.map |x| { x * 2 };              // 트레일링 — OK
```

팀이나 사용자 스타일에 따라 자유롭게 고를 수 있다.

## 4.8.3. 함수 호출의 마지막 인자가 아닌 경우

트레일링 클로저는 마지막 인자 자리만 채울 수 있다. 클로저가 중간 인자라면 명시 괄호를 쓴다.

```nok
fn process(input: str, transform: fn(str) -> str, output: str) -> str { ... }

process("in", |s| { s.to_upper() }, "out");           // 명시 괄호 (중간 인자)
process("in", "out") |s| { s.to_upper() };            // ERROR — 트레일링은 마지막 자리만
```

## 4.8.4. 인자 0 개 호출

호출에 인자가 없을 때, 빈 괄호도 생략 가능.

```nok
task::spawn { heavy() };          // task::spawn() { heavy() } 와 동일
                                   // == task::spawn(|| { heavy() })
```

`task::spawn` 의 매개변수가 클로저 한 개라면 위 형태가 가장 자연스러운 호출.

## 4.8.5. 중첩

트레일링 클로저는 자유롭게 중첩할 수 있다.

```nok
par::scope |s| {
    s.spawn { f() };
    s.spawn { g() };
};
```

내부 클로저에도 같은 단축 규칙 (`{ body }` ↔ `|| { body }`) 을 적용할 수 있다.

## 4.8.6. 파서 모호성 처리

트레일링 클로저의 도입은 일부 코드가 블록 표현식 또는 트레일링 클로저로 해석될 수 있는 모호함을 만든다. 다음 규칙으로 해소한다.

| 위치                                                                     | 의미                                             |
| ------------------------------------------------------------------------ | ------------------------------------------------ |
| 제어 키워드 (`if`, `else`, `for`, `while`, `loop`, `match`) 뒤 `{ ... }` | 제어 본체                                        |
| 함수 호출 직후 `{ ... }`                                                 | 트레일링 클로저 (0-arg)                          |
| 함수 호출 직후 `\|params\| { ... }`                                      | 트레일링 클로저 (1+ arg)                         |
| `x = { ... };` 같은 일반 표현식 자리 `{ ... }`                           | 블록 표현식 (or 0-arg 클로저 호출 — 문맥에 따라) |
| 식 안 `\|...\| { ... }`                                                  | 일반 클로저 식                                   |

핵심 규칙: 함수 호출 직후 (`(args)`) 에 공백이 있어도 없어도 `{ ... }` 또는 `|...| { ... }` 가 따라오면 트레일링 클로저다.

## 4.8.7. `{}` 단독의 일반 블록과 0-arg 클로저

```nok
let x = { 42 };                   // 블록 표현식 (값 42)
let f = { 42 };                   // ??
```

위 두 줄은 문맥상 같은 형태다. 어떤 의미가 우선일까.

규칙: `{ body }` 가 식 자리에 단독으로 등장하면 블록 표현식이다.

0-arg 클로저를 의도하려면 명시적 `|| { body }` 를 적는다.

```nok
let f = || { 42 };                // 명시 0-arg 클로저
let r = f();                       // 호출
```

함수 호출 직후의 `{ body }` 만 트레일링 클로저로 인식된다.

## 4.8.8. par `for` 같은 문 자리의 클로저

병렬 루프, 트랜잭션, 컨텍스트 매니저 같은 자리에서 트레일링 클로저는 키워드처럼 읽히는 DSL 친화적 형태를 만든다.

```nok
par::for_each(xs) |x| { ... }     // par for 처럼 보임
with_lock(mutex) { ... }           // with-statement 처럼 보임
retry(3) { ... }                   // retry 키워드처럼 보임
```

이는 [키워드](../001-lexical/105-keywords.md) 의 예약 키워드 최소화 원칙과 일관된다. 라이브러리 함수와 트레일링 클로저를 결합해 제어 흐름처럼 읽히는 패턴을 만들 수 있다.

## 4.8.9. 이름 있는 인자와의 결합

```nok
fn run(ref state: State, name: str = "task") |body: fn() -> ()| { ... }

run("compute") { ... };           // 위치 + 트레일링 OK
run(name: "compute") { ... };     // named + 트레일링 OK
```

위치 인자와 named 인자, 트레일링 클로저는 자유롭게 결합할 수 있다.

## 4.8.10. 정리

트레일링 클로저는 사양 수준에서 추가 키워드 없이 DSL 같은 표현을 가능하게 한다. 사용자가 언어 키워드처럼 보이는 패턴을 라이브러리로 만들 수 있다.
