# 3.11. `os::` - what only some OSes have

The cross-platform modules (`fs`, `net`, `process`, `io`) hold what every desktop OS can do. What only some OSes have lives under `rok::std::os`, in one module per OS family, as Rust splits it:

| Module | Exists on | Holds |
|---|---|---|
| `os::unix` | `target_family = "unix"` (Linux, macOS, FreeBSD) | `fs`, `io`, `net`, `process` |
| `os::linux` | `target_os = "linux"` | `net`, `process` |
| `os::windows` | `target_os = "windows"` | `fs`, `io`, `process` |

The `fs` parts of `os::unix` and `os::windows` (`PermissionsExt`, `DirExt`, `OsOpenFlags`, `OsCreateFlags`, `CreateFileParams` and the flag constants) are specified with the file types in [3.1.1](301-fs.md#311-core-types); the sections below cover the rest.

A module exists only on its targets: on any other target `use rok::std::os::unix::..` does not resolve. Code that uses one is written under the same `#[cfg]`.

## 3.11.1. Ext traits in the prelude

Methods that only some OSes have are trait methods on the cross-platform types: `PermissionsExt` adds `mode` to `fs::Permissions`, `CommandExt` adds `process_group` to `process::Command`, and so on. On the targets where the trait exists, it is in the prelude ([0.2](../000-meta/002-import.md)), so its methods need no `use`:

| Targets | Prelude names added |
|---|---|
| unix | `PermissionsExt` (`os::unix::fs`), `CommandExt`, `ExitStatusExt` (`os::unix::process`) |
| linux | the unix ones, and `ChildExt` (`os::linux::process`), `TcpStreamExt` (`os::linux::net`) |

On other targets the trait and its impls do not exist, and a call is the not-found error that names the cfg the method needs ([refs-lang 6.3](../../refs-lang/006-meta-system/603-cfg.md)):

```text
error: no method `process_group` found for type `Command`
 = note: `process_group` is only available on unix (`#[cfg(target_family = "unix")]`)
 = help: put the code that uses it under the same `#[cfg(target_family = "unix")]`
```

The raw-handle traits (`AsRawFd`, `AsRawHandle`, ..) are not in the prelude: they are imported where they are used.

## 3.11.2. `os::unix::io` - file descriptors

```rok
// rok::std::os::unix::io
type RawFd = i32;

trait AsRawFd {
    fn as_raw_fd(self) -> RawFd;             // still owned by self; -1 once self is closed
}

trait FromRawFd {
    unsafe fn from_raw_fd(fd: RawFd) -> Self;    // self owns fd from now on
}
```

`AsRawFd` is implemented by `File`, `Socket`, `TcpStream`, `TcpListener`, `UdpSocket`, the Unix sockets (3.11.4), `ChildStdin` / `ChildStdout` / `ChildStderr` and `Stdin` / `Stdout` / `Stderr` (0, 1, 2). `FromRawFd` is implemented by `File` (its errors name it `fd N`) and the sockets. `from_raw_fd` is `unsafe`: `fd` must be open, and nothing else may close it, or two owners close one descriptor (and the second close may hit a file opened since).

The descriptor stays owned by the handle: closing the handle closes it, and `as_raw_fd` returns -1 from then on. A socket adopted with `from_raw_fd` is used as it is; a blocking descriptor makes the blocking calls block in the OS rather than in `poll` (timeouts and `set_nonblocking` then do not apply).

## 3.11.3. `os::windows::io` - handles and sockets

```rok
// rok::std::os::windows::io
type RawHandle = isize;                  // a Win32 HANDLE, pointer-sized
type RawSocket = u64;                    // a Winsock SOCKET

trait AsRawHandle { fn as_raw_handle(self) -> RawHandle; }       // INVALID_HANDLE_VALUE (-1) once closed
trait FromRawHandle { unsafe fn from_raw_handle(h: RawHandle) -> Self; }
trait AsRawSocket { fn as_raw_socket(self) -> RawSocket; }       // INVALID_SOCKET once closed
trait FromRawSocket { unsafe fn from_raw_socket(s: RawSocket) -> Self; }
```

`AsRawHandle` is implemented by `File`, the child pipes and the standard streams (their `GetStdHandle` values); `FromRawHandle` by `File`. `AsRawSocket` and `FromRawSocket` are implemented by `Socket`, `TcpStream`, `TcpListener` and `UdpSocket`. The values are the HANDLE and the SOCKET exactly as Win32 gives them; how the runtime keeps them is not visible. A `from_raw_handle` value that is not a kernel object handle (a pseudo-handle such as `GetCurrentProcess()`) gives a closed `File`.

## 3.11.4. `os::unix::net` - Unix domain sockets

Unix domain sockets come in three types: `UnixListener`, `UnixStream` and `UnixDatagram`. Their shape resembles TCP ([3.2](302-net.md)), but since they communicate only within the same host they use file paths as identifiers, and they provide `pair()`, corresponding to `socketpair(2)`. Fd passing through `SCM_RIGHTS` is meaningful only on Unix sockets, so it is split out into `send_with_fd` / `recv_with_fd`.

```rok
// rok::std::os::unix::net
struct UnixListener { /* opaque */ }
struct UnixStream { /* opaque */ }
struct UnixDatagram { /* opaque */ }

impl UnixListener {
    fn bind(path: Path) throws (IoError) -> UnixListener;             // path must not exist yet; backlog 128
    fn accept(self) throws (IoError) -> (UnixStream, Path | none);   // peer's bound path, none if unnamed
    async fn accept_async(ref self) throws (IoError) -> (UnixStream, Path | none);
    fn local_addr(self) throws (IoError) -> Path | none;
    fn set_nonblocking(self, nb: bool);
    fn try_clone(self) throws (IoError) -> UnixListener;
    fn close(self) throws (IoError);   // throws what the OS reports
}

impl UnixStream {
    fn connect(path: Path) throws (IoError) -> UnixStream;
    async fn connect_async(path: Path) throws (IoError) -> UnixStream;   // on a blocking thread
    fn pair() throws (IoError) -> (UnixStream, UnixStream);          // socketpair
    fn send_with_fd<B: AsBytes>(self, buf: B, fd: RawFd) throws (IoError) -> usize;
    fn recv_with_fd(self, buf: SliceMut<u8>) throws (IoError) -> (usize, RawFd | none);
    async fn send_with_fd_async<B: AsBytes>(ref self, buf: B, fd: RawFd) throws (IoError) -> usize;
    async fn recv_with_fd_async(ref self, buf: SliceMut<u8>) throws (IoError) -> (usize, RawFd | none);
    fn peer_addr(self) throws (IoError) -> Path | none;
    fn local_addr(self) throws (IoError) -> Path | none;
    fn shutdown(self, how: Shutdown) throws (IoError);
    async fn shutdown_async(ref self, how: Shutdown) throws (IoError);   // shutdown never waits
    fn set_read_timeout(self, dur: Duration | none);
    fn set_write_timeout(self, dur: Duration | none);
    fn set_nonblocking(self, nb: bool);
    fn try_clone(self) throws (IoError) -> UnixStream;
    fn close(self) throws (IoError);   // throws what the OS reports
}

impl UnixDatagram {
    fn bind(path: Path) throws (IoError) -> UnixDatagram;
    fn connect(path: Path) throws (IoError) -> UnixDatagram;         // connected to path, itself unbound
    async fn connect_async(path: Path) throws (IoError) -> UnixDatagram;   // never waits
    fn pair() throws (IoError) -> (UnixDatagram, UnixDatagram);      // socketpair
    fn send<B: AsBytes>(self, buf: B) throws (IoError) -> usize;
    fn recv(self, buf: SliceMut<u8>) throws (IoError) -> usize;
    fn send_with_fd<B: AsBytes>(self, buf: B, fd: RawFd) throws (IoError) -> usize;
    fn recv_with_fd(self, buf: SliceMut<u8>) throws (IoError) -> (usize, RawFd | none);
    // + send_async / recv_async / send_with_fd_async / recv_with_fd_async (ref self)
    fn local_addr(self) throws (IoError) -> Path | none;
    fn set_read_timeout(self, dur: Duration | none);
    fn set_write_timeout(self, dur: Duration | none);
    fn set_nonblocking(self, nb: bool);
    fn close(self) throws (IoError);   // throws what the OS reports
}

impl io::Read for UnixStream { ... }
impl io::Write for UnixStream { ... }
impl io::AsyncRead for UnixStream { ... }
impl io::AsyncWrite for UnixStream { ... }
impl io::Close for UnixListener { ... }   // and UnixStream, UnixDatagram
impl io::AsyncClose for UnixListener { ... } // and UnixStream, UnixDatagram
impl Drop for UnixListener { ... }       // releases on an error path
impl Drop for UnixStream { ... }
impl Drop for UnixDatagram { ... }
// + AsRawFd, FromRawFd for all three
```

The common rules of 3.2.0 apply: non-blocking underneath, `set_*_timeout` bounds the blocking calls, `*_async` suspend the task. A stream `connect` waits only while the listener's backlog is full; `connect_async` runs it on a blocking thread. A descriptor received with `recv_with_fd` is the caller's (close-on-exec); hand it to an owner with `FromRawFd`.

## 3.11.5. `os::unix::process` and `os::linux::process`

```rok
// rok::std::os::unix::process
trait CommandExt {
    fn process_group(self, pgid: i32) -> Self;   // 0: a new group the child leads
}
impl CommandExt for Command { .. }

trait ExitStatusExt {
    fn signal(self) -> Signal | none;            // the signal that ended it
}
impl ExitStatusExt for ExitStatus { .. }

fn parent_id() -> u32;                           // getppid

// rok::std::os::linux::process
trait ChildExt {
    fn pidfd(self) throws (IoError) -> RawFd;    // Linux 5.3+; valid until the child is reaped
}
impl ChildExt for Child { .. }
```

`ExitStatusExt::signal` is `none` when the process exited, and also for a signal `Signal` does not name (a real-time signal). The pidfd stays the child's: `wait` / `try_wait` close it.

## 3.11.6. `os::linux::net` - kernel copies

For places where throughput is the cost, such as proxies or file servers, the Linux kernel copy paths are exposed on `TcpStream`. Most users do not need them; `io::copy` already uses them where it can.

```rok
// rok::std::os::linux::net
trait TcpStreamExt {
    fn sendfile(self, ref file: File, offset: u64, count: u64) throws (IoError) -> u64;
                                            // sendfile(2): the bytes sent, fewer if the file ends
    fn splice(self, ref src: File, count: u64) throws (IoError) -> u64;
                                            // splice(2) through a kernel pipe, from src's offset
    fn write_zerocopy(self, buf: List<u8>) throws (IoError) -> usize;
                                            // MSG_ZEROCOPY (Linux 4.14+): some prefix of buf, read in place
}
impl TcpStreamExt for TcpStream { .. }
```

`write_zerocopy` returns once the kernel no longer needs `buf`.

## 3.11.7. `os::windows::process` - Ctrl-Break

```rok
// rok::std::os::windows::process
fn on_ctrl_break(handler: fn() + Send) throws (IoError);
```

`process::on_signal` routes the console events that have a `Signal` (Ctrl-C as `Interrupt`, console close / logoff / shutdown as `Hangup`, [3.7.5](307-process.md#375-signal-handling-advanced)). Ctrl-Break has no Unix counterpart, so it is this Windows-only function: `handler` runs on the `rok-signal` dispatcher thread each time the console sends Ctrl-Break, and a later call replaces it. Without a handler, Ctrl-Break ends the process (the console's default).
